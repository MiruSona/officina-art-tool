# 좋은 도트의 기준

PIL 로 그리든 PixelLab 으로 뽑든 같은 기준이다. **숫자 값의 정본은 프로필 · 템플릿 파일**이고(`arttool profile show` · `arttool template show`),
여기에는 「왜 그 값인가」와 사람이 고르는 기준만 적는다.
근거는 ArtTool `Docs/Research/` 의 조사 문서 셋이다 — 아래 괄호의 「강좌자료」 = `2026-10-04-도트강좌자료조사.md`,
「denchan」 = `2026-10-04-X도트강좌조사-denchan.md`, 「다른작가」 = `2026-10-04-X도트강좌조사-다른작가.md` 의 그 절.

## 그리기 전에 정할 셋

1. **빛 방향** — 하나로 정하고 끝까지 같게. 프로필 `style.light`(`top_left` · `top` · `top_right`).
2. **외곽선 방식** — 아래 넷 중 하나. 프로필 `style.outline`.
3. **팔레트(램프)** — 색표를 먼저 정하고 그 안에서만 칠한다. 바탕색도 팔레트의 한 칸이다.

기준 그림이 있으면 셋을 `arttool style extract` 로 재서 프로필 조각을 받는다 (강좌자료 4장 나-2 · denchan 3절 「색 · 팔레트」).
**종류별로 뽑는다**(`--by-folder`, 하위 폴더 char · obj · tile · bldg · bg … 마다 따로). 무리 전체로 뽑으면 캐릭터 · 건물 · 타일의 외곽선 · 빛이 섞여 표가 늘 갈린다 —
실물에서 종류별로는 char black · tile selout · bldg selout · obj none 처럼 하나씩 모였다.

## 그리는 순서

**실루엣(한 색) → 흑백 도트 선화 → 색 · 그림자 → 외곽선 색 맞추기 → AA · 하이라이트 → 외톨이 · 잡색 치우기.**
단계마다 실제 크기(1배)에서 읽히는지 보고 넘어간다. 이펙트도 흰 1색 모양을 먼저 맞추고 색을 입힌다
(강좌자료 4장 나-1 · denchan 3절 「그리는 순서」 · 「프레임 공식」).

## 크기 고르기 · 작은 캐릭터

| 크기 | 무엇까지 그리나 | 등신 |
| --- | --- | --- |
| 8 | 기호. 눈 1점 · 입 1덩이, 몸은 덩어리 둘 | 1~1.5 |
| 16 | 아이콘 · 첫걸음. 눈은 2px 카드, 볼 · 머리 모양 | 2~3 (SD 는 머리 : 몸 = 1 : 1) |
| 32 | 눈 카드 3px, 머리결 · 옷 장식부터 | 3~4 |
| 48~64 | 장식 · 주름까지 (덩어리를 먼저 맞춘 뒤) | 4 (`tall`) |
| 48×64 · 64×80 (세로 캔버스) | **SD 캐릭터의 기본.** 머리가 몸의 절반 가까이 · 눈은 머리 아래쪽 · 짧은 다리 | 약 2 (`sd`) |

- **외곽선 몫 = (4n−4)/n²** — 1px 외곽선이 그림 넓이에서 차지하는 몫. 8 → 44% · 16 → 23% · 32 → 12% · 64 → 6%.
  **16 이하는 외곽선을 빼거나 색 대비로 가르는 쪽을 먼저 본다** (다른작가 3절 외곽선 · 강좌자료 3장 「외곽선」).
- 눈 줄은 머리 위 ~ 턱 가운데. 작은 눈은 모양을 외워 둔 「카드」로 찍는다 (denchan 3절 「크기와 추상화」).
- 아이콘 · 작은 소품은 **알아보기 쉬운 특징 하나**에 몰아준다 (강좌자료 3장 「작은 캐릭터 · 읽힘」).
- 1px 이 인상을 바꾼다. 얼굴은 1px 씩 옮기며 고친다.
- 템플릿 `char_small` 이 이 표를 크기별 가이드 줄(머리 상자 · 눈 카드 · 가랑이 · 무릎 · baseline)로 그려 준다.
  프리셋은 셋 — `sd`(약 2등신, **64 미만 크기와 48×64 · 64×80 · 72×88 의 기본**) · `chibi` · `tall`(4등신, 64×64 의 기본).
  실물 게임 캐릭터(48×64)는 1.65~2.1등신이었다 — 강좌의 「32 = 3~4등신」 보다 머리가 크다. 화풍에 맞는 쪽을 `--preset` 으로 고른다.

## 외곽선 다섯 방식

| 방식 | 모양 | 고를 때 |
| --- | --- | --- |
| `none` | 선 없음, 색 대비로 가른다 | 16px 이하 · 이펙트 · 평평한 화풍 |
| `black` | 검정(또는 팔레트 `outline` 색) 1색 | 1-bit · 레트로. 그림이 어둡고 납작해지기 쉽다 |
| `solid` | 검정이 아닌 한 색 선(진한 갈색 · 회색 등) | 검정은 너무 세고 selout 은 손이 많이 갈 때. `outline("solid", color="#3A2A30")` |
| `selout` | 칠한 색의 어두운 색 | 대부분의 완성본이 이것 |
| `selout+light` | `selout` + 빛 쪽만 밝게 | 입체감을 더 줄 때 |

- 땅에 닿는 아랫선은 진하게, 부위를 가르는 안쪽선은 바깥선보다 밝아도 된다.
- 큰 그림(건물 · 큰 물건)은 2px 두께 선이 흔하다 — `outline(…, width=2)`. 검사는 가장자리와 1~3px 안쪽을 견줘 2px 선도 선으로 본다.
- `check` 의 `outline` 검사가 그림의 방식을 판정해 프로필과 다르면 경고한다 (denchan 3절 「외곽선」 · 강좌자료 3장 「외곽선」).

## 색 수 · 램프

- **색 수 눈금** : 게임 전체 16~32 · 캐릭터 6~12(부위당 2~3) · 16×16 은 4~8. `check` 의 `color_cap` 기본 표는 8 → 4 · 16 → 8 · 32 → 16 · 48 → 44 · 64 → 48 · 128 → 48 · 256 → 64 (배경은 64).
  48 이상 칸은 실물 게임 그림(건물 · 큰 물건이 40~55색)에 맞춰 넉넉히 잡았다. 작은 그림은 강좌 값 그대로라 더 빠듯하다.
- **램프 = 한 색의 어두운 칸부터 밝은 칸까지 4~6단.** 칸마다 색조를 조금씩 돌린다 — **어두울수록 차갑게(파랑 쪽), 밝을수록 따뜻하게(노랑 쪽)**. 이것이 「색조 이동(hue shift)」이다.
  밝기만 바뀌고 색조가 그대로면 탁해 보인다 (강좌자료 3장 「색 · 팔레트」). 강좌는 칸마다 약 +20° 지만, 실물 게임 그림은 4~11° 로 더 작았다 —
  그래서 `palette_ramp` 템플릿 · `shade` 기본은 **칸마다 10° 이하, 처음 ~ 끝 36° 이하**로 칸 수에 맞춰 줄인다(5칸 9° · 6칸 7.2°).
  프로필 팔레트에 `hue_step` 이 있으면 그 값을 쓴다.
- **금속은 반대** — 밝은 쪽이 차갑고 채도 낮다. 재질별 단 수 : 점액 4 · 목재 4~5 · 돌 5 · 얼음 6 · 보석 7 · 천은 하이라이트 거의 없음 (강좌자료 3장 「재질」 표).
- 램프 초안은 `arttool template render palette_ramp --size 16 --base #RRGGBB --material stone --out pal` 또는 코드에서 `shade(base, steps, hue_step, metal=…)`.
- 순검정 바탕 · 높은 채도 + 높은 명도를 같이 쓰지 않는다.

## AA (계단 다듬기)

- 반투명이 아니라 **중간색 칸**을 손으로 넣는다. 자동 AA 는 끈다.
- 곧은 선 · 45° 에는 넣지 않는다. 선 한쪽에만. 덮인 넓이 3×3 기준으로 100 / 67 / 33 / 0% 단계.
- 바깥 가장자리는 배경을 모르면 넣지 않는다. AA · 하이라이트는 마지막 단계 (다른작가 3절 AA · 강좌자료 3장 「AA」).

## 선 · 둥근 모양

- 곧은 선은 계단 길이가 모두 같다(1·1·1 · 2·2·2). 1·2·1·2 처럼 오르내리면 들쭉날쭉하다.
- 곡선은 계단 길이가 한 방향으로만 바뀐다(줄다가 → 늘다가).
- 둥근 모양 : 정사각 → 모서리 깎기 → 바깥 2점씩 더 (`round_box` 가 이 절차) (다른작가 3절 · 강좌자료 3장 「선 · jaggies」).
- 같은 색 2×2 이상이 선 위에 뭉치면 칸이 보인다.

## 배율 · 내보내기

- **정수 배 + nearest** 만. 한 화면에 섞는 해상도는 2가지까지.
- 줄이거나 키운 그림은 그대로 쓰지 않고 다시 손본다(실루엣 → 빠진 것 → 뺄 것). 「축소만 하면 실패」 (강좌자료 3장 「크기 바꾸기 · 배율」 · denchan 3절 「표시 배율」).

## 애니 프레임 공식 (요지)

| 동작 | 프레임 · 한 칸 길이 | 메모 |
| --- | --- | --- |
| 걷기 | 6 · 8 · 12장, 100ms | 몸 위아래 1~2px, contact 다음이 가장 낮다 |
| 달리기 | 8장, 80ms | 한 다리 4포즈 × 2 |
| idle | 2 · 3 · 6장 (1-2-3-2), 약 100ms | 1px 오르내림, 덩치 그대로 |
| 공격 | 공격 3 + 복귀 4 | 플레이어는 준비 프레임을 뺀다 |
| 이펙트 | 최소 4장, 60~80ms | 대비 → 흰 번쩍 → 모양 → 사라짐 |
| 고리 폭발 | 16×16 · 5장 · 흰 1색 | 2×2 점 → 꽉 찬 원 → 2px 고리 → 1px 고리 → 끊긴 고리 |

- 반복 애니는 **마지막 장이 첫 장 바로 앞**이어야 이음새가 안 보인다 (`loop_seam` 검사).
- 머리카락 · 천 · 오라처럼 흔들리는 것은 **움직임 가이드(점 N개 · 위상 지연)를 먼저** 만들고 따라 깎는다 (`motion_guide` 템플릿).
- 근거 : 강좌자료 3장 「애니메이션 — 캐릭터」 · 「— 이펙트」 · denchan 3절 「프레임 공식」 · 다른작가 3절 애니.
- 템플릿 `cycle_char`(walk · run · idle · attack) · `fx_ring_burst` · `fx_sparkle` · `fx_dust` 가 이 표를 밑판으로 그린다.

## 검사가 보는 것과 고치는 법

`arttool check` 는 **실패 규칙 다섯**(색 수 상한 · 램프 밖 색 · 반투명 · baseline · bbox 흔들림)과 **경고 여덟**을 본다.
경고는 `status` 를 안 바꾼다. 문턱 값은 프로필 `check.warn.<이름>` 에 있다.

| 경고 | 보는 것 | 고치는 법 |
| --- | --- | --- |
| `integer_scale` | 한 장 안에 도트 굵기(×1 · ×2 …)가 섞였나 · bilinear 처럼 부드럽게 키운 흔적 | 키운 그림을 원래 크기로 줄이거나 그 크기에서 다시 그린다 |
| `outline` | 외곽선 방식 판정(`none` · `black` · `solid` · `selout` · `selout+light` · `mixed`)이 `style.outline` 과 다른가 | 외곽선 색을 방식에 맞춰 바꾼다. 원래 검은 물건이면 무시 |
| `isolated` | 8이웃에 같은 색이 없는 외톨이 칸의 몫 (문턱 15% — 결 묘사 점은 게임 그림에도 흔해서 넉넉하다) | 이웃 색으로 덮는다. 눈 하이라이트처럼 「강한 점 하나」는 남긴다 |
| `color_cap` | 크기에 비해 색이 많은가 | 비슷한 색을 합치고 램프로 정리 |
| `near_colors` | RGB 각 칸 4 이하로 붙은 색 쌍이 20쌍 이상 (AI 잡색) | 적게 쓰인 쪽을 많이 쓰인 쪽으로 합친다 (`items` 에 후보) |
| `ramp_shape` | 램프 단 수 · 밝기 순서 · 색조 이동 | 램프 파일을 고친다 (그림이 아니라 팔레트를 본다) |
| `loop_seam` | 반복 애니 마지막 → 첫 장이 튀나 · 첫 장과 같나 | 마지막 장을 첫 장 바로 앞 모양으로 |

**템플릿을 주면**(`--template work/guide/template.json`) 템플릿 값이 문턱이 되고 `template.frames` · `template.size` · `template.colors` 대조가 붙는다.
그리고 **최소 규칙 `must`** 를 본다 — 넷뿐이다.

| 낱말 | 뜻 | 어기면 |
| --- | --- | --- |
| `canvas` | 그림 크기 = 템플릿 크기 | 크기를 맞춘다. 받은 그림을 `trim` 하면 여기서 걸린다 → `intake --no-trim` |
| `alpha` | 반투명 칸 없음 | 알파를 0 · 255 로 (`cutout` · 다시 칠하기) |
| `scale` | 정수 배율 · 부드러운 확대 없음 | 위 `integer_scale` 과 같다 |
| `palette` | 팔레트 밖 색 없음 (팔레트가 있을 때만) | 램프 색으로 바꾼다 |

이펙트 · 움직임 템플릿은 `palette` 가 빠진다 (흰 1색 이펙트는 게임 팔레트 밖일 때가 많다).
보고 맨 위 `must_failed` 가 비어 있지 않으면 고친다.

## 사람 눈으로만 되는 것

빛 방향이 맞나 · 실루엣 · 4색 판에서 무엇인지 읽히나 · 표정과 동작의 맛 · 무엇을 뺄지 고르기.
이것은 `arttool sheet --in clean --kinds zoom,silhouette,colors4,blur --label --out sheet.png` 가 낸 판을 **열어서** 본다 (강좌자료 4장 다).
