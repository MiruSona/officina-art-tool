# ArtTool 명령 안내 — 2026-10-04 개선 판 · 피드백 후속 판

README 의 「명령」 표에서 한 줄로만 적은 새 명령의 자세한 쓰는 법이다.
설계 근거는 `Docs/Design/2026-10-04-ArtTool개선설계.md`, 실물로 잰 숫자는 `Docs/Research/2026-10-04-실물시험.md` 를 본다.
**숫자 문턱의 정본은 프로필 · 템플릿 파일이다.** 여기 적은 값은 대표 값이고, 실제 값은 `arttool --profile P profile show` · `arttool template show <이름>` 으로 본다.

## 0. 모든 새 명령에 같은 것

### 원본 보호

- **쓸 자리가 읽은 그림과 같으면 아무것도 쓰기 전에 종료 2 로 거절한다.** 경로는 링크를 풀고 대소문자를 맞춰 견준다.
  한 곳(`arttool.paths.guard_overwrite` · `guard_outside`)에서 보므로 cutout · trim · intake · sheet · layers diff/mask/view/export · split · ui preview 가 다 같다.
- 「읽는 폴더 안에 쓰기」도 막는다 — 겹 묶음 폴더 안에 `layers view` 미리보기, `intake --out` 안에 `--sheet` 비교판 같은 것.
- `--report` 는 **`.json` 파일만** 받고, 입력 · 출력 PNG 와 같은 경로면 거절한다.
- `template render` 도 템플릿 원본 파일 · `--over` 그림을 못 덮는다.

### 보고 꼴

모든 명령이 JSON 보고를 낸다(`--report` 로 파일, `--json` 이면 화면에도).

| 칸 | 뜻 |
| --- | --- |
| `status` | `ok` · `warn` · `fail`. `fail` 이면 종료 4, 나머지는 종료 0 |
| `warnings` | 걸린 경고만 `{rule, ok: false, detail, items}` 꼴로. **`status` 를 안 바꾸고 `bake` 도 안 막는다** |
| `must_failed` | 템플릿의 최소 규칙(`canvas` · `alpha` · `scale` · `palette`)을 어긴 낱말 목록. 비어 있지 않으면 꼭 고친다 |
| `skipped_files` | `check` 가 건너뛴 가이드 파일 (아래 2절) |

- **실패 까닭은 `failed`(걸린 규칙 이름) · `rules`(규칙마다 `{rule, ok, detail, items}`), 경고는 `warnings` 에 있다.** `warnings` 만 보면 실패를 놓친다.
- `rules[].items` 꼴은 규칙마다 다르다 — `alpha` 는 파일 이름 글자 목록, `max_colors`(낱장) 는 `{where, colors, limit, ok, …}` 사전 목록.
- **색 수는 불투명 칸만 센다.** PIL `getcolors()` 는 투명 칸의 RGB 까지 세어 수가 다르게 나온다.

종료 코드는 0 잘 됨 · 1 일반 오류 · 2 인자가 잘못됨(원본을 덮으려 함 포함) · 4 검수 실패. 전체 표는 README 「종료 코드」.

### 공통 인자 `--dry-run` · `--force` · `--provider` (2026-10-05)

명령 앞에도 뒤에도 붙지만 **받는 명령이 정해져 있다.** 그 밖의 명령에 주면 아무것도 안 하고 종료 2 로 멈추고, 받는 명령 목록을 알려 준다(전에는 조용히 무시했다).

| 인자 | 받는 명령 |
| --- | --- |
| `--dry-run` | 손질 `cutout` · `trim` · `reline` · `tint` · `merge-colors` · `intake`. 한두 장 쓰는 명령 `stitch` · `sheet` · `bands` · `anchors` · `extend period`/`ring`/`canvas` · `style ref` · `layers mask`/`view` · `ui preview`/`font` · `tile offset`/`preview`/`ldtk`/`seam` (2026-10-06). 생성 `tile place` · `provider make`. 파일을 안 쓰는 명령(`check` · `layers check` · `tile inspect` · `ui check` · `ui glyphs` · `profile show` · `template list` · `template show` · `provider list`)은 받아도 결과가 같다 |
| `--force` | `bake` · `ui bake` · `style extract` |
| `--provider` | `provider make` (안 주면 기본 제공자) |

`--dry-run` 의 뜻은 둘이다.

- **손질 · 한두 장 쓰는 명령** : 검사(원본 덮기 · 입력 폴더 안 쓰기 · 인자)는 그대로 돌고, 그림 · 비교판 · 폴더는 하나도 안 만든다. 보고에 `dry_run: true` · `would_write`(쓸 뻔한 파일 목록)가 붙고 `out` · `mark` · `mask` · `b64` · `sheet` 처럼 쓴 파일을 적던 칸은 `null`. `status` · 경고 · 종료 코드는 진짜로 돌릴 때와 같다.
  `intake` 는 검수가 쓴 그림을 다시 읽어야 해서 시스템 임시 폴더에 잠깐 쓰고 끝나면 지운다. `--out` · `--sheet` 에는 아무것도 안 생긴다. 검수 조건(`--out` 의 `frames.json` 등)은 진짜 실행과 같고, 보고에 임시 경로는 안 나온다.
  크기 상한(비교판 · 눈금 그림)과 「파일 쓸 자리가 이미 있는 폴더」 거절(종료 2)도 dry-run 에서 똑같이 걸린다.
- 폴더째 여러 파일을 쓰는 명령(`normalize` · `bake` · `split` · `recolor` · `layers compose`/`diff`/`export` · `tile blob` · `ui frame`/`import`/`icons`/`bake`/`screen` · `template render` · `style extract`)은 dry-run 을 안 받는다. 까닭은 `Docs/Todo/진행상황.md` H행 아래 표.
- **생성 명령**(`tile place` · `provider make`) : 바깥(exe · API)을 안 부르고 요청 JSON 만 쓴다.

보고(`--report`)는 dry-run 에서도 쓴다 — 보고를 출력 폴더 안에 두면 그 폴더는 생긴다.

## 1. 받은 그림 손질 — `cutout` · `trim` · `intake`

```
arttool cutout --in raw/ --out cut/ [--key edge|corner|#RRGGBB] [--tol 10] [--shave N] [--dry-run] [--report r.json]
arttool trim   --in raw/ --out t/ [--pad N] [--square] [--common] [--dry-run] [--report r.json]
arttool intake --in raw/ --out clean/ [--key …] [--tol N] [--shave N] [--pad N] [--square]
               [--template t.json] [--sheet s.png] [--no-cutout] [--no-trim] [--no-check] [--dry-run] [--report r.json]
```

- `--in` 은 PNG 한 장이나 폴더(바로 아래 `.png`)다.
- **`cutout`** — 바탕을 지운다. `edge`(기본)는 네 변에서, `corner` 는 네 모서리에서 번지고, `#RRGGBB` 는 그 색을 그림 전체에서 지운다.
  번질 때는 이웃 색이 아니라 **씨앗 색**과 견줘 그러데이션 바탕이 그림 안으로 새지 않는다. 결과 알파는 0 · 255 뿐이다.
  `--shave N` 은 바깥 N 칸을 먼저 투명으로 만든다. 이때 씨앗은 **깎아 낸 고리**에서 고른다(고리의 25% 이상인 색, 많아야 3개) — 흰 띠 안쪽의 틀 색을 씨앗으로 잡아 틀을 먹던 버그를 고쳤다.
- **`trim`** — 불투명 bbox 로 자른다. `--common` 은 폴더 전체에 bbox 하나(겹 폴더에 쓰면 쌓은 자리가 그대로). 크기가 다른 그림이 섞이면 **종료 2** 로 거절하고 다른 파일 이름 · 크기를 적는다.
  보고에 장마다 `offset: [x0, y0]` 가 있어 원래 자리로 되돌릴 수 있다.
- **`trim --canvas WxH [--anchor bottom] [--margin N]`** (2026-10-06) — 자른 그림을 W×H **투명** 판에 다시 깐다.
  `--anchor` 는 `extend canvas` 의 아홉 이름(기본 `bottom`), `--margin` 은 붙인 변에서 N 칸 띄운다(가운데 축엔 안 먹는다).
  예 : 「바닥 1칸 · 가로 가운데 · 32x32」 = `trim --canvas 32x32 --margin 1`. `--common` 과 쓰면 모든 장이 같은 자리라 프레임이 안 떨린다.
  내용 + margin 이 판보다 크면 `trim.too_big` **종료 2**(아무것도 안 씀). 가운데 축에 남는 칸이 홀수면 `trim.half_pixel` 경고(1칸은 오른쪽 · 아래로).
  `--pad` · `--square` 와 같이 못 쓰고, `--canvas` 없이 `--anchor` · `--margin` 만 주면 종료 2. 보고에 `canvas` · `anchor` · `margin` 이 붙는다(안 주면 옛 보고 그대로).
- `cutout` · `trim` 에 `--dry-run` 을 주면 아무것도 안 쓰고 보고만 낸다(위 0절). 빈 그림으로 건너뛴 장은 `would_write` 에 없다. `intake --dry-run` 도 된다(2026-10-06) — 손질한 그림 · 비교판을 `would_write` 로 보이고, 검수는 임시 폴더에서 돌린다.
- **`intake`** — cutout → trim → check → sheet 를 차례로 한 번에. 보고 하나에 `steps.<단계>` 넷과 가장 나쁜 `status` 를 묶는다.
  - **배경 그림은 cutout 을 건너뛴다.** 배경 판정(`check.background`)에 걸리고, 지운 뒤 남은 칸이 캔버스 3변 이상에 변마다 10% 이상 닿으면
    그 장은 지우지 않고 `cutout.background_kept` 경고만 남긴다(불투명 큰 배경에 구멍을 뚫던 버그). 「90% 넘게 지움」 은 멈추지 않고 경고로 둔다.
  - **이번에 쓴 파일만 검수한다**(`checked_files`, 안 본 것은 `not_checked`). 다시 돌려도 지난 판 PNG 가 섞이지 않는다.
  - check 가 `fail` 이어도 `--sheet` 비교판은 만든다(사람이 보고 고치라고). 보고는 그대로 `status: fail` · `failed_step: check` · 종료 4. cutout · trim 이 실패하면 거기서 멈춘다(비교판 없음).
  - `--sheet` 가 `--out` 안이면 거절한다. 템플릿 크기로 뽑은 그림은 `--no-trim` 을 준다(걷으면 `must.canvas` 에 걸린다).
- 경고 rule 이름 : `cutout.no_seed` · `cutout.erased_most` · `cutout.enclosed` · `cutout.edge_left` · `cutout.background_like` · `cutout.background_kept` · `cutout.emptied` · `trim.empty`.
  `intake` 맨 위 `warnings` 는 같은 꼴에 `step` 칸이 더 붙는다.

## 2. `check` 새 인자 · 경고 여덟

```
arttool check --in clean/ --report c.json [--no-ramps] [--no-warn] [--mode auto|sprite|background] [--template guide/template.json]
```

- **실패 규칙 다섯은 그대로다**(색 수 · 램프 밖 색 · 반투명 · baseline · bbox 흔들림). 새 검사 여덟은 모두 경고다.
- `--no-warn` 은 이번 한 판만 경고를 끈다(보고에 `warnings_off: true`). `must` 줄은 안 꺼진다.
- `--mode` 는 배경 판정을 덮어쓴다. 배경으로 본 그림은 보고 `items` 에 `background: true`.
- `--template` 은 `template render` 가 낸 `template.json` 을 문턱으로 겹친다. 대조 경고는 `template.frames` · `template.size` · `template.colors`.
  `cycle_char` idle 은 그린 장 수(서로 다른 장, 3)와 펼친 장 수(4) 둘 다 받는다.
- **가이드 파일 건너뛰기** : `template.json` 이 있는 render 폴더 안에서, 그 템플릿 이름으로 시작하는 `<이름>_guide/_preview/_over/_mask_*` 만 건너뛴다.
  건너뛴 파일은 보고 `skipped_files` 에 남는다. 보통 폴더의 `game_over.png` 같은 그림은 그대로 검수한다.
- 큰 그림은 2초마다 stderr 에 진행 줄을 찍는다(945×2048 12장 약 20초).
- **낱장 모드 `max_colors` 의 `items` 는 통과한 그림도 다 싣는다.** 장마다 `limit`(그 그림에 쓴 한도) · `ok` 를 본다. 실패한 것만 고르려면 `ok: false` 만 추린다.
- **배경 한도 `check.background.max_colors`** : 배경으로 본 그림의 `max_colors` 한도. 기본 `null` 이면 위 `check.max_colors` 를 물려받는다. 낱장 모드에서만 쓴다(`frames.json` 모드는 한 벌 전체를 한도 하나로 센다).
- **`palette.exact_match`** 는 기본 `true` 다 — 프로필에 램프 파일을 적는 순간 램프 밖 색이 한 칸이라도 있는 그림은 `ramp_colors` 실패다. `false` 면 통과로 두고 `detail` · `items` 로 알리기만 한다.
- **`check.warn.color_cap.table` 은 기본 표에 겹친다.** `{128: 16, 256: 40}` 만 적어도 기본 칸 `8 · 16 · 32 · 48 · 64` 가 남는다. 실제 표는 `profile show` 로 본다.
- **`check.warn.outline.accept`** : `style.outline` 말고도 통과시킬 판정 목록(기본 `[]`). 예 : `selout` 프로필에서 한 색 선 · 빛 쪽 옅은 선도 받으려면 `accept: [solid, selout+light]`. `unset` 은 못 넣는다.
  걸린 항목에는 판정에 쓴 값 `black` · `dark` · `lit` · `solid_share` · `inner_share` · `hue_diff` 가 다 실린다.
- **`ramp_shape` 의 밝기는 luma(Rec.601, 0.299R + 0.587G + 0.114B)** 다 — Lab L* 와 차례가 뒤집힐 수 있다. 경고 글과 `items[].luma` 에 칸마다 잰 값이 있다.

| 경고 | 보는 것 | 대표 문턱 (왜) |
| --- | --- | --- |
| `integer_scale` | 한 장 안 도트 굵기 섞임 · bilinear 같은 부드러운 확대 | `block_ratio` 0.95 · `smooth_ratio` 0.15. 경계가 직선뿐인 칸(꺾인 자리 8개 미만이거나 꺾인 ÷ 경계 × n < 0.4)은 안 센다. 색 ≤ 8 이면 smooth 를 안 본다 |
| `outline` | 외곽선 방식 판정이 `style.outline`(+ `accept`) 과 다른가 | 가장자리와 1~3px 안쪽 중 가장 밝은 칸을 견준다(2px 선을 「없음」 으로 보던 것을 고침). 순흑 문턱 `BLACK_MAX` 32. 판정은 `none` · `black` · `solid`(한 색 선) · `selout` · `selout+light` · `mixed` |
| `isolated` | 외톨이 칸 몫 | `max_ratio` 0.15 (실물 기준 무리 8%만 걸림) |
| `color_cap` | 크기별 색 수 상한 | 8:4 · 16:8 · 32:16 · 48:44 · 64:48 · 128:48 · 256:64. 배경은 `check.background.color_cap` 64 |
| `near_colors` | RGB 각 칸 4 이하로 붙은 색 쌍(AI 잡색) | `max_delta` 4 · `min_pairs` 20(쌍이 20 미만이면 안 걸림). 색이 4096 넘으면 건너뛰고 info `near_colors.skipped` |
| `ramp_shape` | 램프 단 수 · 밝기 순서 · 색조 이동 | 램프 파일을 본다. `steps` 4~6 · 색조 5°~30° |
| `loop_seam` | 반복 애니 마지막 → 첫 장 튐 | `k` 2.0 · idle · walk · run 만 |
| `odd_size` | 피벗이 반 픽셀에 놓이는 홀수 크기 (bottom_center 가로 · center 가로·세로) | 기본 켬 · 낱장은 그림 크기, 프레임 모드는 프로필 프레임만 · 파일을 한 줄에 모음 |

경고 메시지의 비율은 소수 3자리로 찍는다(「0.15 > 0.15」 같은 반올림 착시를 없앴다).

## 3. `sheet` — 비교판

```
arttool sheet --in a.png b/ --out s.png [--kinds zoom,silhouette,colors4,blur,tile] [--scale auto|N] [--tile 2|4] [--bg checker|#RRGGBB] [--label] [--report r.json]
```

- 그림 하나 = 한 줄, 판 하나 = 한 칸. 판정은 없다 — 사람이 열어 본다.
- `--scale` 정수는 64 까지. 판 크기를 그리기 전에 셈해 8192×8192 를 넘으면 거절한다.
- `--label` 은 한글 이름을 그대로 찍는다(Pretendard, README 「라이선스」).
- 게임에 안 넣는 시안을 눈으로 고를 땐 `sheet` 를 쓴다. 꼴끼리 경고 수를 견줄 땐 시안에 `check` 를 돌려도 된다.
- 장면에 얹어 보기(`--bg` 타일 PNG · `--on` · `--find`)는 20절을 본다.

## 4. `style extract` — 화풍 뽑기

```
arttool style extract --in refs/ [--in more/] --out style/ [--name NAME] [--ramp-len N] [--max-colors 64] [--by-folder] [--mode …] [--with-backgrounds] [--force]
```

- 결과 넷 : `NAME_palette.json`(팔레트 꼴) · `NAME_swatch.png`(견본, 칸 16px) · `NAME_profile.yaml`(프로필에 붙일 조각) · `NAME_report.json`. **프로필은 안 고친다** — 사람이 보고 붙인다.
- **`--by-folder` 가 권장 길이다.** `--in` 아래 하위 폴더(char · obj · tile · bldg · bg …)마다 따로 뽑아 `NAME_<종류>_*` 와 요약 `NAME_kinds.json` 을 낸다.
  무리 전체로 뽑으면 외곽선 · 빛 표가 늘 갈린다(실물 시험 2-2).
- `--max-colors` 기본 64. 상한 때문에 뺀 램프가 있으면 `palette_cap` 경고(뺀 색이 16가지 이상이면 「종류별로 뽑아라」 안내).
- 검정 · 거의 검정(각 칸 ≤ 24)은 늘 램프에서 빼 `outline_candidate` 로 둔다. 외곽선 판정이 `solid` 면 외곽선 칸에 가장 많이 쓰인 색이 `palette.outline`(과 램프 파일 `outline`)에 들어가고 램프에서는 빠진다.
  보고 `images` 에 그 색 `edge_color` · 칸 수 `edge_color_count` 가 붙는다(`check` 의 외곽선 재기 보고에는 `edge_top` · `edge_top_count`).
- 램프 처음~끝 색조 차는 40° 까지(분홍 · 베이지 · 노랑이 한 램프로 이어지던 것을 막음). 한 색뿐인 램프는 덧칸 `singles`, 합친 색은 `merge_table {from: to}`(그대로 `recolor` 색표로 쓴다).
- 빛 방향은 같은 색조 램프 덩어리 안에서만 밝기 무게중심을 본다(검정 뺌).
- **두 덩이 그림의 빛 판정 (2026-10-07)** : 불투명 칸(외곽선 포함)을 투명으로 떨어진 덩이로 나눈다 — 검정 선이 안을 갈라도 한 덩이. 8칸 이상이고 가장 큰 덩이의 10% 이상인 「뜻 있는 덩이」만 센다. 뜻 있는 덩이가 둘 이상이면 **덩이마다 따로** 빛 방향을 판정하고(큰 덩이부터 64개까지), 모름을 뺀 판정이 엇갈리면 믿을 만함이 `low` 다. 덩이가 하나뿐이거나 남는 덩이가 없으면 옛 셈 그대로다.
  - 보고 칸 : 장별 `light_confidence`(`"low"` 일 때만 붙는다 — 한 덩이 그림의 장별 보고는 옛 꼴 그대로) · 경고 `light_mixed`(엇갈린 장 목록). 요약 `light` 의 `low`(엇갈린 장 수)는 **0 보다 클 때만** 보고 파일에 실린다 — 없으면 `light` 는 `table` · `pick` 뿐이다.
  - 덩이를 나누는 기준은 투명이다. 외곽선을 같이 쓰거나 외곽선이 서로 닿은 두 덩이는 한 덩이로 세어져 옛 셈 그대로다(못 고치는 경우).
   - 우회 : 그런 그림은 캐릭터를 하나씩 잘라 따로 `style extract` 한다.
  - 예 : 투명으로 떨어진 두 네모(외곽선 두름), 한쪽은 왼쪽 위가 밝고 한쪽은 오른쪽 아래가 밝은 그림. 한 덩이 그림 4장과 같이 뽑은 보고 파일에서 옮겼다.

    ```
    "light" : { "table": { "top_left": 4, "top": 1 }, "pick": "top_left", "low": 1 }
    "images" 의 한 장 : { "file": "refs/two.png", …, "light": "top", "light_confidence": "low" }
    "warnings" 의 한 줄 : { "rule": "light_mixed", "ok": false,
        "detail": "빛 판정이 덩이끼리 엇갈린 그림 1장 — 표를 그대로 믿지 말고 눈으로 본다", "items": ["refs/two.png"] }
    ```

  - 한 덩이 그림은 판정 · 방향 값이 옛 셈과 같다(15장 폴더에 `style extract` 를 옛 · 새 소스로 돌려 출력 파일 4개와 stdout 이 같음을 견줘 확인). 덩이가 둘 이상인 그림은 값이 바뀔 수 있으니 **옛 프로필의 `style.light` 는 다시 뽑아 비교한다**.
  - **`light_mixed` 가 뜨면** : 표(`light_table`)를 그대로 믿지 말고 그림을 눈으로 본 뒤, 사람이 빛 방향을 정해 프로필 `style.light` 에 직접 적는다(프로필은 자동으로 안 고친다).
- 「도트 아님」 : 256px 이하인데 색 > 128 등. **판정 보류**(도트 아닌 그림이 절반 넘음 · 도트 그림 5장 미만 · 외곽선 표나 빛 표가 갈림)면 `check.warn` 제안을 빼고 보고에 `held`.
- `--force` 는 보류여도 낸다. 긴 변 256 까지 nearest 로 줄인 표본 + RGB 8걸음 반올림으로 어림한다(도트 아닌 391장 9.9초).
- 경고 rule : `light_mixed` · `unreadable` · `empty` · `palette_held` · `no_sprites` · `palette_cap` · `no_ramps` · `few_images` · `not_pixel` · `mixed_scale` · `by_kind` · `by_folder_loose`.

## 5. `template` — 그리기 전 밑판

```
arttool template list [--kind K]
arttool template show   <이름|경로> [--size WxH|N] [--preset P] [--profile P] [--base #hex] [--material M]
arttool template render <이름|경로> --size WxH|N --out guide/ [--preset P] [--scale N] [--over 그림.png] [--profile P] [--base #hex] [--material M]
```

- `--size 32` 처럼 수 하나면 정사각. `--base` · `--material` 은 `palette_ramp` 만.
- 목록 밖 크기(`size_range`) · 덩어리 · 소용돌이 · 큰 사람은 22절을 본다.
- `render` 가 쓰는 것 : `<이름>_guide.png` · `_mask_<겹>.png` · `_fNN.png` · `_preview.png` · `template.json` · `layers.json` (`--over` 면 `_over.png`).
- `--over` 는 그림을 **아래 가운데**로 맞추고 판을 큰 쪽으로 늘린다(48×64 그림을 64 판에 얹어도 안 잘린다).
- 빈 마스크는 안 쓰고 `template.mask_empty` 경고를 낸다.
- 이미 그린 겹 묶음 폴더에 다시 render 해도 `layers.json` 의 그림 목록(`items`)을 지킨다. 겹 목록이 다르면 거절한다.
- `steps` 의 `{셈 이름}` 빈칸은 실제 값으로 채워 나온다.
- **`template render` 로 만든 폴더는 커밋하지 않는다.** `template.json` 에 램프 · 템플릿 파일의 절대 경로가 박힌다.

**템플릿 15개** (`arttool template list` 로 크기 · 프리셋을 본다)

## 6. `layers` 묶음 — 겹

```
arttool layers compose --profile P --rig R --in parts/ --out build/ [--anim A]
arttool layers diff    --base base.png --in inpainted/ --out set/ [--template t.json] [--carve report|common|apply] [--report r.json]
arttool layers mask    --in base.png --colors #hex[,#hex] [--grow N] --out mask.png
arttool layers view    --in set/ [--only a,b | --hide c] [--each] --out v.png [--scale N] [--report r.json]
arttool layers check   --in set/ [--original a.png] [--template t.json] [--cover mask.png] [--report r.json]   (--cover 는 17절)
arttool layers fill    --in set/ --mask mask.png --nearest a,b [--color #hex] [--items x,y] --out set2/ [--report r.json]   (17절)
arttool layers export  --in set/ --out unity/ [--flat] [--each] [--trim-common] [--anchor bbox_bottom_center] [--report r.json]
```

- 겹 묶음 = `layers.json` + `<겹>/<그림>.png`. 겹은 캔버스를 안 자른다.
- 옛 줄 `arttool layers --profile …` 은 없어졌다 → `layers compose`.
- **`diff`** : 기본체는 `body` 겹, 나머지는 기본체와 다른 칸. `--carve` 는 깎인 윤곽 다루기 — `report`(기본, 세기만) · `common`(모든 겹이 깎은 칸만 본체에서 뺌) · `apply`(어느 겹이든 깎은 칸을 다 뺌).
  템플릿이 없으면 파일 이름 첫 낱말로 kind 를 짐작하고 body < cloth < face < hair < deco 순으로 쌓는다. `--base` 가 `--in` 안에 있으면 겹에서 빼고 경고.
- **`check`** : 모두 경고. `--original` 을 주면 합친 결과 ≠ 원본이 `fail`. `layer_poke`(아래 겹이 위 겹 밖으로 삐짐)는 `exclusive_with` 짝만 보고, 위 겹이 face 면 건너뛰고, 8이웃으로 4칸 이상 이어진 띠만 센다.
- **`view` · `export`** : `--scale` 상한 64. `export` 는 출력 이름이 겹치면 `--flat` 이어도 거절(종료 1).
- **변형 묶음 · `split` 색상 규칙** : `files` 무늬와 그림별 `pick`, `split` 의 `hue` · `--gray-levels` 는 18절.
- **프레임 굽기** : `arttool frames bake` 는 19절.

## 7. `ui preview` · `tile seam`

```
arttool ui preview --in panel.png --border 26|L,B,R,T --size 300x62[,96x48] --out p.png [--mode stretch|tile] [--scale N]
arttool tile seam  --in tiles/ --report seam.json [--k 2.0] [--pairs] [--sheet s.png --scale 2]
```

- `ui preview` : 안내선 없는 9조각을 늘려 본다. `--border` 순서는 [왼, 아래, 오른, 위]. `.9.png` 면 `--border` 를 빼도 된다.
- `tile seam` 새 칸 : `bad_px`(차이 16 넘고 `k` × 안쪽 평균도 넘은 칸 수) · `bad_px_min`(한 줄의 15% 와 2px 중 큰 값).
  평균 비율이 `k` 를 넘어도 `bad_px < bad_px_min` 이면 통과한다 — 1px 묘사가 이음 줄을 지나는 평평한 타일이 걸리지 않게.

## 8. `arttool.draw` — PIL 로 겹별 그리기

파이썬 공개 모듈이다. `Canvas` 가 템플릿의 겹 목록 · 가이드로 빈 겹을 만들고, `save()` 가 겹 묶음 꼴로 쓴다.
자세한 표는 스킬 `.claude/skills/arttool-usage/그리기-pil.md`.
이번 판에서 바뀐 것 : `outline("solid", color=…)` 한 색 선 · `width` 1~4 · 칠한 색이 램프 맨 아래면 palette `outline` 색을 씀(`report()` 에 `outline_ramp_bottom`) ·
두 번 두르면 `outline_twice` · `Canvas.open` 은 없는 그림 이름을 거절 · `px` 는 판 밖이면 None · `preview()` 는 겹 묶음 폴더 안 경로를 거절 · `shade` 기본 색조 걸음은 `hue_step=None` → 칸 수에 맞춘 자동 값(칸마다 10° 이하 · 처음 ~ 끝 36° 이하).

## 9. 뽑기 전 준비 · 조각 다루기 — `style ref` · `bands` · `stitch` · `tile offset`

```
arttool style ref   --in a.png --canvas 128x128 --out ref.png [--crop X,Y,W,H] [--colors 32] [--b64 ref.txt] [--max-kb 12]
arttool bands       --in raw.png [--axis y|x] [--top 8] [--mark m.png] [--report b.json]
arttool stitch      --in top.png:0-180 mid.png:20-400 floor.png:12- --out wall.png [--axis y|x]
arttool tile offset --in grass.png --out shifted.png --mask cross.png [--band 16]
```

- **`style ref`** : `create_image_pro_flash` 화풍 그림 준비. 캔버스보다 크면 불투명 칸 bbox 가운데로 자르고(`ref.cropped`), 색이 넘으면 줄이고, 알파를 128 문턱으로 0/255 로, 팔레트 PNG 로 쓴다.
  **base64 는 `--b64` 파일로만** 쓴다(화면 · 보고에 안 실린다). `--max-kb`(12) 를 넘으면 `ref.b64_large` 경고.
  키가 큰 캐릭터를 작은 캔버스로 주면 몸 가운데만 남는다 — 머리를 살리려면 `--crop` 으로 먼저 고른다.
- **`bands`** : 가장자리의 흰 띠(세 값 240 이상 또는 투명이 줄의 95%)와, 앞 줄과 색 차가 크고 한 색이 많은 줄(몰딩 · 이음 줄) 상위 `--top` 개를 낸다.
  `--mark` 는 원본 ×2 에 파란(흰 띠 경계) · 빨간(후보 줄) 눈금과 줄 번호를 찍는다. 흰 띠는 `--axis` 방향 끝(위 · 아래 또는 왼 · 오른)만 본다.
- **`stitch`** : `파일:시작-끝` 을 차례로 잇는다. 끝은 안 넣고, `12-` 는 끝까지, 구간을 빼면 그림 전체. `C:\…` 의 드라이브 콜론과 안 헷갈리게 **마지막 `:` 뒤가 숫자 꼴일 때만** 구간으로 본다.
  폭이 다르면 종료 2. 이음 자리 평균 색 차가 24 를 넘으면 `stitch.seam_jump`.
  **무늬 이어 넓히기**(판자 · 울타리)도 이것으로 한다 — 되풀이 구간을 여러 번 준다 : `stitch --in a.png:0-40 a.png:20-40 a.png:20-40 --axis x --out wide.png`.
- **`tile offset`** : (W/2, H/2) 감아 밀어 네 변을 가운데 십자로 모으고, 가림판(검정 바탕 + 흰 십자 = 다시 그릴 자리)을 쓴다. 그 둘을 PixelLab inpaint 에 넣고, 결과가 곧 이어 붙는 타일이다. `tile seam` 으로 확인한다.
  `--band` 는 짝수 · 2 이상 · 짧은 변의 절반 미만.

## 10. 늘리기 묶음 — `extend period` · `ring` · `canvas`

```
arttool extend period --in fence.png [--axis x|y] [--tile 32] [--out unit.png] [--fit N]
arttool extend ring   --in ring.png --border N|L,B,R,T --size WxH --out o.png [--snap]
arttool extend canvas --in bg.png --size WxH --out o.png [--anchor bottom] [--band 1]
```

- **`period`** : 열(또는 줄)마다 간격 p 의 평균 차 d(p) 를 재 「d(p) ÷ (p/2 ~ p-1 간격의 d 평균)」 이 가장 낮은 값의 1.1배 안에서 가장 작은 p 를 고른다. 0.35 를 넘으면 `period.weak`.
  `--tile` 이면 `period % tile` 이 0 이 아닐 때 `period.not_multiple`. `--out` 은 이웃 열과 차가 가장 작은 자리에서 한 단위를 자르고, `--fit`(없으면 `--tile` 의 가까운 배수) 길이로 가장 밋밋한 열을 겹치거나 뺀다(±25% 밖이면 종료 2).
  **주의** : 단위가 타일보다 작으면(예 단위 16 · 타일 32) 배수 경고가 나고, `--tile` 만으로 `--out` 하면 ±25% 밖이라 종료 2 다. 그때는 `--fit` 을 직접 준다.
- **`ring`** : `ui preview --mode tile` 과 같은 셈으로 늘리되, 가운데 길이가 단위의 배수가 아니면 `ring.partial_unit` 과 맞는 크기 둘을 알린다. `--snap` 이면 가까운 맞는 크기로 만들고 보고 `size` 에 실제 크기.
- **`canvas`** : 원본을 `--anchor`(top · bottom · left · right · center · 네 모서리) 자리에 두고, 새 칸은 그쪽 가장자리 `--band` 줄을 바깥으로 되풀이한다. 원본보다 작은 변은 종료 2(자르기는 `trim` · `stitch`).
  `--band 1` 인데 가장자리 줄 색이 4개를 넘으면 `canvas.edge_busy` — 세로 줄무늬(차양 같은)는 한 줄 되풀이로도 괜찮으니 그림을 보고 판단한다.

## 11. 받은 그림 손질 — `reline` · `tint` · `layers diff --drop` · `merge-colors`

```
arttool reline --in raw/ --out o/ [--color #hex] [--pick dark|all] [--scope ring|colors] [--tol 40]
arttool reline --in raw/ --out o/ --from #hex[,#hex…] [--color #hex] [--scope ring|colors]
arttool tint   --in white/ --colors #E85D5D,#5DA0E8 --out t/ [--sheet s.png] [--scale 4]
arttool layers diff … --drop hair:#F2C9A0,#3A5BD9 [--drop hat:#…] [--drop-tol 24]
```

- **`reline`** : 바깥 고리(4방향 이웃에 투명이 있는 불투명 칸) 중 `dark` 는 「고리의 가장 어두운 밝기 + `--tol`」 이하 칸만, `all` 은 고리 전부를 한 색으로. `--scope colors` 는 고른 칸의 색을 그림 전체에서 바꾼다(안쪽 선까지).
  색 차례 : `--color` > `--profile` 을 줬을 때만 프로필 `palette.outline` > 고리의 어두운 칸에서 가장 많은 색. 프로필 외곽선이 `null` · 빈 글이면 셋째로 간다(2026-10-05, 전에는 종료 2). 합친 색이 6개 넘으면 `reline.many_colors`, 투명 칸이 없으면 그대로 복사하고 `reline.no_alpha`.
  `--depth N`(1~8, 기본 1) : 투명에서 N 칸 안의 칸 가운데 고른 선 색 모음에 드는 색까지 이어서 바꾼다(2px 선 안쪽 줄). `--scope colors` 와 같이 못 쓴다. `--color-dark #hex` : 옆 면과 밝기 차가 `--dark-gap`(기본 24) 보다 작은 칸만 둘째 색. 보고 장마다 `changed_ring` · `changed_inner` · `changed_dark`. 경고 `reline.inner_left`(안쪽 줄이 남음 → `--depth 2`) · `reline.low_contrast`(선이 면에 묻힘 → `--color-dark`). (2026-10-06)
  `reline.inner_left` · `reline.low_contrast` 경고는 새 옵션을 안 줘도 난다. 그래서 옛 호출도 보고의 `status` 가 `warn` 이 될 수 있다(종료 코드는 그대로 0).
  **한계** : 고리에 검정 점이 섞이면 밝은 외곽선 색(갈색 선 등)은 기본 설정으로 안 합쳐진다 — `--pick all` 이나 `--tol` 을 키워 푼다.
- **`reline --from`** : 바꿀 선 색을 직접 준다. 고리 칸 중 RGB 가 목록에 든 칸만 바꾼다 — 밝기가 같은 다른 선(붉은 검정 옆 짙은 풀색 등)은 그대로다.
  `--scope colors` 와 같이 주면 **고리와 상관없이** 목록 색인 불투명 칸을 그림 전체에서 바꾼다(낱장에서 「이 색 → 저 색」). `--pick` · `--tol` 과 같이 주거나 hex 가 틀리면 종료 2.
  `--color` · 프로필이 없으면 목록 **밖** 고리 칸에서 그 안 가장 어두운 밝기 + 40 이하 칸 중 가장 많은 색으로 바꾸고, 그런 칸이 없으면 안 바꾸고 `reline.no_target`.
  목록 색이 바꿀 자리(ring 이면 고리, colors 면 그림 전체)에 한 칸도 없으면 그 색을 적어 `reline.from_missing` — hex 오타를 알아챈다.
  보고에 `from`(준 색 목록, 안 주면 `null`)이 붙는다. `--from` 때 `pick` 칸은 안 쓰이고, `tol`(40)은 바꿀 색을 자동으로 고를 때만 쓰인다.
- **`tint`** : 불투명 칸 RGB × 색/255 (알파 그대로). 출력 `<이름>_<RRGGBB>.png`, `--sheet` 는 원본 + 색마다 한 줄. 원본 평균 밝기가 170 미만이면 `tint.dark_source`.
- `reline` · `tint` 도 `--dry-run` 을 받는다(0절) — 그림 · 비교판을 안 쓰고 `would_write` 로 쓸 파일만 보인다. `tint` 는 장마다 `out` 칸이 없어 대신 `sheet: null`.
- **`layers diff --drop`** : 그 겹의 칸 중 준 색과 RGB 각 칸 차가 `--drop-tol` 이하인 칸을 뺀다(본체가 보인다). 겹 줄에 `dropped`, 경고 `diff_dropped`(정보). 없는 겹 이름은 종료 2.

### `merge-colors` — 가까운 색 합치기 (2026-10-05)

AI 가 뽑은 그림에 거의 같은 색이 수십 개 섞여 `check` 가 `max_colors` · `near_colors` 로 걸릴 때 쓴다. 비슷한 색을 **있던 색 중 많이 쓰인 쪽**으로 모은다.

```
arttool merge-colors --in <그림|폴더> --out <폴더|.png> [--tol N] [--max-colors N] [--palette]
                     [--keep #hex,…] [--per-image] [--clean] [--sheet s.png] [--scale 4] [--dry-run] [--report r.json]
```

| 인자 | 뜻 |
| --- | --- |
| `--tol N` | RGB 각 칸 차이의 최댓값이 N 이하인 색끼리 합친다 (0~255). **셋(`--tol` · `--max-colors` · `--palette`) 다 안 주면** `check` 의 `near_colors.max_delta`(기본 4) 와 같은 값 |
| `--max-colors N` | 가장 가까운 짝부터 되풀이해 N 색까지. `--tol` 을 같이 주면 그 안의 짝만 합치고 N 이 되면 멈춘다 |
| `--palette` | 프로필 `ramps_file` 색 중 가장 가까운 색으로 보낸다. `--profile` 이 있어야 하고 `--tol` · `--max-colors` 와 같이 못 쓴다(종료 2) |
| `--keep #hex,…` | 지킬 색. 합쳐지지 않고 「남는 색」으로만 쓰인다 |
| `--per-image` | 장마다 따로 합친다. 안 주면 입력 전체로 표 하나 |
| `--clean` | 합친 **뒤** 홀로 남은 잡티 점을 둘레 색으로 메운다 (기본 끔, 2026-10-06). 아래 「`--clean` 이 메우는 점」 |
| `--sheet` · `--scale` | 장마다 전 · 후를 나란히 놓은 비교판 (`tint` 와 같은 꼴) |
| `--dry-run` | 그림 · 비교판을 안 쓰고 보고만 낸다 (보고에 `dry_run: true` · `would_write`) |

예 둘 :

```
arttool merge-colors --in raw/ --out fixed/ --sheet cmp.png            # 잡색만 걷는다 (tol = near_colors 문턱)
arttool merge-colors --in raw/ --out fixed/ --max-colors 24 --dry-run   # 24색까지 줄이면 무엇이 무엇으로 가나 먼저 본다
```

`check` 로 전 · 후를 본다 : `check --in raw/ --report before.json` → `merge-colors` → `check --in fixed/ --report after.json`.
`failed` 에서 `max_colors` 가, `warnings` 에서 `near_colors` 가 빠졌는지 견준다.
기본 tol 로 돌리면 결과 그림에는 `near_colors` 짝이 남지 않는다(지킨 색끼리의 짝은 빼고).

| 경고 | 뜻 |
| --- | --- |
| `merge.no_change` | 합칠 색이 없어 그대로다 |
| `merge.keep_missing` | `--keep` 색이 그림에 한 칸도 없다 — hex 오타를 본다 |
| `merge.target_unreached` | `--max-colors` 에 못 닿았다. 닿은 데까지는 쓴다. 까닭은 지킨 색이 많거나 `--tol` 범위 밖이라서 |
| `merge.hue_jump` | 색조가 35° 넘게 다른 색끼리 합쳤다 — 다른 램프가 섞였을 수 있다. 막지는 않는다. 한쪽이라도 회색(채도 낮은 색)이거나 **두 색 다** 거의 검정(max(R,G,B) < 64)이면 색조를 안 따진다 — `#020205` · `#050101` 은 눈에 같은 검정인데 색조 차가 120° 로 나온다 (2026-10-06 실물 tol 4 경고 158짝이 전부 이것이었다) |

**`--clean` 이 메우는 점** (2026-10-06). 아래를 **모두** 만족하는 칸만 메우고, 그 밖(하이라이트 · 눈동자 · 무늬 · 외곽 AA)은 살린다.

| 조건 | 까닭 |
| --- | --- |
| 8이웃에 같은 색이 없는 칸(`check` 의 `isolated` 와 같은 셈) 또는 같은 색 2칸 덩어리(대각선 짝 포함). 2칸은 **두 칸 다** 아래 조건을 만족하고 메울 색도 같을 때만 같이 메운다 | 3칸부터는 그린 무늬일 수 있다. 짝 한 칸만 메우면 남은 칸이 새 외톨이가 된다 |
| 이웃 8칸 중 **6칸 이상이 한 색** — 그 색으로 메운다 | 5칸이면 두 면의 경계 위 점까지 먹는다. 6칸이면 「한 면 한가운데 박힌 점」 만 남는다 |
| 그 색까지 체비셰프 거리 ≤ max(2 × tol, 16), 상한 24. tol 이 없으면(`--max-colors` 만 · `--palette`) 16 | 합치기가 tol 안 짝을 걷은 뒤 남는 잡티는 tol 보다 조금 먼 색이다. 상한 24 로 밝기 차 큰 하이라이트 · 눈동자는 못 닿는다(실물 메운 칸의 밝기 차 최대 21) |
| 저와 이웃 8칸이 모두 알파 255 (그림 테두리 칸도 뺀다) · `--keep` 색이 아님 | 외곽 AA · 반투명 칸은 일부러 둔 색이다 |

판정은 메우기 전 그림으로 한 번에 한다(앞에서 메운 칸이 뒤 판정을 안 바꾼다). 보고 `clean` 에 `filled`(메운 칸) · `isolated_before` · `isolated_after`(합친 뒤 · 메운 뒤 외톨이 수 — `isolated_after` 가 살린 외톨이), 장마다 `images[].clean` 에도 같은 칸. `--dry-run` 도 같은 숫자를 낸다. 안 주면 `clean: null`.

**실물 재기 (2026-10-06, 실물 15장 × tol 4 · 8 · 16)** — 요약 :

| 잰 것 | tol 4 | tol 8 | tol 16 |
| --- | --- | --- | --- |
| `merge.hue_jump` 짝 (15장 합, 두 색 다 거의 검정인 짝 빼기 전 → 뒤) | 158 → **1** (어두운 회녹 `#353D39→#394138` 36.7°) | 230 → 17 | 185 → 145 (건물 녹색 잎 → 갈색 66° 등 진짜 사례는 남음) |
| 짝 상한(200만)에 걸려 종료 1 | 0장 | 1장 (2.2만 색) | 2장 (1.4만 · 2.2만 색) |
| `--clean` 외톨이 앞 → 뒤 · 메운 칸 — 바닥 타일 256² | 2397 → 1390 · 1483 | 943 → 489 · 747 | 258 → 66 · 342 |
| 〃 — 화면 배경 540×1200 | 1652 → 1282 · 570 | 1479 → 1176 · 475 | 650 → 613 · 45 |
| 〃 — 건물 256² | 7129 → 7059 · 90 | 6180 → 6120 · 72 | 3597 → 3537 · 86 |

눈으로 본 것 : 바닥 타일의 잔 얼룩이 줄고 풀 무늬는 그대로. 밝기 차 큰 외톨이(하이라이트 · 선 끝 AA)는 셋 다 하나도 안 지웠다. 건물 tol 16 은 판자 결의 어두운 점 일부(밝기 차 15~21)를 메워 결이 조금 옅어진다 — 결을 살리려면 tol 을 낮춘다.

**안 하는 것 · 알려진 한계**

- **「색조로 막기」 옵션은 안 만든다 (2026-10-06).** 기본 tol 4 에서 그림이 상한 짝이 0건이고 tol 16 에서만 4장 나와 문턱 근거가 약하다. 제안 문턱은 남겨 둔다 : 두 색 모두 V ≥ 0.25 · S ≥ 0.2 · 색조 차 > 35°. 지금은 `merge.hue_jump` 경고를 보고 `--keep` 으로 지킨다.
- **두 색 다 거의 검정(max(R,G,B) < 64)인 짝은 `merge.hue_jump` 가 못 본다.** `#3C0A0A → #0A3C0A`(어두운 빨강 → 어두운 녹색) 같은 진짜 이동도 놓친다. 한쪽만 어두우면 따진다.
- **색이 아주 많은 그림(1만 색 넘음)** 은 짝 상한 200만에 걸려 tol 8~16 에서 종료 1 이다(2.2만 색은 tol 8 부터). 6천 ~ 1.4만 색에서는 한 판에 10초 안팎 걸린다. 먼저 `--max-colors` · `--palette` 로 줄이거나 tol 을 낮춘다.

알아 둘 것 :

- **평균색을 만들지 않는다.** 결과 색은 모두 원래 그림에 있던 색이다. 칸 수가 같으면 색 값이 작은 쪽이 남는다(늘 같은 결과).
- **여러 장은 표 하나**다. 입력 전체 칸 수로 정하므로 프레임마다 같은 잡색이 같은 색으로 간다. `--max-colors` 의 색 수도 입력 전체 가짓수다. 서로 상관없는 그림 모음은 `--per-image` 를 준다.
- `--tol` 이 있으면 원래 색에서 남는 색까지의 거리가 늘 tol 안이다 — 합친 색에 또 합쳐지며 멀리 끌려가지 않는다. `--max-colors` 만 주면 멀리도 간다.
- **지킬 색** : `--keep` 색, 그리고 `--profile` 을 주면 그 프로필의 외곽선 색(`palette.outline` — 안 적었으면 기본 `#000000`)과 램프 색. 지킨 색끼리도 안 합친다. 외곽선을 안 지키려면 프로필에 `outline: null`.
- `--palette` 에서는 `--keep` 색도 **갈 곳**으로 쓰인다(램프 색과 같이).
- 프로필이 램프 파일을 가리키는데 그 파일이 없으면 종료 2.
- 색이 아주 많으면 막는다(종료 1) : `--max-colors` 만으로는 2048색까지, `--tol` 은 가까운 짝 200만 개까지. 「`--tol` 을 줄이거나 먼저 `--max-colors` · `--palette` 로 줄인다」.
- 알파 > 0 칸만 세고 바꾼다(`check` 의 색 수와 같다). 알파 값과 투명 칸 RGB 는 그대로다.
- 보고 : `merge_table` 은 `{합쳐진 색: 남은 색}`(`style extract` 와 같은 꼴), `merged` 는 `[{from, to, count}]`.
  `--per-image` 면 이 둘이 맨 위에서는 `null` 이고 `images[]` 마다 들어간다. 장마다 `colors_before` · `colors_after` · `changed` 가 붙는다.
- 하지 않는 것 : 합친 뒤 남는 1~2칸 점 메우기, 외곽선 손질(`reline` 몫).

### `shift` — 색 옮기기 (2026-10-06)

```
arttool shift --in deco/ --out d2/ [--hue D] [--sat K] [--light L] [--pick #RRGGBB,…] [--dry-run] [--report r.json]
```

- `tint` 는 곱하기만 해서 「조금 노랗게 · 조금 밝게」 를 못 했다. `shift` 는 색마다 HSV 로 옮긴다.
  `--hue` 는 색상에 D 도 더하기(-360~360), `--sat` 은 채도 곱하기(0 이상), `--light` 는 명도 V 더하기(-1~1). `check` 의 `hue_sat` 와 같은 HSV 다.
- 셋 다 기본값(0 · 1 · 0)이면 종료 2. `--pick` 을 주면 그 색(정확히 같은 RGB)만 옮긴다. 알파 · 투명 칸은 그대로.
- 보고 : 위에 `hue` · `sat` · `light` · `pick`, 장마다 `changed`(바뀐 칸 수) · `colors: [{from, to, count}]`(`merge-colors` 와 같은 꼴, 칸 많은 순).
- 경고 : `shift.merged`(두 색이 한 색이 됨) · `shift.clipped`(S · V 가 0~1 밖이라 잘림) · `shift.pick_missing` · `shift.gray`(회색은 `--hue` 로 안 움직임).
- **주의** : 옮긴 색은 대개 `ramps_file` 밖이라 `check` 의 `must.palette` · `ramp_shape` 에 걸린다. 게임 팔레트에 맞출 그림이면 뒤에 `merge-colors --palette` 로 램프에 붙이거나 램프를 고친다.

## 12. 보기 · 글자 — `sheet --grid` · `ui glyphs`

```
arttool sheet     --in a.png --out s.png --grid 8 [--grid-color #FF00FF]
arttool ui glyphs --font f.ttf (--text "…" | --text-file chars.txt) [--size 16] [--report g.json]
```

- **`sheet --grid N`** : `zoom` 판에만 원본 N 칸마다 1px 선과 위 · 왼 여백에 원본 좌표. 배율이 4 미만이면 4 로 올린다. `--kinds` 에 zoom 이 없으면 종료 2. 기본 0 = 끔.
- **`ui glyphs`** : 글자마다 그려 「없는 글자 그림(notdef)」 과 같거나 빈 그림이면 없는 글자다. notdef 는 유니코드 비문자 U+FFFF 로 얻는다. **없는 글자가 있으면 `fail`(종료 4)**.
  `--text-file` 은 `ui font` 가 낸 파일을 그대로 받는다. ttf · otf 만 — TMP 폰트 에셋 · 비트맵 글꼴은 못 본다.

## 13. 외곽선 · 채우기 · 비교 · 알고 두는 경고 (2026-10-06)

### `outline` — 외곽선 두르기

```
arttool outline --in raw/ --out o/ [--mode none|black|solid|selout|selout+light] [--where outside|inside] [--width 1~4] [--color #RRGGBB] [--light top_left] [--grow] [--dry-run] [--report r.json]
```

| 인자 | 뜻 |
| --- | --- |
| `--mode` | 선 방식. 기본 `black`. `solid` 는 `--color` 한 색(다른 mode 에 `--color` 를 주면 종료 2). `selout` · `selout+light` 는 프로필 `ramps_file` 의 램프에서 색을 고른다 — **램프가 없으면 종료 2**. `none` 은 안 그린다 |
| `--where` | `outside` 는 칠한 칸 바깥에 더한다(기본). `inside` 는 맨 바깥 칠한 칸을 선으로 바꾼다 |
| `--width` | 두께 1~4 (기본 1) |
| `--light` | `selout+light` 의 빛 방향 (기본 `top_left`) |
| `--grow` | 그리기 전에 캔버스를 사방 `--width` 만큼 늘린다 |

- `--grow` 가 없고 선이 캔버스 밖으로 나가면 그 칸은 못 그린다. 경고 `outline.clipped`(그림마다 못 그린 칸 수) — `--grow` 로 다시 돌린다.
- 보고 : `mode` · `where` · `width` · `grow`, 장마다 `added`(더한 칸 수) · `size`(결과 크기).
- 그 밖에 외곽선 셈이 알린 일은 경고 `outline.<규칙이름>` 으로 나온다(이름은 셈이 정한다).
- 하지 않는 것 : 이미 있는 선을 고치기(`reline` 몫). 결과 선이 프로필과 맞는지는 `check` 의 `outline` 경고가 본다.

### `fill --enclosed` — 틀에 갇힌 투명 칸 채우기

```
arttool fill --in raw/ --out o/ --enclosed --color #rrggbb[aa] [--max-area N] [--dry-run] [--report r.json]
```

- `--color` 의 알파가 0 이면 종료 2.
- 그림 테두리에서 투명 칸으로 못 닿는 투명 칸을 `--color` 로 채운다. `--enclosed` 는 꼭 준다(다른 방식은 아직 없다).
- **대각선으로만 이어진 선도 막힌 틀로 본다** — 투명 칸은 상하좌우로만 번진다. 대각선 틈으로는 새지 않는다.
- `--max-area N` 보다 큰 갇힌 덩이는 안 채운다 — 일부러 뚫은 창을 지킨다.
- 경고 : `fill.none`(갇힌 칸이 없다 — 틀이 열려 있을 수 있다) · `fill.large`(그림 넓이의 25% 를 넘는 덩이를 채웠다 — 창일 수 있다) · `fill.skipped`(`--max-area` 때문에 건너뛴 덩이).
- 보고 : 장마다 `filled`(채운 칸 수) · `regions`(채운 덩이).

### `diff --alpha-only` — 알파가 같은가

```
arttool diff --a a.png --b b.png --alpha-only [--report r.json]
arttool diff --a 옛폴더/ --b 새폴더/ --alpha-only
```

- 두 그림(또는 두 폴더, 같은 이름끼리 짝)의 **알파만** 견준다. 색은 안 본다 — 색을 바꾸는 손질(`shift` · `tint` · `merge-colors`)이 모양을 안 건드렸는지 볼 때 쓴다.
- 다른 칸이 있거나 크기가 다르면 `fail`(종료 4). 같으면 종료 0. **파일을 안 쓴다.**
- 두 폴더에 같은 이름이 하나도 없으면 `fail`(종료 4) + 경고 `diff.no_pairs`.
- 보고 : 장마다 `same` · `changed`(다른 칸 수) · `box`(다른 칸을 감싼 사각형) · `points`. 크기가 다르면 `size_a` · `size_b`. 한쪽에만 있는 파일은 경고 `diff.unpaired`.

### `sheet --strip` · `--kinds fit:N`

```
arttool sheet --in f1.png f2.png f3.png --out strip.png --strip
arttool sheet --in a.png --out s.png --kinds zoom,fit:24,fit:16
```

- **`--strip`** : 여백 0 · 딱지 없음 · 배율 1 · 투명 바탕으로 `--in` 순서대로 가로로 붙인다. 한 줄 애니 시트를 만들 때 쓴다.
  `--kinds` · `--scale` · `--grid` · `--bg` · `--label` · `--tile` · `--grid-color` 를 기본값과 다르게 같이 주면 종료 2, 프레임 크기가 서로 다르면 종료 1.
  보고 : `strip: true` · `frame`(프레임 크기) · `count`(장 수).
- **`--kinds fit:N`** : 긴 변을 N 으로 nearest 줄인 모습 — 게임에서 작게 찍힐 때 알아보기 쉬운지 본다. 딱지는 「맞춤 N」.
  N 이 긴 변보다 크면 키우지 않고 원본 그대로 넣고 경고 `fit_upscale` 을 낸다.

### `tint --gif` — 색 입힌 프레임을 GIF 로

```
arttool tint --in white/ --colors #E85D5D,#5DA0E8 --out t/ --gif t.gif [--duration 110]
```

- 색마다 낸 그림을 순서대로 프레임으로 한 GIF 를 쓴다. `--duration` 은 프레임 한 장 ms(기본 110) — `--gif` 없이 주면 종료 2.
- 공용 팔레트 한 벌, 0번이 투명. **알파 128 미만은 투명, 그 위는 불투명**으로 바꾼다. 반투명 칸이 있으면 경고 `tint.gif_alpha`.
- `--gif` 경로가 `.gif`(대소문자 무시)로 안 끝나면 종료 2.
- 색이 255 를 넘으면 GIF 가 거절돼 종료 1 — 이때 색별 PNG · sheet 도 하나도 안 쓴다.
- 바로 앞 장과 똑같은 장은 GIF 에서 하나로 합친다(경고 `tint.gif_merged`). 합친 장은 duration 이 더해진다.
- 보고 : `gif: {path, frames, duration}`. `frames` 는 합친 뒤 실제 남은 장 수다.

### `check --known` · `--baseline` · `--fail-on-new` — 알고 두는 경고 빼기

```
arttool check --in clean/ --report c.json [--known 목록.json] [--baseline 옛보고.json] [--fail-on-new]
```

목록 꼴 :

```json
[{"rule": "isolated", "where": "idle/*", "note": "일부러 흩뿌린 먼지"}]
```

- `rule` 은 꼭 적는다. `where` 가 없으면 `*`. `*` 는 `/` 도 넘는다. 대소문자는 가리지 않는다. `note` 는 왜 두는지 적는 칸이다.
- 맞추는 단위는 경고의 `items` 한 칸이다. 맞추는 자리(열쇠)는 칸이 글이면 그 글, 묶음이면 `where` → `ramp` → `color` 중 처음 있는 칸, 셋 다 없으면 칸 전체를 JSON 글로 만든 것이다. 그래서 `where` 에 램프 이름(예 `skin`)이나 색(`#RRGGBB`)도 쓸 수 있다. `items` 가 없는 경고 줄은 `where: "*"` 로 맞춘다.
- 맞은 칸은 지우지 않고 보고의 **`known`** 으로 옮기고 `known_by`(`규칙 @ where`)를 붙인다. 안 맞은 칸만 `warnings` 에 남고, **`new_warnings`** 는 그 칸 수다. 빼고 난 뒤에도 경고의 `detail` 글(예 「외곽선 틈 3장」)은 빼기 전 개수 그대로다 — 남은 수는 `items` 길이와 `new_warnings` 로 본다.
- `--baseline` 은 옛 `check` 보고의 경고를 알고 두는 목록으로 더한다. `--known` · `--baseline` 은 여러 번 줄 수 있다.
- `info` : `check.known_stale`(아무 경고와도 안 맞은 낡은 항목 — 고쳐진 경고라 목록에서 지운다) · `check.known_must`(`must.*` 는 목록으로 못 뺀다. 무시한다).
- **`status` · `must_failed` · `failed` 는 안 바뀐다**(`check` 는 원래 경고로 status 를 안 바꾼다). 단 `--fail-on-new` 를 켜고 새 경고가 하나라도 남으면 `status: fail` · 종료 4.
- `--no-warn` 과 같이 주면 종료 2(경고를 안 세면 뺄 것이 없다). 세 옵션을 안 주면 보고는 예전과 같다.
- **쓰는 흐름** : 처음에 `check --in clean/ --report base.json` 으로 지금 경고를 뜬다 → 사람이 한 번 보고 받아들인다 → 다음부터 `check --in clean/ --report c.json --baseline base.json --fail-on-new`. 새로 생긴 경고만 `fail` 로 걸린다.

## 14. 모양 재기 · 가림판 · 여러 입력 (2026-10-06)

### `measure shape` — 한 색 덩이 재기

```
arttool measure shape --in a.png (--at x,y | --color #rrggbb) [--tol 0] [--report s.json]
```

- 그림 속 **한 색 덩이**의 가운데 · 반지름 · 넓이 · 상자 · 원다움을 잰다. **파일을 안 쓴다**(`--report` 만).
- `--at x,y` 는 그 칸과 이어진 같은 색 덩이, `--color` 는 그 색 덩이 가운데 가장 큰 것. 둘 중 하나만 준다(둘 다 주거나 둘 다 안 주면 종료 2). `--at` 칸이 그림 밖이거나 투명해도 종료 2.
- `--tol` 은 색 폭(RGB 각 칸 차이의 최댓값, 기본 0).
- 보고 : `shape: {center, r, r_max, area, box, roundness}`.

| 칸 | 뜻 |
| --- | --- |
| `center` | `[x, y]`. 칸 가운데가 (x+0.5, y+0.5) 인 좌표다 |
| `r` | 같은 넓이의 원 반지름 |
| `r_max` | 보고에 실린 `center` 에서 가장 먼 칸까지의 거리(소수 둘째 자리 올림). 그래서 `--r max` 가림판이 덩이 칸을 모두 덮는다 |
| `area` · `box` | 칸 수 · `[x, y, w, h]` |
| `roundness` | `r / r_max`. 1 에 가까울수록 원 |

- `--color` 는 큰 그림(1024×1024 한 덩이)에서 1~2초 걸린다. `--at` 은 훨씬 빠르다.
- 경고 `measure.not_round`(원다움 0.85 미만 — 원이 아닐 수 있다) · `measure.none`(그 색 덩이가 없다 → 종료 4).

### `mask --from-shape` — 둥근 가림판

```
arttool mask --from-shape s.json (--size w,h | --like a.png) [--r round|max|수] [--invert] --out m.png [--report r.json]
```

- `measure shape --report` 가 남긴 JSON 의 `shape.center` · `shape.r` 로 원을 그린다. 칸 가운데가 원 안이면 **흰색 불투명, 바깥은 투명**. `--invert` 면 거꾸로.
- 크기는 `--size` 와 `--like`(그 PNG 의 크기만 빌린다) 중 하나만 준다.
- `--r` : `round`(기본, `r` 반올림, `.5` 는 올린다 — 2.5 → 3) · `max`(`r_max`) · 양수. `r_max` 가 JSON 에 없는데 `max` 면 종료 2.
- `--size` 는 8192×8192 픽셀(67108864)까지다. 넘으면 종료 1(`UsageError` 가 아니라 `ArtToolError` 라서).
- JSON 의 `center` · `r` 값이 수가 아니면 종료 2.
- 원이 캔버스를 벗어나면 경고 `mask.clipped`.
- `layers mask` 와 다르다 — 저쪽은 「이 색 칸만」, 여기는 잰 원이다.

잇는 예 (재기 → 가림판) :

```
arttool measure shape --in window.png --color #3A6EA5 --report s.json
arttool mask --from-shape s.json --like window.png --out m.png
```

### `check --in A B …` — 폴더 여럿을 한 번에

```
arttool check --in clean/hero clean/npc clean/props --report c.json [--known k.json] [--fail-on-new]
```

- 입력마다 따로 판정한 뒤 **한 보고**로 합친다. 입력이 둘 이상일 때만 보고가 달라진다.
  - `inputs: [{path, label, mode, frames, checked}]` 가 더해진다.
  - 경고 줄마다 `input`(딱지)이 붙고, 칸의 `where` 앞에 `<딱지>/` 가 붙는다.
  - 딱지는 폴더의 실제 이름이다(`./` 를 줘도 그 폴더 이름). 이름 속 `/ \ [ ] * ?` 는 `_` 로 바뀐다. 이름이 겹칠 때만 `1:a` · `2:a` 로 순번을 붙인다.
  - 모든 입력의 모드가 같으면 `checked.mode` 가 실린다.
- 같은 경로를 두 번 주면 종료 2.
- `--known` 의 `where` 에 `<딱지>/*` 를 쓸 수 있다(그 입력 전체).
- `--baseline` : 입력 하나로 만든 옛 보고를 주면 그 항목은 **모든 입력에** 맞춘다. 거꾸로 입력 여럿으로 만든 보고를 입력 하나 판에 주면 맞추지 않고 `info` 에 `check.baseline_shape` 한 줄이 나온다 — 같은 `--in` 꼴로 보고를 다시 만든다.
- 주의 : 입력을 더해 이름이 겹치게 되면 딱지가 `a` → `1:a` 로 바뀌어 옛 baseline 이 어긋난다. 이때도 보고를 다시 만든다.
- `status` 는 하나라도 `fail` 이면 `fail`. `rules` 는 합쳐 묶지 않고 입력 딱지를 단 채 이어 붙는다.
- **입력이 하나면 예전과 같다.**

### `sheet --scale per` — 그림마다 배율

```
arttool sheet --in tiny.png big.png --out s.png --scale per [--label]
```

- 그림(줄)마다 배율을 따로 `auto` 로 정한다. 작은 소품이 큰 그림 탓에 1배로 나오지 않는다.
- 줄 딱지 끝에 ` · ×N` 이 붙는다. 보고 : `scale: "per"` · `items[].scale`.
- `--strip` 과 같이 못 쓴다(종료 2). `--grid` 와 같이 주면 4배보다 작은 줄만 4배로 올린다(경고 `grid_scale`).

## 15. 프로필 손보기 — 그림마다 다른 프로필 · 팔레트 뿌리 · 색 한도 표 (2026-10-06)

### `check --profile-map 지도.yaml` — 그림마다 다른 프로필

```
arttool check --in clean/ --profile-map map.yaml --report c.json
```

한 폴더 안에서 그림마다 다른 프로필을 맞춘다. 지도 꼴 :

```yaml
version: 1
default: profiles/base.yaml
rules:
  - match: "body*"
    profile: profiles/body.yaml
  - match: "*.png"
    set: { check: { max_colors: 2 } }
```

- **위에서부터 처음 맞는 줄 하나**만 쓴다. 안 맞으면 `default`.
- 무늬는 `/` 단위 글롭이다. `*` 는 한 단, `**` 는 0단 이상, 대소문자는 안 가린다.
- 지도를 주면 훑기가 **하위 폴더까지** 내려간다(PNG 만, 링크는 안 따라간다). 무늬를 맞추는 글은 **`--in` 폴더 기준 상대경로(`/` 구분)** 라서 `enemy/**` · `ui/*.png` 같은 폴더 무늬를 쓸 수 있다. 지도를 안 주면 예전 그대로 바로 아래 PNG 만 훑는다.
- 프로필 경로는 지도 파일이 있는 폴더 기준이고, 그 폴더 밖은 못 가리킨다.
- `set` 은 프로필 위에 겹친다. 차례 : 기본 → 프로필 → 지도 `set` → 템플릿.
- 지도를 줄 때만 보고가 달라진다. 줄마다 `profile` 칸이 붙고, 맨 위에 `profile_map: {file, rules, hits, files}` 가 붙는다.
- 경고 칸의 `where` 와 `profile_map.files` 의 열쇠도 같은 상대경로다. `--in` 을 여럿 주면 `hits` 는 입력 전체 합이고 `files` 열쇠는 `<딱지>/<상대경로>` 다.
- 한 번도 안 맞은 줄마다 `info` `profile_map.rule_idle` 이 나온다(오타 난 무늬 찾기). `--no-warn` 이어도 나온다.
- 모든 그림이 `default` 로 갔으면 경고 `profile_map.rule_unused`.
- 지도 `set` 의 램프 경로가 막히거나 지도가 너무 깊게 중첩되면 종료 2.
- 건너뛴 파일 목록 `skipped_files` 에는 하위 폴더 그림도 파일 이름만 적힌다.
- **낱장 검수만** 받는다. `frames.json` 이 든 폴더에 주면 종료 2.
- `--profile` · `--directions` 와 같이 주면 종료 2.
- 상한 : 줄 256개 · 파일 256KB.

### 팔레트 뿌리 `ARTTOOL_PALETTES`

- 환경변수 `ARTTOOL_PALETTES` 에 **있는 폴더의 절대경로**를 주면, 프로필의 램프 경로를 `$palettes/ramps.json` 꼴로 쓸 수 있다.
- `$palettes/` 를 썼는데 환경변수가 없으면 종료 2.
- 값이 틀리면(상대경로 · 없는 폴더 · 링크 · 드라이브 뿌리 `C:\`) `$palettes/` 를 쓸 때만 종료 2 다. 그 밖에는 그 뿌리만 빼고 경고 `palettes.root_ignored`. 드라이브 뿌리는 받지 않는다.
- `template.json` 에 적힌 램프 절대경로는 **프로필 폴더 · 툴 폴더 · `ARTTOOL_PALETTES` 중 하나 아래일 때만** 믿는다.
  아니면 경고 `template.ramps_outside` 를 내고 프로필의 램프를 쓴다. 다른 PC 에서 만든 템플릿을 가져오면 이 경고가 뜬다.

### `table_mode` — 색 한도 표를 통째로 바꾸기

```yaml
check:
  warn:
    color_cap:
      table_mode: replace      # merge(기본) | replace
      table: { 64: 24, 256: 40 }
```

- `merge`(기본)는 기본 표에 겹친다. `replace` 는 **그 겹에 적은 표만** 쓴다.
- `replace` 인데 같은 겹에 `table` 이 없으면 거절한다.
- 기본 표의 칸이 겹쳐 남으면 `check` 보고 `info` 에 `color_cap.table_merged` 가 실린다.
- `table_mode` 는 **프로필과 템플릿에만** 둔다. 프리셋에 있으면 거절하고, 인자(`--set`)로 주면 종료 2.
- 템플릿(JSON)의 색 한도 표 열쇠는 글자(`"16"`)여도 수로 읽는다.

### `profile show` — 읽기 쉬운 줄

- 색 한도 표 · 외곽선을 사람이 읽는 줄로 먼저 찍는다. `--json` 에는 `show_lines` 칸이 실린다.

### `palette check` — 그림 없이 램프만 재기

```
arttool palette check (--profile P | --ramps ramps.json) [--report p.json]
```

- 램프 파일만 보고 `ramp_shape` 를 판정한다. `--ramps` 를 안 주면 프로필의 `palette.ramps_file` 을 쓴다.
- `--report` 를 `--ramps` 와 같은 파일로 주면 거절한다(종료 2).
- 걸려도 종료 0 이고 `status: warn` 이다. 파일이 없거나 깨졌으면 종료 2.
- 보고의 `palette` 칸에는 `used_by`(몇 장이 썼나)가 없다. 그림이 없기 때문이다.

### `check.warn.ramp_shape.report: each | once`

- `each`(기본) : 지금까지처럼 그림마다 경고 줄에 `ramp_shape` 가 붙는다.
- `once` : 경고 줄에서 빠지고, 보고 맨 위 `palette: {파일이름: {ramp_shape: […], used_by: N}}` 로 **한 번만** 실린다.
  묶음 열 개를 돌려도 같은 12줄이 열 번 안 나온다.
- `--known` 에 적어 둔 `ramp_shape` 항목이 `palette` 칸의 판정과 맞으면 낡은 항목(`check.known_stale`)으로 세지 않는다.
- 여러 판을 합칠 때 같은 램프 파일이라도 판정이 다르면(프로필마다 설정이 다름) 열쇠가 `<파일이름> · <딱지>` 로 갈라져 따로 실린다.

### 프로필 검증이 엄격해진 것

- **값 하나 자리에 묶음(dict)을 적으면 거절**한다. 전에는 검사를 조용히 지나고 뒤에서 터졌다.
- `rigs.<이름>.anchors` · `layer_order` 는 **이름 목록**이어야 한다. 전에는 묶음을 적으면 값이 조용히 버려졌다.
- 옛 프로필에 이런 자리가 있으면 새로 거절될 수 있다.
- rig 이름에 점이 들어 있어도 된다.

## 16. 길이 다른 램프 · 한 색 램프 (2026-10-06)

### 한 색 램프

- 눈동자처럼 한 색만 있는 램프(같은 색을 칸 수만큼 되풀이한 것)는 `ramp_shape` 경고를 내지 않는다.
- 대신 `check` 보고 `info` 에 `ramp_shape.single` 이 나온다. `items` 는 램프 이름이다.
- `report: once` 의 `palette` 칸과 `palette check` 보고에는 `single: [이름]` 이 붙는다.
- 한 색 램프가 없으면 보고는 예전과 같다. 스위치는 없고 늘 이렇게 한다.
- 주의 : 전에 이 경고를 `--known` · `--baseline` 에 적어 뒀다면 이제 낡은 항목으로 뜬다. 지우면 된다.

### 되풀이 접기

판정은 **같은 색이 이어진 칸을 한 단으로 접어서** 센다. 끝뿐 아니라 가운데 되풀이도 접는다.
예전부터 그랬고 이번에 시험으로 못 박았다.

### `style extract` 의 `ramp_info`

채운 칸(되풀이)이 있는 램프만 팔레트 json 의 덧칸에 적는다.

```json
"ramp_info": { "eye": { "steps": 1, "kind": "single" }, "skin": { "steps": 4, "kind": "padded" } }
```

- `steps` 는 접은 단 수, `kind` 는 `single`(1단) 또는 `padded`(그 밖). `padded` 는 가운데에서 되풀이된 색도 센다.
- 램프 자체는 `ramp_len` 길이 그대로다. 채운 램프가 없으면 덧칸이 없다.

### 램프 파일 `ramp_len_mode`

램프 파일(json)의 칸이다. 프로필 칸이 아니다.

- `fixed`(칸이 없으면 기본) : 모든 램프 길이가 `ramp_len` 과 같아야 한다.
- `max` : 램프마다 길이가 달라도 된다. 길이는 1 이상 `ramp_len` 이하, **가장 긴 램프가 `ramp_len` 과 같아야 한다.** `ramp_len` 을 안 적으면 가장 긴 길이를 쓴다.

```json
{
  "ramp_len": 6,
  "ramp_len_mode": "max",
  "ramps": {
    "eye":  ["#202040", "#202040", "#202040"],
    "skin": ["#6a3d2a", "#8f5a3e", "#b87a56", "#d9a07a", "#efc5a0", "#fbe3c8"]
  }
}
```

- `bake` 의 LUT 는 짧은 램프의 오른쪽을 **마지막 색으로 채운다.**
- asset json 의 `rampLen` 은 LUT 너비 그대로고, 덧칸 `rampLens`(램프마다 실제 길이)가 붙는다.
- `fixed` 파일의 출력은 예전과 같다.
- `ramp_len_mode: max` 인 파일은 단 수가 모자란다는 경고(`ramp_shape` 의 단 수 경고)를 내지 않는다. 짧은 램프가 뜻한 것이기 때문이다.
- `ramp_info` 의 `padded` 는 가운데에서 되풀이된 색도 센다 (끝에서 채운 것만이 아니다).

## 17. 겹 묶음 넓히기 — `layers.json` 버전 2 · `layers check --cover` · `layers fill` (2026-10-06)

### `layers.json` 버전 2 — `meta` · 작은 겹

- `meta` : 맨 위와 겹마다 둘 수 있는 자유 칸. **도구는 뜻을 안 보고 그대로 지켜 준다.** 한도 64KB · 깊이 32.
- `size` · `offset` : 캔버스보다 작은 겹의 상자. 둘은 함께 쓰고, `offset + size` 가 캔버스를 넘으면 거절한다.
- 도구가 **뜻을 읽는** 칸은 이름 있는 칸 + 버전 올림, 뜻을 **안 읽는** 칸은 `meta` 아래에 둔다.

```json
{"version":2,"canvas":[64,64],"meta":{"author":"a"},
 "layers":[{"name":"body","kind":"body"},
  {"name":"cheek","kind":"face","size":[11,11],"offset":[20,30],"meta":{"pivot":[5,5]}}]}
```

- 버전 1 파일은 그대로 읽는다. 새 칸을 쓸 때만 version 2 로 저장한다. 버전 1 에 `meta`/`size`/`offset` 이 있으면 거절한다.
- `meta` · `size` · `offset` 이 하나도 없는 버전 2 파일은 다시 쓰면 version 1 로 저장된다.
- 작은 겹은 **읽을 때 캔버스 크기로 펴지고**, `draw` 로 저장할 때 상자로 잘린다.
- **상자 밖에 칸을 그리면 거절**한다 (경고가 아니다).
- ~~`split` 과 `layers diff` 쓰기는 작은 겹 묶음을 아직 못 쓴다 (거절).~~ **(7판, 2026-10-07)** 이제 쓴다 — 쓸 때 상자로 자르고, 상자 밖 칸이 있으면 종료 2(「size · offset 을 늘린다」). `split` 은 옛 묶음의 `size` · `offset` 을 이어 받는다.
- 7판에서 버전 2 칸이 둘 늘었다 : 맨 위 `anchor` · 겹 `kind: mask` (25절).

### `layers check --cover` — 덮여야 할 칸 검사

```
arttool layers check --in set/ --cover mask.png [--template t.json] [--report r.json]
```

- 가림판 PNG 는 캔버스 크기, **알파 > 0 인 칸이 덮여야 할 칸**이다. 크기가 다르면 종료 2.
- 보고 맨 위 칸 `cover` : `[{item, mask, cells, empty, overlap}]` (그림마다 한 줄).
- `--cover` 를 안 주면 예전과 같다.

| 경고 | 뜻 | 결과 |
| --- | --- | --- |
| `cover_empty` | 가림판 안인데 어느 겹도 안 덮은 칸 | 실패, 종료 4 |
| `cover_overlap` | 둘 이상 겹이 덮은 칸 | 경고만 |

### `layers fill` — 가림판 안 빈 칸 채우기

```
arttool layers fill --in set/ --mask mask.png --nearest ring,core [--color #hex] [--items f01,f02] --out set2/ [--report r.json]
```

| 인자 | 뜻 |
| --- | --- |
| `--in` | 겹 묶음 폴더 (안 덮는다) |
| `--mask` | 가림판 PNG (캔버스 크기, 알파 > 0 인 칸) |
| `--nearest a,b` | 빈 칸을 붙일 후보 겹. 거리가 같으면 **먼저 적은 겹** |
| `--color` | 주면 이 색, 안 주면 가장 가까운 칸의 색 |
| `--items` | 손볼 그림 (기본 전부) |
| `--out` | 새 묶음 폴더. 비어 있어야 하고 `--in` 과 겹치면 안 된다 |

- 가림판 안의 **빈 칸만** 가장 가까운 겹에 붙여 채운다. 손 안 댄 겹과 `layers.json` 은 그대로 복사한다.
- 보고 : `cover`(가림판 이름) · `nearest` · `color` · `images:[{item, filled:{겹: 칸수}}]` · `out`.
- 7판부터 `--mask` 는 「꼭」 이 아니라 **`--holes` 와 둘 중 하나**다. `--holes` 는 겹 자신의 안쪽 구멍을 메운다 (25절). 마스크 겹(`kind: mask`)은 `--nearest` 후보로 못 쓴다 (종료 2).

| 경고 | 뜻 |
| --- | --- |
| `fill_no_target` | `--nearest` 겹이 그 그림에 없어 건너뜀 |
| `fill_outside_box` | 작은 겹의 상자 밖 칸은 다음으로 가까운 겹이 채운다. 어느 겹도 못 채우는 칸만 비우고 경고 |

- 종료 코드 : 경고만 있으면 0, `--out` 이 비어 있지 않거나 `--in` 과 겹치면 2.
- 낱장 `fill --enclosed`(13절)와 다르다 : 이쪽은 **묶음**에서 **가림판이 정한 칸**을 어느 겹에 줄지 정한다.

## 18. 변형 묶음 · 색조로 겹 나누기 · 회색 단계 — `files` · `pick` · `split` `hue` · `--gray-levels` (2026-10-06)

한 줄로 : 낱장이 한 폴더에 흩어져 있어도 겹 묶음으로 읽고(`files`), 그림마다 겹별 변형을 고르고(`pick`), `split` 은 색상(도)으로 겹을 가르고 회색 단계로 밝기를 눌러 준다.

### `layers.json` — 겹마다 `files` · 그림마다 `pick` (버전 2 칸)

```json
{"version":2,"canvas":[48,48],
 "layers":[{"name":"body","files":"parts/body_{v}.png"},
           {"name":"face","files":"parts/face_{v}.png"}],
 "items":["idle",{"name":"hop0_smile","pick":{"body":"hop0","face":"01"}}]}
```

- `{v}` 가 변형 이름이다. 글자 `"idle"` 은 모든 겹에서 변형 `idle` 을 고른 것과 같다.
- `pick` 에 없는 겹은 **그 그림에 없는 것**으로 친다. 쓸 때만 version 2 로 저장하고, 버전 1 파일에 있으면 거절한다.
- `draw` 로 저장하면 pick 을 이어 쓴다. pick 밖 겹에 그리면 거절한다.
- **`split` 은 변형 묶음에 그림을 더할 수 없다** (거절).
- 작은 겹(`size` · `offset`) 묶음에는 `split` 으로 그림을 더할 수 있다 — 상자로 잘라 쓴다 (7판, 17절).

| 거절 (종료 2) | 뜻 |
| --- | --- |
| 무늬 `{v}` 가 0개 · 2개 이상 · 다른 치환 낱말 | `{v}` 는 정확히 하나 |
| `{v}` 가 마지막 마디에 없음 · `.png` 로 안 끝남 | `{v}` 는 파일 이름 마디에만 |
| `..` · `.` · 빈 마디 · 절대 경로 · `:` · `\` · 영숫자 `_` `-` `.` 밖 글자 · 256자 넘음 | 묶음 폴더 밖을 못 나간다 |
| 두 겹 무늬가 같음 (대소문자 무시) | 한 파일을 두 겹이 못 쓴다 |
| pick 에 없는 겹 · 없는 변형 이름 · 빈 pick · 모르는 칸 | 이름 틀림 |
| `exclusive_with` 짝을 같이 고름 | 서로 막힌 겹 |
| 무늬 글자는 달라도 두 (그림, 겹)이 같은 파일로 풀림 (대소문자 무시, 읽을 때 다 풀어 봄) | 예: `body/{v}.png` 의 그림 `x_y` 와 `body2/x_{v}.png` 의 변형 `y` 가 한 폴더면 겹친다 |
| `files` 첫 마디가 다른 겹 이름 | 남의 기본 폴더에 못 쓴다 |
| 점으로 시작 · 끝나거나 점이 둘 잇닿은 마디 (`body./` · `.{v}.png` · `{v}..png`) | Windows 가 끝 점을 떼어 다른 파일을 읽는다 |
| Windows 예약 이름 마디 · 변형 이름 (con · prn · nul · aux · com1~9 · lpt1~9, 대소문자 무시, 첫 점 앞 기준) | 열 수 없는 파일 이름 |
| pick 변형 이름이 64자 넘음 | 길이 상한 |
| 변형 이름을 채운 파일 이름 전체가 Windows 예약 이름이 됨 (`files` 무늬를 쓴 겹에만) | 열 수 없는 파일 이름 |
| `files` 무늬를 쓰는 폴더에 `template render` 다시 굽기 | 지원 안 함 (무늬를 잃지 않게). pick 만 쓴 묶음은 items · pick 을 잇는다 |

### `layers check` — 변형 묶음일 때

- 보고에 `"variants": {"body": ["hop","idle"], …}` 가 붙는다. 훑기 상한 4096 파일.
- pick 이 고른 변형 파일이 없으면 `check` 는 거절하지 않고 `layer_empty` 경고를 낸다. 읽는 다른 명령은 거절한다.
- 변형 묶음(사전 꼴 `items` 가 하나라도 있음)에 7판 `--counts` 를 주면 종료 2 — 장 수가 뜻이 없다. `variants` 칸을 본다.
- `layers.json` 없이 `<겹>_<v>.png` 만 있는 폴더는 25절 맨 폴더 모드(`--order`)로 읽는다. 이때는 `variants` 칸이 안 붙는다.

| 경고 | 뜻 |
| --- | --- |
| `unused_variant` | 어느 그림도 안 고른 변형 파일 |
| `variant_size` | 변형 크기가 겹 크기(없으면 캔버스)와 다름 |
| `variant_alpha` | 변형에 반투명 칸이 있음 |

### `split` — 색상 규칙 `hue` · `min_sat`

```json
{"hue": [340, 20], "to": "hair", "min_sat": 0.2, "above_y": 8}
```

- `hue` 는 색상 도 범위, 양 끝 포함. 시작이 끝보다 크면 0도를 지나 감는다.
- `min_sat` 기본 0.15. 채도가 이보다 낮은(무채색) 칸은 `hue` 규칙이 안 잡는다.
- 채도가 정확히 0 인 칸(검정 · 흰색 · 회색)은 `min_sat: 0` 이어도 `hue` 규칙이 안 잡는다 — 색조가 없다.
- 표의 `outline` 색은 `hue` 범위 안이어도 `hue` 규칙이 안 잡고 외곽선 투표로 간다. `color` 규칙이 외곽선 색을 직접 적으면 그대로 잡는다.
- `color` 와 `hue` 는 규칙 하나에 하나만. 먼저 맞은 규칙이 가진다(예전과 같음). `above_y` 같은 자리 칸과 같이 쓴다.
- 거절 (종료 2) : 수 둘 목록이 아님 · 0~360 밖 · 시작=끝 · `min_sat` 0~1 밖 · `hue` 없이 `min_sat`.

### `split --gray-levels`

```
arttool split --in a.png --spec split.json --out parts/ --gray-levels 255,180,60
```

- 겹으로 나눈 뒤 칸의 밝기(Rec.601)를 가장 가까운 회색 단계로 바꾼다. 거리가 같으면 어두운 쪽, 알파는 그대로.
- 되돌림 검사는 **회색으로 바꾼 원본**과 견준다. 보고에 `gray_levels`(큰 값부터, 줄 때만).
- 거절 : 2개 미만 · 0~255 밖 · 정수 아님 · 겹치는 값 · `--list-colors` 와 같이.

### 주의

- 변형 묶음에 `split` 으로 그림 더하기는 아직 없다.
- `--gray-levels` 를 주면 원본 색은 나간 파일에 남지 않는다. 밑판용이다.

## 19. 프레임 굽기 — `frames bake` (2026-10-07)

한 줄로 : 프레임 그림 폴더를 받아 발 줄을 맞추고, 가림판으로 덮고, 잘라서, 프레임별 PNG · 띠 한 장 · gif 로 한 번에 굽는다.

```
arttool frames bake --in frames/ --out baked/ --foot auto
arttool frames bake --in frames/ --out baked/ --foot auto --cover mask.png --crop union --strip baked/strip.png --gif baked/walk.gif --duration 110 --scale 4
```

- 처리 순서는 고정이다 : 발 줄 → 덮기 → 자르기 → 띠 → gif. 순서를 바꾸는 인자는 없다.
- 프레임은 파일 이름의 숫자 순으로 읽는다 (`f2` < `f10`). 크기가 모두 같아야 한다.

| 인자 | 뜻 |
| --- | --- |
| `--in` · `--out` | 프레임 PNG 폴더 · 나갈 폴더 (프레임 이름 그대로) |
| `--foot y\|auto` | 맨 아래 불투명 줄을 y 줄로 맞춘다. `auto` 는 첫 프레임의 발 줄. 안 주면 안 맞춘다 |
| `--cover m.png` | 가림판 (프레임 크기). 알파 > 0 인 칸을 기준 그림의 같은 칸으로 덮는다 |
| `--cover-from png` | 덮는 기준 그림. 안 주면 **발 줄을 맞춘 뒤의 첫 프레임**. `--cover` 와 같이만 쓴다 |
| `--crop x,y,w,h\|union` | 모든 프레임을 같은 상자로 자른다. `union` 은 모든 프레임의 불투명 영역을 합친 상자 |
| `--strip png` | 프레임을 가로로 이은 띠 한 장 |
| `--gif gif` | 움직이는 gif |
| `--duration` · `--loop` | 한 장 ms (기본 110) · 반복 횟수 (기본 0 = 계속). `--gif` 와 같이만 쓴다 |
| `--scale` | 띠 · gif 만 N배로 키운다 (1~64, 기본 1). 프레임별 PNG 는 그대로 |

### 보고

`{version, status, frames, size, crop, images, gif, warnings, out}`

- `images` : `[{name, shift_y, covered}]`. `shift_y` 는 아래로 민 칸 수, `covered` 는 덮느라 **값이 실제로 바뀐** 칸 수.
- `gif` : `{path, frames, duration, loop}` (`--gif` 를 안 주면 null). `out` : `{frames, strip, gif}`.

| 경고 | 뜻 |
| --- | --- |
| `frames.foot_clipped` | 발 줄을 맞추려 밀다가 캔버스 밖으로 잘린 칸이 있는 프레임 |
| `frames.gif_alpha_cut` | gif 는 반투명을 못 담아 잘랐다 (알파 경계 위 불투명, 밑 투명) |

| 거절 (종료 2) | 뜻 |
| --- | --- |
| 인자 잘못 · 프레임 크기가 서로 다름 | 한 폴더는 크기가 같아야 한다 |
| 자르기 상자가 캔버스 밖 | `x,y,w,h` 확인 |
| 첫 프레임이 빈데 `--foot auto` | 발 줄이 없다 |
| 프레임 512장 넘음 | 상한 |
| `--duration` · `--loop` 을 `--gif` 없이 · `--cover-from` 을 `--cover` 없이 | 짝이 없는 인자 |
| `--scale` 이 1~64 밖 | 상한 |
| 띠(`장 수 × 너비 × 배율` × `높이 × 배율`) · gif 한 장이 8192×8192 픽셀 넘음 | 키운 그림을 만들기 전에 셈으로 본다 |
| gif 전체(`장 수 × 너비 × 높이 × 배율²`)가 한 장 상한의 4배 넘음 | 상한 |
| `--duration × 장 수` 가 655350 넘음 | gif 지연은 1/100초 16비트. 같은 장이 합쳐지면 지연이 더해진다 |

### 주의

- 거절 검사를 다 마친 뒤에 쓴다. 거절이면 파일이 하나도 안 남는다.
- 검사(gif 색 수 · 지연 포함)에서 걸리면 아무것도 쓰지 않는다. 쓰는 순서는 프레임 PNG → 띠 → gif 다.
- 마스크 자리가 프레임마다 같은 몸 부위에 걸리도록 발 줄을 **먼저** 맞춘다.
- `--dry-run` 이면 파일을 안 쓰고 `would_write` 만 낸다. `out` 은 null.

## 20. 장면에 얹어 보기 — `sheet --bg` · `--on` · `--find` (2026-10-07)

한 줄로 : 그린 그림을 게임 화면 캡처 위에 얹어, 실제로 놓였을 때의 모습을 비교판 칸으로 본다.

```
arttool sheet --in new.png --out s.png --bg tile.png
arttool sheet --in new.png --out s.png --on shot.png --at 40,64 --crop 0,0,160,120
arttool sheet --in new.png --out s.png --on shot.png --find old.png
```

- 칸마다 장면 사본에 스프라이트를 얹는다(알파 합성). 칸 하나가 장면 한 장이다.
- `--find` 는 `--at` 대신 쓴다. 장면에서 옛 그림과 **똑같은 자리**(옛 그림의 투명 칸은 비교하지 않는다)를 찾아 그 자리에 얹는다.
- 음수 자리는 `--at=-2,3` 꼴로 쓴다.

| 인자 | 뜻 |
| --- | --- |
| `--bg` | `checker` · `#RRGGBB` · **PNG 경로**. PNG 는 칸 왼쪽 위부터 타일로 되풀이해 깐다. 반투명 타일은 바둑판 위에 얹는다 |
| `--on 장면.png` | 장면 PNG. 입력 그림 하나하나를 장면 사본에 얹는다 |
| `--at x,y` | 장면 원래 픽셀 좌표 |
| `--crop x,y,w,h` | 장면에서 보여 줄 상자. 큰 캡처의 둘레만 볼 때 |
| `--find 옛그림.png` | `--at` 대신. 옛 그림과 같은 자리를 장면에서 찾는다. 크기가 다른 그림은 **옛 그림의 왼쪽 위에 맞춘다** |
| `--find-clear` | `--find` 와 같이. 찾은 자리의 옛 그림 불투명 칸을 **투명으로 비운 뒤** 얹는다 — 비운 칸에는 `--bg` 가 비친다. 새 그림이 옛 그림보다 작아도 옛 칸이 안 남는다 |

### 보고

`sheet` 의 기존 칸에 `on:{scene, at, crop, find, find_count, find_clear}` 가 붙는다 (`--on` 을 안 주면 붙지 않는다).

- `at` : 얹은 자리 `[x, y]`. `crop` : 자른 상자(안 줬으면 null). `find` : 옛 그림 경로(안 줬으면 null).
- `find_count` : `--find` 자리가 모두 몇 곳인가(안 줬으면 null). `find_clear` : `--find-clear` 를 줬는가.

| 경고 | 뜻 |
| --- | --- |
| `on_clipped` | 얹은 그림이 장면(또는 `--crop` 상자) 밖으로 나가 잘렸다. 잘린 칸 목록이 실린다 |
| `find_many` | `--find` 자리가 여러 곳이다. 위쪽 · 왼쪽 첫 자리를 썼다. 글에 **모두 몇 곳**인지 싣고, 자리 목록은 20개까지 |

| 거절 (종료 2) | 뜻 |
| --- | --- |
| `--at` · `--crop` · `--find` 를 `--on` 없이 | 짝이 없는 인자 |
| `--at` 과 `--find` 를 둘 다 · 둘 다 안 줌 | 하나만 준다 |
| `--crop` 이 장면 밖 | 상자가 장면 안에 있어야 한다 |
| `--find` 가 장면에서 0곳 | 못 찾았다 |
| `--on` · `--find` 파일이 없거나 PNG 가 아님 | 인자 잘못 (`--bg` 와 같다) |
| `--find-clear` 를 `--find` 없이 | 짝이 없는 인자 |
| `--strip` 과 같이 | 띠는 장면을 안 쓴다 |
| `--bg` 가 `#` 로 시작하는데 색이 아니거나 파일이 없음 | 색 꼴이면 색, 아니면 경로로 읽는다 |

### 주의

- `--find` 는 10초가 넘으면 멈춘다. 장면이 크면 `--crop` 으로 줄인다.
- `--find` 는 같은 무늬만 찾는다. 색이 조금 다른 그림은 못 찾는다.
- `--find` 10초 넘김 · 장면 사본 크기 한도 넘김은 종료 1 이다 (다른 명령의 크기 한도와 같다).

### `--compare 전판폴더` — 전 판과 숫자 견주기 (7판)

`arttool sheet --in new/ --out s.png --compare old/` 는 입력 그림마다 `old/<같은 파일 이름>` 을 짝으로 잡아, 보고에 `compare:[{name, colors, isolated, outline_ratio}]` 를 붙인다. 칸마다 **[전, 후, 차]**(차 = 후 − 전)다. 판 그림은 안 바뀐다 — 숫자 표만 더한다. 짝이 없는 그림은 경고 `compare_missing`(이름 목록)으로 알리고 건너뛴다. 폴더가 없으면 종료 1, `--strip` 과 같이 주거나 `--out` 이 짝 그림을 덮으면 종료 2. `--dry-run` 에서도 `compare` 는 나온다. `--compare` 를 안 주면 보고는 예전과 같다.

## 21. UI 시안 그리기 — `ui mockup` (2026-10-07)

한 줄로 : 장면 JSON(그림 · 9조각 패널 · 글자를 자리와 겹 순서로 적은 것)을 읽어 UI 시안 한 장을 그린다.

```
arttool ui mockup --scene ui/main.json --out mock.png --scale 2
arttool ui mockup --scene ui/main.json --out mock.png --set slot=items/sword.png --dry-run
```

장면 예 :

```json
{"version":1,"canvas":[320,180],"background":"#101010",
 "fonts":{"body":{"file":"f.ttf","size":8}},
 "nodes":[{"kind":"image","id":"slot","src":"a.png","at":[0,0],"z":0}]}
```

- 요소 종류 셋 : `image`(`scale` 1~8) · `panel`(`.9.png` 안내선으로 늘림, `mode` stretch · tile, `size` 필요) · `text`(`font` · `text` · `color` · `align`, `\n` 줄바꿈).
- `z` 오름차순으로 그리고, 같으면 적은 순서가 먼저다.
- 겹치는 칸은 알파 합성으로 섞는다 (반투명 그림 · 패널 · 글자가 아래를 지우지 않는다).
- 글자 색은 `#rrggbb` · `#rrggbbaa`. 글자 모양은 0/255 로 끊고, 색의 알파만 섞는다.
- 바탕은 색 · `{image, tile}` · 없음(투명).
- 그림 · 글꼴 경로는 **장면 폴더 안**에서만 읽는다. 밖으로 나가면 거절. 모르는 칸 · 종류도 거절.

| 인자 | 뜻 |
| --- | --- |
| `--scene` | 장면 JSON |
| `--out` | 시안 PNG |
| `--scale N` | 다 그린 뒤 통째로 키운다 (기본 1, 16까지) |
| `--set id=src` | 그 id 노드의 `src` 만 바꿔 그린다. 여러 번 줄 수 있다 (64개까지). `--set` 은 image · panel 노드만 |

### 보고

`{version, status, scene, canvas, scale, nodes, drawn, images, warnings, out}`

- `drawn` : `[{i, kind, z}]` 그린 순서. `images` : 읽은 그림 경로. `out` : 쓴 파일(`--dry-run` 이면 null).
- 경고만 있으면 종료 0 · status 는 warn. 글자가 캔버스 밖으로 나가도 `ui_mockup.clipped` 다.

| 경고 | 뜻 |
| --- | --- |
| `ui_mockup.clipped` | 캔버스 밖으로 나가 잘린 노드가 있다 |
| `ui_mockup.missing_glyph` | 글꼴에 없는 글자가 있다 |

| 거절 (종료 2) | 뜻 |
| --- | --- |
| 장면 JSON 이 깨졌거나 모르는 칸 · 종류 · 빠진 칸 | 장면을 고친다 |
| 그림 · 글꼴 경로가 장면 폴더 밖 · 파일 없음 | 장면 폴더 안으로 |
| `--set` 의 id 가 장면에 없음 · 같은 id 두 번 · text 노드 id | id 확인 |
| `image` 그림 크기 × `scale` 이 너무 큼 | 그리기 전에 그림 머리로 막는다 |
| `panel` 의 `src` 가 `.9.png` 가 아님 | 안내선 있는 그림만 |
| `--out` 이 `.png` 가 아님 | |

상한 : 장면 256KB · 노드 512 · 글꼴 16 · 캔버스 · 패널 한 변 4096 · `at` 절댓값 4096 · 노드 `scale` 8 · `--scale` 16 · 글꼴 크기 256 · 글자 1024자 · 장면 전체 글자 줄 2048 · `--set` 64. 넘으면 거절.

### 주의

- `--dry-run` 이면 그림은 그리되 파일을 안 쓰고 `would_write` 만 낸다.

## 22. 템플릿 넓히기 — 목록 밖 크기 · 덩어리 · 소용돌이 · 큰 사람 (2026-10-07)

한 줄로 : 템플릿이 크기 목록에 없는 크기도 받는다(`size_range`). 새 템플릿 셋(`prop_small` · `char_blob` · `fx_swirl`)과 120×240 큰 사람이 더해졌다.

```
arttool template render prop_small --size 40x40 --out out/
arttool template render char_blob --size 80x80 --out out/
arttool template render fx_swirl --size 64 --out out/
arttool template render char_small --size 120x240 --out out/
```

명령 꼴은 `arttool template --help` 로 본다 (`--size` 는 꼭 준다).
위 네 줄을 돌려 본 결과(2026-10-07) : 종료 0 이 넷이다. `prop_small 40x40` · `char_blob 80x80` · `char_small 120x240` 은 목록 밖 크기라 경고 `template.size_free` 가 붙어 status warn, `fx_swirl 64` 는 status ok.

### 범위 `size_range`

템플릿 JSON 에 `"size_range": [[16,16],[512,512]]` (왼쪽 위 최소 · 오른쪽 아래 최대) 를 적으면, 범위 안의 크기는 목록에 없어도 그린다. `template show` 에 「범위 … ~ …」 가 붙고 `list` 에 `size_range` 칸이 생긴다.

| 템플릿 | 범위 |
| --- | --- |
| `ui9_panel` | 8 ~ 256 (56×54 같은 크기도 받는다) |
| `building` · `machine` | 16 ~ 512 |
| `prop_small` | 16 ~ 96 |
| `char_blob` | 16 ~ 128 |
| `char_small` | 8 ~ 240 |
| `bg_screen` | 180×180 ~ 540×1200 |
| `screen_piece` | 540×60 ~ 540×720 (너비 540 고정) |

| 경우 | 결과 |
| --- | --- |
| 범위 안 · 목록 밖 | 그린다. 경고 `template.size_free` (가장 가까운 목록 크기를 알려 준다). 종료 0 · status warn |
| 범위 밖 | 거절 (종료 2). `받는 것 : … · 또는 8x8 ~ 256x256 사이` |
| 범위 안이어도 그 크기에서 값이 안 맞음 | 거절 (종료 2). 까닭이 붙는다 |
| `size_range` 없는 템플릿(`fx_dust` · `fx_sparkle`) · 목록 밖 크기 | 거절 (종료 2). `이 프리셋은 8x8, 12x12 만 받는다 : small` |
| 템플릿 파일의 `size_range` 꼴이 틀림 | 템플릿 오류 (종료 1) |

- 맨 위 `size_range` 는 프리셋이 자기 `sizes` 를 가져도 듣는다. 범위 안이지만 **그 프리셋의 목록(프리셋 목록이 없으면 맨 위 목록)에 없는** 크기는 경고와 함께 그린다. 예 : `16x16 은 이 프리셋(button)의 정해진 크기가 아니다. 가장 가까운 목록 크기 : 24x24 (숫자 값은 열쇠 "16" 으로 풀렸다)` (`ui9_panel --preset button --size 16x16`, 종료 0).
- 범위 안이어도 값이 크기에 안 맞으면 거절이다. 예 : `ui9_panel --preset bubble --size 32x32` → `이 크기에서는 안 맞는다 : 32x32 — 32x32 에 테두리 L14 B20 R14 T12 가 안 들어간다`. `ui9_panel` 은 범위가 8 ~ 256 이지만 테두리 때문에 8x8 같은 아주 작은 크기는 거절된다. `char_blob` 128x16 처럼 납작한 귀퉁이도 거절된다(`머리 장식 … 가 캔버스 밖이다`).

### 새 템플릿

| 이름 | 무엇 | 기본 크기 | 겹 · 프레임 |
| --- | --- | --- | --- |
| `prop_small` | 작은 소품 틀 | 24 · 32 · 48 · 64 | 겹 `shadow`(선택) · `body` · `top` · `foot` |
| `char_blob` | 둥글고 바닥이 평평한 덩어리 몸 (처리기 `blob`) | 64×64 (몸 42×35) | 겹 `body` · `face` · `deco`, 통통 튀기 4프레임 (바닥 줄 고정) |
| `fx_swirl` | 소용돌이 효과 (흰 1색) | 64×64 | 겹 `fx` · 8프레임 |

### 값 칸

`char_blob` (크기 몫은 캔버스에 곱한다) :

| 칸 | 뜻 |
| --- | --- |
| `body_w_ratio` · `body_h_ratio` | 몸 너비 · 높이 몫 |
| `foot_ratio` | 바닥 여백 몫 |
| `widest_ratio` | 가장 넓은 줄 자리 (몸 높이의 0.63 지점) |
| `face_w_ratio` · `face_h_ratio` · `face_y_ratio` | 얼굴 칸 크기 · 위치 |
| `eye` · `eye_gap_ratio` · `mouth_ratio` | 눈 크기(기본 1px) · 눈 사이 · 입 |
| `deco_ratio` · `deco_rise_ratio` · `deco_dx_ratio` | 머리 장식 크기 · 솟음 · 옆으로 |
| `frames` | 프레임마다 (가로 몫, 세로 몫) 쌍. 넓이 몫(가로×세로)은 0.8 ~ 1.25 |
| `frame_ms` | 프레임 길이 |

`spiral` 모양 :

| 칸 | 뜻 |
| --- | --- |
| `turns` | 바퀴 수, 0.5 ~ 4 |
| `r0` · `r1` | 안쪽 · 바깥 반지름 몫, 0 ≤ r0 < r1 ≤ 1 |
| `width` | 선 굵기, 1 ~ 32 |
| `dir` | `cw` 또는 `ccw` |
| `phase` | 회전 몫, 0 이상 1 미만 |
| `dx` · `dy` | 중심 옮김 |

효과 템플릿의 프레임 상한은 64 다.

### 큰 사람 (120×240)

`char_parts` · `cycle_char` · `char_small` 이 120×240 을 받는다. 키 214(위 여백 26), 머리 : 몸통 : 다리 ≈ 0.40 : 0.23 : 0.37, 눈 13×8. 걷기 프레임(walk 8 · walk6 · walk12)은 바닥 줄을 고정한다. 머리 오르내림(`bob`)은 크기 표라서 짧은 변 120 이상은 ±3px(run 은 최대 6px · idle 은 2px), 그보다 작으면 옛 값(1~2px) 그대로다. 눈 치수가 캔버스보다 크면 템플릿 오류로 거절한다.

### 주의

- 큰 사람의 **무릎 자리 · 눈 사이 · 걷기 오르내림은 실물로 재지 못한 어림값**이다 (`char_small` 의 note 에 적혀 있다).
- `cw` 와 `ccw` 는 정확한 거울상이 아니다. 픽셀 반올림 때문에 한두 점 다를 수 있다.

## 23. draw 고리 — `grid show` · `grid apply` · `lint` (2026-10-07)

한 줄로 : 그림을 **글(글자 한 칸 = 칸 하나)** 로 읽고 쓰고, 결함을 **칸 좌표 박힌 글**로 받는다. 설계는 `Docs/Design/2026-10-07-draw고리설계.md`(끝의 14절이 구현과 다른 자리).
셋 다 입력은 겹 묶음 폴더나 PNG 한 장이다. PNG 는 `body` 한 겹으로 연다. 파이썬 쪽 부품(`to_grid` · `paste_grid` · `lint` · `mark` …)은 README 「draw 고리」 표와 스킬 `그리기-pil.md`.

### 격자 글 꼴

```
k #2A2238
s #F6D0B0

   01234567
 0 ssssssss
 1 sskkskks
```

- 범례 줄 `글자 #RRGGBB` · 빈 줄 · 격자 줄. `.` 은 늘 투명, `#` 줄은 주석. 눈금(`--rulers`)은 읽기용이라 `grid apply` 가 읽을 때 뗀다.
- 글자는 `a-z` → `A-Z` → `0-9` 순으로 자동 배정(62색까지). 같은 색은 같은 글자.
- 줄 너비가 다르거나 범례에 없는 글자가 있으면 줄 번호와 함께 거절한다(종료 1).

### `grid show` — 격자 글 찍기

```
arttool grid show --in work/set --layer face --box 10,12,24,16 --rulers
arttool grid show --in work/flat/idle.png --legend legend.json --json
```

| 인자 | 뜻 |
| --- | --- |
| `--in` | 겹 묶음 폴더 또는 PNG (필수) |
| `--item` | 겹 묶음의 그림 이름 (기본 `idle`) |
| `--layer` | 겹 하나만. 안 주면 합친 그림 |
| `--box x,y,w,h` | 창. **너비 · 높이**로 준다(파이썬 `box` 는 끝 뺌 `x0,y0,x1,y1`) |
| `--rulers` | x 눈금 줄 · y 줄머리. 눈금은 캔버스 절대 좌표 |
| `--legend` | 글자표 JSON `{"k": "#2A2238", …}`. 안 주면 자동 배정 |

- 파일을 안 쓴다. 화면에는 격자 글만 찍고, `--json` 이면 보고 JSON.
- 창 없이 한 변이 **64 를 넘으면 종료 2** 로 거절하고 `--box` 를 안내한다. 축소는 안 한다.
- 보고 열쇠 : `status` · `in` · `layer` · `size` · `legend`(글자 → `#RRGGBB`) · `grid_text`.

### `grid apply` — 격자 패치 덧그리기

```
arttool grid apply --in work/set --grid eye.px --layer face --at 14,20 --out work/set2 --report ap.json
arttool grid apply --in work/set --grid eye.px --layer face --at=-2,3 --mode replace --out work/set2 --dry-run
```

| 인자 | 뜻 |
| --- | --- |
| `--in` | 겹 묶음 폴더 또는 PNG (필수) |
| `--grid` | 격자 글 파일 `.px` (필수) |
| `--out` | **새 자리**(필수). 폴더 입력이면 없거나 빈 폴더, PNG 입력이면 `.png` |
| `--layer` | 덧그릴 겹. 겹이 하나면 안 줘도 된다 |
| `--at x,y` | 패치 왼쪽 위. 안 주면 패치 글의 `# 원점 x,y` 줄(`grid show --rulers` 가 씀) 자리, 그것도 없으면 `0,0`. 원점 줄과 다르면 거절. 음수는 `--at=-2,3` 처럼 `=` 로 |
| `--mode over\|replace` | `over`(기본) : `.` 은 그대로 · `replace` : `.` 은 지움 |
| `--item` · `--legend` | `grid show` 와 같다 |
| `--report` | 보고 JSON 파일 |

- **원본 보호** : `--out` 이 `--in` 과 같거나 원본 묶음 안이면 아무것도 안 쓰고 **종료 2**(0절). 폴더 입력은 묶음 전체를 새 자리로 복사한 뒤 고친 겹만 다시 쓴다 — 손 안 댄 겹 · 다른 그림은 바이트 그대로.
- 캔버스 밖으로 나간 칸은 잘려 `pixels_clipped` 로 센다.
- `--dry-run` 이면 안 쓰고 `would_write` 만 낸다(`out` 은 null).
- 보고 열쇠 : `status` · `in` · `out` · `layer` · `at` · `mode` · `pixels_written` · `pixels_clipped` · `bbox`(`[x0, y0, x1, y1]` 끝 뺌, 바뀐 칸이 없으면 null) · `dry_run` · `would_write`.

### `lint` — 칸 단위 린트

```
arttool lint --in work/set
arttool lint --in work/set --template work/guide --rules orphan,hole,asym --report lint.json
```

| 인자 | 뜻 |
| --- | --- |
| `--in` | 겹 묶음 폴더 또는 PNG (필수) |
| `--item` | 겹 묶음의 그림 이름 (기본 `idle`) |
| `--template` | 팔레트 · 빛 · 외곽선 방식을 읽을 템플릿(이름 · `template.json` · 폴더). 안 주면 팔레트 · 외곽선 방식이 없어 `stray_color` · `outline_gap` 이 안 돈다 |
| `--rules` | 쉼표로 고른 규칙(`orphan` 이든 `lint.orphan` 이든). 안 주면 기본 5개. 모르는 이름은 종료 2 |
| `--report` | 보고 JSON 파일 |

- **파일을 안 쓰고, 걸려도 종료 0**(경고 성격). 종료 코드로 막지 않는다. `check` 에는 합치지 않았다.
- **`asym` 은 CLI 에서 자동으로 안 켜진다.** 파이썬 `Canvas.lint()` 는 symmetry 를 켠 겹에만 자동으로 켜지만, CLI 는 symmetry 정보가 없으니 `--rules …,asym` 으로 직접 준다. 그러면 모든 겹에 돈다.
- 화면에는 이슈 한 줄씩 + 수치 한 줄. `--json` 이면 보고 JSON.

| 규칙 | 뜻 | 기본 |
| --- | --- | --- |
| `lint.orphan` | 8이웃에 같은 RGBA 가 없는 불투명 칸. **가장자리 칸도 잡는다**(`check` 의 `isolated` 는 가장자리를 빼니 다르다). 일부러 둔 점은 `waive` 로 뺀다 | 켬 |
| `lint.hole` | 알파 0 칸 중 **그림 테두리와 4방향으로 이어지지 않은 투명 덩어리**. **덩어리마다 한 줄** — 좌표는 덩어리 왼쪽 위 칸, `detail` 은 `3칸 구멍 (2,3) (3,3) (4,3)`(칸은 8개까지, 넘으면 `…`). `counts` 도 덩어리 수. 테두리에서 파고든 오목한 홈은 안 걸린다. 합친 그림으로 한 번만 잰다 | 켬 |
| `lint.stray_color` | 팔레트 밖 색(팔레트가 있을 때만) | 켬 |
| `lint.alpha_px` | 알파가 0 도 255 도 아닌 칸 | 켬 |
| `lint.outline_gap` | 합친 실루엣 가장자리 중 선이 아닌 칸(외곽선 방식이 `none` · 없음이 아닐 때) | 켬 |
| `lint.double` | 1px 선 위 같은 색 2×2 뭉침(2×2 둘레 12칸 중 같은 색이 1~4칸) | 끔 |
| `lint.asym` | 좌우 거울과 다른 칸(왼쪽만 짚는다) | 끔 |
| `lint.light_mismatch` | 명암에서 추정한 빛이 지정한 빛과 다름(그림 전체 이슈, 좌표 없음) | 끔 |

### 보고

`{status, issues, counts, metrics}`

| 열쇠 | 뜻 |
| --- | --- |
| `status` | `ok` · `warn`. 켠 규칙 중 하나라도 걸리면 `warn` |
| `issues[]` | `{rule, layer, x, y, color, detail}`. 합친 그림으로 재는 `hole` · `outline_gap` · `light_mismatch` 는 `layer` 가 null, `light_mismatch` 는 `x` · `y` 도 null |
| `counts` | 켠 규칙마다 걸린 수 |
| `metrics.symmetry` | 거울과 같은 불투명 칸 ÷ 불투명 칸 (0~1) |
| `metrics.center` · `center_offset` | 불투명 칸 질량 중심 `[x, y]` · bbox 중심과의 차 |
| `metrics.bbox` | `[x0, y0, x1, y1]` 끝 뺌 |
| `metrics.light_guess` | `top_left` · `top` · `top_right` · `unknown` |

수치는 규칙을 어떻게 골라도 늘 채운다. 불투명 칸이 없으면 `symmetry` · `center` · `bbox` 는 null.

### 거절 · 주의

| 거절 (종료 2) | 뜻 |
| --- | --- |
| `--in` 이 폴더도 PNG 도 아님 · `--grid` 파일 없음 | 경로 확인 |
| `grid apply` 의 `--out` 이 `--in` 과 같음 · 원본 안 · 비어 있지 않은 폴더 | 새 자리를 준다 |
| `--layer` 를 안 줬는데 겹이 여럿 | 겹 이름을 준다 |
| `--box` · `--at` 가 정수 개수가 안 맞음 · 너비 · 높이가 0 이하 | `x,y,w,h` · `x,y` |
| `lint --rules` 에 모르는 이름 | 목록에서 고른다 |

- 눈 흰 점처럼 **일부러 둔 칸**은 파이썬 `c.lint(waive=[(x, y), …])` 로 뺀다. CLI 에는 `waive` 인자가 없다.
- `--legend` 로 글자표를 고정하면 `grid show` 와 `grid apply` 를 여러 번 오가도 같은 색이 같은 글자다.

## 24. 로컬 그림 모델로 뽑기 — `provider make --provider local` (2026-10-07)

한 줄로 : ComfyUI 서버를 불러 **소품(`prop`)** 새 그림과 **`inpaint`** 를 뽑는다. 돈이 안 든다(`cost_usd` 0). 설계는 `Docs/Design/2026-10-07-provider-local설계.md`, 실측 근거는 `Docs/Research/2026-10-07-로컬그림모델실측1단계.md` · `2단계.md` · `2026-10-07-provider-local실측.md`.

**실물 확인함(ComfyUI 0.31, 2026-10-07).** 내장 본보기(`klein_prop` · `klein_inpaint`)는 노드 하나 안 고치고 그대로 돌았다(`2026-10-07-provider-local실측.md`). 장당 10~11초, 미니PC 메모리 피크 +14.6GB. 다른 서버 버전이라 노드가 안 맞으면 종료 1, 「이 노드가 서버에 없다」.

### 켜는 법과 명령

```
set ARTTOOL_LOCAL_ENDPOINT=http://<ComfyUI 주소>:<포트>
arttool provider make --provider local --kind prop --spec req.json --out gen/ --dry-run
arttool provider make --provider local --kind prop --spec req.json --out gen/
arttool provider make --provider local --kind inpaint --spec fix.json --out gen/ --json
```

- 켜지는 조건은 ComfyUI 주소가 있을 때다. 환경변수 `ARTTOOL_LOCAL_ENDPOINT` 나 설정 파일의 `endpoint`. `http://` · `https://` 만 받는다.
- `--kind` 는 `prop` 또는 `inpaint`. 다른 kind(`character` 등)는 `local` 이 못 만든다(PixelLab 길).
- 주소가 없으면 `provider list` 에서 빠지고, 대놓고 고르면 「켤 수 없다」로 멈춘다.

### spec JSON 칸

`--spec` 파일 하나에 다 적는다. 안 적은 칸은 설정 파일 · 기본값을 쓴다.

| 칸 | 뜻 | 기본 |
| --- | --- | --- |
| `size` | 받을 그림 크기 `[w, h]` | `[64, 64]` |
| `prompt` | 그릴 것 | 빈 글 |
| `negative` | 피할 것 | 빈 글 |
| `seed` | 시드. **안 주면 무작위로 정하고** 결과 JSON 의 `seed` 에 남긴다 | 무작위 |
| `variants` | 한 번에 몇 장. 시드는 `seed`, `seed+1` … | 1 |
| `reference` | inpaint 의 **원본** PNG 경로 (`size` 와 같은 크기여야 한다) | — |
| `mask` | inpaint 마스크 PNG. **흰 칸 = 고칠 곳**, 크기는 원본과 같다 | — |
| `workflow` | 내장 본보기 대신 쓸 API 꼴 워크플로 JSON 경로 | 내장 본보기 |
| `models` | 워크플로 자리표시에 넣을 값(`unet` · `text_encoder` · `vae` · `lora` · `lora_strength` 등). 키별로 설정 파일 값을 덮는다 | 설정 파일 |
| `work_size` | 모델에 줄 작업 크기(긴 변). 64~2048 정수 | 512 |
| `extra_colors` | inpaint 마스크 안에 새로 쓸 색 목록 (`"#RRGGBB"`) | 없음 |
| `snap` | inpaint 마스크 안 색 맞추기. `source`(원본 색 + `extra_colors`) · `profile`(`palette` 색 + `extra_colors`) · `none`(안 맞춤. 색이 수백이 되어 `check` 에 걸린다, 날것 보기용) | `source` |
| `palette` | `snap: profile` 일 때 쓸 색 목록. **프로필 파일을 읽지 않는다** — 색을 spec 에 직접 적는다 | — |

- **작업 크기는 「요청 크기 × 정수 배율」** 이다. 긴 변이 `work_size` 를 넘지 않는 정수 배율 중 **두 변이 다 16 의 배수가 되는 가장 큰 것**을 고른다(모델 잠재 공간이 16 단위라서). 64px 요청에 512 면 8배(512×512), 60×120 이면 4배(240×480)다.
- 그런 배율이 없으면(예 33×33) 가장 큰 배율로 키운 뒤 **오른쪽 · 아래를 투명 칸으로 16 의 배수까지 덧대고**(495 → 496) 결과에서 그만큼 잘라 낸다. inpaint 마스크의 덧댄 칸은 「안 고침」이다.
- `size` 는 양의 정수 둘이고 긴 변이 `work_size` 이하여야 한다. `seed` 는 0 이상 정수(`seed + variants - 1` 이 2^64-1 이하), `variants` 는 1~64, `prompt` · `negative` 는 글자다. 어기면 종료 2.
- spec · 설정 파일에 **모르는 칸이 있으면 종료 2** 「모르는 칸 : … (아는 칸 : …)」. 오타를 조용히 넘기지 않는다.
- 워크플로 자리표시 칸 이름은 `$prompt` `$negative` `$seed` `$width` `$height` `$image` `$mask` 와 `models` 의 키다. 값이 문자열 통째로 `"$이름"` 인 칸만 바뀐다.

### 설정 파일

주소 말고 모델 이름 같은 값은 YAML 설정 파일에 둔다. 빈 본보기는 저장소 맨 위 `local.example.yaml` — **복사해서 git 밖에 두고** 환경변수 `ARTTOOL_LOCAL_CONFIG` 로 그 경로를 알린다. 실제 주소 · 모델 파일 이름은 저장소에 안 적는다.

| 칸 | 뜻 | 기본 |
| --- | --- | --- |
| `endpoint` | ComfyUI 주소 | — |
| `models` | 워크플로 자리표시 값 (`unet` · `text_encoder` · `vae` · `lora` · `lora_strength`). **ComfyUI 모델 폴더 안 이름**이다. 비워 두면 「안 적음」 | — |
| `workflows.prop` · `workflows.inpaint` | kind 별 사용자 워크플로 파일. 상대 경로는 설정 파일 옆 기준 | 내장 본보기 |
| `work_size` | 작업 크기(긴 변) | 512 |
| `timeout_s` | 한 판을 기다리는 최대 초 | 600 |
| `heavy` | 메모리 큰 워크플로 **파일 이름** 목록 | 없음 |

**앞이 이기는 차례** :

| 값 | 차례 (앞이 이긴다) |
| --- | --- |
| ComfyUI 주소 | 환경변수 `ARTTOOL_LOCAL_ENDPOINT` > 설정 파일 `endpoint` |
| 모델 이름 (`models`) | spec `models` > 설정 파일 `models` (키별로 덮는다) |
| 워크플로 | spec `workflow` > 설정 파일 `workflows.<kind>` > 내장 본보기 |
| 작업 크기 | spec `work_size` > 설정 파일 `work_size` > 512 |
| `timeout_s` · `heavy` | 설정 파일 > 기본값 (spec 으로는 못 준다) |

모델 이름은 **코드 · 내장 본보기 어디에도 박혀 있지 않다.** 안 주면 자리표시가 남아 종료 2 가 난다.

### 흐름 10단계

| 단계 | prop (새 그림) | inpaint | 누가 |
| --- | --- | --- | --- |
| 1 입력 준비 | — | 원본 · 마스크를 NEAREST 로 작업 크기까지 키움 | 제공자 |
| 2 워크플로 채우기 | `$prompt` · `$seed` · `$width` … 를 값으로 바꿈 | 같음 + `$image` · `$mask` | 제공자 |
| 3 ComfyUI 호출 | 상태 확인 → 노드 확인 → 그림 올리기 → 줄 세우기 → 기다리기(1초 폴링) → 받기 | 같음 | 제공자 |
| 4 날것 남기기 | `raw/<종류>_<번호>_<받은 폭>.png` (덧댄 크기 그대로) | 같음 | 제공자 |
| 5 축소 | BOX 로 요청 크기까지 | 같음 | 제공자 |
| 6 색 맞추기 | — | 마스크 안 칸만 가까운 색으로 (`snap`) | 제공자 |
| 7 합성 | — | 마스크 밖 = 원본 그대로. 밖 바뀐 칸을 세어 `meta.outside_changed`(늘 0, 아니면 종료 1) | 제공자 |
| 8 바탕 지우기 | `cutout --key corner` | (원본이 투명이라 보통 안 함) | 기존 명령 |
| 9 색 줄이기 | `merge-colors --max-colors 16` | (6 에서 끝) | 기존 명령 |
| 10 검사 | `check` | `check` · `layers diff` | 기존 명령 |

- 1~7 은 제공자가 한다. 결과 그림은 `<종류>_000.png`(prop 이면 `prop_000.png`, `variants` 면 `_001` …) 로 `--out` 안에 쓰인다.
- SaveImage 노드가 여러 장을 내면 **첫 장만** 쓰고 경고를 남긴다.
- 서버 쪽 출력 파일은 지우지 않는다. 서버가 준 파일 이름은 받을 때만 쓰고 저장 이름은 툴이 정한다.
- inpaint 때 서버 input 폴더에 올린 `arttool_*.png` 도 **지우지 않는다**(ComfyUI 에 지우는 API 가 없다). 쌓이면 서버에서 손으로 치운다.
- **inpaint 로 「지우기」는 못 한다.** 색 맞추기가 마스크 안 칸을 늘 불투명으로 만들기 때문이다. 칸을 투명으로 비우려면 `layers` · `fill` 같은 기존 명령을 쓴다.
- `variants` 여러 장 중 가운데서 실패하면 오류 메시지 끝에 「이미 쓴 파일 N장 : …」 이 붙는다. 그 파일은 남아 있다.
- 받은 그림의 긴 변이 작업 크기의 2배를 넘거나 압축 폭탄이면 풀기 전에 거절한다(종료 1).

### 뽑은 뒤 차례

```
# prop (소품 · 건물 · 이펙트)
arttool cutout --in gen --out cut --key corner --tol 10
arttool merge-colors --in cut --out clean --max-colors 16 --per-image --sheet s.png
arttool check --in clean --report c.json

# inpaint
arttool check --in gen --report c.json
arttool layers diff --base base.png --in gen --out set --template t.json
```

`merge-colors` 는 `cutout` 뒤에 둔다(바탕이 지워진 그림에서 색을 센다). **여러 장 묶음에는 `--per-image` 를 붙인다** — 안 붙이면 묶음 전체 색이 한도 2048 을 넘어 종료 1 이 난다. **inpaint 원본은 정리가 끝난(`merge-colors` 뒤) 그림을 쓰고, 새 색이 필요하면 spec 의 `extra_colors` 로 준다** — 정리 전 원본이면 `check` 가 색 수로 걸린다. `intake` 를 쓸 거면 `merge-colors` 를 그 사이에 넣어야 한다. 결과 비교판은 `sheet` 로 눈으로 본다.

### `--dry-run`

**네트워크를 하나도 안 부른다.** 요청 검사 · 워크플로 읽기 · 자리표시 채우기 · inpaint 원본/마스크 크기 검사까지 한다(남은 자리표시가 있으면 여기서 종료 2). 쓰는 것은 `--out` 안 `local_request.json` 하나 — 채운 워크플로 · 올릴 그림 목록 · 쓸 파일(`would_write`) · 시드 · `heavy` 경고를 담는다. 주소는 있어야 한다(제공자가 켜져야 고를 수 있다).

### 종료 코드

| 코드 | 언제 |
| --- | --- |
| 2 | 인자 · 설정이 틀림. size · seed · variants · prompt 꼴 · 모르는 칸 · 남은 자리표시(`$lora` 등 채울 값 없음) · 화면 저장 꼴 워크플로(API 꼴로 내보낸다) · inpaint 에 `reference` / `mask` 없음 · 원본과 마스크 크기 다름 · 마스크에 흰 칸 없음 · `snap: profile` 인데 `palette` 없음 · 설정 파일 깨짐 |

### 무거운 판 경고 (`heavy`)

메모리를 크게 먹는 워크플로(Qwen-Edit · Wan 급, 피크 22~25GB)는 설정 `heavy` 에 파일 이름을 넣는다. 그 워크플로로 돌리면 결과 · dry-run 에 「무거운 판 : … 다른 큰 프로세스(LLM 서버 등)를 내린 뒤 돌린다」 경고가 붙는다. **툴은 서버를 끄고 켜지 않는다.** 무엇을 내리는지는 쓰는 사람 몫이다. 결과 `meta.seconds` 가 갑자기 길어지면 메모리가 밀린 것이다.

## 25. 7판 겹 검사 넓히기 — `layers check` 검사 여섯 · 맨 폴더 · `view --tint` · `fill --holes` (2026-10-07)

한 줄로 : 겹 묶음을 가른 뒤 사람이 눈으로 찾던 것(장 수 · 기준점 흔들림 · 층 마스크 빈틈 · 안쪽 구멍 · 전 판에 없던 색 · 겹끼리 같은 흰색)을 `layers check` 가 숫자로 낸다. `layers.json` 이 없는 폴더도 `--order` 로 읽는다.

**새 인자를 안 주고 새 칸(`anchor` · `kind: mask`)도 안 쓴 묶음은 보고가 예전과 바이트까지 같다.** 새 보고 칸은 그 인자를 줄 때만 생긴다.

### `layers.json` 새 칸 (버전 2)

```json
{"version":2,"canvas":[440,560],"anchor":"bbox_bottom_center","anchor_layer":"content",
 "layers":[{"name":"content","kind":"content"},
           {"name":"tier1","kind":"mask"},{"name":"tier2","kind":"mask"}]}
```

| 칸 | 뜻 |
| --- | --- |
| 맨 위 `anchor` | 기준점. `bbox_bottom_center` · `bbox_center` · `bbox_top_center` 중 하나, 또는 정수 `[x, y]`. **`[x, y]` 는 변 좌표, 이름 꼴은 칸 좌표**다 — `[x, y]` 는 0 ≤ x ≤ 너비 · 0 ≤ y ≤ 높이라 캔버스 바닥 `[220, 560]` 도 된다 |
| 맨 위 `anchor_layer` | 기준점을 잴 그리는 겹 하나(선택, `anchor` 와 같이만). 없으면 마스크를 뺀 겹을 다 쌓은 그림. 튀어나온 도구 겹이 bbox 를 끄는 묶음에 쓴다. 마스크 겹 · 없는 이름은 종료 2 |
| 겹 `kind: mask` | 그리지 않는 겹(층 경계 표시 같은 것). **쌓기에서 빠진다** — `view` 합침 · `export --flat` · `check --original` · `--cover` 셈 · `layer_poke` · `layer_exclusive` · `fill --nearest` 후보. 크기 · 반투명 검사는 받는다 |

- 둘 중 하나라도 쓰면 version 2 로 저장한다. 버전 1 파일에 있으면 「version 2 로 올려라」 로 거절(종료 2).
- `split` · `template render` 가 같은 폴더 목록을 다시 써도 `anchor` · `anchor_layer` 는 이어 받는다(`anchor_layer` 는 그 겹이 남아 있을 때만).
- 겹 이름이 `mask` 여도 kind 가 저절로 `mask` 가 되지 않는다(`split` · `draw` · 짐작은 kind 낱말 목록에 `mask` 가 없다).

### `layers check` 새 인자

```
arttool layers check --in set/ [--counts] [--anchor-tol 1] [--mask-of content]
                     [--holes [--holes-under lid] [--hole-min 2] [--hole-max 32]]
                     [--before set_v1/] [--shared-colors [--shared-tol 8] [--shared-ignore "#000000"]]
                     [--original f0.png [--dents]]
                     [--known k.json] [--baseline old.json] [--fail-on-new] [--report r.json]
```

| 인자 | 보는 것 | 경고 | 보고 칸 |
| --- | --- | --- | --- |
| `--counts` | 겹마다 파일(장) 수 | `layer_count` (`detail` 에 `bowl 8 · lid 4`) | `counts: {겹: 수}` |
| (`anchor` 칸) | 장마다 마스크를 뺀 겹을 다 쌓은 그림(`anchor_layer` 가 있으면 그 겹 하나)의 bbox 기준점 하나. 이름이면 **첫 장**과 칸 좌표로, `[x, y]` 면 bbox 아래변 가운데 `(floor((x0+x1)/2), y1)` 를 변 좌표로 견준다 | `layer_anchor` (어긋난 장의 기준점 좌표) | `anchors: [{item, at: [x, y]}]` (`at` 은 anchor 와 같은 꼴, 빈 장은 `at: null`) |
| `--anchor-tol N` | 기준점 허용폭(가로 · 세로 차 중 큰 값). 기본 0, 0~64 | | |
| `--mask-of 기준겹` | 마스크 겹 합집합이 기준겹 불투명 칸을 덮나 | `layer_mask_gap` · `layer_mask_overlap` · `layer_mask_outside` (모두 경고) | `mask_of: {base, masks, items: [{item, gap, overlap, outside}]}` |
| `--holes` | 겹마다 안쪽 구멍(테두리에서 투명 칸만 따라 못 닿는 투명 칸, `fill --enclosed` 와 같은 뜻) | `layer_hole` (**덮이지 않은** 구멍만) | `holes: [{item, layer, count, cells, covered, open, regions: [{box, cells, covered}]}]` (구멍 있는 겹만) |
| `--holes-under a,b` | 이 겹들 중 **구멍 난 겹보다 위 겹**이 구멍을 다 덮으면 `covered` | | |
| `--hole-min N` | N 칸 미만 구멍은 안 센다 (기본 1) | | |
| `--hole-max N` | N 칸 넘는 구멍은 일부러 둔 빈 곳(손잡이 안)으로 본다. 기본 없음 = 전부 | `layer_hole` · `open` 셈에서 뺀다 | `regions[]` 에 `large: true`, 줄에 `large: 개수` (줄 때만) |
| `--before 폴더` | 전 판과 같은 그림 · 같은 겹 짝의 색. 새 색 = 이번 판 색 − 전 판 색 | `layer_new_color` · `layer_before_missing` (짝 없음, 양쪽 다) | `before: {in, items: [{item, layer, colors: [전, 후], new, new_cells}]}` |
| `--shared-colors` | 겹 짝마다 서로 가까운 색(RGB 각 칸 차 ≤ `--shared-tol`) | `layer_shared_color` (큰 것부터 8색) · `layer_shared_skipped` (한 겹 색이 256 넘어 건너뜀) | 없음 (경고만) |
| `--shared-tol N` | 기본 8, 0~64 | | |
| `--shared-ignore "#000000,…"` | 이 색들과 `--shared-tol` 안인 색을 **견주기 전에** 양쪽 겹에서 뺀다(외곽선처럼 모든 겹이 같이 쓰는 색). 256색 상한도 뺀 뒤 색 수로 본다. `#RRGGBB` 만, 32색까지 | 뺀 색은 `detail` · 좌표에서 사라진다 | `shared_ignored: ["#000000"]` (대문자 · 준 순서 · 겹침 뺌, 줄 때만) |
| `--dents` (`--original` 과 같이) | 원본 짝 그림에서 그리는 겹마다(맨 위 겹 빼고) 「원본엔 칠했는데 그 겹까지 쌓은 그림이 빈 칸」 중 **그 겹 bbox 안**(`bare`)을 위 겹이 덮나. 바깥과 이어진 패인 자리도 센다(`--holes` 는 못 잡는다) | `layer_dent` (안 덮인 칸, 처음 비는 가장 아래 겹 한 줄) | `dents: [{item, layer, bare, bare_outside, covered_by: {위 겹: 칸}, open}]` (원본 크기가 다르면 칸 없음) |
| `--known` · `--baseline` · `--fail-on-new` | `check` 13절과 같은 알고 두는 경고 | | `known` · `new_warnings` (셋 중 하나를 줄 때만) |

- 마스크 겹은 기준점 · 구멍 · 색 견줌에서 빠진다. `--mask-of` 만 마스크 겹을 본다.
- 구멍 덩이는 8방향으로 묶고 큰 것부터 64개까지만 `regions` 에 싣는다. 넘으면 `more: n`.
- `--before` 의 전 판도 이번 판과 같은 길로 연다 — `layers.json` 이 있으면 그것, 없으면 같은 `--order` · `--masks`. 크기가 달라도 색은 견준다.
- 외곽선 색처럼 모든 겹이 같이 쓰는 색은 `layer_shared_color` 로 늘 뜬다 — `--shared-ignore` 로 빼거나 `--known`/`--baseline` 으로 접는다.
- `--dents` 에서 볼 값은 `open` 이다. `bare_outside` 는 그 겹 bbox 밖 칸(위 겹이 실루엣 밖에 칠한 칸 — 뚜껑 자체)이라 참고로만 싣는다. 같은 open 칸은 처음 비는 가장 아래 겹 줄에만 실리고, 그 장에 없는 겹은 줄이 없다.
- `--dents` 의 `covered_by` 는 위 겹마다 따로 세어 겹끼리 겹치면 합이 `bare` 를 넘는다. 안 덮인 칸은 `roundtrip_diff` 에도 들어 이미 fail 이다 — `layer_dent` 는 어느 겹 아래에서 비었는지를 알린다.
- 알고 두는 경고의 열쇠는 `items` 칸 좌표 글(`"[5, 5]"`)이다. 그림 이름은 `detail` 에만 있어 「그림 f03 만」 처럼 좁히지는 못한다. `where: "*"` 로 규칙째 빼는 것은 된다.

| 거절 (종료 2) | 뜻 |
| --- | --- |
| 변형 묶음에 `--counts` | 장 수가 뜻이 없다 |
| `anchor` 칸이 없는데 `--anchor-tol` · 범위 밖 | |
| `--mask-of` 에 마스크 겹 · 없는 겹 · 이름 둘 이상 · 묶음에 마스크 겹이 없음 | `view --mask-of` 도 같은 검사 |
| `--holes` 없이 `--holes-under` · `--hole-min` · `--hole-max` / `--holes-under` 에 마스크 겹 · 맨 아래 겹 / `--hole-min` · `--hole-max` 0 이하 | 맨 아래 겹은 아무것도 못 덮는다 |
| `--shared-colors` 없이 `--shared-tol` · 범위 밖 | |
| `--shared-colors` 없이 `--shared-ignore` / 낱말이 `#RRGGBB` 가 아님(`#000` · `000000` · 빈 글자 · 빈 낱말 — 끝 쉼표 `#000000,` · `#000000,,` 포함. 쉼표 뒤 빈칸은 받는다) / 32색 넘음 | |
| `--original` 없이 `--dents` / 그리는 겹이 하나뿐 | 덮을 위 겹이 없다 |

`--before` 폴더가 없으면 종료 1.

### 맨 폴더 모드 — `--order a,b [--masks m]`

`layers.json` 없이 파일만 있는 폴더를 묶음으로 읽는다. `layers check` · `view` · `fill` 이 받는다(`export` · `diff` 는 `layers.json` 이 있어야 한다).

| 꼴 | 알아보는 법 | 겹 · 그림 |
| --- | --- | --- |
| 가. 하위 폴더 | `--order` 이름과 같은 하위 폴더가 하나라도 있다 | `<겹>/<그림>.png` |
| 나. 한 폴더 | 하위 폴더가 없다 | `<겹>_<그림>.png`. 접두가 겹치면(`hair` · `hair_front`) 파일마다 **가장 긴 겹 이름**에만 간다 |

- **순서는 짐작하지 않는다** — `--order` 가 아래 → 위 순서다. kind 는 이름으로 짐작(`body` · `hair_…` 등, 아니면 `deco`), `--masks` 에 적은 겹만 `mask`.
- 그림 목록은 모든 겹 그림 이름의 합집합(자연 정렬, `f2` < `f10`). 겹마다 장 수가 달라도 읽힌다 — 겹은 모두 `optional` 이라 그림마다 `layer_empty` 가 쏟아지지 않고, 장 수는 늘 `counts` · `layer_count` 한 줄로 나온다.
- canvas 는 `--order` 앞 겹의 이름순 첫 파일 크기. 다른 크기 그림은 `layer_canvas` 경고.
- 보고 맨 위(`version` 다음)에 `inferred: true` · `order: [...]` 가 붙는다(맨 폴더일 때만).
- `layers fill` 은 `layers.json` 을 만들지 않고 같은 꼴(하위 폴더 또는 `<겹>_<그림>.png`)로 쓴다.
- 거절 (종료 2) : `layers.json` 이 있는데 `--order` · 가 · 나 꼴 섞임 · `--order` 없이 `--masks` · `--masks` 가 `--order` 밖 · 겹 전부가 마스크 · `--masks` 이름 겹침 · 겹 이름 꼴 틀림 · 겹 이름 겹침 · 한 폴더에 항목 4096 넘음. 그림이 하나도 없으면 종료 1.

### `layers view --tint` — 물들인 미리보기 판

```
arttool layers view --in set/ --out v.png --tint "content=#cc8844,glass=#44aa88" [--tint tints.json] [--mask-of content]
```

- 글자 꼴 `겹=#hex,…` 는 판 한 칸(칸 이름 = 그 글자), `.json` 은 `[{"name": "apple", "tint": {"tier1": "#cc8844"}}, …]` 로 칸 여럿. 되풀이하면 칸이 는다. 32칸까지.
- 칠하기는 `tint` 명령과 같은 곱하기. 표에 없는 겹은 그대로.
- **열쇠가 마스크 겹이면** `--mask-of` 기준겹의 **그 마스크 안 칸만** 그 색으로 곱한다(층마다 다른 색). 기준겹 원래 색에 곱한다. 마스크 겹 자체는 안 그린다.
- 판 꼴 : 줄 = 그림, 칸 = 물들임 표. 보고에 `tints: [칸 이름…]` (줄 때만).
- 거절 (종료 2) : `--each` 와 같이 · 없는 겹 · 색 꼴 틀림 · 마스크 열쇠인데 `--mask-of` 없음 · `--tint` 없이 `--mask-of` · `--mask-of` 가 check 와 같은 검사에 걸림 · JSON 꼴 틀림 · 32칸 넘음.

### `layers fill --holes` — 겹 안쪽 구멍 메우기

```
arttool layers fill --in set/ --holes content,glass --out set2/ [--hole-max 32] [--items f0,f1]
```

- 메울 자리 = 그 겹 자신의 안쪽 구멍. 칠할 색도 **그 겹 자신**에서 가져온다 : ① 같은 행 가장 가까운 불투명 칸(거리 같으면 왼쪽) ② 그 행에 없으면 가장 가까운 칸. **평균을 안 내고 칸 색을 그대로 옮긴다**(결 복사) — 새 색이 안 생긴다.
- 위 겹이 덮는 구멍(`covered`)도 메운다.
- `--hole-max N`(기본 32) 보다 큰 구멍은 뜻한 빈 곳(고리 · 손잡이 안)일 수 있어 안 메우고 경고 `fill_hole_skipped`.
- 보고 : `holes` · `hole_max` · `images: [{item, filled: {겹: 칸수}, new_colors: {겹: 0}}]`. `new_colors` 는 메운 뒤 색을 **실제로 다시 센 값**이라 0 이 아니면 그 자체가 버그 신호다.
- 손 안 댄 겹과 `layers.json` 은 바이트 그대로 복사한다(맨 폴더면 `layers.json` 없이).
- 거절 (종료 2) : `--mask` 와 `--holes` 둘 다 · 둘 다 없음 · `--holes` 와 `--color`(새 색을 만든다) · `--holes` 와 `--nearest` · `--holes` 에 마스크 겹 · `--hole-max` 0 이하 · `--mask` 인데 `--holes` 없이 `--hole-max`.

### 주의

- 숫자 넷(`--tint` 32칸 · 구멍 목록 64 · `fill --hole-max` 32 · `--shared-tol` 8). `fill --hole-max` 만 실측으로 256 에서 32 로 낮췄다(실수 구멍 최대 19칸, 일부러 둔 구멍 2~1,759칸). 나머지는 사례 크기에서 어림한 값이다.
- 440×560 겹 셋 × 8장 묶음에 새 검사를 다 켜면 약 1.65초, 새 인자 없이는 약 0.5~0.7초(실측 2026-10-07).
- 램프(팔레트) 파일과 견주는 길은 없다 — 전 판(`--before`)과만 견준다.

### 7-다 셋 — 작은 겹 쓰기 · `tail_at` · `sheet --compare`

- **작은 겹 쓰기** : `split` · `layers diff` 가 작은 겹(`size` · `offset`) 묶음에도 쓴다. 상자로 잘라 쓰고, 상자 밖 칸은 종료 2. `split` 은 겹 · canvas 가 다른 작은 겹 묶음에는 쓰기 전에 종료 2 (17절).
- **`ui9_panel` 꼬리 자리** : 값 `tail_at` = `left` · `center`(기본) · `right` (5절 표).
- **`sheet --compare 전판폴더`** : 같은 이름 그림끼리 색 수 · 떨어진 점 · 외곽선 비율을 [전, 후, 차] 로 보고에 (20절). 입력 둘이 같은 파일 이름이면 경고 `compare_duplicate`, 짝이 입력 자신이면 `compare_self`.
- **`draw` 캔버스** : `Canvas.open` 으로 연 묶음의 마스크 겹은 `merged()` · `preview` · `outline()` · 겹마다 `lint()` · `report()` 의 색 · 반투명 · exclusive 훑기에 안 들어간다(빈 겹 판정은 받는다). 저장 · 다시 열기는 그대로.
