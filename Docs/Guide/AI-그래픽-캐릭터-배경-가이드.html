AI 캐릭터·배경 아트 가이드

캐릭터 및 배경을 그리는 데 좀 더 빠르고 효과적인 AI 활용 방법에 대한 가이드를 제공하기 위함. AI를 활용할 때 리마인드하여 좀 더 효과적인 AI 아트를 생산할 수 있도록 문서를 작성.

문서 개요

문서 목적

  • 캐릭터 및 배경을 그리는 데 좀 더 빠르고 효과적인 AI 활용 방법에 대한 가이드를 제공하기 위함.
  • AI를 활용할 때 리마인드하여 좀 더 효과적인 AI 아트를 생산할 수 있도록 문서를 작성.

주요 방향성

  • 아트의 토큰 리소스를 절감하는 것을 목표로 함.
  • 리팩토링을 최소화시키는 것을 목표로 함.
  • 이미지에 대한 수정을 하더라도 크게 수정하지 않는 방향으로 진행할 수 있도록 함.

사전 전제 조건

  • 포토샵을 활용하지 않도록 함.
  • 지속적인 비용을 최대한 절감할 수 있도록 함.
  • 최적화는 가능한 선에서만 함.

제작 목표

  • 원하는 캐릭터를 제작하는 것을 목표로 한다.
  • 현재 가능한 선에서만 제작하는 것에 대한 설명을 진행함.

AI 사용 이유

PixelLab은 고전에 가까운 그림체를 가지고 있고, ChatGPT는 그런 것에 구애받지 않고 이미지에 대한 그래픽 컨셉 자유도가 높아서 오히려 ChatGPT가 그래픽 컨셉을 설정하는 데에 있어서는 더 낫다고 생각함. 그리고 이미지에 대한 리팩토링 작업을 디테일하게 진행할 수 있음. 또한 필요에 따라서 실사 그래픽과 대화 등 여러 가지를 지원하니 ChatGPT를 보다 추천할 수 있음.

AI 사용 이유

일단 아트의 영역에서는 애니메이션 같은 경우, 한 번에 디테일을 잡을 수 없음. 직접 빠르게 제작한 후 적용을 해보며 수정을 하는 게 좋음. Spine은 로컬 PC에 대한 API 연결이 필요(폴더 경로 내에 있는 이미지 경로 인식이 필요). 따라서 Claude 홈페이지 내에서 명령을 진행하는 형태의 AI 명령 사용은 불가능함.

3

제작 가능 범위 설명

3-1배경

  • 배경은 썸네일 범위까지 가능.
  • 실제 게임 배경에 대한 범위도 가능은 함.
  • 현재 추천은 ChatGPT, PixelLab 등이 있음.
  • 단, 배경이 너무 큰 경우엔 API 연결을 통해 이미지 생성이 필요.
    • 2048 사이즈가 넘어가는 경우, ChatGPT API, PixelLab을 연결해서 사용 필요.
  • 썸네일 퀄리티는 레퍼런스가 있냐 없냐에 따라 많이 나뉨.
  • 원하는 썸네일, 캐릭터가 내부에 포함되어 있어야 한다면 그 썸네일을 그림판으로라도 위치나 형태를 간단하게 그린 후 AI에게 전달해야 디테일이 증가함.

3-2캐릭터

  • 현재 그래픽 컨셉을 UI나 캐릭터, 배경에 맞추는 가능한 범위는 3~5등신 캐릭터까지만 가능함.
  • 5등신 캐릭터도 리터칭이 필요할 수 있음.
  • 장신구(무기 포함)가 많으면 많을수록 리터칭이 매우 어려움.

3-3스프라이트 애니메이션

  • 현 시점에선 애니메이션이 가능은 함.
  • 단, 애니메이션에 대한 디테일 가이드라인 그림 이미지가 필요함.
  • 레퍼런스 이미지가 없는 경우, 재가공에 필요한 시간이 거의 하루 이상을 소비하게 되는 거 같음.
  • 간단한 무기 모션, 점프, 이동 등 전반적으로 애니메이션이 가능.

3-4UI

  • UI는 전반적으로 다 가능.
4

프롬프트 작성 방법

4-1공통

  • 공통적으로 디테일한 프롬프트와 간단한 프롬프트 2가지 방법엔 아래와 같은 장단점이 존재.

[ 디테일한 프롬프트 ]

장점

원하는 항목(장신구, 악세서리, 방어구, 무기) 등은 다 추가 가능. 디테일한 요소가 필요할 시엔 빠른 속도감을 체감할 수 있음.

단점

리팩토링 하는 시간이 매우 오래 걸림. AI랑 대화하는 피로도가 매우 많이 소비하게 된다.

>>결론적으로 방치형 / 뱀서류 등 약간의 퀄리티를 지향하면 사용하는 게 좋음.

[ 간단한 프롬프트 ]

장점

스트레스를 덜 받음. 빠른 속도를 지향. 디테일한 작업이 필요 없으면 무조건 이 방식을 추천.

단점

디테일한 게 필요한데 이 방식으로 하면 리팩토링이 오래 걸림. 토큰 소비도 디테일한 방법보다 많이 소요가 될 수 있음.

>>결론적으로 캐주얼 / 하이퍼 캐주얼에 적합함. 캐주얼도 좀 더 그래픽 요소가 많이 필요하면 부합하지 않을 수 있음.

과정을 나누는 이유

  • 과정을 나누지 않으면, AI가 하나의 TASK에서 여러 개를 하려다 보니 이미지의 컨셉을 오히려 해치는 경우가 많음. 따라서 이미지 디자인을 바꾸고 싶으면 [이미지 생성 과정] 내에서 컨셉을 바꾸는 것을 추천함.

4-3제작 가이드

필수 항목

  1. AI를 실행할 때엔 무조건 레퍼런스 이미지가 있어야 한다.
    • 레퍼런스 이미지가 없으면 무조건 수정한다, 라는 생각을 기본적으로 가지고 있어야 함.
    • 실제로 사람들끼리 구두로만 이야기하면 전달력이 중간중간 없듯이 AI도 마찬가지라는 생각을 기본적으로 가지고 있어야 함.
  2. 웬만하면 계획을 미리 공유해야 한다.
    • AI한테 사전에 이 캐릭터에 애니메이션이 포함될 예정이니 “파츠 같은 것들 분리해서 제작해야 한다”와 같은 간단한 컨셉 계획도 미리 공유를 해야 한다. 안 그러면 그 AI는 파츠 분리나 제작 방식에 대해 미리 인지하지 않음.
  3. 아트는 창작 영역이기 때문에 최대한 많은 레퍼런스를 AI에게 제공하는 게 좋다.
    • 그래픽 컨셉, UI 컴포넌트 유형 정보, 장식, 크기 등을 고려한 UI 레퍼런스를 AI에게 제공하는 게 좋음.
  4. 되도록 파츠로 분리하는 걸로 생각하는 게 좋다.
    • 미드저니와 같이 AI는 디자인적으로 그리 똑똑하지 않음.
    • 인지성이 좋은 건 맞으나, 현 시대에서 그래픽 컨셉을 계속 통일화시킬 만큼 AI가 그렇게 기억력이 좋지 않다. 따라서 토큰 소모량을 줄이고 그래픽 컨셉을 통일화시키려면 파츠를 여러 개로 분리해서 조립하는 개념으로 이미지를 생성 요청하는 게 좋다. (배경 제외)
    • 간단한 그래픽 32px × 32px 미만의 캐릭터는 굳이 파츠를 분리할 필요는 없음.
  5. 웬만하면 여러 개의 이미지를 요청해라.
    • 하나의 큰 이미지 내에 여러 개의 사물(나무 / 장신구 / 무기 / 방어구 / 캐릭터 등), UI를 요청하는 게 프롬프트를 다시 추가해서 요청하는 것보다 훨씬 효과적이다.

4-4개별 전제

[ 캐릭터 ]

  • 유니티 에셋 스토어 썸네일이나 게임 레퍼런스, 레퍼런스 이미지를 통해 프롬프트를 설계 진행. 사이즈는 되도록 크게 구성하는 게 좋음.
  • 크게 이미지를 구성한 후 리사이징을 진행한다.
  • 캐릭터 파츠는 무조건 분리하는 게 애니메이팅할 때 좋다.

[ 배경 이미지 ]

  • 배경 이미지도 어떤 이미지가 필요한지 캡쳐 혹은 구글 서치, 게임 배경 서치 등을 통해 레퍼런스를 가지고 제작한다.
  • 만약 비슷한 이미지가 없는 경우, 어떤 컨셉인지 그래픽 컨셉이라도 안내가 필요함.
  • 이미지 사이즈도 크게 구성한 후 사이즈를 줄이는 게 제작하는 데 효과적임.

[ UI ]

  • 컴포넌트 필요한 걸 정확하게 명시하여 AI에게 요청을 진행하는 게 좋음.

[ 파티클 ]

  • 파티클도 커스텀 윈도우를 통해서 AI에게 명령을 내린 후, 그걸 통해 프리팹을 생성할 수 있도록 요청하는 게 효과적임.
