# 배경 툴 후보 검증 (미확인 항목 조사)

> 앞선 조사 : `2026-08-20-배경그림조사.md`, `2026-08-20-배경그림오픈소스대안조사.md`
> 두 문서의 "아직 확인 못 한 것" 을 실제로 확인했다. **검색이 아니라 저장소를 직접 조회**했다. (2026-08-20 기준)

## 결론 먼저

1. **부풀리기(①-b)는 예상보다 훨씬 좋다. 그림 6장이면 47장이 나온다.** AI 나 사람이 만들 그림이 6장으로 줄어든다. 이번 조사 최대 수확.
2. **텍스처 합성(①-a)은 거의 전멸이다.** 후보 셋 중 둘은 **라이선스가 아예 없고**, 나머지 하나는 **보관 처리(archived)** 됐다. 우선순위를 내리고 **팔레트 + 기반 에셋** 쪽으로 무게를 옮겨야 한다.
3. **아이소메트릭과 셰이더 포팅은 걱정할 일이 아니었다.** 둘 다 비용이 낮다.
4. **오토타일 도구들은 다 MIT 지만 다들 2~3년째 멈춰 있다.** 갖다 쓰는 게 아니라 **읽고 우리가 다시 짜는 재료**로 봐야 한다.

## 2. 최대 수확 : 그림 6장이면 47장이 나온다

Aseprite 확장 **AutoBlob** 이 하는 일이 정확히 이거다.

```
템플릿 6장                      →  47장 blob 전체
· 내부 1장                          (팔레트도 그대로 유지)
· 안쪽 모서리 십자 1장
· 2×2 섬의 네 모서리 4장
```

**왜 47장인가** : 8이웃(직교 4 + 대각 4)이면 경우의 수가 256이다. 그런데 **"대각 이웃은 양옆 직교 이웃이 둘 다 있을 때만 친다"** 는 규칙을 적용하면 겹치는 게 걷혀서 **47가지**만 남는다. 이 규칙이 없으면 모서리가 아닌 곳에 모서리 그림이 붙는 티가 난다.

**구현이 더 쉬워지는 요령** : 타일 한 장을 **네 조각(쿼터 타일)로 쪼개면**, 각 조각은 이웃 3개(직교 2 + 대각 1)만 알면 된다. 조각당 경우의 수가 **2³ = 8가지**뿐이다.

**이게 우리한테 중요한 이유** :

- AI 나 사람이 만들 그림이 **47장이 아니라 6장**이다. PixelLab 이 없어도 부담이 확 준다.
- 6장은 기반 에셋에서 잘라내거나 손으로 그려도 되는 양이다.
- 참고 자료가 좋다 — **redblobgames 의 오토타일 대화형 안내**와 **BorisTheBrave 의 타일셋 분류** 문서가 규칙을 정리해 뒀다.

## 3. 아이소메트릭 : 걱정할 일 아니었다

앞 조사에서 "47-blob 은 사각 전용이라 아이소는 얼마나 들지 모름" 이라고 적었는데, **틀렸다.**

- **47-blob 규칙은 정사각 격자와 위상이 같다.** 8이웃을 보는 판정은 그대로고, **그림만 다이아몬드**다. 규칙을 새로 만들 필요가 없다.
- **깊이 정렬(무엇이 앞에 오나)도 Unity 기본 기능이다.**
  - `Edit > Project Settings > Graphics > Camera Settings > Transparency Sort Mode` 를 **Custom Axis** 로
  - 축은 **(0, 1, 0)** — Y 가 높을수록 먼저 그려서 뒤로 감
  - 높낮이가 있는 `Isometric Z as Y` 타일맵이면 **(0, 1, −0.26)** (격자가 (1, 0.5, 1) 일 때 값)

**→ 아이소 비용 : 낮음.**

## 4. Godot 셰이더 → URP 포팅 : 쉽다

패럴랙스 배경용 픽셀 구름 셰이더 때문에 걱정했던 부분이다.

- GDShader 는 **GLSL ES 3.0 기반**이고, **HLSL 을 알면 90%는 그대로다.**
- 차이는 대부분 표기다 — `vec3` → `float3`, `texture()` → `tex2D()`. 표준 함수 대응표가 문서에 있다.
- 주의할 점 하나 : **Godot 에는 `Properties` 블록이 없다.** Unity 로 옮길 때 이걸 직접 만들어 줘야 한다.
- URP 쪽은 `HLSLPROGRAM` / `ENDHLSL` 안에 정점·프래그먼트 함수를 넣는 구조다.

**→ 셰이더 포팅 비용 : 낮음.**

## 5. 아직 못 푼 것

- **PixelLab MCP 의 토큰 비용** — 저장소에 라이선스가 없고 README 에 도구 목록이 안 적혀 있다. **실제로 붙여서 재봐야 안다.** Unity MCP 때와 같은 고민이라 나중에 같이 판단하는 게 낫다.
- **미니PC VRAM 을 Qwen 과 이미지 모델이 나눠 쓸 수 있는지** — **미니PC 의 GPU 사양을 몰라서 계산을 못 했다.** 사양을 알면 "둘을 동시에 올릴지, 번갈아 올릴지" 가 바로 갈린다.
- **텍스처 합성이 64×64 픽셀아트에서 쓸 만한지** — 여전히 안 해봤다. 다만 위 라이선스 문제로 **우선순위가 내려갔다.**
