# 로컬 그림 모델 무거운 판 실측 — Qwen-Edit · Wan 을 `provider local` 로 (2026-10-08)

`2026-10-07-provider-local실측.md` 7절 「Qwen-Edit · Wan 무거운 판은 게임 서버가 내려간 뒤」와 진행상황 ⑪(검은 테) · ⑬(2차 범위)의 실측이다. 2단계(`2026-10-07-로컬그림모델실측2단계.md`)는 손 스크립트로 돌렸고, 이번엔 **ArtTool `provider make --provider local` 로 사용자 워크플로를 꽂아** 돌렸다. 코드는 한 줄도 안 고쳤다.

## 결론

- **네 워크플로(Qwen-Edit inpaint · 화풍 참조 · 자세 편집 · Wan I2V) 전부 1차 코드 그대로 돌았다.** 11판 모두 종료 0 · 시간 초과 0 · 자리표시 0. 뒤 사슬(`check` / `cutout → merge-colors → check`)도 전부 ok.
- 시간은 2단계와 같다 : **Qwen-Edit 52~62초 · Wan 17프레임 79~86초.** used 피크 **18.7~24.9GB**(≤25GB 통과), GTT 피크 Qwen 14.7GB · Wan 12.3GB.
- **inpaint 밖 0픽셀은 Qwen-Edit 에서도 지켜진다** (5판 `outside_changed` 0).
- **⑪ 검은 테는 생긴다.** 마스크가 투명 칸에 걸치면 `LoadImage` 가 알파를 떼어 검정 바탕을 모델에 넣고, 모델이 그 검정을 그대로 그린다. 새로 칠한 128칸 중 118칸(시드 1000) · 25칸(1001)이 검정. `snap: source` 도 못 막는다(외곽선 색이 어두워 검정이 그리로 눌린다). **2차 코드 몫** — 올리기 전에 투명 칸을 흰색(또는 원본 바깥 색)으로 깔아야 한다.
- prop 에 참조 그림을 주는 길은 **`models.ref_image` 우회**(서버 input 폴더 파일 이름)로 된다. 정식 칸 · 올리기는 2차.
- Wan 은 17장을 내고 제공자는 **첫 장만 받고 경고를 낸다**(설계대로). 첫 장은 원본과 거의 같아 혼자서는 쓸모가 없다 — 프레임 묶음 결과 꼴이 2차.

## 1. 워크플로 (ArtTool 자리표시 꼴)

2단계 `run2.py` 의 그래프를 API 꼴 JSON 으로 옮기고 값을 자리표시로 바꿨다. 모델 이름은 설정 `models` 의 새 키(`qe_unet` · `qe_lora` · `qe_clip` · `qe_vae` · `wan_high` · `wan_low` · `wan_lora_high/low` · `wan_style_lora` · `wan_style_strength` · `wan_clip` · `wan_vae` · `ref_image`)로 받는다. 설정 `heavy` 에 넷을 넣어 경고가 붙는지도 봤다.

| 파일 | kind | 바꾼 것 | 자리표시 |
| --- | --- | --- | --- |
| `qe_inpaint.json` | inpaint | run2 inpaint 꼴에서 22 · 23번(ImageCompositeMasked · 둘째 SaveImage) 뺌 — 합성은 제공자가 한다 | `$image` `$mask` `$prompt` `$negative` `$seed` + qe 넷 |
| `qe_style.json` | prop | `EmptySD3LatentImage($width,$height)` + 참조 `LoadImage($ref_image)` | `$width` `$height` `$ref_image` … |
| `qe_edit.json` | prop | `VAEEncode(참조)` denoise 1.0 — 자세 편집 | `$ref_image` … |
| `wan_i2v.json` | prop | `WanImageToVideo($width,$height, length 17, start_image=$ref_image)` · `noise_seed: $seed` 둘 | `$ref_image` … |

- `$ref_image` 는 제공자가 안 올리는 자리라 **spec `models.ref_image` 에 서버 input 폴더 안 파일 이름**을 넣는다(참조는 scp 로 미리 올림). 우회이지 정식 길이 아니다.
- dry-run 여섯 판 : 종료 0 · 남은 자리표시 0 · 경고 「무거운 판 : … 피크 ~25GB」 붙음(H1).

## 3. H6 — 검은 테 (⑪)

마스크 `mask_edge.png` : 통 왼쪽 변에 걸친 16×16, 256칸 중 **128칸이 원본 투명**. 판정은 `check_edge.py`(결과 64px 에서 「마스크 안 ∧ 원본 투명」 칸 중 밝기 < 40 인 칸 수).

| 판 | raw 512 마스크 안 검정 비율 | 결과 64px 새 칸(128) 중 검정 | 밖 바뀜 | 눈 |
| --- | --- | --- | --- | --- |
| 시드 1000 (snap source) | 51.9% | **118** | 0 | 통 왼쪽에 검은 네모 덩어리 |
| 시드 1001 (snap source) | 33.6% | **25** | 0 | 둥근 뚜껑 비슷한 것을 그렸고 그 둘레가 검정 |
| 시드 1000 (snap none) | 51.9% | 118 | 0 | 위와 같은 자리. snap 은 색 수만 바꾼다(17 → 106) |

- 원인은 L10 ④ 그대로 : 제공자가 RGBA 를 올리고 `LoadImage` 가 알파를 버려 **투명 칸이 검정**으로 모델에 들어간다. 모델은 「검정 바탕 위 통」으로 보고 마스크 안을 검정으로 잇는다.
- `snap: source` 는 못 막는다 — 원본 색 중 외곽선(어두운 색)이 있어 검정이 그리로 눌릴 뿐이다.
- **고치는 자리는 제공자 `_upload`** : 올리기 전에 투명 칸을 흰색(또는 spec 으로 주는 바탕색)으로 깔고, 돌려받은 뒤 밖은 지금처럼 원본으로 되돌린다. 마스크 안 새 칸이 「바탕색」으로 나오면 그건 `cutout` 몫. 2차 코드.

## 4. 눈 (참고 — 판정은 사람 몫)

비교판 `post/sheet_inpaint.png` · `post/sheet_prop.png`(스크래치패드).

- H2 : 두 시드 모두 통 가운데 빨간 경고 딱지가 또렷하다. 1000 은 삼각형 경고표, 1001 은 빨간 네모에 흰 줄. L10 klein C 판과 같은 수준.
- H3 : 갈색 통 · 회청색 띠, 흰 바탕. 참조(파스텔 흰 캐릭터)의 팔레트는 안 따라왔다 — 2단계 결론(「픽셀풍까지만」) 그대로.
- H4 : 둘 다 「흰 덩어리 + 노란 왕관 + 노란 볼」은 지켰다. 1000 은 오른쪽을 보는 옆모습인데 눈이 하나 · 입이 없고, 1001 은 눈 · 입 자리가 틀어졌다. 같은 캐릭터로 읽히지만 얼굴은 손질이 필요하다(2단계 「4방향 후보 + 손질」 그대로).
- H5 : 첫 프레임이라 원본과 거의 같다. 애니 판정은 서버 output `arttool_heavy/wan/`(34장)을 받아야 한다 — 이번 범위 밖.

## 6. 재현

1. git 밖 local 문서의 「ArtTool provider local 설정」 절대로 컨테이너 · 터널 · 설정 YAML. 설정 `models` 에 위 1절의 키를 더하고 `heavy` 에 네 파일 이름.
2. 참조 그림을 서버 input 폴더에 올린다(scp). spec `models.ref_image` 에 그 파일 이름.
3. `arttool provider make --provider local --kind <prop|inpaint> --spec <spec> --out <폴더> --json`. 워크플로 · spec · 측정 스크립트(`measure.ps1` · `check_edge.py`)는 이번 세션 스크래치패드 `heavy/`.
