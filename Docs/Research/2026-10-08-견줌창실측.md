# 견줌 창 실측 — 바퀴 안에서 원본 창을 나란히 읽으면 닮음이 오르나 (2026-10-08)

`2026-10-07-draw고리실측.md` 4절 후보 1(견줌 창)의 실측이다. 고리 방식(B)에 **「자기 격자 창을 읽을 때 원본의 같은 창을 `grid show` 로 나란히 읽는다」** 를 더한 **B+견줌(C) 3장**을 새로 그려, 2차의 A · B 와 같은 채점기로 견줬다.

## 결론

- **닮음이 크게 오른다.** near_shifted 평균 A .533 · B .537 → **C .874 (+0.34)**. 통과선(B + 0.10 · A + 0.10)을 넉넉히 넘는다. 윤곽 겹침도 .89 → .99, 똑같은 칸(exact)도 .42 → .77.
- **토큰은 A 의 2.6배(235K, 통과선 3배 안)**, 시간은 B 의 약 4배(16분). 통과선은 넘지만 싸지 않다.
- **까닭은 「견줌」이 아니라 「옮겨 적기」다.** 세 에이전트 모두 원본 창 글자를 읽어 2×2 → 1칸으로 머리로 줄여 자기 격자에 통째로 붙였다. 창 6개로 그림의 85~90% 를 덮었고, 토큰 · 시간의 대부분이 이 손 셈에 들었다.
- **판정 : 견줌 창은 채택.** 「원본 베끼기」 용도의 고리 갈래로 `고리-그리기.md` 에 넣는다. 다만 지금 꼴(사람이 2×2 를 셈)은 비싸서, **`grid show` 에 「½ 로 줄여 보기」 를 더하는 2차 코드**가 있으면 같은 닮음을 훨씬 싸게 얻을 수 있다(5절).

## 2. 지시문 차이 (B → C)

2차 B 지시문(2차 문서 6절 요지, 「왼쪽을 본다」 오타는 「오른쪽」으로 고침)에 아래를 더했다.

> 견줌 창 : 바퀴 안에서 자기 격자를 `c.to_grid(box=…, rulers=True)` 로 읽을 때, 같은 자리의 원본 창을 `arttool grid show --in original.png --box 2x,2y,2w,2h --rulers` 로 나란히 읽고 차이 나는 칸을 고친다. 원본 (2x+i, 2y+j) 네 칸이 내 격자 한 칸이다. 창은 한 변 64 칸까지라 내 창은 32×32 이하. 한 바퀴 창 최대 2개, 최대 3바퀴. 어느 창을 봤는지와 고친 칸 수를 `loops.md` 에 적는다.
> 금지 : `original.png` 를 PIL · numpy · `arttool` 의 다른 명령으로 열거나 줄이거나 붙여 넣기.

지시문 오류 하나 : `to_grid(box=…)` 는 **(x0, y0, x1, y1)** 인데 `grid show --box` 와 같은 (x,y,w,h) 꼴로 적었다. 셋 다 첫 창이 조용히 잘려 나온 뒤 알아채고 고쳤다(4절 피드백 1).

- C 셋은 이동 (0,0) 에서 최고다 — 칸 자리까지 원본의 ½ 에 맞았다는 뜻. A · B 는 1~2칸 밀어야 가장 잘 맞았다.
- C1 의 orphan 57 은 에이전트가 「원본의 주름 · 눈 흰 점 · 손 결을 ½ 로 줄이며 생긴 한 칸 점이라 고치면 덜 닮는다」며 일부러 남긴 것. C2 · C3 는 이웃 다수 색으로 정리하고 4칸만 waive 했다. 정리한 쪽(C2 · C3)이 닮음에서 손해 본 건 없다(.871 · .876).
- C 는 셋 다 **도구 외곽선(`c.outline`)을 안 둘렀다.** 원본 선을 칸째 옮겨서 두르면 두 겹이 된다.

### 3-2. 눈으로 본 것

메인 세션이 정답지 · C1 · C2 · C3 를 `sheet --kinds zoom` 으로 나란히 봤다. **셋 다 정답지와 거의 구별이 안 된다** — 머리 결 밝은 띠 · 눈 · 볼 · 후드 주름 · 뒤로 내린 손 · 바지 선 · 신발까지 같은 자리. B2 · A3 를 같이 놓으면 그쪽은 「같은 사람」이지 「같은 그림」은 아니다.

### 3-3. 에이전트가 실제로 한 것

세 에이전트의 `loops.md` · `draw.py` 가 같은 꼴이다.

1. 1바퀴 : 눈으로 본 원본을 도형으로 어림 → **크게 틀린다** (C1 머리 폭을 50px 로 봤는데 실제 95px, C2 머리를 8칸 높게).
2. 창 2개씩 3바퀴 = 창 6개로 머리 · 얼굴 · 몸 · 다리 · 신발을 차례로 **원본 창을 읽어 2×2 다수결로 줄여 통째로 다시 씀**(`paste_grid(mode="replace")`). 한 창에 300~700 칸.
3. 32×32 창 6개(약 6,000칸)는 60×120(7,200칸) 의 85% — 못 본 자리(머리 오른쪽 위 · 신발 밑줄 · 오른쪽 끝 열)는 어림으로 남았다.

즉 **「그리고 → 견줘서 → 고치기」 가 아니라 「창 단위로 옮겨 적기」** 가 됐다. 닮음이 오른 까닭이 이것이다.

## 4. 판정

| 항목 | 결과 | 통과? |
| --- | --- | --- |
| 닮음 (near_shifted C ≥ B + 0.10 · ≥ A + 0.10) | C .874 · B .537 · A .533 — +0.34 | **통과** |
| 토큰 (C ≤ A × 3 = 270K) | 235K (2.6×) — C1 244K 가 가장 큼 | **통과** (여유 13%) |
| 린트 (참고) | C2 · C3 는 3 · 4 (waive 4), C1 은 57 (일부러 남김) | 섞임 |
| 시간 (참고) | A 의 10× · B 의 4× | 느리다 |

**견줌 창은 채택한다.** 원본이 있고 「닮게 옮기기」가 목표일 때 고리에 견줌 창을 붙이면 닮음이 .53 → .87 로 오르고 비용은 통과선 안이다.
2차 결론 「고리는 깨끗하게 마무리 용」은 그대로이고, 거기에 **「원본 베끼기 용 : 고리 + 견줌 창」** 갈래가 하나 더 생긴다.

## 5. 소견과 다음 할 일

### 5-1. 소견

- **닮음은 「견줌」이 아니라 「옮겨 적기」 가 올렸다.** 그렇다면 사람이 2×2 를 머리로 줄이는 셈(토큰 · 시간의 대부분)을 도구가 대신하면 같은 닮음을 훨씬 싸게 얻는다. 2차 코드 후보 ①.
- **.87 에서 멈춘 까닭** : 정답지는 2×2 **평균 → 팔레트 스냅**이고 에이전트는 2×2 **다수결**이라 가장자리 · 1px 선에서 색이 다르다. 창 6개로 못 덮은 10~15% 도 어림이다. ①이 들어오면 둘 다 사라진다.
- **지금 꼴로도 쓸 수 있는 자리** : 원본 하나를 ½ 로 옮기는 일회성 작업(예 큰 손님 그림 → 작은 판). 토큰 240K · 16분을 감수할 때만.
- **`grid show --legend` 가 이미 있다.** 에이전트 셋 다 「창마다 범례 글자가 바뀌어 헷갈린다」고 했는데, 지시문에 `--legend` 를 안 적어 못 썼다. 고정 글자표 JSON 을 주면 창이 달라도 같은 색이 같은 글자다(이 세션에서 돌려 봄). 다음 판 지시문 · `고리-그리기.md` 에 적는다.

### 5-2. 2차 코드 필요 (「`grid show` 로 안 되는 것」)
