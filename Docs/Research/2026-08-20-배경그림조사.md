# 배경 그림 조사

## 결론 먼저

1. **배경은 캐릭터와 문제가 다르다.** 캐릭터는 "한 장을 잘 그리기"지만, 배경은 **"타일 몇 장으로 무한히 이어붙이기"** 다. 그래서 그림을 만드는 것보다 **이어붙이는 규칙**과 **배치**가 본체다.
2. **3단으로 쪼개서 봐야 한다.** ① 타일 그림 만들기 ② 이어붙이기(오토타일) ③ 맵 배치. 셋 다 해법이 다르다.
3. **"가능하면 AI 말고 코드로" 원칙이 배경에서 더 잘 맞는다.** ②와 ③은 **100% 코드로 끝난다.** AI 가 필요한 건 ①뿐이다.
4. **①은 PixelLab 이 이미 답에 가깝다.** 결제한 계정이 있고, 탑다운·사이드스크롤·아이소 타일셋을 다 만들며, 오토타일 포맷(Wang / 3×3 / dual-grid)으로 바로 내보내고, MCP 서버까지 있다. 여기서 출발하는 게 맞다.

---

## 1. 배경은 세 부분이다

| 단계 | 하는 일 | 어떻게 |
| --- | --- | --- |
| **① 타일 그림** | 풀·흙·돌·벽 한 장씩 그리기 | PixelLab / 기반 에셋 변형 / 사람이 그리기 |
| **② 이어붙이기** | 풀-흙 경계를 자연스럽게 | **순수 코드** — Wang / 3×3 / dual-grid 규칙 |
| **③ 배치** | 어디에 뭘 놓을지 | **순수 코드** — WFC, 룰 기반 |

②가 핵심이다. 타일 한 장을 잘 그려도 경계 처리가 없으면 격자무늬 바둑판이 된다. 반대로 ②만 제대로 되면 **기본 타일 몇 장으로 넓은 맵이 나온다.** 배경에서 그림 생성 비중이 캐릭터보다 훨씬 작은 이유다.

## 2. 투영에 따라 배경이 달라진다

시점 3축(`Docs/Guide/프로젝트개요.md`)이 배경에도 그대로 걸린다.

| 투영 | 타일 모양 | 추가로 필요한 것 |
| --- | --- | --- |
| 정면 (횡스크롤) | 사각 | **패럴랙스 레이어** (하늘·구름·산이 다른 속도로 흐름) |
| 쿼터뷰 / 순수 탑다운 | 사각 | 없음. 오토타일이 전부 |
| 아이소메트릭 | 다이아몬드 | **깊이 정렬**(무엇이 앞에 오나) |

- **방향 수**는 배경에 의미 없다. (배경은 안 돌아본다)
- **이동**은 의미 있다. 중력이면 발판 타일과 패럴랙스가, 평면이면 바닥 타일맵이 중심이 된다.

→ **툴은 캐릭터와 따로 만들되, 프로필(축 설정)은 같이 쓴다.**

## 3. 후보 조사

### ① 타일 그림 만들기

| 이름 | 종류 | 쓸모 | 메모 |
| --- | --- | --- | --- |
| **PixelLab** | 유료(계정 있음) | **가장 강력** | `create_tileset` (두 지형을 잇는 Wang 타일셋), `create_isometric_tile` (16~64px), 탑다운 지형 체이닝, 사이드스크롤러 타일셋. **Wang / dual-grid 15 / 3×3 포맷으로 내보내기** → ②와 바로 연결. MCP 서버 있어서 AI 가 직접 호출 가능 |
| Tilesetter | 유료, 비공개 소스 | 참고 | 기본 타일 1장 → 스마트 타일셋 자동 생성. Unity·Godot 로 바로 내보냄. **우리가 만들 ② 툴의 목표 모습** |
| Pixelorama | 오픈소스 | 보조 | 타일 모드, 아이소 그리드. 사람이 그리는 툴이라 자동화는 약함 |
| Sprite Fusion | 웹, 무료 | 참고 | 오토타일 + 타일맵 에디터. 브라우저에서 돔 |
| Kenney / OpenGameArt | 무료 에셋 | **기반 에셋** | CC0 타일셋. 백지에서 안 그리고 변형하는 우리 방식에 맞음 |

### ② 이어붙이기 (오토타일) — 코드로 끝난다

- **Wang 타일 / 3×3(블롭) / dual-grid** 세 가지 규칙이 표준이다.
- Unity 는 Tilemap 에 **RuleTile** 이 기본으로 있다. 새로 만들 필요가 없을 수도 있다.
- **PixelLab 이 이 포맷들로 바로 내보내주므로 ①과 ②가 자연스럽게 이어진다.** 이게 이번 조사에서 제일 반가운 부분이다.

### ③ 배치 (맵 생성) — 코드로 끝난다

| 이름 | 메모 |
| --- | --- |
| `mxgmn/WaveFunctionCollapse` | WFC 원본. 예시 그림 한 장으로 비슷한 맵을 무한 생성 |
| **DeBroglie** | **C# 라이브러리 + Unity 플러그인.** 우리 환경에 제일 맞음 |
| `Tilemap Generator` | MIT, Unity 프로젝트 |
| 룰 기반 / BSP / 드렁큰 워크 | 더 단순하고 **통제하기 쉽다** |

> 주의 : **WFC 는 결과가 예쁘지만 통제가 어렵다.** "여기에 문을 놓아라" 같은 요구를 넣기 힘들다. 기획 의도가 있는 맵이면 룰 기반이 낫다. (BorisTheBrave 의 팁 문서에 이 주제가 정리돼 있음)

### ④ 손으로 배치하는 경로

자동 생성만으로는 부족하다. AI 가 맵을 뽑고 사람이 다듬는 길이 필요하다.

| 이름 | 상태 |
| --- | --- |
| **LDtk + LDtkToUnity** | 2026-04 까지 갱신됨. ScriptedImporter 로 LDtk 저장 시 자동 재임포트, 애니메이션 타일 지원 |
| Tiled + SuperTiled2Unity | 2025-07 에 2.4.0. Unity Tilemap 으로 프리팹을 만들어줌 |

LDtk 쪽이 더 최근이고 파일 포맷이 JSON 이라 **AI 가 직접 읽고 쓰기 좋다.** 우리 목적에는 이쪽이 유리해 보인다.

### ⑤ 패럴랙스 배경 (횡스크롤 전용)

- **셰이더로 생성** — Godot Shaders 의 픽셀 구름 셰이더 같은 예시가 있다. **URP 로 포팅이 필요**하지만, "코드로 만든다" 원칙에 가장 잘 맞는 길이다.
- `diceyecid/Parallax-Background-Generation` — 사진을 레이어로 쪼개고 픽셀아트풍으로 바꿔줌
- itch.io 무료 패럴랙스 팩 (vnitti 등) — 라이선스 개별 확인 필요

## 4. 추천 방향

1. **①은 PixelLab 을 먼저 연구한다.** 이미 결제했고, 투영 3종을 다 커버하고, MCP 가 있어 AI 가 바로 부를 수 있다. 새로 만들 이유가 약하다.
2. **②·③은 우리가 코드로 만든다.** 여기가 "AI 말고 코드로" 원칙이 가장 잘 맞는 자리다. 밑바닥부터 안 만들어도 되고 DeBroglie 같은 걸 가져다 쓰면 된다.
3. **④는 LDtk 로 붙인다.** JSON 이라 AI 가 맵을 직접 써낼 수 있다.
4. **⑤는 뒤로 미룬다.** 횡스크롤 프리셋을 고를 때만 필요하고, 기본값은 탑다운 액션이다.

즉 **배경 툴 = PixelLab 호출 + 오토타일 코드 + 배치 코드 + LDtk 내보내기** 조합이다. 캐릭터 툴처럼 그림 생성이 중심이 아니다.
