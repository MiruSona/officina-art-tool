# 작은 다듬기 모델 조사 취합 (2026-11-08)

> 클라우드 세션에서 한 백지 조사 3갈래 × 3판(+ 앞선 1판)을 메인이 합친 것.
> 네트워크가 막혀(x.com · huggingface.co · arxiv.org · kaggle · itch · opengameart 등) **거의 모든 수치가 검색 요약(2차)** 이다. PC 에서 원문으로 다시 확인해야 한다.
> 앞 맥락 : 도형 렌더러는 모양은 잡지만 새 그림이 게임 그림보다 납작해 섞으면 티가 난다 (`2026-11-08-도형렌더러보완고리.md`). 그래서 「렌더러 → 작은 전용 모델이 화풍으로 다듬기」 길을 본다.

## 결론

1. **학습 전에 PixelLab 약관부터 정리해야 한다.** 약관(2025-11-23 판)에 「PixelLab 생성 그림으로 자기 모델을 학습하지 말 것(서면 허락 예외)」 문장이 있다고 검색 요약에 인용됐다(원문 못 봄, 70%). 게임 그림 1,781장의 뿌리 대부분이 PixelLab 이다. 원문을 사람이 확인해야 한다.
2. **모델은 아주 작게 된다.** 3단 U-Net(채널 16-32-64 ~ 32-64-128), 파라미터 13만~52만, ONNX 0.5~2MB. 이 세션 CPU 에서 64px 3~8ms, 256px 50~140ms(무작위 가중치, **실측**). 화질은 확인 못 함.
3. **출력은 RGB 가 아니라 「칸마다 팔레트 색 하나 고르기」(분류)** 로 한다. 팔레트 밖 색·중간색이 구조상 안 나온다. 같은 꼴의 2026 오픈 툴(ai2pixelart)이 있다 — 단 비상업 라이선스라 생각만 빌린다. **입력은 RGB** 로 둔다(팔레트 번호 입력은 과적합했다는 논문 결과).
4. **짝은 게임 그림을 「렌더러처럼 납작하게」 되돌려 만든다.** 가장 큰 위험은 지름길 학습(망가뜨린 방식만 되돌리는 법을 배움). 대책: 납작화를 **렌더러와 같은 코드 길**로 하고, 망가뜨리기를 무작위로 섞고, **실제 렌더러 출력 고정 셋**으로만 판정한다.
5. **신경망 없는 기준선을 먼저 둔다.** 「5×5 이웃 모양 → 팔레트 색」 표(kNN·결정트리)는 하루치 구현에 CPU 로 즉시 돈다. 이게 작은 U-Net 의 비교 기준이 된다.
6. **판정 자(평가)를 학습보다 먼저 만든다.** 원본 그룹 단위 분할 · 근접 중복 제거 · 씨앗 5 짝 비교 · A/A 잡음 바닥 · 진짜 대 진짜 바닥값 · 판정 자와 학습 신호 분리. JudgeModel 에서 겪은 것과 같은 결론이다.
7. **바깥 재료는 CC0 만, 사전학습에만.** DCSS 32×32 타일(6천+), Kenney, 0x72, Ninja Adventure. 미세조정은 우리 그림만으로. LPC(CC-BY-SA)·HF 모음집·상용 게임 긁은 셋은 피한다.
8. **사용자가 준 X 링크 둘은 못 열었다.** 두 계정 모두 중국어 AI·오픈소스 도구 소개 계정이고 글은 11-06·11-07 에 올라왔다(글 ID 로 계산). PC 에서 브라우저로 본다.

## 2. 갈래 2 — 작은 모델 기법 (3판)

| 방법 | 무엇 | 쓸모 |
| --- | --- | --- |
| 이웃 표 찾기 (kNN / 해시 버킷 / 결정트리) | 5×5 이웃(영역 번호 · 명암 순위 · 외곽선 거리 · 빛 쪽 여부) → 팔레트 색 | **기준선**. 하루 구현, CPU 즉시, 무엇을 배웠는지 보인다 |
| 작은 U-Net + 팔레트 분류 출력 | 3단, 13만~52만 파라미터, CE 손실 | **본선**. 실측 속도 위 결론 2 |
| 학습한 LUT (MuLUT, MIT) | 작은 CNN 을 표로 굽기 | 배포를 표 몇 MB 로. 회귀라 팔레트 분류로 개조 필요 |
| Few-shot patch 학습 (Texler 2020) | 무작위 조각으로 학습해 과적합 줄임 | 학습 데이터 꼴로 빌림 (32~48px 조각) |
| pix2pix 축소 + 작은 PatchGAN | Coutinho 2022: 184~776장으로 스프라이트 변환 | 밋밋하면 나중에 GAN 손실을 얹는다(처음부터 X) |
| 제약 ConvChain (MCMC) | 외곽선·경계 고정, 안쪽 질감만 원본 통계로 다시 뽑기 | 디더·잔무늬 다듬기 선택 단계 |
| WFC C1 검사 | 출력 3×3 조각 중 원본에 없던 비율 | 「화풍 이탈률」 지표 |
| Ebsynth (PatchMatch) | 한 장 단위 질감 옮기기 | 비교용 상한선만. Adobe 특허 경고 있음 → 제품엔 안 넣음 |
| CycleGAN · CUT (짝 없이) | 렌더러 출력과 게임 그림을 짝 없이 | 예비안. 작은 망에서 불안정 |

**배포** : PyTorch 학습 → ONNX(opset 17, **ir_version 13 이하로 고정** — onnx 1.23.2 기본 IR 14 는 onnxruntime 1.31.1 이 못 읽음, 실측) → onnxruntime CPU. ArtTool 기본 의존성은 그대로 두고 **선택 extra**(`arttool[ml]`)로. onnxruntime wheel win 14.9MB / linux 23.8MB, torch 는 학습 PC 에만.

## 3. 갈래 3 — 판별기와 평가 (3판)

| 층 | 무엇 | 숫자 (출발점) |
| --- | --- | --- |
| 묶음 점수 | DINOv2 + CLIP 특징으로 **KID · CMMD** (작은 표본에서 FID 보다 낫다) | 진짜 대 진짜 KID 바닥값부터 재고 「바닥의 몇 배」로 읽는다 |
| 장 단위 점수 | 얼린 특징 + 선형 머리 **C2ST**, k-NN realism + 최근접 진짜 3장(베끼기 점검) | C2ST ≤ .6 · KID ≤ 바닥 2배면 「섞여도 됨」 후보 |
| 사람 판정 (최종) | 라인업(진짜 4 + 가짜 1), 진짜만 든 대조판 20%, 함정판 5%, 판정자 5~8명 | 「티 난다」: 라인업 35% 를 잡으려면 56판, 맞힌 수 ≥ 17. 「티 안 난다」: 2AFC 약 400판 동등성(95% 구간 위끝 < 60%) |
| VLM 보조 | 순서 바꿔 두 번 묻고 일관된 답만 | 사람과 κ ≥ .6 · 순서 일관 ≥ 80% 일 때만 선별기로 |
| 일치율 | 원 일치율 + Fleiss κ + Gwet AC1 함께 | 사람끼리 κ < .4 면 취향 문제 신호 |

**지름길 대책** (판별기가 크기·색 수·격자 어긋남·알파·파일 형식으로 이기는 것): 양쪽을 같은 정규화(1칸=1화소, 같은 캔버스·배경·PNG, nearest 정수배)에 통과시키고, **단순 특징만으로 돌린 기준선 분류기가 .5 근처인지** 먼저 본다.

**평가 규약** : 그룹 단위 분할(메타데이터 그룹 → dHash/pHash ≤ 5 → 임베딩 2차 → union-find 로 추이 묶기 → 경계 쌍 눈 검수) · 학습 70 / 검증 15 / 봉인 시험 15 · 실제 렌더러 출력 골드 셋 50~150 · 판별기 전용 셋 따로 · 씨앗 5 짝 비교 + bootstrap 구간, Δ > 2σ 일 때만 「나아짐」 · 판정용 판별기는 학습에 절대 안 씀(Goodhart).
