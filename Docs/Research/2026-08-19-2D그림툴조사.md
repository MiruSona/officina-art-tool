# 2D 그림 툴 조사

대상: `Docs/Todo/AI게임스튜디오.md` 의 **"2D 그림을 그려주는 툴"** 항목만.

## 추천안

1. **직접 만들 툴의 뼈대는 "레이어 합성(paper doll) 파이프라인"이다.** 몸통 · 머리 · 옷 · 무기를 정해진 규격의 PNG 조각으로 쌓아 올려 스프라이트시트를 굽는다. AI는 "어떤 조각을 어떤 팔레트로 몇 번째 층에 올릴지"를 JSON 으로만 정하고, 실제 픽셀은 Python(Pillow) 코드가 찍는다.
2. **그 구조의 완성된 본보기가 LPC 캐릭터 제너레이터**다. 조각 목록·층 순서·애니메이션 행을 전부 JSON 으로 갖고 있어서, 웹 UI 는 버리고 데이터 규격만 그대로 베끼면 된다. 그림 소스는 LPC(CC0 만 걸러 쓰기) + Kenney(전부 CC0).
3. **새 원본이 필요할 때만 PixelLab 을 쓴다.** 이미 결제한 계정이 있고 MCP · REST API · Python SDK 가 다 있다. 단 생성형 AI 이므로 "베이스 1장 뽑기"까지만 맡기고, 그 뒤 변형·조합·색갈이는 전부 코드가 한다.
4. **`sprite-gen` 은 베끼되 그대로 쓰진 않는다.** 매 프레임을 AI로 만드는 구조라 우리 전제와 반쯤 어긋난다. 다만 "AI는 행(row) 단위 원본만 → 나머지는 결정적 후처리 → atlas + manifest.json" 이라는 뼈대는 우리가 원하는 그림 그대로다.
5. **장비 붙이기는 Unity 쪽이 이미 다 해준다.** 2D Animation 패키지의 Sprite Library Asset + Sprite Resolver 가 정확히 그 기능이다. 툴이 할 일은 그림을 합치는 게 아니라 **모든 조각이 같은 규격(프레임 크기·행 순서·기준점)을 지키게 강제하는 것**이다.

## 2. 직접 찾은 후보

### 2-1. 레이어 합성 · 캐릭터 생성 (가장 중요)

**Universal LPC Spritesheet Character Generator** — [repo](https://github.com/LiberatedPixelCup/Universal-LPC-Spritesheet-Character-Generator) / [데모](https://liberatedpixelcup.github.io/Universal-LPC-Spritesheet-Character-Generator/)

- 별 1.6k, 커밋 2,167개. 현역이다. 웹(Vite + Node 22.18+) 이고 **공식 CLI 는 없다.**
- 그런데 우리한테 진짜 값진 건 UI 가 아니라 **데이터 규격**이다. `sheet_definitions/` 에 카테고리별 JSON 이 있고, `spritesheets/` 에 실제 PNG 가 있다.
  - JSON 필드: `name`, `type_name`, `layer_0`/`layer_1`... 각각에 `zPos`(겹치는 순서), 체형별(male/female/child/teen/muscular/pregnant) 경로, `variants`(색·종류 목록), `animations`, `credits`(작가·라이선스·출처)
  - `animations` 를 안 적으면 기본값: `spellcast, thrust, walk, slash, shoot, hurt, watering`
- 즉 **"어떤 조각이 있고 / 몇 번째 층에 / 어떤 색 변형이 있고 / 어떤 애니메이션을 지원하는지"가 전부 기계가 읽는 JSON 으로 이미 정리돼 있다.** 우리 툴은 이 JSON 을 읽어 Pillow 로 겹쳐 굽기만 하면 된다. 웹 코드는 안 가져와도 된다.
- **라이선스 주의**: 에셋마다 다르다. CC0 / CC-BY 4.0 / CC-BY-SA 4.0 / OGA-BY 3.0 / **GPL-3.0** 이 섞여 있다. 상업 게임에 쓰려면 **CC0 와 CC-BY 만 걸러 쓰는 게 안전하다.** `credits` 필드가 있으니 필터링은 코드로 자동화된다.

**ComfyUI 2D Character Pipeline** — [repo](https://github.com/mor-o/comfyui-2d-character-pipeline). 캐릭터 1장 → 부위별(머리카락·눈·옷) 따로 색칠 가능한 레이어 스프라이트시트로 쪼개는 ComfyUI 워크플로. 생성형 AI 기반이라 우선순위는 낮지만 "레이어 분리" 발상은 참고할 만하다. 라이선스 확인 못함.

### 2-2. 절차적(procedural) 스프라이트 생성기

| 도구 | 내용 | 판단 |
| --- | --- | --- |
| [ZzSprite](https://github.com/KilledByAPixel/ZzSprite) | JS, MIT, 별 167. 좌우대칭 픽셀 스프라이트를 무작위 생성, 시드로 변형, 스프라이트시트 PNG 저장 | 결정적이고 가볍지만 **무작위**다. "자연어로 지시" 와는 잘 안 맞는다. 아이템 아이콘 대량 생산 정도 |
| [MaartenGr/Sprite-Generator](https://github.com/MaartenGr/Sprite-Generator) | Python. 템플릿을 주면 그에 맞춰 스프라이트 생성 | 템플릿 기반이라 통제는 되지만 결과물 품질이 낮다. **라이선스 확인 못함** |
| [danielgjackson/sprite](https://github.com/danielgjackson/sprite) | JS 8비트 아바타 생성기 | 아바타용. 게임 캐릭터엔 부족. **라이선스 확인 못함** |

### 2-3. 스크립트로 조종 가능한 픽셀아트 편집기

| 도구 | 라이선스 | 자동화 수단 | 판단 |
| --- | --- | --- | --- |
| **Aseprite** | 유료 · 독점 EULA (소스는 공개지만 재배포 금지). **만든 에셋의 상업 이용은 가능** | `--batch` [CLI](https://www.aseprite.org/docs/cli/) + [Lua 스크립팅 API](https://www.aseprite.org/api/). `--sheet`, `--data`, `--sheet-type` 로 스프라이트시트+JSON 바로 뽑음 | 자동화 능력은 이 바닥 최강. **단 툴을 남에게 배포할 수 없다** (사내/개인 파이프라인이면 문제 없음) |
| **Pixelorama** | MIT | [CLI + `--headless`](https://pixelorama.org/user_manual/cli/) 로 일괄 내보내기 | 배포 제약이 없다. Aseprite 대안 1순위 |
| **LibreSprite** | GPL-2.0 (Aseprite 의 GPL 시절 포크) | Aseprite 옛 CLI 수준 | 개발이 느리고 기능이 뒤처진다. 우선순위 낮음 |

**Aseprite MCP 서버가 이미 여럿 있다** — [diivi/aseprite-mcp](https://github.com/diivi/aseprite-mcp) (104개 툴), [Vollkorn-Games/aseprite-mcp](https://github.com/Vollkorn-Games/aseprite-mcp), [ayigityol/aseprite-mcp](https://github.com/ayigityol/aseprite-mcp) 등. 전부 속으로는 **Lua 스크립트를 만들어 `aseprite --batch --script` 로 실행**하는 방식이다. "AI가 지시 → 코드가 그림" 을 이미 그렇게 구현해 놓은 셈이라, 우리 툴의 실행 계층 설계에 그대로 참고할 수 있다.

### 2-4. 팔레트 스왑 · 패킹

- 팔레트 스왑: [dfatka/paletteswapper](https://github.com/dfatka/paletteswapper) (Python, numpy + Pillow), [SkyAphid/PaletteSwapper](https://github.com/SkyAphid/PaletteSwapper) (텍스트 파일로 규칙 지정). 둘 다 **라이선스 확인 못함**. 사실 이 기능은 Pillow 로 50줄이면 되니 직접 짜는 게 빠르다. Lospec 팔레트(`.hex`/`.gpl`) 를 읽어오는 정도만 신경 쓰면 된다.
- 스프라이트시트 패킹: [free-tex-packer-cli](https://github.com/odrick/free-tex-packer-cli) — 회전·트리밍·멀티팩 지원, json/xml/godot/phaser/cocos2d 로 내보냄. **Unity 전용 포맷은 목록에 없다.** Unity 는 자체 Sprite Atlas 가 있으니 굳이 필요 없을 수 있다.

### 2-5. 스켈레탈 2D 애니메이션

- **Unity 2D Animation 패키지** — 엔진 기본 제공. PSD Importer + Skinning Editor + Sprite Library. 별도 도구 없이 이게 제일 낫다.
- **DragonBones** — [Unity 런타임](https://github.com/DragonBones/DragonBonesUnity)은 MIT 라고 하나, **에디터는 비공개이고 사실상 개발이 멈췄다** (정확한 유지보수 상태 확인 못함). 권하지 않는다.
- **Spine** — 유료 상용. 이번 조사 범위 밖으로 뒀다.

> 참고: 픽셀아트에는 스켈레탈보다 **프레임 애니메이션 + 레이어 합성**이 맞다. 뼈로 돌리면 픽셀 격자가 깨진다. 스켈레탈은 나중에 픽셀아트가 아닌 스타일을 할 때 다시 보면 된다.

## 3. PixelLab (결제 계정 있음)

**정체**: 픽셀아트 전용 생성형 AI SaaS. 웹 에디터 + REST API + MCP 서버를 다 제공한다.

**접속 수단** (셋 다 확인됨)

| 수단 | 주소 |
| --- | --- |
| MCP | `https://api.pixellab.ai/mcp` (HTTP transport, Bearer 토큰) — [문서](https://api.pixellab.ai/mcp/docs), [안내](https://www.pixellab.ai/mcp) |
| REST API | `api.pixellab.ai/v1/docs`, `api.pixellab.ai/v2/docs` — [소개](https://www.pixellab.ai/pixellab-api) |
| Python SDK | [pixellab-code/pixellab-python](https://github.com/pixellab-code/pixellab-python), [PyPI `pixellab`](https://pypi.org/project/pixellab/) |

**뭘 만들어 주나** (MCP 툴 기준, 크게 묶으면)

- 캐릭터: 4방향/8방향 회전 스프라이트 생성 → 걷기·달리기·대기 등 애니메이션 추가 → 상태(state) 변형 생성
- 타일셋: 탑다운 Wang 타일셋, 사이드뷰 플랫폼 타일셋, 아이소메트릭 타일, 길 타일, 건물 키트
- 오브젝트: 배경 투명 맵 오브젝트, 1방향/8방향 오브젝트, 오브젝트 애니메이션
- 기타: UI 패널, 픽셀 폰트, 초상화, 립싱크 말하는 GIF, 원본 이미지 편집(`edit_image`)·부분 재생성(`inpaint_image`)
- 관리: `get_balance`(크레딧 잔량), `list_jobs`, `cancel_job`

**작동 방식**: 생성 요청은 **비동기**다. 즉시 job ID 만 돌려주고 백그라운드에서 보통 2~5분 걸린다. 그래서 툴을 짤 때 "요청 → 폴링 → 다운로드" 3단계로 나눠야 한다.

**스타일 일관성 / 프리셋** — 여기가 우리한테 제일 중요한 부분이다.

- 스타일 참조: `style_image_base64` / `style_image_url` (팔레트·외곽선·디테일·셰이딩을 참조 그림에서 복사), `style_character_id` / `style_object_id` (이미 만든 캐릭터의 8방향 스타일을 기준으로 삼기)
- 정체성 참조: `reference_image_base64` / `reference_image_url` (생김새 그대로 옮기기)
- 색 고정: `use_color_palette_from_reference` (원본 캐릭터 색에 맞춰 스냅)
- 복사 범위 선택: `style_copy` = `color_palette` / `outline` / `detail` / `shading` 중 고르기
- 프리셋
  - 체형: `default, chibi, cartoon, stylized, realistic_male, realistic_female, heroic`
  - 외곽선: 단색 검정 외곽선 / 단색 외곽선 / 선택적 외곽선 / 외곽선 없음
  - 셰이딩: `flat, basic, medium, detailed, highly detailed`

**비용**: 기본 생성은 1 generation, pro 품질은 20~40 generations. 구독제이고 크레딧은 `get_balance` 로 확인한다. **정확한 요금표는 로그인이 필요해 확인하지 못했다.**

**우리 파이프라인에서의 자리**: 생성형 AI 최소화 원칙과 정면으로 부딪히지만, "백지에서 새로 그릴 필요는 없다"는 전제와는 잘 맞는다. → **베이스 아트(몸통 1벌, 스타일 기준 그림 1장)를 뽑는 단계에만 쓰고, 그 뒤 색 변형·장비 조합·애니메이션 프레임 확장은 전부 코드로 한다.** 스타일 참조 기능이 있으니 "베이스를 뽑을 때 스타일이 흔들리는" 문제도 어느 정도 막을 수 있다.

## 4. 툴의 몫 vs Unity 의 몫

할일 문서에 적힌 "이건 유니티 애니메이션으로 되려나?" 에 대한 답이다.

| 기능 | 누가 | 이유 |
| --- | --- | --- |
| **기본 애니메이션 프레임** | **툴** | 프레임 PNG 와 규격(프레임 크기·행 순서·기준점)을 굽는 건 코드 일이다. 결과물은 `스프라이트시트.png` + `manifest.json` |
| **색 / 프리셋 덧입히기 (종류 적음)** | **툴** | Pillow 팔레트 스왑으로 미리 구워 PNG 여러 벌. 런타임 비용 0 |
| **색 / 프리셋 덧입히기 (조합 폭발)** | **Unity** | 셰이더 팔레트 스왑(1D LUT 텍스처). 원본 1장으로 무한 색 변형 |
| **장비 · 악세사리 붙이기** | **Unity** | 2D Animation 패키지의 [Sprite Library Asset + Sprite Resolver](https://docs.unity3d.com/Packages/com.unity.2d.animation@15.0/manual/SpriteSwapIntro.html) 가 정확히 이 용도다. 부위별로 Category/Label 을 두고 런타임에 갈아끼운다. 프레임 애니메이션·스켈레탈 둘 다 된다 |
| **조합 결과 미리 굽기** | 툴 (선택) | 조합 수가 적고 드로우콜을 아끼고 싶을 때만 |

**Unity Sprite Swap 주의점 2가지**

1. 한 Animator Controller 안에서 **어떤 클립은 `SpriteRenderer.sprite` 를 바꾸고 어떤 클립은 `SpriteResolver` 해시를 바꾸는 식으로 섞으면 안 된다.** 한 방식으로 통일하거나 컨트롤러를 분리해야 한다.
2. 스켈레탈로 갈 경우 교체되는 스프라이트끼리 **뼈대가 완전히 같아야** 한다.

**그래서 툴의 진짜 핵심은 그림이 아니라 규격이다.** 장비 조각이 몸통 프레임과 픽셀 단위로 안 맞으면 Unity 에서 아무리 갈아끼워도 어긋나 보인다. 그 규격(프레임 크기, 애니메이션 행 순서, 방향 순서, 기준점 좌표)을 정하고 **모든 조각이 그걸 지키는지 검사·보정하는 것**이 우리가 만들 툴의 값어치다. LPC 가 정확히 그 규격을 이미 정해놨으니 그대로 가져다 쓰면 된다.

## 5. 제안하는 파이프라인 뼈대

```
[사람/AI 자연어]
      ↓  (Claude 가 해석)
[지시 JSON]  예: { base:"lpc_male", 옷:"tunic", 색:"lospec/nyx8", 장비:["sword"], 상태:["walk","slash"] }
      ↓
[카탈로그 조회]  에셋 인덱스 JSON (조각 목록·층 순서·라이선스·프레임 규격)
      ↓
[결정적 합성 코드]  Pillow: 레이어 겹치기 → 팔레트 스왑 → 규격 검사
      ↓  (원본이 없을 때만) PixelLab 으로 베이스 1장 → perfectPixel 로 격자 정리 → 카탈로그에 등록
[스프라이트시트.png + manifest.json]
      ↓
[Unity]  Sprite Library Asset 생성 → Sprite Resolver 로 장비 교체
```

- 할일 문서의 "그리는 툴 + RAG 분리?" 에 대해: **당장은 RAG 가 필요 없어 보인다.** 에셋 카탈로그를 JSON 인덱스로 두고 태그 검색만 해도 충분하다. 조각 수가 수천 개로 늘어나면 그때 다시 보면 된다.
- 로컬 Qwen 이 짜기에 적당한 크기다. 합성 코드는 순수 Pillow 이고 외부 의존이 거의 없다.

## 6. 아직 확인 못한 것

- **PixelLab 생성물의 저작권·상업 이용 조건** — 약관을 못 봤다. 상업 게임에 쓸 거면 제일 먼저 확인해야 한다.
- PixelLab 요금표와 크레딧 단가 — 로그인이 필요하다. 사용자 계정으로 `get_balance` 를 호출하면 바로 나온다.
- **AetherAI 가 [aetherforgeai.com](https://www.aetherforgeai.com/en/tutorial) 이 맞는지** — 이름만 비슷한 다른 것일 수 있다. 공개 저장소·API 는 못 찾았다.
- 참고 유튜브 쇼츠의 채널명과 영상 내용 — 제목만 확인했고 영상은 못 봤다. 제목상 sprite-gen · perfectPixel · Kenney 소개라 새 정보는 없어 보인다.
- `sprite-gen` 의 마지막 커밋 날짜 (커밋 8개로 아주 새 프로젝트라는 것만 확인)
- `MaartenGr/Sprite-Generator`, `danielgjackson/sprite`, `paletteswapper`, `PaletteSwapper`, `comfyui-2d-character-pipeline` 의 라이선스
- DragonBones 의 현재 유지보수 상태
- LPC 에셋에서 CC0/CC-BY 만 거르면 실제로 몇 개가 남는지 (실측 안 함)

## 7. 사용자에게 물어볼 것

1. **아트 스타일과 캔버스 크기**를 정해야 다음 단계로 간다. 16×16? 32×32? LPC 규격(64×64)? 이게 정해져야 어떤 소스를 쓸지 결정된다.
2. **시점**: 탑다운(LPC·Kenney 강점)인가, 사이드뷰 플랫포머인가?
3. **캐릭터 커스터마이즈 조합 수**가 대략 몇 가지인가? 적으면 툴에서 미리 굽고, 많으면 Unity 런타임 교체로 간다.
4. **PixelLab 을 파이프라인에 넣어도 되나?** 생성형 AI 최소화 원칙과 충돌한다. "베이스 원본 만들 때만" 으로 한정하는 안을 추천한다.
5. **LPC 의 CC-BY-SA / GPL 에셋을 배제할지** — 배제하면 안전하지만 쓸 수 있는 조각이 줄어든다.
6. **Aseprite 를 파이프라인에 넣을지** — 자동화 능력은 최고지만 유료이고 툴 재배포가 금지된다. 개인·사내용이면 문제 없다. 배포까지 생각하면 Pixelorama.
