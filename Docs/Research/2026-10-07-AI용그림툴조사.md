# AI 에이전트용 오픈소스 그림(도트) 툴 조사 (2026-10-07)

**갈아탈 툴은 없다. 빠진 것은 툴이 아니라 「그리고 → 보고 → 고치는 고리」이고, 그것을 `arttool.draw` 위에 얹는다. PixelLab 대체는 안 된다.**

독립 조사자 셋(D · E · F)에게 「AI 에이전트용 오픈소스 그림(도트) 툴이 있나 — PIL 직접 그리기 한계를 푸나, PixelLab 대체가 되나」를 백지로 주고 각자 웹 조사만 하게 한 뒤, 메인이 셋을 견줘 이 한 장으로 합쳤다.
**셋 다 직접 설치해 돌려 보지는 않았다.** 근거는 GitHub API(마지막 push · 라이선스 · 별) · README · 일부 소스 원문 · 공개 벤치 글이다.

### 왜 조사했나

- 지금 PIL 길(`arttool.draw`)은 에이전트가 **좌표를 글로 적어** 칸을 찍는다. 아이콘 · 타일은 되지만 **캐릭터는 무너진다** — 그린 결과를 에이전트가 보지 않고(7단계가 「사람 눈」) 좌표를 또 적기 때문이다.
- 같은 날 `2026-10-07-PixelLab로컬대체조사.md` 에서 「로컬 확산 모델로 PixelLab 을 대체하나」를 봤다. 이 문서는 그 짝 — **「결정적 도구 쪽에서 대체하거나 보완할 것이 있나」**.

### 우리가 이미 가진 것 (`arttool.draw` · `arttool-usage` 스킬, 2026-10-07 기준)

| 있는 것 | 어디 |
| --- | --- |
| 겹(`Layer`) 캔버스 · 템플릿 가이드(`Guide` — 머리 상자 · 눈 카드 · baseline) · 팔레트 램프(`pick` · `shade`) | `Canvas` · `guide.py` · `palette.py` |
| 도형 : `dot` · `line` · `box` · `round_box` · `ellipse` · `disc` · `ring` · `drop` · `fill`(플러드) · `paint(mask)` · `spiral` | `shapes.py` · `Layer` |
| 손질 : `erase` · **`mirror()`(왼쪽 반 → 오른쪽 거울)** · `recolor` · `px(x, y)` | `Layer` |
| 외곽선 다섯 방식(`none` · `black` · `solid` · `selout` · `selout+light`) · 바깥/안쪽 · 두께 1~4 | `outline.py` · `Canvas.outline` |
| `report()` 경고 : `palette`(팔레트 밖 색) · `guide_color` · `alpha` · `exclusive` · `outline_twice` · `outline_ramp_bottom` · `empty` — **파일 · 겹 단위, 칸 좌표 없음** | `Canvas.report` |
| `preview(path, scale)` 전체 확대 PNG · `merged` · `save`/`open` 겹 묶음 | `Canvas` |
| CLI 검사 여덟(`integer_scale` · `outline` · `isolated`(외톨이 칸 **몫**) · `color_cap` · `near_colors` · `ramp_shape` …) · `sheet --kinds zoom,silhouette,colors4,blur` · `sheet --grid 8` 눈금 판 · `layers check` · `tile seam` · `tile blob` | `check.py` · `sheet.py` |
| 스킬 절차 9단계(밑판 → 겹별 그리기 → report → layers check → export → check → **sheet 를 사람이 연다**) · 템플릿 18개 · 크기별 등신 · 애니 프레임 공식 | `arttool-usage/SKILL.md` · `그리기-pil.md` · `기준.md` |

없는 것 : **문자 격자 읽기/쓰기** · **칸 좌표가 박힌 결함 목록** · `clip`(실루엣 안에만 칠하기) · 대칭을 겹 속성으로 켜 두기 · **편집마다 바뀐 영역만 미리보기** · 에이전트가 되보고 고치는 **절차 규칙**.

## 4. 「그리고 → 보고 → 고치는 고리」 설계 밑그림

셋의 3절이 가리키는 모양은 하나다. **에이전트가 적는 것을 「좌표」에서 「격자 글」로, 돌려받는 것을 「PNG」에서 「PNG + 글(격자 · 위치 박힌 결함)」로 바꾸고, 2~3바퀴를 절차로 못 박는다.**

```
① 계획      크기 · 팔레트(램프) · 실루엣을 먼저 정한다 (dotloom · ehm-93 둘 다 「팔레트 먼저」)
② 그리기    큰 덩어리는 지금처럼 도형 + 가이드 겹, 세부(얼굴 · 손 · 보석)는 문자 격자(pxart .px 꼴 : 범례 + 행)
            캐릭터는 실루엣 겹을 반만 그려 mirror, 팔 · 다리 · 무기는 별도 겹(파츠)
            clip 으로 실루엣 밖에는 칠해지지 않게
③ 글로 읽기  to_text(mode=mask|value|palette) — 한 글자 = 한 픽셀, 행 diff
            「축소 PNG 는 14행이 13행보다 한 칸 어긋났는지 말해 주지 못한다 — 격자가 검증하고 PNG 가 승인한다」(dotloom)
④ 린트      칸 좌표가 박힌 결함 목록 — 고아 픽셀 · 더블 · 1px 구멍 · 끊긴 외곽선 · 대칭 어긋남 · 팔레트 밖 · 타일 이음
            + 수치 : 대칭 점수 · 질량 중심 · 빛 방향 (rexxkelley)
⑤ 그림 보기  편집 뒤 바뀐 영역 bbox 만 ×8 확대 PNG (ehm-93) + sheet zoom · silhouette 를 에이전트가 Read 로 직접 본다
⑥ 비판      체크리스트를 글로 한 항목씩 답한다 — 실루엣 읽힘 · 램프 밖 색 · 외곽선 끊김 · 빛 방향 일치 · 색 예산
            (Gamezxz validations.md 꼴)
⑦ 고치기    바뀐 글자만 다시 적어 paste(from_text). 되쓰기 전 「본 것과 지금 것이 같다」 지문 검사(pxart diff · PixelLab --expect)
            바뀐 칸 수를 숫자로 돌려준다 (MalloyTheDev pixels_written)
            → ③ 으로. 최소 2~3바퀴를 스킬 규칙으로 못 박고 바퀴마다 before/after 비교판을 남긴다
```

- **되읽기 채널은 둘(글 + 그림)** 이어야 한다. D · E · F 모두, Pixel Art Bench 도 같은 말.
- 조합은 **지금 스택 유지 + 흡수** : `arttool.draw`(그대로) + pxart 식 격자 입출력 + ehm-93/rexxkelley 식 린트 + Gamezxz 식 스킬 절차. **새 의존성 · 외부 바이너리 없음.**
- 보류한 길 둘 : (B) dotloom 을 MCP 로 옆에 붙여 리그 · SVG trace · 오토타일을 얻는 길 — 1인 신생이라 **실측 한 판 뒤 결정** (D). (C) SVG 로 모양 잡기 → 도트화 — 작은 크기에서 도트 특유의 선이 안 나오고 전용 도구가 없다 (E 가 못 찾음, D 는 SketchAgent 근거로 제안).

## 6. 메인 판정

- **같은 말(3/3)** : 갈아탈 툴은 없다 · 빠진 건 「그리고 → 보고 → 고치는 고리」(한 글자 = 한 픽셀 문자 격자 되읽기, 위치 박힌 결함 린트, 대칭 · 클립, 편집마다 변경 영역 미리보기) · 2025~26 에이전트용 도트 툴 5개 이상이 독립적으로 이 설계로 수렴 · PixelLab 대체는 안 된다(전부 결정적 도구, 상상 못 함) · Aseprite 계열이 가장 성숙하지만 EULA 라 툴킷에 못 넣음(개인 개발기용) · Pixelorama/LibreSprite/GIMP/Krita 는 나아지는 것 없음 · pixel-sprite-generator(마스크 → 거울 → 테두리 → 색칠)는 알고리즘 참고 · LPC 는 그림 CC-BY-SA 라 우리 규칙과 충돌 · 사람형 캐릭터 모양을 규칙으로 만드는 오픈소스는 없다 · 벤치(2025-07 2.5/5, pebbly 솜씨 56%)가 보여주듯 고리는 무너진 걸 알아채 고칠 기회를 줄 뿐 실루엣 감각을 주진 않는다.
- **엇갈린 것** : ① 1순위 — D : dotloom-mcp(TS · Apache · 리그/SVG trace/오토타일, 별 1), E : pxart(Python 단일 파일 · MIT) 1순위 + dotloom 2순위, F : pxart + pixel-art-studio 절차 + rexxkelley 검사. → 메인 : **pxart 를 1순위로 코드 흡수**(같은 스택), dotloom 은 리그 · SVG trace 때문에 설계 참고 + 선택 실측, aseprite-ai-artist 는 규칙 62 · 템플릿 400 참고만. ② rexxkelley/pixelart-mcp 라이선스 — README MIT / API 빈 값 → 미확인, 코드 베끼기 전 확인. ③ PixelLab `pixelart_workbench` — F · E 는 「고리의 완성형, 구독 중이니 손질엔 지금 써라」, D 는 참고 → 메인 : 게임 저장소에서 손질 단계에 지금 쓰고, 공개 툴킷 설계의 참고로 삼되 의존하지 않는다.
- **결론** : PixelLab 대체 질문은 닫는다. 대신 **ArtTool `draw` 에 고리를 얹는 설계 판**을 잡는다 : (1) 문자 격자 읽기/쓰기(pxart 식) (2) 위치 박힌 결함 린트(check 보강) (3) symmetry · clip (4) 편집 뒤 변경 영역 미리보기 (5) `arttool-usage` 스킬에 2~3바퀴 보고 고치기 절차. 그 다음 **같은 캐릭터를 지금 방식 vs 고리 방식으로 그려 실측**해 값어치를 잰다. 순서는 `provider local` 설계와 함께 사용자 결정.

## 7. 못 찾은 것 · 불확실한 것

- **사람형 캐릭터를 규칙 · 파츠 · 스켈레톤으로 만드는 오픈소스 Python CLI 는 없다.** 프로시저럴은 우주선 · 몬스터(대칭 마스크), 파츠 조립은 LPC(그림 자산 · 화풍 고정). dotloom 리그는 Node, PixelLab 리그는 비공개 (D · E · F).
- **어느 후보도 직접 돌려 보지 않았다.** 기능 목록은 README · 일부 소스(`pixelstudio.py` def 목록 · Pixelorama `Main.gd` · jcscocca CI yml · PixelLab `describe`)에서 읽었다. E 의 README 요약은 WebFetch 소형 모델을 거쳤다 (D · E · F).
- dotloom `evaluate` · 리그 · `trace_svg` 의 **실제 품질** 미확인. 기여자 1 · 별 1 · 09-25 생성 (D · E).
- rexxkelley/pixelart-mcp LICENSE 파일 유무 미확인 (D · E · F). stb · SketchAgent 라이선스 표기도 엇갈림 (각주).
- LibreSprite `--batch` + 스크립트가 사람 없이 도는지 미확인 (D · E · F). Pixelorama 확장 API 로 headless 그리기가 되는지 미확인 (D · E · F).
- Aseprite `LAF_BACKEND=none` 빌드가 **Windows 에서도** 되는지 미확인 — jcscocca CI 는 Linux (D · E). GIMP 3 python-fu-eval 의 Windows headless 미확인 (F).
- LPC 생성기 `scripts/` 가 사람 없이 CLI 로 시트를 뽑는지는 파일 이름만 봤다 (F).
- **SVG → 도트화 전용 도구는 없었다.** 검색된 것은 반대 방향(도트 → SVG)뿐. cairosvg 등 Pillow 밖 래스터라이저가 필요하다 (E).
- 후보 대부분이 2026-06~10 생 · 별 0~1 이라 **반 년 뒤 살아 있을지** 모른다 (E · F).
- **고리가 캐릭터 품질을 얼마나 올리나** 는 우리 흐름에서 실측 없음. 벤치 둘은 다른 모델 · 다른 도구 (D · E · F). D 는 이번에 arttool 의 실제 캐릭터 실패 사례를 보지 않았다 (F 도 같음).
- **로컬 LLM(Qwen3.6 · Flash-Next) 이 격자 고리를 따라올지** 별개 실측 필요. ljvmiranda 실험에서 Qwen3 32B 는 캐릭터를 못 그렸다 (E).
- 검색은 WebSearch + GitHub API 뿐. itch.io · 중국어권 · arXiv 의 도트 DSL 은 덜 훑었다 (D).
