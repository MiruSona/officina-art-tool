# draw 고리 실측 — 「그리고 → 보고 → 고치기」가 그림을 낫게 하나 (2026-10-07)

`Docs/Design/2026-10-07-draw고리설계.md` 7절의 실측이다. 같은 캐릭터를 **지금 방식(A) 3장 · 고리 방식(B) 3장** 그려 견줬다. 1차는 원본 없이 글귀만, 2차는 원본 그림을 주고 얼마나 닮게 옮기나를 쟀다.

## 결론

- **닮음은 차이 없다.** 원본 대비 근사 일치율(near_shifted)이 A .533 · B .537 이라 통과선(B ≥ A + 0.10)에 못 미친다. 고리는 그림을 「원본에 더 가깝게」 만들지 못했다.
- **깨끗함은 B 가 확실히 낫다.** 최종 린트 외톨이(orphan)가 1차 A 의 약 ¼, 2차 평균 4.3 → 0.7. 바퀴 안에서 0 에 닿고, 덮여 사라진 손 같은 숨은 결함을 격자 읽기로 찾아 살렸다.
- **비용은 토큰 1.2~1.3배(통과선 3배 안), 시간 약 2.5배.** → 고리는 **「깨끗하게 마무리」 용도로 쓰고, 「닮게 그리기」 용도로는 안 된다.** 스킬 「어느 길을 고르나」 표는 바꾸지 않는다.

## 0. 무엇을 견줬나

| | A 지금 방식 | B 고리 방식 |
| --- | --- | --- |
| 그리는 법 | 도형 · 좌표로 한 번 그린다 | `to_grid` · `paste_grid` 로 문자 격자를 읽고 쓴다. symmetry · clip 을 건다 |
| 보는 법 | `report()` 한 번 | `lint`(좌표 박힌 결함) · `mark/changed/preview_changed/diff_grid`(바뀐 자리 미리보기) — 글과 그림 둘 다 |
| 고치기 | 없음 | 최대 3바퀴 |
| 절차 문서 | `ArtTool/.claude/skills/arttool-usage/SKILL.md` | `ArtTool/.claude/skills/arttool-usage/고리-그리기.md` |

- 모든 판은 **Opus 서브에이전트가 같은 지시문으로 따로따로** 그렸다. 서로의 결과를 못 본다.
- 설계 7절의 원래 통과선 : **B 사람 점수 평균 ≥ A + 1.0 그리고 B 3장 중 2장 린트 0 그리고 B 토큰 ≤ A × 3.** 셋 다 되면 「어느 길」 표에 「캐릭터 : PIL 고리도 됨」을 더하고, 하나라도 안 되면 고리는 「선택」으로 남긴다.
- 사람 점수는 비교 기준이 없어 1차에서 매기지 못했다. 그래서 2차는 원본을 두고 **기계 점수(닮음)** 로 통과선을 바꿨다(2절).

## 1. 1차 실측 — 원본 없음, 글귀만

과제 : 32×32 정면 SD 캐릭터 「갈색 단발 · 빨간 윗옷 · 파란 바지」. 템플릿 `char_small`.

| | A1 | A2 | A3 | B1 | B2 | B3 |
| --- | --- | --- | --- | --- | --- | --- |
| 시간 | 1:17 | 1:05 | 0:53 | 2:51 | 4:04 | 2:56 |
| 토큰 | 92K | 90K | 88K | 111K | 107K | 107K |
| 최종 린트 orphan/hole (합친 평면, 팔레트 없이) | 14/2 | 15/0 | 12/3 | 3/0 | 4/0 | 2/0 |
| 색 수 (한도 16) | 25 | 31 | 24 | 25 | 21 | 21 |
| `check` | ok + color_cap 경고 | 같음 | 같음 | 같음 | 같음 | 같음 |
| 바퀴 안 린트 | — | — | — | 외곽선 뒤 orphan 2 | 0 (waive 4) | 외곽선 뒤 2 |
| 자기 점수 읽힘/귀여움/깔끔 | 4/3/4 | 4/3/3 | 3/2/2 | 5/4/4 | 4/3/4 | 4/3/3 |

- 여섯 장 모두 메인 세션이 보기에 「갈색 단발 · 빨간 윗옷 · 파란 바지」로 읽혔다.
- **사람 눈 점수는 매기지 않았다.** 사용자가 「비교군이 있어야 한다」고 해서 원본을 두는 2차로 넘어갔다.

**1차에서 본 한계**

- 원본이 없으니 「닮음」을 잴 수 없다.
- 린트는 B 가 A 의 약 ¼ 이지만 **0 은 아니다.** 외곽선을 두른 뒤 생기는 외톨이 칸이 바퀴 안에서는 안 보이기 때문이다(외곽선은 바퀴가 끝난 뒤 두른다).
- 색 수는 양쪽 다 한도(16)를 넘었다. selout(겉선을 옆 색의 어두운 판으로 칠하는 외곽선)이 색 띠(램프)마다 어두운 색을 하나씩 더하고, 팔레트 없이 그린 탓이다.

## 2. 2차 실측 — 원본 있음

### 2-1. 판 짜기

- **원본** : 게임 저장소의 정식 손님 그림. 네 겹(body · shirt_red · face_01 · hair_01_brown)을 합친 120×240 PixelLab 옆모습 손님 — 갈색 단발 · 빨간 후드 · 파란 바지 · 흰 신발, 오른쪽을 본다. 59색.
- **목표 크기** : 60×120 (½).
- **정답지** : 원본을 2×2 칸씩 평균 내 줄이고 원본 팔레트에 맞춘(스냅) 그림. 53색 · 불투명 2,768칸.
- **에이전트가 받은 것** : 원본 PNG(Read 로 눈으로만 보기)와 팔레트 글자 목록뿐. 정답지 · 채점기는 못 본다. 원본 PNG 를 PIL 로 열거나 줄여서 붙여 넣는 것은 금지.

### 2-2. 채점기 `score.py`

| 점수 | 뜻 |
| --- | --- |
| silhouette_iou | 윤곽 겹침. 불투명 칸 마스크의 교집합 ÷ 합집합 |
| exact | 정답지의 불투명 칸 중 RGBA 가 똑같은 칸 비율 |
| near | 그림도 불투명이고 RGB 채널 차가 모두 24 이하인 칸 비율 |
| near_shifted | 그림을 ±2칸 안에서 밀어 본 near 중 가장 큰 값. **닮음의 주 점수** |

채점기 자가 시험 : 정답지 자신 1.0 · 오른쪽으로 1칸 밀면 near .72 → near_shifted 1.0 · 전부 투명 0 · 색을 +10 밝게 하면 exact 0 / near 1.0. 넷 다 뜻대로 나왔다.

**2차 통과선(바꾼 것)** : B near_shifted 평균 ≥ A + 0.10 **그리고** B 토큰 ≤ A × 3. 린트 · 시간은 참고로만 본다.

### 2-4. 눈으로 본 것

- 메인 세션이 여섯 장과 정답지를 나란히 놓고 봤다. **여섯 장 모두 원본으로 읽힌다.** 차이는 머리 윤곽의 둥긂 · 앞머리 결 · 눈 크기 · 후드 볼록함 정도다.
- **손** : A1 · A2 와 B 의 1바퀴 그림들은 손이 바지/소매에 덮여 사라졌다. B 는 2~3바퀴에서 격자를 읽다가 이걸 찾아 살렸다 — **린트가 잡은 게 아니라 격자를 읽어서 찾았다.** A3 도 손이 거의 안 보인다.
- 모든 에이전트가 「지시문의 '왼쪽을 본다'와 원본(오른쪽을 봄)이 다르다」고 보고하고 원본을 따랐다. 지시문 오타이고 결과엔 영향이 없다.

## 3. 판정

| 항목 | 결과 | 통과? |
| --- | --- | --- |
| 닮음 (2차 통과선) | near_shifted A .533 · B .537 — 차이 +0.004 | **미달** (+0.10 필요) |
| 토큰 (2차 통과선) | 1차 약 1.2× · 2차 1.3× | 통과 (3× 안) |
| 린트 (참고) | 1차 약 ¼ · 2차 orphan 4.3 → 0.7, 바퀴 안에서 0 도달 | B 가 낫다 |
| 시간 (참고) | 약 2.5× | B 가 느리다 |
| 원래 통과선 「B 3장 중 2장 린트 0」(참고) | 1차 0장(3·4·2) · 2차 1장(B2) | 미달 |
| 원래 통과선 「사람 점수 +1.0」 | 매기지 않음 | 판정 못 함 |

- **닮음은 첫 그림을 얼마나 잘 보고 옮기느냐가 정하고, 바퀴는 그걸 못 바꾼다.** 바퀴 안에서 에이전트가 보는 것은 자기 그림의 격자와 린트뿐이고, 원본은 같은 꼴(격자)로 견줘 보지 못한다. 그러니 바퀴가 닮음을 끌어올릴 길이 없다 — 숫자도 그렇게 나왔다.
- **깨끗함은 바퀴가 올린다.** 린트가 좌표를 찍어 주니 외톨이 칸 · 구멍을 바로 지우고, 격자를 읽다가 덮인 손 같은 린트 밖 결함도 찾는다.
- **결론 : 고리는 「깨끗하게 마무리」 용, 「닮게 그리기」 용으로는 안 된다.** 통과선 미달이라 SKILL 「어느 길을 고르나」 표는 그대로 둔다.
- **권고** : `고리-그리기.md` 머리에 「무엇에 좋고(린트 · 숨은 결함 정리) 무엇엔 소용없나(원본 닮게 하기)」 한 줄을 넣는다. → 반영됨.

## 4. 다음 후보 (권고)

1. **견줌 창** — 바퀴 안에서 원본 PNG 를 `to_grid` 로 같은 창 격자로 바꿔 자기 그림 격자 옆에 나란히 읽게 한다. 닮음을 올릴 가능성이 있는 **유일한 길**로 본다(아직 안 재 봄).
2. **외곽선을 바퀴 안으로** — 외곽선을 두른 뒤 생기는 외톨이 칸이 바퀴 밖에 남는 문제(1차 B1 · B3)를 없앤다.
3. **템플릿 없는 큰 캔버스 준비 절차 문서화** — 2차처럼 60×120 에 마스크 · 가이드가 없으면 clip 을 못 건다.

## 6. 재현 방법

- **산출물(여섯 장 × 2차례 · 정답지 · `score.py` · 바퀴별 그림)은 세션 스크래치패드에 있었고 저장소엔 없다.** 다시 재려면 아래 요지로 새로 만든다.
- **지시문 요지**
  - 공통 : Opus 서브에이전트 하나가 한 장. 같은 지시문, 서로 결과를 못 본다. 시간은 벽시계, 토큰은 에이전트 사용량.
  - A : `SKILL.md` 의 PIL 길대로 도형 · 좌표로 한 번 그리고 `report()` 를 본 뒤 끝낸다. 고치기 없음.
  - B : `고리-그리기.md` 절차대로 격자 읽기 · 쓰기 · 린트 · 변경 미리보기로 최대 3바퀴. 바퀴별 린트 수를 적는다.
  - 1차 : 32×32 정면 SD, 「갈색 단발 · 빨간 윗옷 · 파란 바지」, `char_small`.
  - 2차 : 원본 PNG(눈으로만) + 팔레트 글자 목록을 주고 60×120 으로 옮겨 그린다. PIL 로 원본을 열거나 줄여 붙이기 금지. 정답지 · 채점기는 안 준다.
- **채점** : 정답지 = 원본 2×2 평균 → 원본 팔레트 스냅. 점수 넷은 2-2 표대로. 채점 전에 2-2 의 자가 시험 넷을 먼저 돌려 본다.
