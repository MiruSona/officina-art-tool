# 로컬 그림 모델 실측 1단계 (2026-10-07)

`2026-10-07-PixelLab로컬대체조사.md` 7절의 **1단계(LLM 띄운 채, 기능 1 새 그림 · 2 inpaint)** 를 미니PC 에서 실제로 돌렸다.
LLM 서버(`llama`)는 꺼져 있었고 대신 **다른 사람의 게임 서버(약 4~10GB)가 떠 있는 채**로 쟀다.

## 결론

- **둘 다 돈다.** FLUX.2 klein 4B(fp8) 는 512px 한 장 **약 9초**, Z-Image-Turbo(GGUF Q6_K) 는 **약 21초**. GPU 멎음 · 오류 0건.
- **inpaint 마스크 밖 0픽셀**은 `ImageCompositeMasked` 노드로도, Pillow 합성으로도 **0** 이 나왔다. 모델이 낸 그대로는 밖이 37% 바뀐다 → 합성 단계가 필수라는 조사 결론이 맞다.
- ArtTool 흐름(512 → 축소 → `cutout` → `merge-colors` → `check`)에 넣으면 **16색 · `check` ok** 까지 간다. 64px 소품 · 이펙트는 쓸 만하고, **24px 아이콘은 뭉개지고 48px 타일은 격자가 안 맞아** 손질이 남는다.
- **판단 : 기능 1(소품 · 이펙트 급) 과 2(inpaint) 는 로컬로 넘길 수 있다.** 아이콘 · 타일은 2단계 또는 다른 뽑기 방식(더 큰 격자 · 타일 LoRA)이 필요하다. 캐릭터는 이번에 안 봤다.

주의 : klein LoRA 를 올릴 때 `lora key not loaded: *_modulation.*` 경고 6줄이 뜬다(modulation 층은 ComfyUI 가 안 받음). 결과 화풍엔 문제가 없어 보였으나 LoRA 가 **부분 적용**이다.

## 3. 장당 시간 · 메모리

조건 : 512×512 · klein 4스텝 euler cfg1 (distilled) · Z-Image 8스텝 res_multistep cfg1 shift3 · LoRA 세기 1.0 · `--cache-none` 이라 **장마다 인코더 · 모델을 다시 올린다** (시간에 포함). 프롬프트 넷 × 시드 2 = 모델당 8장. 메모리는 0.5초마다 `/proc/meminfo`(MemTotal−MemAvailable) · `mem_info_gtt_used` · 게임 서버 `VmRSS` 를 찍은 최댓값. 원자료 `~/imggen/out/<모델>/bench.jsonl`.

| 모델 | 첫 장 | 2~8장째 | 시스템 used 피크 (쉴 때) | GTT 피크 | 게임 서버 RSS |
| --- | --- | --- | --- | --- | --- |
| klein 4B fp8 + LoRA | 12.4초 | **8.4~10.1초 (평균 9.0)** | 24.0~27.9GB (쉴 때 7.2GB → **+17~21GB**) | 11.6GB | 4.78 → 4.59GB |
| Z-Image-Turbo Q6_K + LoRA | 24.2초 | **20.8~21.9초 (평균 21.5)** | 23.7~24.1GB (쉴 때 12.0GB → **+12GB**) | 11.0GB | 4.49 → 3.90GB |

- klein 의 +21GB 는 **"20GB 를 넘기지 마라" 를 살짝 넘긴다.** 8GB bf16 인코더가 먼저 올라갔다 내려가고 모델이 올라가는 틈의 합으로 보인다. 인코더를 fp8(5.6GB, Comfy-Org `qwen_3_4b_fp8_mixed`)로 바꾸면 내려갈 것 — **다음 판에서 확인**.
- 게임 서버 RSS 는 12:07 **10.0GB** → 생성 전 4.8GB → 끝난 뒤 3.7GB 로 줄었고 swap 은 75MB → 535MB. 서버가 죽거나 멎지는 않았다(프로세스 그대로). **이미지 당기기 · 모델 받기 때 페이지 캐시에 밀린 것으로 보이나 원인은 못 박지 못했다.** 생성 중 변화는 0.1~0.6GB.
- 커널 `dmesg` 에 ring timeout · device lost · gpu reset **0건**.

## 4. inpaint 0픽셀 검사

Z-Image 결과(통 그림) 한 장에 160~352 네모 마스크(36,864px) 를 씌우고 `VAEEncode → SetLatentNoiseMask → KSampler(denoise 0.85)` 로 다시 그렸다. 21.4초. 워크플로 `~/imggen/workflows/zimage_inpaint.json`.

| 합성 | 마스크 밖 다른 픽셀 / 225,280 | 마스크 안 다른 픽셀 |
| --- | --- | --- |
| 모델이 낸 그대로 (노드 없이) | **83,545 (37%)** | 36,747 |
| `ImageCompositeMasked` 노드 | **0** | 36,747 |
| Pillow `Image.composite` | **0** | 36,747 |

안쪽은 초록 흐름이 지워지고 빨간 경고표가 붙었다(프롬프트대로). Crop&Stitch 노드는 컨테이너에 없어 안 썼다.

## 5. ArtTool 검수

흐름 : 512 → Pillow BOX 축소(아이콘 24 · 소품 64 · 타일 48 · 이펙트 64) → `cutout --key corner --tol 40`(흰 바탕 둘만) → `merge-colors --per-image --tol 48 --max-colors 16` → `check --no-ramps`. NEAREST 축소도 같이 돌렸다. 비교판 `scratchpad/step5/compare_sheet.png`.

| 그림 | 축소 직후 색 수 (klein / Z-Image) | 합친 뒤 | `check` 경고 (BOX) |
| --- | --- | --- | --- |
| p1 아이콘 24px | 132 / 159 | 17 / 17 | `color_cap` 둘 다, klein 은 `isolated` 0.16 |
| p2 소품 64px | 894 / 1048 | 17 / 17 | 없음 |
| p3 타일 48px | 381 / 1841 | 16 / 16 | klein `isolated` 0.30 · Z-Image `integer_scale` + `isolated` 0.15 |
| p4 흰 이펙트 64px | 520 / 384 | 16 / 16 | 없음 |
| 참고 `ArtTool/Example/Front.png` 64px | 27 | — | 없음 |

- `status` 는 넷 다 ok, `must_failed` 없음. 색 수는 모델이 그린 것이 수백~수천이라 **합치기 없이는 못 쓴다**.
- 눈으로 : **64px 소품(통) · 흰 이펙트는 둘 다 쓸 만**하다(외곽선 · 명암이 살아 있음). **24px 아이콘은 BOX 축소에서 뭉개져** 알아보기 어렵다(모델이 512 안에 약 6~8px 굵기로 그려 24 로 줄이면 1픽셀 미만). **타일은 둘 다 격자가 안 맞고** 잡티 비율이 높다. Z-Image 타일은 돌이 아니라 파란 벽돌풍으로 나왔다(프롬프트 해석 차이).
- PixelLab 결과 나란히 비교 : PixelLab 을 새로 부르지 않았고, 저장소의 참고 그림 `ArtTool/Example/Front.png` 만 같은 비교판에 넣었다. 종류(캐릭터 vs 소품)가 달라 직접 비교는 아니다.

## 6. 막힌 것 · 못 한 것

- Z-Image bf16 · klein bf16 은 20GB 한도 때문에 안 받았다 → 양자화 판 품질만 봤다.
- 화풍 참조 그림 입력(klein 다중 참조)은 안 했다. 1-가 계획의 "PixelLab 결과 1장을 화풍 참조로" 는 2판 몫.
- 캐릭터 · 건물 · 배경 프롬프트는 안 돌렸다(이번 범위는 소품 · 아이콘 · 타일 · 이펙트 넷).
- LLM 서버를 띄운 채로는 못 쟀다(`llama` 가 꺼져 있고 켜지 말라는 규칙). 게임 서버가 떠 있는 채로 잰 것이라 "LLM 띄운 채 15GB" 조건은 **대신 검증이 안 됐다** — klein 피크 +21GB 라 LLM 42GB 와 같이 올리면 넘칠 수 있다.
- 게임 서버 RSS 가 줄어든 원인을 못 박지 못했다.
