# PixelLab MCP — 손님 그림 시험에서 막힌 것

> 떡 농장 게임의 가판대 손님(동물 4종 · 사람 4명)을 PixelLab MCP 로 뽑아 본 기록 중
> **툴 자체에서 막히거나 헷갈린 것**만 적는다. 그림 판정은 게임 저장소 쪽에 있다.
> 날짜 2026-09-22 · 쓴 사람 AI(아트 세션)

## 막힌 것

- **방향을 고를 길이 없다.** `create_image_pro_flash` 에는 방향 인자가 없고, 설명에
  「facing left three-quarter view, not a full side profile」 을 넣어도 **열 장 전부 정면(south)** 으로 나왔다.
  `agent_help` 도 「MCP 어디에도 왼쪽 3/4 값은 없다. 참고 그림으로만 잡아라」고 답했다.
  → 참고 그림(첫 판)이 정면이면 그 뒤로 전부 정면이 된다. **방향은 참고 그림이 통째로 정한다.**
- **낱색이 500개 넘게 나온다.** 48×64 한 장에 ±2 씩 흔들린 잡색이 541~670개였다
  (반투명 픽셀은 0개라 격자 자체는 1:1 로 깨끗하다). 평면 화풍(10~14색)에 쓰려면 밖에서 줄여야 한다.
  `reduce_colors` 툴이 있지만 generations 를 먹을 것 같아 PIL 로 줄였다 — **줄이는 일에 값이 드는지 안 드는지
  `get_pro_flash_capabilities` 나 도구 설명에 안 적혀 있다.**
- **크기를 못 박을 길이 없다.** 48×64 캔버스를 줘도 내용이 50~59px 로 꽉 차게 나온다.
  「키 44px · 위에 여백 20px」 같은 말은 안 먹었다.
- **한 장이 서버 사정으로 실패했다** (`Generation failed due to a temporary server issue`).
  같은 인자로 다시 돌리니 통했다.
  **실패한 판에는 값이 안 들었다** — 11번 불러 10장 성공, 잔액이 딱 50회(10×5) 줄었다.

## 걸린 시간 (실측)

| 무엇 | 걸린 시간 |
| --- | --- |
| 48×64 한 장 (혼자 돌릴 때) | 35 ~ 87초 |
| 48×64 한 장 (여섯 장 같이 띄울 때) | 62 ~ 156초, `eta` 는 440초까지 부풀어 뜬다 |

- `wait_for_jobs` 가 알려주는 `eta` 는 **한참 부풀어 있다** — 440초라 해도 실제로는 30초 만에 끝나기도 했다.
  eta 를 보고 일을 접지 말 것.

## 잘 된 것

- **`create_image_pro_flash` 의 커스텀 크기(베타)가 쓸 만하다.** 48×64 처럼 4의 배수면 받는다.
  한 장에 **5 generations** 라 `create_1_direction_object`(20~40회)보다 네 배 넘게 싸다.
- **`style_image` 에 `source_image_id` 를 주는 되먹임이 아주 잘 듣는다.**
  첫 판을 뽑고 그 `source_image_id` 를 뒤 석 장의 `style_image` 로 주니
  몸 크기 · 외곽선 굵기 · 볼 위치까지 거의 같게 나왔다. **묶음 화풍은 이 길로 잡는 것이 맞다.**
- `agent_help` 의 답이 정확했다 — 「방향 인자는 없다」도, 「참고 그림이 글보다 세다」도 실제와 맞았다.

## 툴에 바라는 것

1. `create_image_pro_flash` 에 **방향(또는 pose) 인자**. 한 방향 스프라이트에 3/4 각을 주는 길이 지금은 없다.
2. **낱색 상한 인자** (`max_colors` 같은 것). 평면 픽셀아트 갈래에서는 거의 늘 필요하다.
3. `reduce_colors` · `correct_pixelart` 가 **generations 를 먹는지 안 먹는지** 도구 설명에 한 줄.
4. **실패한 판의 과금 여부**를 실패 응답에 적어 주기.

## 이어서 — 겹(레이어) 나누기 시험 (2026-09-22)

뽑은 사람 손님 한 장을 몸·머리카락·옷·표정 네 겹으로 나누고, 가려졌던 자리를
`inpaint_image_pro_flash` 로 메워 봤다.

### 잘 된 것

- **`inpaint_image_pro_flash` 가 마스크 밖을 정말 한 픽셀도 안 건드린다.** 도구 설명의
  「preserving unmasked RGBA bytes exactly」 는 사실이었다 — 보존 약속 자리 1841 픽셀이 모두 그대로였고
  **자리(좌표)가 하나도 안 밀려서** 나눠 둔 머리카락·표정 겹을 그대로 다시 얹을 수 있었다.
  겹 작업에 쓰기 좋은 성질이다.
- 48×64 커스텀 크기에서 마스크 PNG(같은 크기 · 흰=그림 · 검=보존)를 받아 준다. **27초**로 빨랐고 5 generations 였다.

### 막힌 것

- **`crop_to_mask` 가 `const: true` 라 끌 수 없다.** 마스크가 큰데 그 안 일부만 다시 그리고 싶어도 고를 수 없다.
- **「그리지 마라」를 잘 안 듣는다.** 설명에 「Absolutely no hair and no red shirt」 라고 못 박았는데
  머리는 안 그렸지만 **민 몸통을 흰 러닝셔츠로 그렸다.** 그 러닝셔츠 밑단이 원래 윗옷보다 아래로 내려와
  다른 옷을 얹었을 때 허리에 흰 줄이 남는다. **덮일 것을 전제로 한 「밑판」은 AI 에게 맡기기 어렵다** —
  이번에는 PIL 로 윗옷 실루엣을 그대로 메우는 쪽이 나았다.
- 마스크를 base64 로 넘기는 길은 됐다. 다만 **마스크가 비면 거절**이라는 것 말고는
  「마스크가 캔버스의 몇 %를 넘으면 안 된다」 같은 한계가 도구 설명에 없다 — 이번엔 절반 넘게 흰색이어도 돌았다.

### 툴에 바라는 것 (앞 절에 더해)

5. **`crop_to_mask` 를 끌 수 있게** 해 주기.
6. 「이 자리는 다른 그림에 **덮일 밑판**이니 실루엣 밖으로 나가지 마라」를 시킬 인자.
   지금은 프롬프트로 못 막는다.

## 덧붙임 (2026-09-22 · 겹 16장 굽기)

나눈 겹을 팔레트만 갈아 끼워 열여섯 장으로 구웠다 (`bake_palette.py`). PixelLab 은 안 썼고 PIL 만 썼다.
그 과정에서 나온 것 둘.

- **나누기가 남긴 세 점짜리 조각.** 긴 머리 겹 `purple_hair.png` 의 (33,49)~(34,50) 에
  옷 색면이 머리로 잘못 가 떨어진 조각이 남아 있었다. 원본 조합에서는 윗옷에 가려 안 보여 몰랐다.
  머리만 따로 쓰면 허공에 점으로 뜬다 — **겹을 나눈 뒤에는 「붙어 있지 않은 자잘한 덩어리」 검사를 한 번 돌려야 한다.**
- **`crop_to_mask` 말고도 캔버스 유지가 잘 됐다.** 나눈 겹 넷이 모두 48×64 좌표계 그대로라
  색만 갈아 끼우면 쌓았을 때 자리가 한 픽셀도 안 틀렸다 (되돌림 검사 자리다름 0).
