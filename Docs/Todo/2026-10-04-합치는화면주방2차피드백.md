# 합치는 화면 · 주방 정식 2차 작업 피드백 (2026-10-04)

> 게임 저장소 반복 04. 합치는 화면을 기계실로 다시 뽑고, 기계 동작 · 칸 조각 · 절구 떡메 동작 · 쟁반 · 접시 · 마루를 PixelLab 으로 뽑았다. 크레딧 약 268회.

## 막힌 것

- **`animate_image` 가 기계 창 속에 김 덩이를 그렸다.** 「window glass stays plain grey」 라고 적어도 생긴다.
  프레임마다 창 원을 쉬는 그림으로 덮는 손질을 스크립트에 넣어 풀었다.
- **`create_image_pro_flash` 의 화풍 그림 제한 두 가지.** 캔버스보다 크면 거절되고, base64 가 길면 잘려서 「Could not decode image」 가 난다.
  48~64px 조각을 16색으로 줄여 넣어 풀었다. 이 제한이 오류 문구에 안 나와 두 번 헤맸다.
- `create_image_pro` 벽 한 판(20402)이 또 위 42 줄 흰 띠로 왔고 둥근 창 속이 흰색이었다. 창 속은 inpaint 로 다시 채웠다.
- 서랍 inpaint 첫 판이 마스크 오른쪽 끝에 세로 줄 하나를 남겼다. 좁은 마스크로 한 번 더 inpaint 했다.
- `edit_image_pro_flash` 로 서랍을 열게 하니 서랍이 발 아래로 내려왔다. 상태 조각을 한 캔버스에 맞추려면 피벗에 여유를 둬야 했다.
- 쟁반 · 접시 첫 판이 캔버스보다 훨씬 작게 왔다. 「fills the whole canvas width edge to edge」 를 넣으니 맞았다.
- `wait_for_jobs` 가 같은 계정의 다른 갈래 작업까지 보여 줘서 내 작업이 어느 것인지 job id 로 골라야 했다.

## 잘 된 것

- `animate_image` 가 6~7회로 싸고, 받침 · 절구 몸통이 프레임 내내 같은 자리에 남았다. 떡메 7장은 옮김 없이 그대로 썼다.
- 마루를 「Even, uniform lighting everywhere: no light spots, no bright circles」 + 1차 마루 조각을 화풍 그림으로 주니 얼룩 없는 판이 한 번에 나왔다.
- `source_image_id` 로 갤러리 그림을 바로 원본 · 화풍으로 쓸 수 있어 base64 길이 걱정이 없었다.

## 툴에 바라는 것

- 프레임 묶음을 「발 줄 맞추기 · 정한 원/사각 칸을 기준 그림으로 덮기 · 같은 칸으로 자르기 · 띠 · gif」 로 한 번에 굽는 공용 명령. 합치는 화면 · 주방이 거의 같은 코드를 썼다.
- 9-slice 미리보기 함수(나무 표 · 버튼 · 말풍선)를 공용으로. 갈래마다 다시 쓴다.
- pro_flash 화풍 그림을 캔버스에 맞게 자르고 색을 줄여 base64 로 만드는 작은 명령.
