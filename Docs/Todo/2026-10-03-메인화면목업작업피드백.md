# 메인 화면 목업 작업 피드백

> 2026-10-03 · 게임 저장소 반복 03 에서 메인 화면 시안 두 안을 만들며 느낀 것.
> 한 일 : PixelLab 으로 건물·하늘·UI 조각을 뽑고 PIL 스크립트로 540×960 · 540×1200 목업을 합성했다.

## 결론

**이번 일에는 이 툴 명령을 하나도 안 썼다.** 쓴 것은 이 툴의 `.venv` 파이썬(PIL · numpy)뿐이다.
목업 합성(부품 다듬기 → 배치 → 확대 → 글자)은 지금 이 툴에 맞는 명령이 없어 스크립트를 새로 짰다.

## 막힌 것

- **9조각 미리보기가 없다.** PixelLab 패널을 「이 크기로 늘리면 어떻게 보이나」를 보려고 9조각 함수를 직접 짰다.
  `ui frame` 은 코드가 그리는 패널용이고 `ui import` 는 `.9.png` 안내선이 있어야 한다.
  → 바람 : `<툴> ui preview --in panel.png --border 26 --size 300x62 --out x.png` 처럼 border 숫자만 주고 늘린 그림을 보는 명령.
- **배경 지우기가 없다.** 바탕색을 깔고 뽑은 그림(버튼·구름·숲)의 바탕을 지우는 일을 세 번 했다 (색 한 값 지우기 · 모서리에서 번지며 지우기).
  09-20 재료 아이콘 피드백의 「뒤처리 옵션」과 같은 갈래다.
  → 바람 : `<툴> cutout --in a.png --key corner|#RRGGBB [--tol N]`.
- **투명 여백 걷기도 매번 손으로 한다.** `ui icons --fit` 은 정사각형 아이콘만 받는다. 건물(144×146)처럼 네모가 아닌 그림은 못 넣는다.

## 헷갈린 것

- README 의 「아직 안 붙인 것」에 「PixelLab 은 이 PC 에 없다 · `--dry-run` 요청 JSON 까지만」이라고 적혀 있는데, 실제 작업은 PixelLab MCP 로 한다.
  **「그림 뽑기는 MCP 로, 이 툴은 그 뒤 규격·검수」** 라는 한 줄이 README 머리에 있으면 처음 읽는 에이전트가 `provider make` 를 찾아 헤매지 않는다.
- 목업(시안)처럼 「게임에 안 넣는 그림」에도 `check` 를 돌려야 하는지 README 에 안 나온다. 이번에는 안 돌렸다.

## 잘 된 것

- `.venv` 에 PIL · numpy 가 이미 있어 따로 깔 것이 없었다. 저장소 뿌리에서 `Tools/<이 툴>/.venv/Scripts/python.exe` 한 줄로 돌았다.
- 「겹은 캔버스를 안 자른다」 규칙 덕에 주인공·손님 겹을 같은 좌표에 쌓기만 하면 맞았다.

## 다음에 해 볼 것

- 시안이 확정돼 UI 조각을 게임에 넣을 때 `ui import` → `ui check` 로 9조각 border 와 홀수·최소 크기를 검사한다 (이번 패널은 258×122 · 버튼 48×48).
- 부품표 굽기(이름·크기 딱지를 붙여 모으기)는 `recolor --sheet` 와 비슷하다. 아무 PNG 폴더나 받는 `<툴> sheet --in parts/ --scale 2 --label` 이 있으면 스크립트가 준다.

## v2 작업에서 더 본 것 (2026-10-03)

- **막힌 것** : `create_topdown_tileset` 은 「muted · low saturation」을 적어도 풀이 형광 연두로 왔다. 타일 색을 지키게 하려면 pro_flash 에 색 값(#A6D49A)을 적어 뽑는 쪽이 맞았다. 이 툴 문서에 「타일 묶음은 색을 못 믿는다」 한 줄이 있으면 한 판을 아낀다.
- **막힌 것** : 가로 울타리를 160×32 한 장으로 뽑으면 기둥 간격이 37px 로 와서 32 격자에 안 맞는다. `<툴> check` 에 「되풀이 단위가 타일 크기의 배수인가」 검사가 있으면 넣기 전에 걸린다.
- **잘 된 것** : `edit_image_pro_flash` 로 흰 몸에 회색 선·명암을 넣게 했더니 윤곽이 한 픽셀도 안 바뀌었다 (bbox 같음). 곱하기 색 겹을 지키면서 화풍을 바꾸는 길로 쓸 만하다.
- **다음에 해 볼 것** : 「흰 겹 × 색 곱하기」 미리보기를 `<툴> recolor --multiply #hex… --sheet` 로 뽑을 수 있으면 이번 비교판 스크립트가 필요 없다.

## 가게 · 합치는 화면 v1, 메인 화면 v3 에서 더 본 것 (2026-10-03)

- **막힌 것** : pro_flash 는 그림을 캔버스보다 작게 그린다. 136×32 에 「기둥 다섯, 끝에서 끝까지」를 주문해도 그림 폭이 109, 기둥 간격이 26px 이었다. 타일 격자에 맞는 조각은 주문만으로는 안 나온다 — 이 툴에 「띠에서 되풀이 단위를 찾아 N px 타일로 잘라 맞추기」가 있으면 이번에 손으로 짠 `fence32` 가 필요 없다.
- **막힌 것** : 캔버스가 256 까지라 화면 폭(540)의 절반을 넘는 건물을 한 장으로 못 뽑는다. 큰 그림을 조각으로 나눠 뽑아 잇는 길이 문서에 있으면 좋겠다.
- **헷갈린 것** : 「청록 바탕」으로 뽑은 그림의 가장자리에 흰 띠가 둘러 올 때가 있다 (큰 말풍선). 모서리에서 번지는 배경 지우기가 통째로 실패한다 — 4px 안쪽을 자른 뒤 지웠다.
- **헷갈린 것** : 같은 화풍 그림을 주고 뽑은 풀 변형 타일의 바탕색이 6~10 쯤 어둡게 와서 깔면 네모가 보였다. `<툴> check` 에 「타일 묶음의 바탕색이 같은가」가 있으면 걸린다.
- **잘 된 것** : `edit_image_pro_flash` 를 같은 글 · 같은 씨앗으로 뛰는 그림 4장에 돌렸더니 네 장 모두 윤곽이 한 픽셀도 안 바뀌었다. 다만 선 회색이 장마다 137~164 로 달라 값 맞추기가 따로 필요하다.
- **잘 된 것** : `style_image` 에 앞서 뽑은 그림의 `source_image_id` 를 주면 base64 를 안 실어도 된다.

## 농장 새 화풍 · 가게 · 합치는 화면 v2 에서 더 본 것 (2026-10-03)

- **잘 된 것** : `create_image_pro` 는 캔버스가 512 까지라 화면 폭을 채우는 건물(508×428)을 한 장으로 뽑았다. 40회가 든다. 앞 소절의 「256 이라 큰 건물을 못 뽑는다」는 이 길로 풀린다.
- **막힌 것** : `create_image_pro_flash` 는 화풍 그림이 캔버스보다 크면 거절한다 (「Style image must fit the native canvas」). 128 캔버스에 160×96 화풍 그림을 못 준다.
- **막힌 것** : 갤러리 그림 id 로는 내려받기 주소가 404 다 (job id 로만 된다). `create_image_pro` 의 화풍 그림은 조각을 base64 로 직접 실었다.
- **헷갈린 것** : `create_tiles_pro` 의 타일은 낱장마다 가장자리가 어두워 깔면 격자가 보인다. 「이음매 없는 바닥」 용도에는 안 맞았다.
- **헷갈린 것** : pixflux 에 「바닥만」을 주문해도 위쪽에 건물 · 담 · 나무가 딸려 온다. 위 50px 쯤을 잘라 썼다.
- **헷갈린 것** : 240×160 캔버스에 받침을 주문했는데 그림이 80×83 으로 왔다. 크기를 글로 못 박아도 작게 온다.
- **다음에 해 볼 것** : 「한 바퀴 그림에서 모서리 · 가로 단위 · 세로 단위를 잘라 길이를 늘리기」를 손으로 짰다 (`Ring`). 이 툴에 있으면 울타리 · 테두리에 다시 쓴다.
- **다음에 해 볼 것** : 「32 격자 선의 색 차 ÷ 다른 곳의 색 차」 이음매 값을 손으로 쟀는데 거칠다. `<툴> check --seam` 같은 검사가 있으면 좋겠다.

## 가게 · 합치는 화면 v3 (실내) · 건물 단순화에서 더 본 것 (2026-10-03)

- **잘 된 것** : `create_image_pro` 는 272×608 세로 캔버스도 받는다. 화면 한 장(270×480 · 270×600)짜리 실내 배경을 한 번에 뽑았다 (40회). 9:20 에 맞춰 뽑고 9:16 은 위를 자른다.
- **잘 된 것** : `create_image_pro_flash` 의 `style_options` 에서 detail 을 끄고 글로 「단순하게 · 큰 면 · 장식 2~3개」 를 시키면 화풍 그림의 색 · 외곽선은 따라오고 장식만 준다. 가게 80색 → 38색, 기계 71색 → 28색.
- **잘 된 것** : `edit_image_pro_flash` 로 기계에 천 덮개를 씌우면 캔버스 안 자리가 그대로라 같은 좌표에 바꿔 놓을 수 있다.
- **헷갈린 것** : 「화면 속 물건의 좌표」(깔때기 입구 가운데 · 창 가운데 · 접시 자리)를 손으로 확대해 쟀다. 이 툴에 격자 확대 미리보기(좌표 눈금 포함)가 있으면 빨라진다.
- **헷갈린 것** : 「한 화면 도트 굵기 하나」 를 지키려면 사람 그림을 화면마다 다른 크기로 뽑아야 한다 (손님 64×80 · 큰 손님 78×146). `<툴> check` 에 「한 장에 섞인 도트 굵기」 검사가 있으면 ×2 로 키운 그림이 섞인 것을 잡는다.
- **다음에 해 볼 것** : 「앞 테두리 조각을 잘라 위에 덮기」(주인공 캐릭터가 깔때기 안에 든 것처럼)를 타원 식으로 손으로 짰다. 마스크 그림 한 장을 받아 앞 · 뒤로 나누는 명령이 있으면 다시 쓴다.

## 가게 v4 · 주방 화면 · 합치는 화면 v4 에서 더 본 것 (2026-10-03)

- **막힌 것** : `create_image_pro` 에 272×480 을 주니 그림이 흰 테두리와 함께 왔다 (내용은 y 31~451). 272×608 은 그렇지 않았다. 받은 뒤 `getbbox` 로 내용 크기를 꼭 본다.
- **잘 된 것** : 화풍 그림이 캔버스보다 크면 `create_image_pro_flash` 가 거절한다. 그림을 캔버스 크기(144×144) 투명 판에 채워 base64 로 주면 통과하고, 같은 물건을 더 작은 크기로 다시 뽑을 수 있었다 (기계 135×144 → 95×103).
- **잘 된 것** : 32px 아이콘 한 장은 5회면 된다. 큰 손님 한 명은 6회다.
- **헷갈린 것** : 시안 판에 글자를 나중에 한꺼번에 찍는 짜임이라, 종이 패널을 덮어도 뒤 화면의 글자가 패널 위에 찍혔다. 글자 목록을 패널 앞뒤로 나눠야 한다. 「겹 순서를 가진 글자」 를 이 툴 합성 명령이 받아 주면 덜 틀린다.
- **다음에 해 볼 것** : 「—」 처럼 글꼴에 없는 글자는 네모로 찍힌다. 합성 전에 글꼴에 없는 글자를 알려 주는 검사가 있으면 좋다.

## 가게 v5 「안쪽 버전」 · 보관함 단순화에서 더 본 것 (2026-10-03)

- **잘 된 것** : `create_image_pro` 272×608 에 「왼쪽 70% 는 계산대 · 오른쪽 끝은 문 · 가운데 칠판 · 아래 3분의 1 은 빈 마루」 처럼 자리를 번호 매겨 적으니 한 번에 그 배치로 왔다 (40회).
- **막힌 것** : 같은 272×608 인데 이번에는 위 30 줄 · 아래 29 줄이 흰 띠로 왔다 (v3 때는 안 그랬다). 9:20 높이가 모자라 위를 한 가지 색으로 채웠고 들보가 끊겼다. 받은 뒤 내용 줄 수를 꼭 잰다.
- **막힌 것** : `create_image_pro_flash` 는 그림이 캔버스를 거의 채워서 온다 (144 캔버스 → 113×96, 96 캔버스 → 93×82). 「캔버스 폭의 60%」 라고 적어도 안 듣는다. 크기는 캔버스로 맞춘다.
- **잘 된 것** : 방금 뽑은 그림의 `source_image_id` 를 다음 장의 화풍 그림으로 주면 후보 셋의 색 · 선이 한 벌로 맞는다. base64 는 첫 장에만 실었다.
- **잘 된 것** : 화풍 그림을 32색 팔레트 PNG 로 줄이면 base64 가 3~5KB 라 MCP 인자로 실을 만하다.
- **헷갈린 것** : 화풍 그림(기계)은 갈색 선인데 뽑힌 상자는 거의 검은 선으로 왔다. 「dark brown 1px outline」 을 적어도 그랬다. `<툴> check` 에 「외곽선 색이 기준 그림과 같은가」 가 있으면 걸린다.
- **헷갈린 것** : 작업이 덜 끝난 그림의 내려받기 주소는 62바이트짜리 오류 글을 준다. 파일 크기를 안 보면 깨진 PNG 로 저장된다.
