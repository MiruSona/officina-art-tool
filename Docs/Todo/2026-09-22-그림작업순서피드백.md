# 그림 작업 순서 피드백 (2026-09-22)

> 게임 저장소에서 떡 11장 · 손님 16장을 만든 뒤 사용자가 **그림 작업 순서**를 다섯 자리로 못 박은 기록이다.
> ArtTool 이 그 순서의 어디에 서나와, 그래서 바라는 것을 적는다. 그림 판정 자체는 게임 저장소 쪽에 있다.
> 날짜 2026-09-22 · 쓴 사람 AI

## 결론 — 정한 순서

| # | 자리 | 무엇을 하나 |
| --- | --- | --- |
| 1 | 레퍼런스 조사 | 분위기를 한 줄로 묻고, 참고가 없으면 웹 조사부터 한다 |
| 2 | PIL 프로토타입 | 시안 두 벌을 PIL 로 그리고, 실제 쓰임 크기 비교 그림으로 사용자 판정을 받는다 |
| 3 | 베이스 그림 얻기 | 직접 그리기 · PixelLab · 다른 생성기. 우리 프로젝트는 PixelLab 으로 뽑는다 (**확인 받은 뒤에만**) |
| 4 | PIL 겹 나누기 | 베이스를 다시 겹(레이어)으로 가른다. 예 : 손님 = 몸·머리·옷·표정 넷 (`Docs/Reference/Art/손님/pixellab/layers/`) |
| 5 | ArtTool (필요하면) | 색 갈아 여러 장 굽기 · 규격 맞추기 · 검수 · 굽기 (`normalize` → `anchors` → `check` → `bake`) |

키트에서 PixelLab 은 선택이다 (09-26 사용자 결정). 베이스 그림이 어디서 왔든 ④ 겹 나누기에 그대로 들어간다.

**ArtTool 은 마지막 자리다.** README 가 말하듯 「그려 주는 툴이 아니다」 — 그려진 것을 불리고 검수하는 자리라
①~④ 가 끝난 뒤에 온다.

## 왜 이 순서인가 (09-21 ~ 22 실측)

- **PIL 프로토 없이 PixelLab 부터 가면 시안이 8~9판 갔다.** 떡과 손님 둘 다 그랬다.
  PIL 로 두 벌을 먼저 보여 주고 고른 뒤 가면 PixelLab 은 한두 판이면 된다.
- **PixelLab 결과는 겹으로 갈라야 배선이 쉬웠다.** 손님을 몸·머리·옷·표정 넷으로 가르고
  팔레트를 미리 구워(`bake_palette.py`) 16장을 만드니 Unity 쪽은 겹만 쌓으면 됐다.
  한 장짜리 그대로 넣었으면 색 변종마다 PixelLab 을 다시 돌려야 했다.
- **Aseprite 는 안 썼다.** 겹 나누기 · 색 줄이기 · 팔레트 굽기 전부 PIL 로 됐다 (`2026-09-22-PixelLab손님시험.md`).

## ArtTool 에 바라는 것 (제안 — 할 일로만 적는다)

1. **④ 겹 나누기**가 지금은 게임 저장소의 손 스크립트(`split_layers.py`)다. ArtTool 명령으로 들어오면 좋겠다.
   나눈 뒤 「붙어 있지 않은 자잘한 덩어리」 검사까지 같이 돌면 더 좋다 (손님 시험에서 세 점짜리 조각이 남았다).
2. **⑤ 팔레트 미리 굽기**도 손 스크립트(`bake_palette.py`)다. 겹 몇 장 + 색표 몇 벌 → N장 굽기가
   ArtTool 의 `bake` 옆에 붙으면 게임 저장소에서 스크립트를 판마다 새로 안 짜도 된다.

둘 다 제안이다. `진행상황.md` 의 「한 장 → 겹 나누기」 미룬 항목과 같은 줄기라 그때 같이 본다.
