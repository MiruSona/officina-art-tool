# 화풍 통일 준비 피드백 (2026-10-05)

게임 저장소에서 게임용 프로필 여섯 · 공용 팔레트 · 겹 묶음 꼴을 **게임 저장소 쪽 폴더**에 만들고, 그림 111장을 종류별 프로필로 잰 경험이다.
쓴 명령 : `profile show` · `check --profile <yaml 경로>` (낱장 모드) · `layers check`.

## 막힌 것

| # | 무엇 | 바라는 것 |
| --- | --- | --- |
| 1 | **`palette.ramps_file` 은 프로필 폴더 아래(또는 툴 폴더 아래)만 된다.** 게임 저장소에서 `profiles/` 와 `palettes/` 를 나란히 두면 `..` 가 거절돼 못 가리킨다. `profiles/palettes/` 에 사본을 두고 스크립트로 두 파일이 같은지 지켰다 | 프로필 폴더의 **윗 폴더 한 단** 까지 찾기, 또는 `<툴>_PALETTES` 같은 팔레트 뿌리 칸. (`<툴>_HOME` 은 프리셋 · 템플릿 자리까지 같이 옮겨 못 썼다) |
| 2 | **램프 길이가 모두 같아야 한다** (`load_ramps`). 손으로 고른 팔레트는 램프가 1 ~ 5칸으로 제각각이라 밝은 끝 색을 되풀이해 채웠다. 그러면 `ramp_shape` 가 「단 수 모자람」 으로 건다 | 길이가 다른 램프 받기 (LUT 를 구울 때만 길이를 따지기), 또는 한 색 · 두 색 램프를 `singles` 칸으로 받기 |
| 3 | **`ramp_shape` 경고가 모든 `check` 에 똑같이 붙는다.** 그림이 아니라 팔레트를 보는 검사라, 묶음 열 개를 돌리면 같은 12줄이 열 번 나온다. 「밝기 위주 램프(색조 안 돌림)」 로 정한 게임은 끌 수밖에 없다 | 팔레트 검사를 `palette check` 같은 따로 명령으로, 또는 `check` 보고에서 그림 경고와 다른 칸으로 |
| 4 | **`color_cap.table` 이 기본 표에 겹쳐진다.** `{128: 16, 256: 40}` 만 적어도 기본 칸 `8 · 16 · 32 · 48 · 64` 가 남아, 48px 그림이 적지 않은 한도 44 를 받았다 (`profile show` 를 보고서야 알았다) | 표를 적으면 통째로 바꾸기, 또는 안내에 「기본 표에 겹친다」 한 줄 |
| 5 | **`color_cap` 이 긴 변 하나로만 고른다.** 같은 120×240 겹이라도 머리통 16 · 색 바꾼 겹 6 · 몸 40 처럼 겹마다 한도가 다른 것을 한 프로필로 못 적는다 | 파일 이름 무늬 → 한도 표 |
| 6 | **겹 묶음 꼴은 「`<겹>/<그림>.png`」 만 받는다.** 게임 그림은 `body_hop0.png` · `face_01.png` 처럼 낱장이 흩어지고 조합이 자유라(몸 4 × 표정 10 × 악세 2), `layers check` 를 돌리려면 임시 폴더에 조합을 세워야 했다 | `layers.json` 에 겹마다 파일 무늬(`"files": "face_*.png"`)를 적고 낱장 폴더를 그대로 검사 |
| 7 | **캔버스보다 작은 겹(11×11 볼)을 못 넣는다.** 코드가 자리에 붙이는 작은 겹이다. `optional` 로 순서 자리만 잡고 비워 뒀다 | 겹에 `size` · `offset` 칸 |
| 8 | **`layers.json` 은 모르는 칸을 거절한다.** 피벗 · 바닥 줄 · 파일 이름 규칙을 같이 적고 싶었는데 못 적어 README 표로 뺐다 | `note` · `pivot` 같은 덧칸 (팔레트 파일은 덧칸을 받는다) |
| 9 | `--in` 은 폴더 하나라, 여러 폴더에 흩어진 한 종류(`Cake/` + `Ingredient/`)나 한 폴더에 섞인 여러 종류(`Screen/`)는 임시 폴더로 복사해야 했다 | `--in` 여러 개, 또는 파일 목록 `--files @list.txt` |

## 헷갈린 것

- `exact_match` 기본이 `true` 라, 팔레트 파일을 적는 순간 **지금 그림 전부가 `ramp_colors` 실패**가 된다. `false` 로 두면 알리기만 한다는 것은 `check.py` 를 읽고 알았다. 명령안내에 한 줄 있으면 좋겠다.
- `palette.outline: null` 이 되는지 안내에 없다 (`profile show` · `check` 는 통과했다. `reline --profile` 은 안 돌려 봤다).
- `check` 보고의 한국어가 Git Bash 에서 `python` 으로 다시 찍을 때 깨졌다 — 보고 파일은 멀쩡하고 콘솔 쪽 일이다 (`PYTHONIOENCODING=utf-8` 로 풀림).

## 잘 된 것

- `profile show --profile <yaml 경로>` 가 **툴 폴더 밖 프로필**을 그대로 읽는다. 게임 저장소에 프로필을 두는 길이 한 번에 됐다.
- `check.background.max_colors` · `color_cap` 로 배경 한도(68)를 따로 여니 지난 점검의 배경 실패 셋이 없어졌다.
- `style.outline` 을 적자 외곽선 판정이 「정보」 에서 「경고」 로 바뀌어, 종류별로 고칠 그림이 바로 목록으로 나왔다 (사람 17 · 아이콘 16).
- 팔레트 파일이 덧칸(`comment` · `real_len`)을 받아 「진짜 칸 수」 를 같이 적을 수 있었다.
- 111장 열 묶음 + 겹 검사 둘이 한 번에 1분 안쪽으로 돌았다.

### 헷갈린 것

- `rules[].items` 꼴이 규칙마다 다르다. `alpha` 는 파일 이름 글자 목록, `max_colors` 는 `{where, colors, …}` 사전 목록이다. 실패한 파일 이름을 모으려면 둘 다 다뤄야 했다.
- `color_cap.table` 이 기본 표에 겹친다는 것(#4)은 이번에도 `profile show` 로 봐야 알았다. 16px 칸은 적지 않아 기본 8 이 남았다.

### 잘 된 것

- 111장 + 겹 둘이 한 번에 1분 안쪽으로 돌아, 프로필 · 팔레트를 고칠 때마다 다시 재 보기가 쌌다 (이번에 세 번).
- 보고 JSON 의 경고 항목마다 `where` 가 있어 파일 무늬로 「알고 두는 것」 을 가르기 쉬웠다.
- `color_cap` 표를 설계 값(32px 까지 16 · 64 까지 32 · 그 위 48)으로 바꾸자 경고 8 이 바로 풀렸다.
