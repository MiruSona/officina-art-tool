# 타일 작업 피드백 (2026-09-20)

> 반영 (2026-09-21) : ①`setup.ps1` 로 `.venv` 가 한 줄에 선다 ③`check` 가 낱장을 받고 `--no-ramps` 로 팔레트 없이도 돈다 ④낱장 길을 README 에 1급으로 적었다. `tile inspect/seam/preview` 는 다음 판이다 (`진행상황.md`).

게임 저장소에서 32×32 바닥 타일 3장 + 울타리 조각 5장을 만든 판의 기록이다.
**이 툴은 한 번도 못 돌렸다** — 아래는 README 만 보고 견준 것과, 대신 무엇을 했는지다.

## 결론

- **`.venv` 가 없어 아무것도 못 돌렸다.** 판단은 README 로만 했다.
- **정작 필요했던 것은 이 툴에 없었다.** 「낱장 타일 이음매 검사 · 여러 장 조립 미리보기 ·
  낱장 bbox/알파 검사」를 **매번 새 스크립트로 직접 짰다.** 이것이 명령으로 있었으면 바로 썼다.
- 있는 명령들은 이번 일에는 **너무 크거나(47장 전환 셋) · 앞 조건이 안 갖춰졌거나(팔레트) ·
  게임 쪽과 역할이 겹쳤다.**

## 잘 된 것

| --- | --- |
| README 만으로 명령별 쓸모를 견줄 수 있었다 | 못 돌려도 「이번 판에 쓸지」를 표로 판단할 수 있었다 |

## 막힌 것

| # | 무엇 | 어떻게 됐나 | 바라는 것 |
| --- | --- | --- | --- |
| 1 | **`.venv` 가 없다** | 한 명령도 못 돌렸다. 시험을 통과시키는 것이 먼저라 이번 판에서 통째로 뺐다 | 설치 한 줄(`install` 또는 `bootstrap`)로 venv 까지 서게 한다 |
| 2 | **타일 「변종 2~3장 섞기」에 쓸 명령이 없다** | 이번 일은 같은 바닥의 변종 3장이었는데, 있는 것은 47장 전환 셋 전용이라 과했다 | 「같은 바탕의 변종 N 장」을 다루는 가벼운 갈래를 둔다 |
| 3 | `check` 가 팔레트 파일이 있어야 값이 난다 | 팔레트가 아직 미정이라 검수에서 얻을 것이 거의 없었다 | 팔레트 없이도 되는 검사(색 수 · 반투명 · bbox)만 따로 돌 수 있게 한다 |
| 4 | `bake` 가 게임 쪽 자동 임포터와 역할이 겹친다 | 게임 저장소는 낱장 + 임포터로 이미 자동이라 아틀라스를 만들 값이 없었다 | 낱장 그대로 쓰는 파이프라인을 1급으로 인정하고 문서에 적는다 |
| 5 | **정작 쓴 것은 직접 짠 스크립트다** | 값잡음 얼룩 · 풀 뭉치 · 좌표 32 감싸기 · bbox/알파 검사 · 12×13 조립 미리보기 · 3×3 이음매 확인을 **판마다 새로 짰다** | 아래 셋을 명령으로 둔다 |

## 있었으면 바로 썼을 명령 셋

| 이름(가칭) | 무엇 |
| --- | --- |
| `tile seam <png…>` | 낱장을 3×3 으로 붙여 **상하좌우 이음매**가 보이는지 검사한다. 어긋난 줄의 좌표를 찍는다 |
| `tile preview <배치표>` | 여러 장을 실제 칸 수(예: 12×13)로 **조립해 미리보기 PNG** 를 낸다. 반복 티를 눈으로 본다 |
| `tile inspect <png…>` | 낱장의 **bbox · 알파 · 캔버스 밖으로 새는 픽셀**을 한 표로 낸다. 팔레트가 없어도 된다 |
