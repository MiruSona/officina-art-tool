# 가게 갈래 피드백 (2026-10-05)

게임 저장소의 그림 화풍 통일 B 갈래(손님 · 주인 선 색, 계산대 · 꽃병, 진열장, UI 틀)에서 이 툴을 쓰며 느낀 것이다.
쓴 명령 : `reline` · `check --profile` · `layers check`.

## 막힌 것

| # | 명령 | 무엇이 | 바라는 것 |
| --- | --- | --- | --- |
| 1 | `reline --scope ring` | 고리(4방향 이웃이 투명)만 바꿔서, **2px 두께 선이나 꺾인 자리의 안쪽 칸**이 옛 검정으로 남는다. 손님 머리통 한 장에서 고리 229칸 + 안쪽 56칸이었다 | `--depth N` (투명에서 N칸 안, 고른 칸과 붙은 같은 색까지). `--scope colors` 는 눈동자까지 바꿔서 못 썼다 |
| 2 | `reline --color` | 색이 하나뿐이다. 남색 바지 · 검은 머리 옆에서는 `#352E27` 선이 면과 밝기가 같아져 선이 사라진다 | 「옆 면이 어두우면 이 색」 둘째 색(`--color-dark`)이나 램프에서 고르기 |
| 3 | `reline --pick dark --tol` | 밝기 폭으로만 고른다. 꽃병은 붉은 검정(화분 · 꽃 선)과 짙은 풀색(잎 선)이 같은 밝기라 잎 선까지 먹는다 | 바꿀 색을 직접 주는 `--from #hex,#hex` |
| 4 | `reline` 폴더 입력 | 장마다 `--tol` 이 달라야 했다 (몸은 26, 나머지 14). 폴더로 한 번에 못 돌려 한 장씩 불렀다 | 그대로 둬도 된다 — 적어만 둔다 |
| 5 | `check` 의 `outline` | 프로필이 `selout` 일 때 **갈색 한 색 선**을 「solid」 로 읽어 경고한다. 설계는 「selout + 바깥 선은 line 램프 한 색」 이라 늘 걸린다 | `style.outline` 에 「selout 인데 바깥 고리는 정한 색」 값, 또는 `palette.outline` 이 있으면 solid 도 받기 |

## 헷갈린 것

- `reline` 보고의 `changed` 가 고리 칸 수인지 그림 전체 칸 수인지 `--scope` 에 따라 다르다. 보고에 `scope` 가 있지만 장마다 「고리 n · 안쪽 m」 으로 나눠 주면 읽기 쉽다.
- PIL 의 `getcolors()` 로 색을 세면 투명 칸의 RGB 까지 세어 `check` 의 색 수와 다르게 나온다 (56 대 57 · 34 대 40). 툴 탓은 아니고, 명령 안내에 「색 수는 불투명 칸만 센다」 한 줄이 있으면 좋겠다.

## 잘 된 것

- `reline` 이 원본을 안 덮고 `--out` 으로만 쓰는 것, 보고에 `merged_colors` 가 찍혀 무엇을 합쳤는지 바로 보이는 것. `reline.many_colors` 경고 덕에 몸 그림에서 음영까지 먹는 것을 알아챘다.
- `check` 를 고치기 전 · 뒤로 돌려 `max_colors` 실패 → 통과, `near_colors` 사라짐을 숫자로 봤다.
- `layers check` 가 겹을 다시 쌓아 봐 줘서 귀 · 볼 손수정 뒤에도 겹이 안 깨졌는지 한 번에 확인했다.

## 없어서 PIL 로 한 것

| 일 | 한 길 |
| --- | --- |
| 비슷한 색 합치기 (말풍선 56 → 24색) | 가장 가까운 두 색을 되풀이해 합침. `style extract` 의 `merge_table` 은 램프를 뽑을 때만 나와 한 장 손질에는 못 썼다 → `recolor --merge-near N` 같은 명령이 있으면 좋겠다 |
| 틀에 갇힌 투명 칸 채우기 (진열장 유리) | 가장자리에서 번져 못 닿는 투명 칸을 찾음 → `cutout` 의 거꾸로 (`fill --enclosed #hex`) |
| 화면 캡처 위에 고친 그림 덧대 보기 | 스프라이트 자리를 캡처에서 찾아 바뀐 칸만 바꿈 → 비교판 종류로 있으면 사용자 확인이 빨라진다 |
