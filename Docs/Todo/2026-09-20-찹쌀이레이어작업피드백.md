# 찹쌀이 레이어·점프 애니 작업 피드백 (2026-09-20)

> 반영 (2026-09-21) : `setup.ps1` 과 README 「파이썬 3.11 이상」 줄을 넣었다. `canvas.frame 48` 은 ArtTool 프로필이 이미 64 라 고칠 것이 없다. 겹 나누기·squash 프레임은 다음 판이다 (`진행상황.md`).

게임 저장소(ProjectMozzi2)에서 주인공 「찹쌀이」 그림을 레이어로 나누고 점프 애니를 붙였다.
**이 작업은 ArtTool 을 거치지 않았다** — PixelLab MCP 로 뽑고 PowerShell `System.Drawing` 으로 픽셀을 직접 고쳤다. 그 기록이다.

## 결론

- **ArtTool 이 맡을 만한 일을 손으로 했다.** 「레이어 나누기」와 「한 장에서 squash/stretch 프레임 뽑기」 둘이다.
- 게임 쪽 캔버스 규격이 **48 → 64 로 바뀌었다.** 프로필 초안 값(`canvas.frame [48, 48]`)이 낡았다.

## 어긋난 것

| 무엇 | 자세히 | 제안 |
| --- | --- | --- |
| 캔버스 규격이 48 → 64 로 바뀌었다 | 게임 쪽 아트 규칙(`Docs/Design/06-아트규칙.md` 표)의 프로필 초안은 `canvas.frame [48, 48]` 인데, 실제 찹쌀이는 몸 64 · 볼터치 11 · 표정 64 · 악세사리 64 로 그렸다 (mem `20260920-ca7f4400` · `20260920-11bd2a72`) | 이 게임용 프로필을 만들 때 64 로 잡는다. `canvas.baseline_y` · `center_x` 도 64 프레임에서 다시 잰다. `slime_demo.yaml` 을 본보기로 쓰려면 48 전제가 남아 있는지 본다 |

## ArtTool 이 맡을 만한 일 (이번에 손으로 한 것)

| 무엇 | 이번에 어떻게 했나 | 제안 |
| --- | --- | --- |
| 레이어 나누기 | 한 장으로 나온 그림을 **몸 · 볼터치 · 표정 · 악세사리** 네 겹으로 손으로 잘라 냈다. 표정은 10종 | 「한 장 → 겹」 나누기와 겹마다 앵커 뽑기를 명령으로 만든다. 프리팹 앵커에 끼우는 것이 목적이라 앵커가 핵심이다 |
| 점프 프레임 뽑기 | 한 장에서 **납작·길쭉(squash/stretch) 프레임 4장**을 손으로 만들었다. 포물선 이동은 코드가, 재생은 Unity Animator 가 한다 (mem `20260920-65f02b0c`) | 「한 장 + 세기 → squash/stretch 프레임 N장」을 명령으로 만든다. 값만 바꿔 다시 뽑을 수 있어야 한다 |

## 환경에서 걸린 것

- 이 PC 에 **Pillow · ImageMagick 이 없다.** 그래서 PowerShell 5.1 + `System.Drawing` 으로 픽셀을 직접 만졌다.
- **PS 5.1 은 BOM 없는 UTF-8 한글 스크립트를 깨뜨린다.** 픽셀 스크립트를 쓸 때 BOM 을 붙이거나 한글을 안 넣어야 했다.
- ArtTool 이 Python(Pillow) 전제라면, 파이썬이 없는 기계에서 무엇이 되고 무엇이 안 되는지 README 에 한 줄 있으면 좋겠다.
