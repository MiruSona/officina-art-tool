# 반복 06 그림 갈래 피드백 (2026-10-05)

게임 저장소의 반복 06 그림 갈래(계산대 넓히기 · 합성 창 가림 원)에서 이 툴을 쓰며 느낀 것이다.
그림은 PIL 스크립트로 만들고 이 툴 `check` 로 검사했다.

## 잘 된 것

- 계산대를 **판자 무늬를 이어 붙여** 585×122 로 넓힌 그림과, 합성 창 **가림용 흰 원** 60×60 을 PIL 로 만들었고 검사가 통과했다. 새로 칠한 것이 없어(있는 칸을 잇기 · 단색 원) 화풍 프로필에 그대로 맞았다.

## 막힌 것

| # | 무엇이 | 본 것 | 바라는 것 |
| --- | --- | --- | --- |
| 1 | 그림 안 부품의 자리를 재는 길이 없다 | 지시서에 적힌 합성 기계 창 자리(56×56 · 중심 (97, 117))가 실제 그림(60×60 · 중심 (95, 116) · 반지름 30)과 달랐다. PIL 로 직접 재서 고쳤다 | **그림에서 원 · 네모 자리를 재 주는 명령.** 예 : `measure shape <그림> --at x,y` 가 그 칸이 든 같은 색 덩어리의 둘레 네모 · 중심 · (원이면) 반지름을 준다. 가림 그림 · 코드 좌표를 만들 때 지시서 숫자를 믿지 않고 바로 잴 수 있다 |

## 없어서 PIL 로 한 것

| 일 | 한 길 |
| --- | --- |
| 무늬를 이어 캔버스 넓히기 (계산대) | 되풀이되는 판자 구간을 잘라 오른쪽으로 이어 붙임 → `extend --tile x0:x1 --to-width N` 같은 명령이 있으면 스크립트가 필요 없다 |
| 창 모양 가림 그림 만들기 | 잰 중심 · 반지름으로 흰 원을 그림 → 위 `measure shape` 결과를 받아 가림 그림을 뽑는 `mask --from-shape` 가 있으면 한 줄이다 |

## 덧붙임 — 창 속 반죽 소용돌이 애니 (같은 날)

PixelLab 으로 두 색 반죽이 도는 프레임 애니를 뽑고, PIL 로 겹 셋(a · b · top)으로 갈랐다.

### 잘 된 것

- **`animate_image_pixminimax` 가 「한 바퀴 돌기」를 제대로 그렸다.** 16프레임에 시계 방향 360°, 끝 그림이 첫 그림 자세로 돌아와 한 장 걸러 8장을 고리로 썼다. 값 2회.
- 뽑을 때 두 덩이를 **분홍 · 민트**로 시켰더니 `r > g` 한 줄로 겹이 갈렸다.
- `sheet --kinds zoom --scale 6 --label` 로 밑그림 셋을 한 판에서 골랐다.

### 막힌 것

| # | 무엇이 | 본 것 | 바라는 것 |
| --- | --- | --- | --- |
| 1 | `animate_image` 는 회전을 못 한다 | 열어 둔 8프레임은 4분의 1 바퀴 뒤 뭉쳤고, 끝 그림을 첫 그림으로 묶은 16프레임은 반쯤 돌다 색이 뒤바뀌며 되돌아왔다 | `뽑기-pixellab.md` 에 「도는 움직임은 `animate_image_pixminimax`」 한 줄 |
| 2 | pixminimax 는 색을 바꾼다 | 첫 두 장만 원래 옅은 색, 셋째 장부터 진한 분홍 · 초록. 빈틈에 회색 `#80807F` 을 채우는 프레임도 있다 | 같은 문서에 「첫 1~2장은 버리고 색은 다시 입힌다 · 빈틈 회색은 키로 지운다」 |
| 3 | 색 곱하기용 회색 겹을 볼 프로필이 없다 | `<게임>_fx`(흰 1색)로는 실패, `<게임>_prop` 로 봤다 | 툴 일은 아니고 게임 쪽 프로필 일이다 — 여기엔 적기만 한다 |

### 없어서 PIL 로 한 것

| 일 | 바라는 명령 |
| --- | --- |
| 프레임 폴더를 색(색조)으로 겹 나누고 밝기를 회색 N 단계로 | `split` 에 「색조 범위 → 겹」 규칙과 `--gray-levels 255,220,180` |
| 프레임 낱장 → 가로 시트 · 색 입힌 GIF | `sheet --strip` · `tint … --gif --duration 110` |
| PixelLab 애니 프레임 한꺼번에 내려받기 | `fetch --job <id> --out raw/<이름>` |

## 덧붙임 2 — 소용돌이 꽉 채우기 (같은 날)

사용자가 「꽉 채우면 좋겠다」고 해서 빈틈을 없앴다. 다시 뽑은 판과 빈틈을 기계적으로 채운 판 둘을 만들었다.

### 잘 된 것

- **꽉 찬 밑그림을 주면 pixminimax 가 16프레임 내내 꽉 찬 채로 돌렸다.** 빈틈 있는 밑그림을 주면 빈틈이 프레임마다 따라온다 — 밑그림이 정한다.
- 화풍 그림(`style_image`)으로 빈틈 있는 앞 그림을 주고 「빈틈 없이」라 적으면 빈틈이 그대로 온다. 화풍 그림을 빼고 「solid filled disc touching all four canvas edges」로 적으니 꽉 찼다.

### 없어서 PIL 로 한 것

| 일 | 바라는 명령 |
| --- | --- |
| 가림 원 안의 빈 칸을 가까운 겹에 한 색으로 붙이기 | `layers fill --in set --mask m.png --nearest a,b --color #B4B4B4` |
| 겹 묶음의 「빈 칸 0 · 겹침 0」 세기 | `layers check` 에 `--cover mask.png` (가림 원 안이 다 덮였나) |
