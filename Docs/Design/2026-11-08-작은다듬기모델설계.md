## 0. 결론

> **2026-11-09 접음** — 이웃 표가 골드 짝에서 Δ > 2σ 를 못 넘었고(LOO +.021 ± .110), 재료를 수십 장 더 그려도 얻는 것은 「렌더러 출력에 하이라이트 점 몇 개」 수준이다.
> 그건 렌더러 `finish` 손 규칙이 더 싸고 예측 가능하다. 판정 셋 · 납작화 · `shape flatten/polish` 명령 · 시험 58개는 남겨 재료가 쌓이면 그대로 다시 돌린다. 실측과 까닭은 10절.

- **만드는 것** : 렌더러가 그린 납작한 PNG 를 받아 **칸마다 팔레트 색 하나를 다시 고르는** 작은 모델. 명령 `arttool shape polish`. 모양(알파)은 안 바꾸고 색만 바꾼다.
- **엔진 둘** : `table`(5×5 이웃 표, numpy 만, 기준선) · `onnx`(3단 U-Net, 13만~52만 파라미터, 선택 extra `arttool[ml]`). 모델 파일 꼴 · 명령은 같다.
- **재료** : 사전학습 = 바깥 CC0 넷(DCSS 32×32 6천+ (2차) · Kenney · 0x72 DungeonTileset II · Ninja Adventure). 미세조정 = 우리 비PixelLab 그림 약 51 묶음. **PixelLab 생성 · 파생 그림은 학습 · 검증 · 평가 어디에도 안 쓴다.** CC-BY · CC-BY-SA 도 안 쓴다.
- **본선은 「PixelLab 없이 도형 렌더러 → 다듬기 모델」** 이다. PixelLab 은 켜는 사람만 쓰는 선택 제공자다 (사용자 결정 2026-11-08).
- **짝** : 우리 그림을 렌더러 뒷단 코드(칠 · 선 · 잠금 · 색 수)로 다시 칠해 납작하게 만든 것 → 원본.
- **자 먼저** : 그룹 분할 · 골드 셋 · 바닥값을 얼린 뒤에 학습한다.

| 단계 | 통과 기준 (봉인 시험, 씨앗 5) |
| --- | --- |
| 기준선(표) | 「바뀐 칸 맞힘」이 손 안 댐(입력을 팔레트에 붙이기만)보다 Δ > 2σ |
| U-Net | 같은 자로 표보다 Δ > 2σ · 「안 바뀐 칸 지킴」 ≥ .95 |
| 판별기 선별 | C2ST ≤ .6 · KID ≤ 진짜 대 진짜 바닥 × 2 (2차, 출발점) |
| 최종 | 섞어 놓기 판 56판에서 가짜를 맞힌 판 ≤ 16 |

- **접는 곳 넷** (8절) : 재료가 얇음 · 지름길을 못 막음 · 표가 신호를 못 잡음 · U-Net 이 표를 못 이김(→ 표만 낸다).
- 렌더러 · 기존 명령 결과는 안 바뀐다. `render()` 를 둘로 쪼개기만 하고, 칸까지 같음을 시험으로 지킨다.

## 1. 재료

**결론** : CC0 넷은 git 밖 `ArtTool/external.local/<묶음>/` 에 라이선스 원문과 함께 받는다. 우리 그림은 복사하지 않고 목록으로만 가리킨다. 중복은 해시 + union-find 로 그룹을 만들고, 그룹 단위로만 나눈다.

**까닭** : `*.local/` 은 이미 `.gitignore` 에 있어 규칙을 안 고쳐도 된다. ArtTool 은 공개 저장소라 재료 · 우리 그림이 들어가면 안 된다.

### 1-1. 받기

| 묶음 | 받는 곳 | 크기 | 둘 곳 | 같이 둘 것 |
| --- | --- | --- | --- | --- |
| DCSS 32×32 타일 | OpenGameArt 「Dungeon Crawl 32x32 tiles」 CC0 판 | 6,000장+ (2차) | `external.local/dcss/` | 페이지 라이선스 문구 저장본 |
| Kenney | kenney.nl 픽셀 팩 zip | 팩마다 수백 (2차) | `external.local/kenney/<팩>/` | 팩 안 `License.txt` 그대로 |
| 0x72 DungeonTileset II | itch.io 페이지 | 수백, 16px (2차) | `external.local/0x72/` | 페이지 문구 · 작가 댓글 저장본 |
| Ninja Adventure | itch.io 페이지 | 천 안팎, 16px (2차) | `external.local/ninja/` | 팩 안 라이선스 |

- 압축은 묶음마다 새 빈 폴더에 푼다. 받은 자료 안 스크립트는 안 돌린다.
- `external.local/sources.json` 한 장 : 묶음마다 `{name, url, license, license_file, fetched, sha256}`. **라이선스 원문을 읽고 CC0 를 확인한 묶음만** `"license": "CC0-1.0"`. 학습 스크립트는 이 값이 아닌 묶음을 안 읽는다.
- 1칸 = 1화소로 맞춘다 : 기존 `arttool normalize` 로 정수배 키운 그림을 줄이고, `style.extract.not_pixel_reasons()` 가 이유를 내면 뺀다.
- 우리 그림 : `ArtTool/train.local/ours.json` 에 `{path, group, kind, origin: "pil" | "hand" | "cc0"}`. 경로는 이 파일에만 적는다. 재료 세기(2026-11-08)의 C 갈래 중 **PIL 규칙 그림 · 손그림 41 + 외부 CC0 10**. CC-BY 류 · 근거 없음(D) · 다른 AI 그림은 넣지 않는다.

### 1-2. 중복 거르기

1. **메타 그룹** : 같은 폴더 + 이름 끝 숫자만 다름 → 한 그룹 (애니 프레임 · 변형).
2. **해시** : dHash · pHash 64비트, 해밍 ≤ 5 면 잇는다. 투명 칸은 중간 회색 바탕에 얹어 잰다. (재료 세기의 「다른 칸 5% 미만」 규칙은 투명 칸이 많은 작은 그림을 지나치게 묶었다.)
3. **union-find** 로 추이 묶기. 큰 그룹 상위와 경계 쌍(해밍 5~8) 30쌍을 눈으로 검수한다.
4. **CC0 ↔ 우리 그림 겹침**도 같은 셈으로 본다. 우리 외부 CC0 10장이 Kenney 에서 왔으면 같은 그룹이 된다 → 우리 쪽에 두고 사전학습에서 뺀다.

- 코드 : 재료 세기 때 쓴 해시 · 묶기 스크립트를 `ArtTool/train/polish/groups.py` 로 옮겨 쓴다. dHash · pHash 는 PIL + numpy 로 20줄 남짓. 출력 `train.local/groups.json`.

## 2. 판정 셋 얼리기

**결론** : 학습 전에 그룹 분할과 골드 셋 둘을 만들고 sha256 으로 얼린다. 판 사이에 안 바꾼다(학습판규칙 4-1).

**까닭** : 짝은 납작화로 만든 가짜 입력이다. 실제 렌더러 출력으로 재야 지름길을 잡는다(조사 결론 4 · 6).

| 셋 | 무엇 | 몇 | 쓰는 곳 |
| --- | --- | --- | --- |
| 학습 | 우리 그룹 70% → 납작화 짝 | 약 36 그룹 | 미세조정 |
| 검증 | 15% 그룹 | 약 7 그룹 | 멈춤 · 체크포인트 고르기 (골드 짝으로) |
| 봉인 시험 | 15% 그룹 | 약 8 그룹 | 판 결과 보고 끝에 한 번 |
| **골드 짝** | 검증 · 시험 그룹 그림을 렌더러 명세로 따라 그린 출력 ↔ 원본 | 15 그룹 × 보는 방향 | 장 단위 지표 (5절) |
| **골드 홀** (짝 없음) | 틀 · 부품 명세를 무작위 값으로 렌더 | 50~150 | 지름길 검사 · 판별기 · 섞어 놓기 판 |
| 판별기 전용 진짜 | 검증 + 시험 그룹 그림 (모델이 안 본 것) | 15 그룹 | KID · C2ST 진짜 쪽 |

- 분할은 종류(아이콘 · 건물 · 인물 · 외부 CC0)로 층을 나눠 씨앗 고정 → `train.local/split.json`.
- **골드 짝 만드는 법** : 기존 명세 꼴(틀 2-5 · 부품 2-6 · 질감 2-7 · 잠금 2-8 · 2-9)을 그대로 쓴다. 틀이 있는 아이콘 묶음은 preset 값만 적는다. `arttool shape render spec --out … --ref 원본 --report r.json` 으로 뽑고, 보고의 `silhouette_iou` ≥ .85 인 짝만 둔다(모양이 틀린 짝은 색 판정을 흐린다). 명세 · 출력은 `train.local/gold/` (우리 그림 색을 담아 git 밖).
- **골드 홀 만드는 법** : 렌더러 실측에 쓴 명세 · 틀 preset × 보는 방향 × 질감 seed 로 50~150 장. **학습 그룹을 따라 그린 명세는 넣지 않는다.**

| 바닥 | 재는 법 | 쓰는 곳 |
| --- | --- | --- |
| A/A (학습 잡음) | 같은 설정 씨앗 5 → 지표 σ. 짝 비교는 Δ > 2σ 일 때만 「나아짐」 | 5 · 8절 |
| 평가 잡음 | 골드 짝을 그룹 단위 bootstrap 1000번 → 95% 구간 | 모든 표 |
| 진짜 대 진짜 KID | 판별기 전용 진짜를 그룹 단위로 반씩 20번 나눠 KID → 평균 · 95% 위끝 = 바닥 | 6절 「바닥의 몇 배」 |
| 진짜 대 진짜 C2ST | 같은 반쪽끼리 C2ST → .5 ± .1 인지 (아니면 특징이 그룹을 외운다) | 6절 |

## 3. 납작화 짝

**결론** : 원본 그림에서 렌더러의 `Hits`(맞음 · 깊이 · 노멀 · 도형 번호)를 흉내 내 만들고, `render()` 의 **뒷단을 그대로** 돌린다. 「납작함」이 렌더러와 같은 코드에서 나온다.

**까닭** : 렌더러 출력이 납작한 것은 재질마다 램프 몇 단 · 노멀 빛 하나 · 한 색 선 · 잠금 때문이다(보완 고리 문서). 입력도 같은 단계를 거쳐야 실제 렌더러 출력에 일반화된다.

| 단계 | 함수 | 새 / 재사용 |
| --- | --- | --- |
| `render()` 쪼개기 | `render.render(spec, view)` = `trace()` + 새 `render.finish(spec, hits, yaw, view)` | 함수 몸 옮기기만 |
| 재질 덩어리 뽑기 (부품 추출) | 새 `flatten.regions(arr)` : 바깥 테(`draw.outline.edge`) 떼기 → `lock.to_lab` 으로 색 → 색조 · 밝기로 무리 → 4연결 덩어리 | 새 (numpy) |
| 램프 | 덩어리 색을 L 차례로 2~4 단 (`image.quantize_luma` 의 「칸 수 순위」 셈) | 셈 방식 재사용 |
| 가짜 Hits | `hit` = 알파 · `owner` = 덩어리 번호 · `normal` = 덩어리 안 거리장(테 → 안쪽) 기울기 · `depth` = 덩어리 차례 · `point` = (x, y, depth) | 새 (`Hits` 꼴 그대로) |
| 가짜 Spec | 덩어리마다 `spec.Material` + 재질 이름만 쓰는 가짜 `sdf.Prim` | 꼴 재사용 |
| 칠 · 선 · 잠금 · 색 수 | `finish()` 안 : `shade_pixels` → `pattern.apply` → `texture.apply` → `inner_lines` → `draw_outline` → `material_lines` → `lock.apply` → `cap_colors` | **그대로** |

```python
def finish(spec: Spec, hits: Hits, yaw: float, view: str) -> tuple[np.ndarray, dict]   # render.py
def regions(arr: np.ndarray) -> tuple[np.ndarray, list[list[RGB]]]                       # flatten.py
def flatten(arr: np.ndarray, seed: int, light: str = "top_left") -> tuple[np.ndarray, dict]
```

- `shade_pixels` 는 `spec.prims` 를 「도형 번호 → 재질」 표로만 쓴다. 단 `bands` 는 `trace()` 를 다시 부르므로 **납작화에서는 bands 를 끈다.**
- `pattern.apply` 는 `hits.point` 를 쓴다 → 화면 좌표를 넣는다. `texture.apply` 가 가짜 Hits 에서 도는지는 P3 의 첫 확인이다. 안 되면 납작화에서 질감을 끈다.

| 섞는 손잡이 | 범위 | 렌더러 칸 |
| --- | --- | --- |
| 램프 단 | 2 ~ 4 | `ramp` |
| ambient | .3 ~ .9 | `ambient` |
| 디더 | 0 · .25 · .5 | `dither` |
| 바깥 외곽선 | solid · selout · selout+light · none | `outline.mode` |
| 안쪽 선 | 끔 · gap 1 ~ 3 | `inner_gap` |
| rim · highlight | 각 50% | `rim` · `highlight` |
| 질감 | 없음 60% · 1~2 규칙 (strength .25 ~ .5) | `texture` |
| 잠금 | 모델 팔레트 family 잠금 50% | `palette_lock` |
| 색 수 상한 | 8 ~ 16 | `max_colors` |
| 노멀 잡음 | 높이장 흐림 0 ~ 2칸 | — |

- 씨앗 하나가 손잡이를 다 정한다 → 짝이 재현된다. 그림 한 장마다 씨앗 8개.

**지름길 검사 (학습 전 관문, P4)**

| 칸 | 값 |
| --- | --- |
| 두 쪽 | 납작화(검증 그룹 그림, 씨앗 여럿) vs 골드 홀(실제 렌더러 출력) |
| 특징 | 1000칸당 색 수 · 재질별 램프 단 수 · 외곽선 색 수 · 맨 많은 선 색 몫 · 3×3 조각 고유 수 · 불투명 몫 · 크기 |
| 분류기 | 로지스틱 회귀, 그룹 단위 5겹 교차 |
| 통과 | AUC ≤ .65 |
| 넘으면 | 무게가 큰 특징을 보고 섞기 범위를 고친다. 3번까지. 그래도 넘으면 접는다 (8절) |

## 4. 기준선 — 이웃 표

**결론** : 칸마다 5×5 이웃을 64비트 열쇠로 접어 「열쇠 → 팔레트 색 번호 세기」 표를 만든다. 추론 = 열쇠 셈 + 표 찾기. numpy 만 쓰고 `arttool[ml]` 없이 돈다.

**까닭** : 하루 안에 만들고 무엇을 배웠는지 보인다. U-Net 이 이걸 못 이기면 U-Net 은 필요 없다(조사 결론 5).

| 특징 (칸 하나) | 값 | 비트 |
| --- | --- | --- |
| 가운데 색 → 모델 팔레트 번호 (`palette.snap_nearest`) | 0 ~ K−1 | 6 |
| 5×5 각 칸이 가운데와 같은 덩어리인가 (`flatten.regions`) | 24칸 × 0/1 | 24 |
| 덩어리 안 밝기 순위 | 4단 | 2 |
| 테까지 거리 | 0 · 1 · 2 · 3+ | 2 |
| 가장 가까운 테가 빛 쪽인가 | 0 / 1 | 1 |

- **물러나기 사다리** : 전체 열쇠 → 24칸 모양을 3×3 로 줄인 열쇠 → (색, 순위, 거리) → 입력 색 그대로. 칸마다 몇 번째 사다리에서 답했는지 보고에 싣는다.
- **표 크기** : 열쇠 50만 개 상한(적게 본 것부터 지움), `.npz` 수 MB (짐작).
- **시간 목표** (짐작) : 64px < 20ms · 256px < 300ms.
- 학습 : `train/polish/table.py`, numpy 만. kNN · 결정트리(sklearn)는 학습 PC 에서 견줌만, 보고만.

## 5. 작은 U-Net

**결론** : RGBA 입력 → 팔레트 K 로짓. 불투명 칸 CE 손실. 사전학습(CC0) → 미세조정(우리 그림), 씨앗 5. ONNX(opset 17, IR ≤ 13)로 내보낸다.

| 칸 | 꼴 |
| --- | --- |
| 입력 | `(N, 4, H, W)` float, RGBA / 255. H · W 는 4의 배수 (명령이 투명 칸으로 채움) |
| 출력 | `(N, K, H, W)` 로짓. K = 모델 팔레트 색 수 (≤ 64) |
| 후처리 | 불투명 칸만 argmax → 팔레트 색. 알파는 입력 그대로 |
| 구조 | 3단(내림 둘). 단마다 3×3 conv ×2 + GroupNorm + SiLU. 내림 stride 2 conv, 올림 nearest ×2 + conv, 건너뛰기 이음 |
| 크기 | S : 16-32-64 (약 13만) · L : 32-64-128 (약 52만). S 먼저 |
| 손실 | 불투명 칸 CE. **「바뀐 칸」(목표 ≠ 입력 붙인 색) 무게 2** — 안 그러면 베끼기가 이긴다 |

| 학습 설정 | 사전학습 (CC0) | 미세조정 (우리) |
| --- | --- | --- |
| 조각 | 32 ~ 48px | 32 ~ 48px |
| 배치 | 64 | 32 |
| 걸음 | 20k | 3k, 검증 골드 짝 손실로 일찍 멈춤 (인내 500) |
| 학습률 | AdamW 1e-3, cosine | 3e-4 |
| 씨앗 | 0 ~ 4 | 0 ~ 4 (사전학습 씨앗과 짝) |
| 견줌 판 | — | 「사전학습 없음」 판도 씨앗 5 (사전학습이 도움 되나) |

- 사전학습 목표는 CC0 그림을 팔레트 P 에 붙인 것이다(`lock.apply` family). 색은 흐트러지지만 칠 · 선 구조를 배우는 몫이다.

**멈춤 규칙** (학습판규칙에서 빌림)

| # | 규칙 | 원본 |
| --- | --- | --- |
| 1 | 판을 열기 전 이번 판 목표 · 가설을 판 문서 0절에 한 줄 | 1-1 |
| 2 | 앞 판 가설마다 학습 없는 확인 하나 먼저 (예측 혼동표 : 팔레트 색 × 종류) | 1-2 |
| 3 | 같은 종류 × 지표가 **두 판 연속** 깨지면 다음 판을 안 띄우고 진단 → 사람 | 1-3 |
| 4 | 학습 전 점검표 : 그룹 겹침 0 · 종류별 조각 수 · 팔레트 색별 목표 칸 수(0 이면 경고) · 지름길 AUC | 2절 |
| 5 | 깨짐은 「진짜 무너짐」과 「문턱 근처」로 나눠 적는다 | 3-1 |
| 6 | 대체 판을 미리 정하지 않는다 | 3-2 |
| 7 | 자(골드 셋 · 지표 · 문턱)는 판 사이에 고정 | 4-1 |
| 8 | 한 쪽이라도 씨앗 5 가 없으면 비교하지 않는다 | 4-3 |

| 지표 (골드 짝) | 뜻 | 자리 |
| --- | --- | --- |
| 바뀐 칸 맞힘 | 목표가 입력과 다른 칸 중 맞힌 몫 | **주** |
| 안 바뀐 칸 지킴 | 목표 = 입력인 칸 중 그대로 둔 몫 | 지킴 (≥ .95) |
| near_shifted | `score.similarity()` | 보조 |
| 화풍 이탈률 | 출력 3×3 조각 중 학습 그룹에 없던 몫 (WFC C1 꼴) | 보조 |
| lint | `draw.lint.lint()` counts | 보고만 |

```python
torch.onnx.export(model, dummy, path, opset_version=17, input_names=["rgba"], output_names=["logits"],
                  dynamic_axes={"rgba": {2: "h", 3: "w"}, "logits": {2: "h", 3: "w"}})
m = onnx.load(path); m.ir_version = min(m.ir_version, 13); onnx.checker.check_model(m); onnx.save(m, path)
```

- 내보낸 뒤 골드 홀 전체에서 torch 와 onnxruntime 의 argmax 가 다른 칸 0 인지 확인한다.

## 6. 판별기

**결론** : 판별기는 **사람 판에 올릴 후보 고르기**용이다. 학습(손실 · 체크포인트 고르기)에는 절대 안 쓴다. 학습 PC 에서만 돈다.

| 특징 | CPU 부담 | 쓰는 곳 |
| --- | --- | --- |
| DINOv2 ViT-S/14 | 224px 한 장 .1 ~ .3초 (짐작) → 300장 1 ~ 2분 | KID · C2ST |
| CLIP ViT-B/32 | 비슷 (짐작) | CMMD |
| 손 특징 (3절 지름길 특징 + `style.extract.measure_one`) | 즉시 | 지름길 기준선 · **무거우면 대안** |

- 그림은 같은 nearest 정수배로 224 근처까지 키우고 같은 회색 바탕에 얹는다. 한 번 재는 데 10분을 넘으면 손 특징만 쓴다.
- 진짜가 15 그룹뿐이라 **48px 조각 단위로 늘리고 그룹 단위로 나눈다.**

| 지표 | 견줌 | 문턱 (2차, 판 사이 고정) |
| --- | --- | --- |
| 지름길 기준선 | 손 특징만으로 C2ST | .5 ± .1. **아니면 정규화부터 고치고, 그 전 C2ST 는 안 읽는다** |
| KID | 다듬은 골드 홀 vs 판별기 전용 진짜 | ≤ 바닥 × 2 |
| C2ST | 얼린 특징 + 로지스틱, 그룹 5겹 | ≤ .6 |
| CMMD | 같음 | 보고만 |
| 최근접 진짜 3장 | 베끼기 점검, 눈으로 | 보고만 |

**섞어 놓기 판 (최종, 사람)**

| 칸 | 값 |
| --- | --- |
| 판 꼴 | 라인업 : 진짜 4 + 가짜(다듬은 렌더러 출력) 1, 자리 무작위 |
| 판 수 · 「티 난다」 | 56판 · 가짜를 맞힌 판 ≥ 17 (우연 20%, 35% 를 잡는 힘) (2차) |
| 대조판 · 함정판 | 진짜만 든 판 20% (「없음」 칸) · 눈에 띄게 틀린 가짜 5% (2차) |
| 판정자 | 5 ~ 8명. 원 일치율 + Fleiss κ + Gwet AC1. κ < .4 면 취향 문제로 따로 적음 |
| 진짜 칸 | 검증 + 시험 그룹 그림만. 같은 진짜는 판 전체에서 4번까지 |
| 정규화 | 1칸 = 1화소 → 같은 배율 nearest · 같은 바탕 · PNG |
| 「티 안 난다」 증명 | 원하면 2AFC 약 400판, 95% 구간 위끝 < 60% (2차) |

- 판 만들기 `train/polish/lineup.py` → HTML 한 장 + 정답 JSON(따로 둔다). 판 순서 · 자리 씨앗 고정.

## 7. ArtTool 통합

**결론** : 새 명령 둘. 모델 파일은 git 밖. onnxruntime 은 `arttool[ml]` 로만. 안 부르면 아무것도 안 바뀐다.

```
arttool shape polish <in.png> --out <png> --model <model.json> [--ref 원본.png] [--report r.json]
arttool shape flatten <in.png> --out <png> --seed N [--report r.json]
```

- `polish` : 모델 JSON 의 `engine` 으로 표 · onnx 를 고른다. 알파 그대로, 불투명 칸만 팔레트 색. 보고 = 바뀐 칸 수 · 색 수 · ms · lint · (`--ref` 면 `score.similarity`). `render` 보고와 같은 꼴.
- `flatten` : 짝 만들기를 재현 · 시험하는 명령. 학습 스크립트도 같은 함수를 부른다.
- 출력 경로는 `paths.jailed_output` · `guard_overwrite` (render 와 같음).

```json
{ "version": 1, "kind": "shape_polish", "engine": "onnx",
  "file": "polish-s-seed0.onnx", "sha256": "…", "palette": ["#RRGGBB", "…"], "pad": 4, "input": "rgba",
  "train": { "seed": 0, "split_sha256": "…", "commit": "…" } }
```

- 둘 곳 `ArtTool/models.local/polish/`. sha256 이 다르면 한 줄 `ArtToolError`.
- 팔레트가 모델에 박힌다 → **모델 하나 = 팔레트 하나.** 종류별 팔레트는 종류별 모델(나중).

```toml
[project.optional-dependencies]
ml = ["onnxruntime>=1.20"]   # 하한은 IR 13 을 읽는 가장 낮은 판을 확인한 뒤 고친다
```

- onnxruntime 은 `polish` 안에서 늦게 import. 없으면 「onnx 엔진은 `pip install arttool[ml]` 가 필요하다」.
- 학습 코드 `ArtTool/train/polish/` : 패키지 밖, torch · sklearn · onnx 는 `train/polish/requirements.txt` 에만.

| 파일 | 무엇 |
| --- | --- |
| `src/arttool/shape/render.py` | `finish()` 떼어 내기 |
| `src/arttool/shape/flatten.py` (새) | `regions` · 가짜 Hits · `flatten` · `run(args)` |
| `src/arttool/shape/polish.py` (새) | 모델 읽기 · 표 / onnx 추론 · `run(args)` |
| `src/arttool/cli.py` | `_add_shape` 에 둘, 명령 표에 두 줄 |
| `train/polish/*.py` (새) | groups · split · pairs · table · unet · export · judge · lineup |

| 시험 | 확인 |
| --- | --- |
| `test_shape_render.py` + 렌더 해시 고정 | 쪼개기 전후 `Example/` · 시험 명세 렌더가 칸까지 같음 |
| `test_shape_flatten.py` (새) | 같은 seed 같은 결과 · 알파 그대로 · 색이 덩어리 램프 안 · 렌더러 출력을 넣으면 덩어리 수 ≈ 재질 수 |

- `arttool[ml]` 없이 기존 시험이 모두 통과해야 한다.

**CC0 표가 해로운 까닭** : CC0 묶음은 검은 외곽선 그림체다. 그 표를 우리 그림에 쓰면 검은 테를 두른다. 사전학습 재료는 그림체부터 맞춰야 한다.

**접은 까닭**

1. 재료를 수십 장 더 그려도 얻는 것은 「렌더러 출력에 하이라이트 점 몇 개」 수준이다.
2. 그 정도는 렌더러 `finish` 의 손 규칙이 더 싸고 결과를 미리 안다.
