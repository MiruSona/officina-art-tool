# inpaint 흰 칸 되돌리기 설계 (2026-10-12)

**권고 : 제공자 안(`_finish_inpaint`)에서, 색 맞추기(snap) 앞에, 「마스크 안 ∧ 원본이 투명(alpha 0) ∧ 올림 바탕색(흰색)과 가까움 ∧ 바깥 투명과 4방향으로 이어짐」 칸만 원본(투명)으로 되돌린다. spec 칸 `clear_background`(기본 켬) · `clear_tol`(기본 16) 둘을 더한다. `cutout` 사슬(①)은 쓰지 않는다.**

실측 그림 두 장(H6 시드 1000 · 1001)에 이 규칙을 그대로 흉내 내 보니, 흰 칸 25 · 116 칸이 투명으로 돌아오고 모델이 그린 쇠판 · 쇠고리는 한 칸도 안 지워졌다(3-2). 같은 그림에 `cutout` 을 걸면 기본 `--key edge` 는 아무것도 못 지우고, snap source 결과에 색 키를 주면 **마스크 밖 원본 테두리 20칸까지 지운다**(3-1).

## 1. 문제와 원인

10-12 에 `providers/local.py` `_upload` 가 원본의 투명 칸을 흰 바탕(`local_plan.UPLOAD_BACKGROUND`)에 섞어 불투명으로 올리게 바꿨다. ComfyUI `LoadImage` 가 알파를 버려 투명 칸이 검정으로 들어가던 검은 테(H6)는 이걸로 없어졌다. 대신 모델은 그 자리를 「흰 바탕」으로 보고 그대로 흰색으로 돌려준다. 마스크 밖은 `composite_outside` 가 원본으로 덮어 투명이 남지만, **마스크 안의 원래 투명 칸은 흰 불투명 칸으로 남는다.** snap none 이면 흰색(시드 1001 : 128칸 중 116칸), snap source 면 원본에서 가장 밝은 색(통 그림은 `#E6E6E6` 테두리 색)으로 눌려 밝은 회색 네모가 된다. 제공자가 넣은 흰색을 제공자가 치우지 않아 생긴 일이다.

## 2. 선택지 견줌

| 선택지 | 어디서 · 무엇을 | 부작용 | 1차 설계 원칙과 맞나 |
| --- | --- | --- | --- |
| ① `cutout` 사슬 | inpaint 뒤 사람이 `cutout --key …` 를 돌린다 | **마스크를 모른다.** `--key edge` 는 캔버스 바깥이 투명이라 씨앗을 못 잡아 0칸. `--key #FFFFFF` 는 그림 전체에서 흰 칸을 지워 원본의 흰 하이라이트도 지운다. **기본값 snap source 에선 흰색이 이미 원본 색(`#E6E6E6`)으로 눌려** 키를 그 색으로 줘야 하고, 그러면 마스크 밖 원본 테두리 20칸이 같이 지워진다 → inpaint 계약 「밖 0」이 깨진다. 「원본이 투명이던 칸」도 모른다 — 원래 불투명이던 칸에 그린 흰색도 지운다 | 글자로는 맞다(「바탕 지우기는 명령 사슬」). 하지만 그 원칙은 **모델이 낸 바탕**을 두고 한 말이다. 이번 흰색은 제공자가 올릴 때 넣은 것이다 |
| ② 제공자 안 되돌리기 | `_finish_inpaint` 에서 snap 앞에 「마스크 안 ∧ 원본 alpha 0 ∧ 바탕색과 `clear_tol` 안」 칸을 원본(투명)으로 | 모델이 **원래 투명 칸에 일부러 흰색(또는 아주 밝은 색)을 그리면** 지운다 — 예 : 새로 그린 쇠판 위 흰 반짝임, 흰 천. 덩어리 가장자리의 「흰색 + 그림」 섞인 칸(BOX 축소)은 `clear_tol` 밖이면 밝은 테로 남는다 | 맞다. 「BOX 축소 · inpaint 합성은 제공자」 쪽이다 — 올릴 때 깐 바탕을 돌려받을 때 걷는 것은 `composite_outside` 와 같은 「합성」의 짝이다. snap 앞에서만 흰색을 알아볼 수 있어 제공자 안이어야만 한다 |
| ③ ② + 이어짐 검사 (권고) | ② 에 더해 **바깥 투명(마스크 밖 원본 투명 칸 · 캔버스 가장자리)과 4방향으로 이어진** 흰 칸만 되돌린다. 이어지지 않은 흰 칸은 남기고 경고 | 그린 물건 **안에 갇힌** 흰 반짝임은 안 지운다. 대신 원본에 마스크로 완전히 둘러싸인 투명 구멍(예 : 고리 안쪽)이 흰색으로 채워지면 그대로 남는다 → 경고로 알린다 | ② 와 같다 |

### 「일부러 그린 칸」 위험

- **어두운 · 진한 색으로 그린 것**(쇠판 · 쇠고리 · 외곽선)은 흰색과 멀어 애초에 안 걸린다. 실측 시드 1000 의 쇠판은 흰색에서 RGB 차이 97 넘는 칸이 98칸이고, 하나도 안 지워졌다.
- **흰색 · 아주 밝은 색으로 그린 것**이 진짜 위험이다. 두 겹으로 막는다.
  1. 이어짐 검사(③) : 그린 덩어리 안에 들어 있는 흰 칸은 바깥 투명과 안 이어지니 남는다.
  2. 덩어리 바깥 둘레에 붙은 흰 칸(흰 테)은 막지 못한다 — 흰 바탕과 붙은 흰 그림은 칸만 봐서는 가를 길이 없다. 이건 바탕을 흰색으로 고정한 결정(mem `20261012-3517363f`)의 값이다. 흰 물건을 그려야 하면 spec `clear_background: false` 로 끄고 손으로 지운다.
- **원래 불투명이던 칸**은 아예 대상이 아니다. 원본 위에 덧그린 흰색은 그대로 snap 으로 간다.

## 3. 근거 (실측 그림으로 흉내)

10-12 H6 결과(`~/.arttool/measure/heavy/out-1012/`)에 규칙을 파이썬으로 걸어 봤다. 코드는 안 고쳤다.

### 3-1. ① `cutout` 를 걸면

| 그림 | 키 | 마스크 안 지운 칸 | 마스크 밖 지운 칸 |
| --- | --- | --- | --- |
| snap none · 1000 / 1001 | `edge` | 0 / 0 (씨앗 없음) | 0 / 0 |
| snap none · 1000 / 1001 | `#FFFFFF` | 25 / 116 | 0 / 0 |
| snap source · 1000 / 1001 | `edge` | 0 / 0 (씨앗 없음) | 0 / 0 |
| snap source · 1000 / 1001 | `#E6E6E6` | 25 / 117 | **20 / 20** (원본 테두리) |

### 3-2. ③ 를 걸면 (snap none 결과 = snap 앞 그림과 같음)

「마스크 안 ∧ 원본 투명」 128칸의 흰색과 거리(255 − 가장 작은 채널) :

| 시드 | 0~8 | 9~16 | 17~24 | 25~32 | 33~48 | 49~64 | 65~96 | 97 넘게 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1000 | 24 | 1 | 0 | 0 | 1 | 4 | 0 | 98 |
| 1001 | 116 | 0 | 0 | 1 | 0 | 3 | 2 | 6 |

- 흰 칸과 그린 칸 사이가 크게 비어 있다. `clear_tol` 16 · 24 · 32 · 48 어느 것이든 되돌린 칸이 25(1000) · 116~117(1001)로 거의 같다. 기본 16 이면 충분하다.
- 이어짐 검사로 빠진 칸(갇힌 흰 칸)은 두 시드 모두 0.
- 되돌린 뒤 snap source 를 남은 칸에만 걸면 쇠판 · 쇠고리는 그대로, 흰 네모만 사라진다(눈으로 확인, 비교판은 이 판 스크래치패드에만 있다).

## 4. 구현 설계

### 4-1. 바뀌는 자리

| 파일 · 함수 | 바뀌는 것 |
| --- | --- |
| `providers/postproc.py` 새 `clear_background(arr, source, area, background, tol) -> (out, cleared, enclosed)` | `was_clear = area & (source[...,3] == 0)` · `near = was_clear & (max(abs(rgb − background)) <= tol)` · 시작 = `(~area & source 투명)` ∪ 캔버스 바깥 한 바퀴 · 지날 수 있는 칸 = `near ∪ (~area & source 투명)` · 닿은 `near` 칸을 `source` 값으로 덮는다. `cleared` = 되돌린 칸 수, `enclosed` = `near` 인데 못 닿은 칸 수 |
| 번지기 | `edit/cutout.py` 의 `flood(start, passable)` 를 그대로 가져다 쓴다(`from ..edit.cutout import flood`). `edit` 쪽은 `providers` 를 안 불러 돌고 도는 import 가 없다. 같은 번지기 규칙을 두 벌 두지 않는다 |
| `local.py` `_finish_inpaint` | 차례를 **되돌리기 → snap(`area & ~cleared` 칸만) → `composite_outside` → 밖 세기** 로. snap 이 `area` 전체를 불투명으로 만들기 때문에 되돌린 칸은 snap 범위에서 빼야 한다. 반환에 `cleared` · `enclosed` 를 더한다 |
| `local.py` `_one_variant` · `_run` | `meta["cleared"]` = variant 별 되돌린 칸 수 목록. `enclosed` 가 0 이 아니면 경고 「`inpaint_000` : 바탕색인데 바깥 투명과 안 이어져 남긴 칸 N개 (원본 구멍이면 `cutout --key #RRGGBB` 로)」 |
| `local_config.py` | `OPTION_KEYS` 에 `clear_background`(bool, 기본 `true`) · `clear_tol`(정수 0~255, 기본 16). 꼴이 틀리면 종료 2. `LocalSettings` 에 두 칸 |
| `local_plan.py` | `Plan` 에 `clear_tol: int \| None`(끄면 None) — `_finish_inpaint` 가 plan 만 보고 정하게. 바탕색은 `UPLOAD_BACKGROUND` 를 그대로 쓴다(올린 색과 걷는 색이 늘 같다) |

- 반투명 원본 칸(0 < alpha < 255)은 대상이 아니다 — 흰색과 섞여 올라갔으니 돌려받은 색도 원본과 다르다. 도트 원본에는 드물어 1차는 뺀다.
- prop 에는 안 건다(올림 바탕이 없다).

### 4-2. dry-run `local_request.json`

inpaint 일 때만 한 칸 더한다. prop 이면 `null`.

```json
"clear_background": {"color": [255, 255, 255], "tol": 16}
```

끄면(`clear_background: false`) `null`. 기존 `upload_background` 는 그대로 둔다.

## 5. 공수 · 신뢰도

**공수 S** — 함수 하나(약 25줄) · 설정 두 칸 · 차례 바꾸기 · 시험 6 · 문서 두 곳. 실물 확인은 H6 두 시드를 다시 돌려 `meta.cleared` 가 25 · 116 근처인지만 본다(무거운 판 아님, 장당 50초).

| 항목 | 신뢰도 | 근거 |
| --- | --- | --- |
| ① 은 쓸 수 없다 | 95% | 실측 그림 4장에 실제 `cutout` 함수를 돌려 「edge 0칸 · 색 키면 밖 20칸」을 봤다 |
| ③ 가 흰 칸만 지우고 그린 쇠붙이는 남긴다 | 85% | 실측 2시드에 같은 규칙을 흉내 내 수와 그림으로 봤다. 마스크 하나(`mask_edge`) · 그림 하나(통)뿐이라 다른 모양은 못 봤다 |
| 기본 `clear_tol` 16 | 75% | 두 시드 모두 흰 칸은 0~16 에 몰리고 그린 칸은 33 넘게 떨어졌다. 다른 프롬프트(밝은 색 물건)는 안 봤다 |
| 구현 설계대로 하면 S 로 끝난다 | 80% | 바뀌는 자리 다섯을 코드에서 직접 확인했다. `flood` 는 흉내 스크립트에서 `arttool.edit.cutout` 에서 가져다 실제로 돌렸다. 시험 6 은 아직 없다 |
