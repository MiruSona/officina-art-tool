## 1. 공통 약속 (앞 설계에서 그대로)

| 약속 | 내용 |
| --- | --- |
| 부르기 | 새 명령은 `cli.py` 의 `LATE` 표가 `모듈.run(args) -> dict` 로 늦게 부른다. 모듈이 없으면 「아직 구현 안 됨」 종료 2 |
| 보고 | dict 의 `status` 는 `ok` · `warn` · `fail`. `--report` 는 cli 가 쓴다(`.json` 만, 입력과 같으면 거절) |
| 경고 꼴 | `warnings` 목록, 한 줄은 `{rule, ok, detail, items}`. rule 이름은 `<명령>.<무엇>` (예 `ref.b64_large`) |
| 종료 코드 | 0 = ok · warn / 1 = `ArtToolError`(그림을 못 읽음 · 만들 것이 없음) / 2 = `UsageError`(인자 · 값 · 원본 덮어쓰기) / 4 = `fail` |
| 원본 보호 | 쓸 경로는 `jailed_output` · `resolve_root`+`safe_join` 으로 감옥에 태우고, **아무것도 쓰기 전에** `paths.guard_overwrite(writes, reads)` · 필요하면 `guard_outside`. 겹치면 종료 2 |
| 쓰기 | `image.save` · `paths.write_text` (tmp → rename). 지우는 코드 경로는 만들지 않는다 |
| 폴더 입력 | `paths.png_files` (바로 아래 `.png` 만, 대소문자 무시) |
| 기존 명령에 붙는 새 인자 | 배선 전에도 돌게 모듈은 `getattr(args, "<dest>", 기본값)` 으로 읽는다 (`sheet --grid` · `layers diff --drop`) |
| 큰 원칙 | AI 는 짧은 인자 · JSON 만 다루고 그림은 코드가 만든다. 검수도 코드로 한다 |
| 새 라이브러리 | 없다. PIL · numpy 만 쓴다 |

## 3. 항목별 설계

### 3-1. `style ref` — 화풍 그림 준비 (R1)

- **왜** : `create_image_pro_flash` 는 화풍 그림이 캔버스보다 크면 거절하고, base64 가 길면 잘려 「Could not decode image」가 난다. 네 장의 피드백에서 매번 손으로 자르고 · 색을 줄이고 · base64 로 바꿨다.
- **동작** : ① `--crop` 이 있으면 그 칸. 없고 그림이 캔버스보다 크면 **불투명 칸 bbox 의 가운데**를 기준으로 캔버스 크기만큼 자른다(경고 `ref.cropped`). **키우기 · 줄이기는 안 한다** — 도트 굵기가 깨진다. 작으면 그대로 둔다(PixelLab 이 가운데 놓는다).
  ② 색이 `--colors` 넘으면 PIL `quantize`(FASTOCTREE, 디더 없음)로 줄인다. ③ 알파는 128 문턱으로 0/255 로(반투명이 있었으면 경고 `ref.soft_alpha`). ④ **팔레트 PNG**(mode P + 투명 색 하나)로 저장. ⑤ `--b64` 를 주면 base64 한 줄을 그 파일에.
- **base64 를 stdout · 보고에 안 싣는다.** 문맥을 먹는다. AI 는 `--b64` 파일을 읽어 인자로 넣는다. 보고에는 `size` · `crop` · `colors_before` · `colors_after` · `png_bytes` · `b64_bytes` 만.
- **실패** : 캔버스 꼴 틀림 · `--colors` 가 2~256 밖 · `--crop` 이 그림 밖 → 2. 불투명 칸 0 → 1. `b64_bytes` 가 `--max-kb`(기본 12) 넘으면 경고 `ref.b64_large`(「색을 더 줄이거나 더 잘라라」, status warn).
- **시험** `tests/test_style_ref.py` : `test_ref_crops_bbox_center_when_larger` · `test_ref_explicit_crop` · `test_ref_crop_outside_exit2` · `test_ref_no_resize_when_smaller` · `test_ref_reduces_to_palette_png` · `test_ref_keeps_transparency` · `test_ref_b64_matches_png` · `test_ref_warns_large_b64` · `test_ref_bad_canvas_exit2` · `test_ref_refuses_overwrite_input`

### 3-2. `bands` — 흰 띠 · 몰딩 줄 찾기 (P7)

- **왜** : `create_image_pro` 가 위아래 18~42 줄씩 흰 띠를 둘러 오고, 세 조각을 이을 자리(몰딩 · 걸레받이 · 널 이음 줄)를 **줄마다 색을 찍어 눈으로** 찾았다.
- **찾는 것 둘** : `blank` — 가장자리에서 이어지는 줄 중 칸의 95% 이상이 흰색(세 값 모두 240 이상) 또는 투명인 띠(처음 · 끝 각각 `[시작, 끝)`).
  `lines` — 앞 줄과의 평균 색 차 `delta` 가 큰 줄 상위 `--top` 개. 줄 안 최다 색 비율 `uniform` 을 같이 적고 점수 = `delta × uniform` 순. 몰딩 · 이음 줄은 둘 다 높다.
- **출력** : 보고 `blank` · `lines[{y, delta, uniform, score}]`. `--mark` 를 주면 원본 ×2 에 왼쪽 여백을 붙여 빨간 눈금과 줄 번호(`image.draw_label`)를 찍은 PNG.
- **실패** : `--axis` 가 x · y 밖 · `--top` < 1 → 2. 흰 띠도 후보 줄도 없으면 0건이 아니라 경고 `bands.none`(「그림이 고르다 — 이을 자리가 안 보인다」).
- **시험** `tests/test_edit_bands.py` : `test_bands_finds_white_top_bottom` · `test_bands_transparent_rows_count_as_blank` · `test_bands_ranks_molding_line_first` · `test_bands_axis_x` · `test_bands_none_warns` · `test_bands_mark_png_written` · `test_bands_mark_refuses_input_path`

### 3-3. `stitch` — 조각 잇기 (R2)

- **왜** : 게임 저장소의 실내 배경 세 장이 「조각 · 줄 구간」만 다른 같은 잇기 코드를 세 번 썼다.
- **꼴** : `--in` 에 `파일:시작-끝` 을 차례대로. 끝은 포함하지 않고, 비우면 끝까지(`12-`), 구간을 통째로 빼면 그림 전체. **파일 경로의 드라이브 콜론(`C:\`)과 안 헷갈리게 마지막 `:` 뒤가 `숫자?-숫자?` 일 때만 구간으로 본다.**
- **동작** : `--axis y`(기본)면 위에서 아래로 붙인다. 조각 폭이 다르면 종료 2(조각마다 폭을 적는다). 이음 자리마다 앞 조각 마지막 줄과 뒷 조각 첫 줄의 평균 색 차를 보고 `joins[{at, delta}]` 에 적고, 24 넘으면 경고 `stitch.seam_jump`.
- **실패** : 구간이 그림 밖 · 시작 ≥ 끝 · 조각 하나뿐 → 2. 출력이 입력 조각과 같으면 2.
- **시험** `tests/test_edit_stitch.py` : `test_stitch_three_pieces_height` · `test_stitch_open_end_range` · `test_stitch_whole_file_without_range` · `test_stitch_windows_drive_colon` · `test_stitch_width_mismatch_exit2` · `test_stitch_range_outside_exit2` · `test_stitch_seam_jump_warns` · `test_stitch_axis_x` · `test_stitch_refuses_overwrite_piece`

### 3-4. `tile offset` — 반 칸 밀기 + 십자 가림판 (R3)

- **왜** : 바탕 있는 256 그림은 「seamless」 글로는 네 변이 안 이어진다. 농장 · 잔디 두 판 모두 **반 칸 밀기 → 가운데 십자 16px inpaint** 로 풀었고, 매번 workbench `copy_region` 넷과 마스크를 손으로 만들었다.
- **동작** : 그림을 (W//2, H//2) 만큼 감아 민다(`np.roll`). 원래 네 변이 가운데 십자로 모인다. 가림판은 **불투명 검정 바탕 + 흰 십자**(흰 = 다시 그릴 자리, PixelLab inpaint 마스크 꼴). 띠는 이음 줄을 가운데에 두고 `--band` 칸 폭.
- **보고** : `shift` · `band` · `seam_before`(원본을 자기 자신과 이은 이음 값 — `tiles.seam.check_pair` 를 부른다). 맨 바깥 한 줄 테두리도 십자 안에 들어가 inpaint 로 지워진다.
- **뒤 흐름** : inpaint 결과가 곧 이어 붙는 타일이다(다시 밀어 되돌리지 않는다). `tile seam` 으로 확인한다.
- **실패** : `--band` 가 홀수 · 2 미만 · 짧은 변의 절반 이상 → 2. `--out` 과 `--mask` 가 같거나 입력과 같으면 2. 투명 칸이 있으면 경고 `offset.has_transparent`(바탕 타일은 꽉 차야 한다).
- **시험** `tests/test_tile_offset.py` : `test_offset_moves_edges_to_center` · `test_offset_odd_size` · `test_offset_mask_cross_width` · `test_offset_mask_is_opaque_black_white` · `test_offset_band_odd_exit2` · `test_offset_band_too_wide_exit2` · `test_offset_reports_seam_before` · `test_offset_transparent_warns` · `test_offset_refuses_same_out_and_mask`

### 3-5. 늘리기 묶음 `extend` (R4 · R9 · R8)

설계 15절의 「늘리기 도구」를 한 명령 묶음으로 푼다. 셋 다 **줄 · 칸을 되풀이하거나 빼기만 하고 크기를 늘이고 줄이는 보간은 안 한다**(도트가 깨지지 않게).

**`extend period` (R4, M)**

- **왜** : 울타리를 한 장으로 뽑으면 기둥 간격이 37 · 26px 로 와서 32 격자에 안 맞았다. 손으로 `fence32` 를 짰다. 「되풀이 단위가 타일 크기의 배수인가」 검사도 바랐다.
- **찾기** : `--axis x` 면 세로 줄(열)마다 RGBA 를 한 벡터로 보고, 간격 p(4 ~ 길이/2)마다 `d(p)` = 열 i 와 i+p 의 평균 차. 점수 = `d(p) / (p/2 ~ p-1 간격의 d 평균)`(8절에서 바꿈). 점수가 가장 낮은 값의 1.1배 안에 드는 것 중 **가장 작은 p**(배수를 안 고르려고). 점수 0.35 넘으면 경고 `period.weak`.
- **검사** : `--tile` 을 주면 `period % tile` 을 보고, 0 이 아니면 경고 `period.not_multiple`(가까운 배수 둘을 적는다).
- **맞추기** : `--out` 을 주면 한 단위를 자른다. 자르는 자리는 **이웃 열과 차가 가장 작은 열**(기둥 한가운데를 안 자르게). 폭은 `--fit N`, 없으면 `--tile` 의 가장 가까운 배수, 둘 다 없으면 그대로. 모자라면 가장 밋밋한 열을 겹쳐 넣고, 남으면 가장 밋밋한 열부터 뺀다. 보고 `removed` · `duplicated` 열 번호.
- **실패** : 단위를 못 찾으면(길이 < 2p) 경고 `period.not_found` · `period: null`, `--out` 까지 줬으면 종료 1(만들 것이 없다). `--fit` 이 p 의 ±25% 밖이면 2(그림이 일그러진다).
- **시험** `tests/test_extend_period.py` : `test_period_finds_37` · `test_period_prefers_smallest_not_multiple` · `test_period_axis_y` · `test_period_not_multiple_warns` · `test_period_weak_warns_on_noise` · `test_period_not_found_short_strip` · `test_period_fit_to_32_keeps_post_columns` · `test_period_fit_out_of_range_exit2` · `test_period_out_without_period_exit1`

**`extend ring` (R9, S)**

- **왜** : 한 바퀴 그림(모서리 · 가로 단위 · 세로 단위)을 잘라 길이를 늘리는 `Ring` 을 손으로 짰다. `ui preview --mode tile` 이 이미 같은 셈(`ui.ninepatch.slice_stretch(mode="tile")`)을 하지만, **가운데 길이가 단위의 배수가 아니면 끝 단위가 잘린다**는 것을 알려 주지 않는다.
- **동작** : `slice_stretch` 를 **부르기만** 한다(ui 쪽은 안 고친다). 가로 · 세로 가운데 길이가 원본 가운데 길이의 배수가 아니면 경고 `ring.partial_unit` + 맞는 크기 둘(작은 쪽 · 큰 쪽). `--snap` 이면 가까운 맞는 크기로 바꿔 만들고 보고 `size` 에 실제 크기.
- **실패** : border 합 ≥ 원본 · 최소 크기 미만 → 2 (`ui preview` 와 같은 말).
- **시험** `tests/test_extend_ring.py` : `test_ring_whole_units_no_warning` · `test_ring_partial_unit_warns_with_sizes` · `test_ring_snap_changes_size` · `test_ring_border_lbrt` · `test_ring_too_small_exit2` · `test_ring_refuses_overwrite_input`

**`extend canvas` (R8, S)**

- **왜** : 360×800 배경이 한 판에 안 돼(pixflux 400 까지) 위아래를 PIL 로 늘렸다. 하늘은 한 줄 되풀이, 바닥은 띠 되풀이였다.
- **동작** : 원본을 `--anchor` 자리에 두고(기본 `bottom` — 위로 늘린다) 새로 생긴 칸은 **그 쪽 가장자리의 `--band` 줄을 바깥으로 되풀이**해 채운다(되풀이 위상은 원본에서 이어지게). anchor 값 : `top` · `bottom` · `left` · `right` · `center` · `top-left` · `top-right` · `bottom-left` · `bottom-right`.
- **실패** : `--size` 가 원본보다 작은 변이 있으면 2(자르기는 `trim` · `stitch` 몫). `--band` 가 그 변 길이 넘으면 2. `--band 1` 인데 가장자리 줄 색이 4개 넘으면 경고 `canvas.edge_busy`(세로 줄무늬가 생긴다 — `--band 16` 같은 값을 권함).
- **시험** `tests/test_extend_canvas.py` : `test_canvas_up_repeats_top_row` · `test_canvas_band_tiles_in_phase` · `test_canvas_center_both_sides` · `test_canvas_width_left` · `test_canvas_smaller_exit2` · `test_canvas_band_too_long_exit2` · `test_canvas_edge_busy_warns`

### 3-6. 받은 그림 손질 (P2 · R7 · R5)

**`reline` — 외곽선 단색 맞추기 (P2)**

- **왜** : 받은 그림의 외곽선이 장마다 여러 어두운 색으로 와서 「맨 바깥 1px 를 한 색으로 · 가장 어두운 색들 → 한 색」 스크립트를 두 갈래가 따로 짰다. `arttool.draw` 의 `outline` 은 그릴 때만, `recolor` 는 ±2 색만 합친다.
- **동작** : 바깥 고리 = 불투명 칸 중 4방향 이웃에 투명이 있는 칸. `--pick dark`(기본)는 고리 칸 중 밝기가 「고리의 가장 어두운 색 + `--tol`(기본 40)」 이하인 칸만, `all` 은 고리 전부. `--scope ring`(기본)은 고른 칸만, `colors` 는 **고른 칸의 색과 같은 색을 그림 전체에서** 바꾼다(안쪽 선까지).
- **색** : `--color` > 프로필 `palette.outline`(**`--profile` 을 줬을 때만** — 8절) > 고리에서 가장 많이 쓴 어두운 색.
- **보고** : 장마다 `changed` · `merged_colors` · `target`. 합친 색이 6개 넘으면 경고 `reline.many_colors`(음영까지 먹었을 수 있다). 투명 칸이 없는 그림은 그대로 복사하고 경고 `reline.no_alpha`.
- **실패** : `--color` 꼴 틀림 · `--pick` · `--scope` 값 밖 → 2. 출력 폴더가 입력과 겹치면 2.
- **시험** `tests/test_reline.py` : `test_reline_ring_dark_to_one_color` · `test_reline_keeps_light_ring_pixels` · `test_reline_pick_all` · `test_reline_scope_colors_inner_lines` · `test_reline_color_from_profile` · `test_reline_many_colors_warns` · `test_reline_no_alpha_copies_and_warns` · `test_reline_refuses_in_place`

**`tint` — 흰 겹 × 색 곱하기 (R7)**

- **왜** : 「흰색 ~ 밝은 회색으로」 뽑은 겹에 색을 곱해 변종을 늘리는 길이 세 번 나왔고(목업 v2 · 손님3 · 부품2), 미리보기 비교판 스크립트를 따로 짰다.
- **이름** : 설계 15절의 `recolor --multiply` 대신 **새 명령 `tint`** 로 한다. `recolor` 는 색표(1:1 바꾸기) 명령이고 LATE 밖이라, 곱하기를 끼우면 그 명령의 인자 · 시험을 같이 흔든다.
- **동작** : 불투명 칸의 RGB 를 `색/255` 로 곱한다(알파 그대로). 출력 `<원래이름>_<RRGGBB>.png`. `--sheet` 를 주면 원본 + 색마다 한 줄 비교판(`image.contact_sheet`, `--scale` 기본 4).
- **실패** : 색 꼴 틀림 · 색 0개 → 2. 출력 이름이 겹치면 2. 원본 불투명 칸의 평균 밝기가 170 미만이면 경고 `tint.dark_source`(곱하면 탁해진다).
- **시험** `tests/test_tint.py` : `test_tint_multiplies_rgb_keeps_alpha` · `test_tint_white_becomes_color` · `test_tint_names_per_color` · `test_tint_sheet_written` · `test_tint_dark_source_warns` · `test_tint_bad_hex_exit2` · `test_tint_refuses_in_place`

**`layers diff --drop` — 겹 떼기 색 거르기 (R5)**

- **왜** : 머리 inpaint 가 마스크 안의 귀 · 뺨 · 깃까지 다시 그려, 차이를 그대로 머리 겹으로 쓰면 색 바꿀 때 뺨이 물들었다. 「옅은 살색 · 파란 옷 점은 머리 겹에서 뺀다」 거르기를 손으로 했다.
- **꼴** : `--drop 겹이름:#hex,#hex`(여러 번), `--drop-tol`(기본 24, RGB 각 칸 차 최댓값). 그 겹의 칸 중 이 색들에 가까운 칸을 뺀다. 뺀 칸은 아래 본체(기본체)가 그대로 보인다.
- **보고** : 겹 줄에 `dropped` 칸 수, 경고 `diff_dropped`(정보). 없는 겹 이름 → 2.
- **자리** : `run_diff` 의 「겹끼리 같은 칸」 정리 **앞**에 넣는다. 읽기는 `getattr(args, "drop", None)`.
- **시험** `tests/test_layers_diff_drop.py` : `test_drop_removes_skin_from_hair` · `test_drop_tol` · `test_drop_unknown_layer_exit2` · `test_drop_bad_hex_exit2` · `test_drop_absent_keeps_old_behavior`

### 3-7. 보기 · 글자 (R6 · R10 일부)

**`sheet --grid N` (R6)**

- **왜** : 화면 속 물건의 좌표(입구 · 창 가운데 · 놓을 자리)를 손으로 확대해 쟀다. 눈금 판이 있으면 사람도 AI 도 좌표를 바로 읽는다.
- **동작** : `zoom` 판에만 원본 N 칸마다 1px 선(기본 `#FF00FF`, `--grid-color`)과 위 · 왼 여백에 원본 좌표 숫자. 배율이 4 미만이면 4 로 올리고 보고 `scale` 에 적는다.
- **실패** : `--grid` < 2 → 2. `--kinds` 에 `zoom` 이 없으면 2. 기본 0 = 끔(예전 그대로).
- **시험** `tests/test_sheet_grid.py` : `test_grid_lines_every_n` · `test_grid_labels_margin` · `test_grid_raises_scale_to_4` · `test_grid_requires_zoom_exit2` · `test_grid_off_by_default_same_output`

**`ui glyphs` — 글꼴에 없는 글자 (R10 의 작은 쪽)**

- **왜** : 「—」 처럼 글꼴에 없는 글자가 네모로 찍혔다. 게임 UI 글꼴에도 같은 일이 난다(`ui font` 는 글자 목록만 낸다).
- **동작** : PIL `ImageFont.truetype(font, --size 16)` 로 글자마다 비트맵을 그려 **없는 글자 그림(notdef, 유니코드 비문자 U+FFFF 로 얻음 — 8절)과 같으면** 없는 글자로 본다. 공백이 아닌데 빈 비트맵이어도 없는 글자. `--text-file` 은 `ui font` 가 낸 글자 파일을 그대로 받는다(BOM · cp949 폴백은 `ui.font.read_text`).
- **보고** : `checked` · `missing[{char, code:"U+2014"}]` · `method: "notdef_compare"`. 없는 글자가 있으면 **`fail`(종료 4)**. notdef 가 빈 그림인 글꼴이면 경고 `glyphs.notdef_blank`(빈 그림 규칙만 쓴다).
- **한계** : ttf · otf 만. TMP 폰트 에셋 · 비트맵 글꼴은 못 본다.
- **실패** : 글꼴 파일 없음 · 못 읽음 → 1. `--text` · `--text-file` 둘 다 없거나 둘 다 → 2.
- **시험** `tests/test_ui_glyphs.py` : `test_glyphs_all_present_ok` · `test_glyphs_missing_dash_fails` · `test_glyphs_skips_spaces` · `test_glyphs_text_file_bom` · `test_glyphs_needs_one_source_exit2` · `test_glyphs_bad_font_exit1` (시험 글꼴은 툴 안 Pretendard)

실물 한 바퀴(사본)에서 본 문턱 이야기 — 고치지 않고 적어 둔다.

- `extend period` : 깔끔한 널판 띠에서도 점수가 0.337 로 `weak` 문턱 0.35 바로 아래였다. 단위가 타일보다 작으면(16 · 타일 32) `not_multiple` 경고가 나고 `--tile` 만으로 `--out` 하면 ±25% 밖이라 종료 2 다 — `--fit` 을 직접 줘야 한다.
- `extend canvas` : 세로 줄무늬 차양처럼 가장자리 줄 색이 많아도 한 줄 되풀이가 자연스러운 그림에서 `edge_busy` 가 난다(헛경고).
- `reline` : 캐릭터 한 장에서 합친 색 7개로 `many_colors` 가 났지만 결과 그림은 멀쩡했다(어두운 외곽선 색이 원래 여러 벌).
- `style ref` : 키 큰 캐릭터(120×240)를 64 캔버스로 주면 몸 가운데만 남는다 — `--crop` 으로 먼저 고른다.
