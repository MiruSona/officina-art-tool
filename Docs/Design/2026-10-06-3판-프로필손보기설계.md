## 0. 결론

- **프로필 꼴은 거의 그대로 두고, 「어느 그림을 어느 프로필로 볼지」를 바깥 지도(`--profile-map`)로 푼다.**
  머리 16색·몸 40색, 폴더별 외곽선, 유리 한 장만 반투명(`alpha_except`)이 다 이 길로 풀린다.

- 두 덩이로 나눈다. **3-가** = 지도 · 외곽선 정리 · 한도 표 통째 바꾸기 · `palette check` · 팔레트 뿌리 · 보안 · 보류 둘.
  **3-나** = 길이 다른 램프(한 색 램프 표시 → 실제 가변 길이).

## 2. 항목별

### 2-1. `--profile-map` (3-가)

**꼴.** `arttool check --profile-map map.yaml <폴더>`. `--profile` 과 같이 주면 종료 코드 2.

```yaml
version: 1
default: profiles/game_base.yaml        # 꼭 있어야 한다. 아무 무늬에도 안 걸린 그림이 쓴다
rules:                                  # 위에서부터 첫 일치 하나만 쓴다
  - match: "chars/*/head*.png"
    profile: profiles/char_head.yaml    # 통째 프로필
  - match: "chars/**"
    set: { check: { warn: { color_cap: { table: { 256: 40 } } } } }   # default 위에 덧씌우기
  - match: "props/**/display_case*.png"
    set: { check: { allow_alpha: any } }                              # = alpha_except
```

- `match` 는 **훑는 뿌리 폴더 기준 상대경로**, `/` 로 맞추고 대소문자 접어서 비교한다. `*` 는 한 단, `**` 는 여러 단.
- `profile` 은 그 프로필 파일 하나를 그대로 쓴다(옛 뜻 그대로). `set` 은 `default` 위에 `deep_merge` 한 덧칸이다.
  둘 다 있으면 `profile` 위에 `set`. 덧칸도 `reject_unknown` · `validate` 를 그대로 지난다(오타 즉시 실패).
- 프로필 경로는 **지도 파일 폴더 아래 상대경로만** 받는다(`check_relative` + `safe_join`). 2-7 의 감옥과 같은 함수.
- 프로필은 경로별로 한 번만 읽어 둔다(그림마다 다시 안 읽는다).

**왜 프로필 안 `kinds:` 가 아닌가.** 프로필 꼴을 늘리면 `profile show` · template.json 에 박히는 style · 검증이 다 같이 바뀐다.
지도는 프로필 바깥이라 옛 프로필이 그대로이고, 「무늬 → 한도」 · 「무늬 → 외곽선」 · 「무늬 → 알파」 를 한 길로 푼다.
그래서 `alpha_except` 칸도 따로 안 만든다 — 코드 피드백 원문이 바란 「파일 이름 단위 예외」 가 `match` + `set` 한 줄이다.

**보고.** 지도를 썼을 때만 그림마다 `"profile"` 칸이 붙고, 맨 위에 `profile_map` 요약이 붙는다.

```json
{ "profile_map": { "file": "map.yaml", "rules": 3, "hits": { "0": 12, "1": 40, "2": 1, "default": 7 } },
  "items": [ { "file": "chars/hero/head.png", "profile": "rule 0 · profiles/char_head.yaml", "status": "ok" } ] }
```

**경고·종료 코드.** 지도에 안 걸린 그림이 0 이 아닌데 `rules` 의 어느 줄도 한 번도 안 쓰였으면 경고 `profile_map.rule_unused`(오타 무늬 찾기용, 종료 코드 안 바꿈).
지도 파일 오류(모르는 칸 · `default` 없음 · 경로 감옥 밖)는 종료 코드 2.
※ 종료 코드 표는 README 171행의 0·1·2·4 를 그대로 쓴다. 「2 = 입력·설정 오류」 는 구현 때 README 표와 대조한다.

### 2-2. 외곽선 받는 값 (3-가)

- **`style.outline` 은 글자 하나 그대로.** 목록으로 바꾸면 `profile show` · template.json 의 style · `judge_outline(m, style_outline: str, accept)` 가 다 깨진다.
- 받는 값 = `{style.outline} ∪ check.warn.outline.accept`. 이건 이미 코드가 그렇게 한다(`outline.py:208`). 새 칸은 안 만든다.
- 바꾸는 것 둘 :
  1. `profile show` 가 `외곽선 : selout (+ 받기 solid, selout+light)` 처럼 한 줄로 보여 준다.
  2. 폴더마다 다른 외곽선은 2-1 지도의 `set: { style: { outline: solid } }` 로 푼다.
- 53장 「읽기 차이」 는 `accept` 로 대부분 풀린다. 남는 것은 실물로 다시 잰다(시험 목록).

### 2-3. 색 한도 표 통째 바꾸기 (3-가)

```yaml
check:
  warn:
    color_cap:
      table: { 128: 48, 256: 64 }
      table_mode: replace      # 없거나 merge = 지금처럼 기본 표 위에 겹치기
```

- 기본 `merge` — 옛 프로필 뜻 그대로. `replace` 면 프로필(·지도 `set`)의 표만 쓴다. 표보다 작은 그림은 **가장 작은 칸**의 한도를 쓴다(지금 `color_cap_table()` 의 「칸 고르기」 그대로).
- 겹칠 때 `profile show` 가 `색 한도 표 : 기본 표 8·16·32·48·64 가 겹쳐 남았다 (통째로 쓰려면 table_mode: replace)` 한 줄을 낸다.
  `check` 는 같은 내용을 한 판에 한 번 `notes` 로 낸다(종료 코드 안 바꿈).
- 겹치는 차례 : 기본 → 프로필 → 지도 `set` → 템플릿. `table_mode` 는 마지막에 겹친 쪽 값을 따른다.

### 2-4. `ramp_shape` → `palette check` (3-가)

- 새 명령 `arttool palette check (--profile P | --ramps file.json)` — 램프 파일 하나를 **한 번** 잰다. 종료 코드 0(경고만) · 2(파일 오류).
- `check` 안에서는 램프 파일마다 **한 판에 한 번만** 재고, 결과를 그림 줄이 아니라 맨 위 `palette` 칸에 둔다 :

```json
{ "palette": { "lpc_cloth.json": { "ramp_shape": ["skin: 밝기 순서 어긋남 (3→4)"], "used_by": 48 } } }
```

- **옛 보고 호환** : 그림 줄의 옛 `ramp_shape` 경고는 프로필 `check.warn.ramp_shape.report: each`(기본)일 때 그대로 남는다.
  `report: once` 를 켜면 그림 줄에서 빠지고 위 `palette` 칸에만 남는다. `palette` 칸은 늘 붙는다(새 칸이라 옛 읽는 쪽이 안 깨진다).
- 12줄 되풀이 → 1줄이 목표. 기본값을 `once` 로 뒤집는 것은 보고 `version` 을 올릴 때 같이 한다(못 정한 것).

### 2-5. 길이 다른 램프 (3-나)

**(가) 한 색 램프 · 되풀이 채움 알아보기** — 파일 꼴은 그대로(모든 램프 길이 = `ramp_len`).

- `ramp_shape` 가 **밝은 끝의 같은 색 되풀이를 채움으로 본다.** 실제 단 수 = 끝 되풀이를 접은 수. 단 수 검사(`steps`)는 이 수로 한다.
  접은 수가 1 이면 「한 색 램프」 로 표시만 하고(`info`) 모양 경고는 안 낸다.
- `style extract`(`extract.py:118`) : 같은 색이 되풀이되면 접어서 실제 단 수를 덧칸 `ramp_info: { name: { steps: 1, kind: "single" } }` 에 적는다.
  램프 자체는 여전히 `ramp_len` 길이로 채워 낸다(`load_ramps` 는 모르는 칸을 무시하므로 옛 읽는 쪽 그대로).

**(나) 실제 가변 길이** — 팔레트 json 에 새 칸 `"ramp_len_mode": "max"` 를 적었을 때만.

| 자리 | 지금 (`fixed`, 칸 없음 = 기본) | `max` 일 때 |
| --- | --- | --- |
| `ramp_len` 뜻 | 모든 램프 길이 | 가장 긴 램프 길이(1 ≤ 각 길이 ≤ `ramp_len`) |
| `load_ramps` (`palette.py:59-85`) | 길이 다르면 거절 | 받는다. `Ramps` 에 `lengths: dict[str,int]` 를 더한다 |
| LUT (`build_lut`, 123행) | 너비 = `ramp_len` | 너비 = `ramp_len` 그대로. 짧은 램프는 **오른쪽을 마지막 색으로 채운다** → 셰이더가 읽는 자리 뜻이 안 바뀐다 |
| 내보내기 `rampLen` (211행) | LUT 너비 | **그대로 LUT 너비**. 덧칸 `rampLens: {name: n}` 을 더한다 |
| 저장 검증 (230행) | 모든 길이 = `ramp_len` | 각 길이 1..`ramp_len`, 최댓값 = `ramp_len` |
| 프로필 `palette.ramp_len` | 기본 길이 | 그대로 「새로 만들 램프 길이」(`template --base` · `style extract`) |

- **`rampLen` 을 받는 쪽** : 이 저장소 · 게임 저장소의 `.cs` · `.shader` · `.hlsl` 에 `rampLen` 을 읽는 코드가 **하나도 없다**(2026-10-06 Grep). 받는 셰이더는 아직 안 만들어졌다.
  그래도 `rampLen` 뜻(= LUT 너비)을 안 바꾸고 덧칸만 더하므로, 나중에 만들 셰이더가 옛 뜻으로 읽어도 맞는다.
- 다른 램프 사용처도 `ramps.ramp_len` 을 「모든 램프 길이」로 가정하는지 구현 첫 단계에서 Grep 으로 센다(`recolor` · `sprite/merge.py:292` · `ui/frame.py:28` · `draw/canvas.py` · `bake.py:169`). 짧은 램프에서 칸 번호로 색을 고르는 곳은 `min(i, len-1)` 로 막는다.

### 2-6. 팔레트 뿌리 `ARTTOOL_PALETTES` (3-가)

- `ramps_file: "$palettes/lpc_cloth.json"` 처럼 **`$palettes/` 로 시작할 때만** 환경변수 `ARTTOOL_PALETTES` 폴더 아래에서 찾는다.
  접두가 없으면 옛 차례(프로필 폴더 → 툴 폴더) 그대로라, 환경변수를 켜도 옛 프로필이 다른 파일을 집지 않는다.
- 환경변수 값 : 절대경로 · 있는 폴더 · 링크 아님. 한 번만 정규화해 둔다. 안 켰는데 `$palettes/` 를 쓰면 종료 코드 2.
- 나머지 경로는 `check_relative` → `safe_join(뿌리)` → 보통 파일 · `.json` · 링크 거절.
- 게임 저장소에서 사본 + 같은지 지키는 스크립트가 필요 없어진다.

**둘째 후보 「프로필 폴더의 부모 한 단 · `.json` 만 · 링크 거절」** — 환경변수 없이 바로 된다는 장점이 있다.
그러나 ① 프로필을 어디 두느냐에 따라 감옥이 저절로 넓어지고(홈 폴더 바로 아래 프로필이면 홈 전체), ② 뿌리가 넷이 된다(프로필 폴더·툴 폴더·환경변수 또는 부모).
보안 규칙은 뿌리를 셋 넘기지 않는다. 그래서 환경변수만 넣고 이 안은 안 한다.

### 2-7. template.json 절대경로 닫기 (3-가)

**누가 쓰나.** `template` 명령(`template/run.py:141`)이 프로필의 `ramps_path()`(감옥을 지난 자리)를 `resolve()` 한 절대경로로 적는다.
**믿어도 되나 — 아니다.** template.json 은 작업 폴더의 보통 파일이다. 사람이 고치거나, 게임 저장소에 커밋돼 다른 PC 로 넘어간다.
읽는 쪽이 셋이다 : `check.py:313-316` · `draw/guide.py:118` · `draw/canvas.py:261-262`(조사에서 빠졌던 자리).

**닫는 법.** 세 곳이 함수 하나 `trusted_ramps(path_text, prof) -> Path | None` 을 지난다.

1. 정규화(링크까지 푼 실제 경로) → 보통 파일 · `.json` · 링크 아님.
2. 팔레트 뿌리 셋(지금 프로필의 폴더 · 툴 폴더 · `ARTTOOL_PALETTES`) 중 하나 아래에 있어야 한다. 대소문자 접어서 접두 비교.
3. 못 지나면 **실패가 아니라** 경고 `template.ramps_outside` 를 내고 프로필의 `ramps_path()` 로 돌아간다.

**깨지는 옛 template.json.** 툴이 쓴 값은 다 위 뿌리 안이라 같은 PC · 같은 자리면 그대로 지난다.
다른 PC 로 옮겨 온 것은 지금도 `is_file()` 에서 빠지거나 엉뚱한 파일을 읽는다 — 이제는 경고 한 줄 뒤 프로필 램프로 돈다. 종료 코드는 안 바뀐다.

### 2-8. `alpha_except` · 09-18 보류 둘 (3-가)

- `alpha_except` : 2-1 지도의 `set: { check: { allow_alpha: … } }` 로 푼다. 새 칸 안 만든다.
- **보류 1 — `FREE_MAPS` 무늬.** `profile.py:46` 은 `"rigs.*.marker_colors"` 처럼 `*` 를 쓰는데, 381행은 실제 경로(`rigs.walk.marker_colors`)와 **글자 그대로** 비교해 `*` 줄은 한 번도 안 맞는다.
  지금 돌아가는 것은 우연이다 — `_child_schema`(414행)가 dict 아닌 자리에 `{}` 를 돌려주고, `_allowed_names`(411행)가 `tuple({}) == ()` 를 「자유 칸」 으로 보기 때문.
  같은 까닭으로 **DEFAULTS 가 스칼라인 자리에 dict 가 오면 검사가 조용히 통과**하고 뒤(`validate` · 사용처)에서 `TypeError` 가 난다.
  → 마디별 무늬 비교 함수 하나로 `FREE_MAPS` 를 맞추고, 「자유」 는 `FREE_MAPS` · `anim` · `rigs` 로만 정한다. 스칼라 자리에 dict 면 `ProfileError("… 는 값 하나 자리다")`.
  주의 : 이걸 고치면 지금 우연히 통과하던 rig 안쪽 칸(`anchors` 등 `FREE_MAPS` 에 없는 dict)이 거절될 수 있다 → 고치기 전에 `profiles/*.yaml` 과 시험 자료로 회귀를 먼저 돌린다.
- **보류 2 — `load_ramps` 가 `jsonio` 를 안 거침.** `palette.py:61` 이 BOM · 줄끝을 혼자 처리한다 → `jsonio.read_json` 으로 바꿔 BOM · CRLF · cp949 폴백 · 되살림 경고를 한 곳에 모은다. `template/run.py:139` 처럼 같은 파일을 두 번 읽는 자리도 한 번으로.

## 5. 보안 — 경로 감옥

| 뿌리 | 무엇을 여나 | 검사 |
| --- | --- | --- |
| 프로필 폴더 · 툴 폴더 (있던 것) | 램프 파일 | `check_relative` · `safe_join` (그대로) |
| `ARTTOOL_PALETTES` (새) | `$palettes/…` 램프 파일 | 뿌리 한 번 정규화 · 링크 거절 · `.json` · 보통 파일 |
| 지도 파일 폴더 (새, 프로필용) | 지도의 `profile` yaml | `check_relative` · `safe_join` · `.yaml/.yml` · 링크 거절 |

- 램프 뿌리는 셋에서 멈춘다(규칙 「셋 넘기지 않기」). 둘째 후보(부모 한 단)를 안 하는 까닭이다.
- template.json 절대경로는 2-7 의 `trusted_ramps` 하나만 지난다. 읽는 자리 셋이 다 이 함수를 부른다.
- 지도의 `match` 는 경로가 아니라 무늬라 파일을 열지 않는다. 훑는 뿌리 밖 그림은 지금처럼 훑기 단계에서 빠진다.
- 모르는 칸은 지도 · 덧칸 · 새 팔레트 칸 모두 즉시 실패(보안 규칙 7절). `ramp_len_mode` 의 모르는 값도 실패.

## 8. 못 정한 것

- `ramp_shape.report` 기본을 언제 `once` 로 뒤집나 — 보고 `version` 올림과 묶을지.
- 종료 코드 2 가 README 표의 「입력·설정 오류」 자리가 맞는지(구현 첫 단계에서 대조).
- 지도의 `set` 덧칸이 `style.*` 을 바꿀 때 template.json 에 박힌 style 과 어느 쪽이 이기나 — 지금 안은 「지도 → 템플릿」 차례(템플릿 `fixed` 칸만 템플릿이 이김)를 그대로 따른다.
- template 이 앞으로 절대경로 대신 `$palettes/` 나 프로필 기준 상대경로를 적게 할지(다른 PC 로 옮겨도 되게).
- `max` 램프에서 셰이더가 짧은 램프 끝을 「채움」 으로 알아야 하는 일이 생기면 `rampLens` 를 LUT 옆 텍스처로 넘길지.
