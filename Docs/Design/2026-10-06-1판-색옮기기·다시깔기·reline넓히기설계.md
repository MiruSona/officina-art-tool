## 결론 먼저

- **새 명령 하나(`shift`) + 기존 명령 넓히기 셋(`trim` · `check` · `reline`).** 모두 피드백에서 사람이 PIL 스크립트를 손으로 짠 자리다.
- **옛 호출은 결과가 안 바뀐다.** 새 옵션은 모두 「안 주면 지금과 같은」 기본값이다.
  예외는 `check` 의 새 경고 `odd_size` 하나 — 기본 켬으로 정했다(3절, 까닭 있음). 종료 코드는 그대로 0 이다.
- `pad` · `place` 새 명령은 만들지 않는다. `trim --pad` · `tile place` 와 이름이 헷갈려서, `trim` 에 `--canvas` 를 붙인다.
- 크기는 A1 · A2 · B 가 S~M, A3 은 S. 모두 합쳐 반나절 남짓.

## 1. A1 `shift` — 색 옮기기 (새 명령)

**장면** : `tint` 는 흰 겹에 색을 곱하기만 해서, 장식 색을 잔디 색에 「조금 노랗게 · 조금 밝게」 맞출 수 없었다.
바란 꼴이 `shift --hue -10 --light +0.03 --sat 2.4 --pick <색 목록>` 이다.

### 인자

| 인자 | 기본 | 뜻 |
| --- | --- | --- |
| `--in` | (필수) | PNG 한 장 또는 폴더 |
| `--out` | (필수) | 결과 폴더 |
| `--hue D` | 0 | 색상에 D 도 더한다. 360 으로 돌린다. 범위 -360~360 |
| `--sat K` | 1.0 | 채도에 K 를 곱한다. 0 이상 |
| `--light L` | 0 | HSV 의 V 에 L 을 더한다 (-1~1). **check 의 `hue_sat` 와 같은 HSV** 를 쓴다 |
| `--pick 색,색` | 없음 | 이 색만 옮긴다. 없으면 불투명 색 전부 |
| `--report` | 없음 | 보고 JSON |

셋 다 기본값이면(바꿀 것이 없음) `UsageError`. 알파는 건드리지 않는다. 투명 칸(알파 0)은 늘 그대로.

### 처리 순서

1. `tint.parse_colors` 로 `--pick` 을 읽는다. 값 범위를 본다.
2. 그림마다 불투명 칸의 서로 다른 색을 뽑는다 (`--pick` 이 있으면 그 색만, 정확히 같은 RGB).
3. 색 하나마다 `colorsys.rgb_to_hsv` → h + D/360 (mod 1) · s × K · v + L → 0~1 로 자르기 → RGB 반올림.
   (`draw/outline._computed` 와 같은 colorsys 길)
4. 색 표 `{원래 색: 새 색}` 를 칸에 한 번에 입힌다 (`merge.py` 의 색 표 꼴).
5. `is_dry_run` 이면 저장만 건너뛴다.

### 보고 예

```json
{"version": 1, "status": "warn", "hue": -10, "sat": 2.4, "light": 0.03, "pick": ["#6A8F3C", "#4E6B2B"],
 "images": [{"file": "deco.png", "out": "out/deco.png", "changed": 212,
             "colors": [{"from": "#6A8F3C", "to": "#5C9A1F", "count": 140}]}],
 "warnings": [{"rule": "shift.clipped", "ok": false, "detail": "…", "items": ["deco.png"]}], "out": "out"}
```

`changed` 는 바뀐 칸 수, `colors` 는 `merge-colors` 보고와 같은 `{from, to, count}` 꼴(칸 많은 순).

### 경고

| rule | 언제 |
| --- | --- |
| `shift.merged` | 서로 다른 원래 색 둘 이상이 같은 새 색이 됨 (색 수가 줄어 명암이 뭉갤 수 있다) |
| `shift.clipped` | `--sat` · `--light` 로 S 나 V 가 0~1 밖으로 나가 잘림 |
| `shift.pick_missing` | `--pick` 색이 그림에 한 칸도 없음 (`reline.from_missing` 과 같은 말투) |
| `shift.gray` | `--hue` 를 줬는데 고른 색이 채도 0(회색)이라 색상이 안 움직임 |

**알림 줄(문서 · 도움말)** : 옮긴 색은 대개 `ramps_file` 밖으로 나간다. 그러면 `check` 의 `must.palette` · `ramp_shape` 에 걸린다.
게임 팔레트에 맞춰 둘 그림이면 옮긴 뒤 `merge-colors` 로 램프에 붙이거나 램프를 고친다.

**종료 코드** : 0 ok · warn / 1 그림을 못 읽음 / 2 인자 · 원본 덮기. **dry-run** : `DRY_RUN_TAKES` (안 쓰고 보고만, `tint` 와 같은 줄).

## 2. A2 `trim` 넓히기 — 바닥 맞춰 다시 깔기

**장면** : 점검 #9 「여백 걷고 바닥에서 1칸 띄워 같은 크기로」, 아이콘 #6 「바닥 1칸 · 가로 가운데」. 둘 다 손으로 짰다.

### 새 인자

| 인자 | 기본 | 뜻 |
| --- | --- | --- |
| `--canvas WxH` | 없음 (= 지금 동작) | 자른 그림을 이 크기의 **투명** 판 위에 놓는다. `extend.parse_size` 로 읽는다 |
| `--anchor 이름` | `bottom` | 판의 어디에 붙이나. `extend/canvas.py` 의 `ANCHORS` 아홉(`top` · `bottom` · `left` · `right` · `center` · `top-left` …) |
| `--margin N` | 0 | 붙인 변에서 N 칸 띄운다. 가운데로 놓는 축에는 안 먹는다 |

- `--canvas` 없이 `--anchor` · `--margin` 을 주면 `UsageError`.
- `--canvas` 와 `--pad` · `--square` 를 같이 주면 `UsageError` (판 크기가 정해지면 둘은 뜻이 없다).
- `--common` 과 같이 쓰면 폴더 전체에 bbox 하나 → 모든 장이 같은 자리에 놓여 **프레임이 안 떨린다**.

### 처리 순서

1. bbox 를 잡는다 — `--common` 이면 `common_bbox`, 아니면 장마다 `image.bbox`.
2. `crop_box(arr, box)` 로 자른다 (pad 0, square 아님).
3. 놓을 자리 : 축마다 `canvas._offset(anchor, 그림, 판, low, high)` 를 쓰고, 붙인 변 쪽이면 margin 만큼 안으로 민다.
4. **새 투명 판**을 만들어 붙인다. `extend canvas` 는 가장자리 줄을 되풀이해 채우므로 그 채움 코드는 쓰지 않는다 — `_offset` 셈만 빌린다.
5. `offset` = 결과 (0, 0) 이 원본에서 어디였나. 지금 뜻 그대로(놓은 몫까지 넣은 값).

### 보고

위에 `canvas: [W, H]` · `anchor` · `margin` 을 더한다(`--canvas` 를 줄 때만 붙는다. 안 주면 보고가 옛 것과 같다). 장마다 칸은 지금과 같다(`offset` 포함).

### 경고 · 종료

| 이름 | 언제 | 결과 |
| --- | --- | --- |
| `trim.too_big` | bbox + margin 이 판보다 큼 | **`UsageError` 종료 2**, 아무것도 안 쓴다. 메시지에 이름 · 파일 · 크기 |
| `trim.half_pixel` | 가운데 놓는 축에서 남는 칸이 홀수 | warn. 남는 1칸은 `_offset` 셈대로(오른쪽 · 아래로) 간다 |

**dry-run** : 이미 `DRY_RUN_TAKES` 에 있다. 바꿀 것 없음.

## 3. A3 `check` 경고 `odd_size`

**장면** : 가로 21 그림을 피벗 `bottom_center` 로 굽자 가운데가 반 픽셀에 걸려 흐려졌다(4-D5).

### 규칙

- 피벗은 `bake.pivot_of` 와 같은 프로필 값(`canvas.pivot`, `PIVOTS`)을 본다.
  `bottom_center` → 가로가 홀수면 걸림. `center` → 가로 · 세로 중 홀수인 쪽. `top_left` → 안 봄.
- `check.py` 의 `_warnings` 에 한 줄, `profile.py` 의 `WARN_DEFAULTS` 에 `"odd_size": {"enabled": True}`, `validate_warn` 도 같이.
- 경고 한 줄에 걸린 파일을 `items` 로 모은다(장마다 한 줄 아님). detail 예 : `가로 21 — bottom_center 피벗이 반 픽셀에 놓인다. trim --canvas 22x… 로 짝수로 맞춘다`.

### 정한 것 : **기본 켬**, 프레임 모드는 **프로필 프레임 크기만 한 번** 본다

| 물음 | 정한 것 | 까닭 |
| --- | --- | --- |
| 기본 켬/끔 | 켬 | 이 사고는 눈으로 잘 안 보이고 게임 안에서야 드러난다. 끄면 아무도 안 켠다. 경고라 종료 코드는 0 그대로 |
| 시끄럽지 않나 | 파일을 한 줄에 모은다 | 홀수 그림이 많아도 경고는 한 줄 |
| 프레임 모드 | `prof.frame` 이 홀수일 때 한 번 | 프레임 모드에선 칸 크기를 프로필이 정한다. 시트 안 그림 크기는 피벗과 상관없다. 기본 프레임 64x64 라 거의 안 뜬다 |
| 낱장 모드 | 그림 크기 그대로 | 「한 개짜리 떡」이 바로 이 경우다 |
| 기존 시험 | 구현 판이 전체 시험을 돌려 새 경고가 낀 곳만 기대값을 고친다 | 시험 자료에 홀수 그림이 있으면 `warnings` 가 늘 수 있다 |

끄는 법 : 프로필 `warn.odd_size.enabled: false`. **dry-run** : `check` 는 이미 표에 있다.

## 4. B `reline` 넓히기

**장면**
- #1 : `--scope ring` 은 바깥 1칸 고리만 바꿔서, 2px 선 · 꺾인 자리의 안쪽 칸이 옛 검정으로 남았다(고리 229칸, 안쪽 56칸). `--scope colors` 는 눈동자까지 바꿨다.
- #2 : 선 `#352E27` 이 남색 바지 · 검은 머리 옆에서 면과 밝기가 같아 선이 사라졌다.
- 헷갈린 것 : `changed` 뜻이 scope 마다 다르다.

### 새 인자

| 인자 | 기본 | 뜻 |
| --- | --- | --- |
| `--depth N` | 1 (= 지금) | 투명에서 N 칸 안까지 본다. 2 이상이면 안쪽 칸도 바꾼다 |
| `--color-dark #hex` | 없음 (= 지금) | 둘째 선 색. 면과 밝기가 비슷한 자리에만 쓴다 |
| `--dark-gap G` | 24 | 밝기(luma 0~255) 차가 G 보다 작으면 둘째 색. `--color-dark` 없이 주면 `UsageError` |

`--depth` 가 1 아닌데 `--scope colors` 면 `UsageError` (colors 는 이미 그림 전체라 깊이가 뜻이 없다). `--depth` 는 1~8.

### 안쪽 칸 고르기 (`--depth N ≥ 2`)

안쪽 칸은 아래 셋을 **모두** 만족할 때만 바꾼다.

1. 투명(또는 그림 밖)에서 4방향 걸음으로 N 칸 안이다. (`ring_mask` 가 1칸 고리이니, 그 걸음 거리를 N 까지 늘린 판)
2. 색이 **고른 고리 칸의 색 모음** 중 하나다. `--from` 이 있으면 **`--from` 목록 색** 중 하나다.
3. 고른 고리 칸에서 1 · 2 를 만족하는 칸만 밟아 4방향으로 이어진다.

→ 2px 선 · 꺾인 자리 안쪽은 이어져 있어 바뀌고, 떨어진 눈동자는 안 바뀐다.
눈동자가 선에 붙어 있고 거리가 N 안이면 같이 바뀔 수 있다 — 그래서 기본은 1, 보통 2 로 쓴다고 안내한다.

**`--depth` 와 `--from` 을 같이 줄 때(정한 것)** : 씨앗은 「`--from` 색인 고리 칸」, 넓히기도 「`--from` 색인 칸」만 밟는다.
`--from` 이 「이 색만 선으로 본다」는 뜻이니 깊이도 그 색 안에서만 판다. 목록 밖 색은 깊이와 상관없이 그대로다.

### 둘째 색 (`--color-dark`)

- 바꿀 칸마다, 4방향 이웃 중 **안쪽 면 칸**(불투명이고 이번에 안 바뀌는 칸)의 평균 밝기를 잰다.
- `|luma(선 색) − 평균|` < G 이면 그 칸은 `--color-dark` 로 칠한다. 안쪽 면 이웃이 없으면 기본 색.
- luma 는 `checks.luma` (Rec.601, 0.299 R + 0.587 G + 0.114 B) 를 그대로 쓴다.

### 처리 순서

`ring_mask` → `_pick`(또는 `--from`) → (depth ≥ 2) 안쪽 넓히기 → (color_dark) 칸마다 색 고르기 → 칠하기 → 셈 · 경고.

### 보고

위에 `depth` · `color_dark` · `dark_gap`(없으면 `null`). 장마다:

```json
{"file": "clerk.png", "out": "out/clerk.png", "changed": 285, "changed_ring": 229, "changed_inner": 56,
 "changed_dark": 31, "merged_colors": [], "target": "#352E27"}
```

- `changed` = 바뀐 칸 합계. **지금 뜻과 같다**(옛 호출이면 `changed_inner` 0 · `changed_dark` 0 이라 값이 그대로).
- `changed_ring` = 바깥 고리에서 바뀐 칸, `changed_inner` = 안쪽에서 바뀐 칸, `changed_dark` = 그중 둘째 색으로 칠한 칸(겹쳐 세는 몫).
- `--scope colors` 일 때는 `changed_ring` · `changed_inner` 를 고리 안/밖으로 나눠 센다. 「헷갈린 것」은 이 둘로 풀린다.

### 경고

| rule | 언제 |
| --- | --- |
| `reline.inner_left` | depth 1 인데, 바꾼 고리 칸에 4방향으로 붙은 **같은 옛 색** 안쪽 칸이 남음. detail 에 칸 수와 「`--depth 2` 를 본다」 |
| `reline.low_contrast` | 바꾼 칸 중 면과 밝기 차가 `--dark-gap` 보다 작은 칸이 있는데 `--color-dark` 를 안 줌. detail 에 칸 수와 「`--color-dark` 를 본다」 |

`reline.low_contrast` 는 `--color-dark` 를 안 줘도 G = 24 로 잰다(알려주기만). **dry-run** : 이미 `DRY_RUN_TAKES` 에 있다.

| `reline` | 같은 그림 · 같은 `changed` | depth 1 · color_dark 없음이 지금 동작. 새 칸은 더하기만 |
| `check` | 같은 must · 같은 종료 코드. 홀수 낱장이면 `warnings` 에 한 줄 · `status` 가 warn 이 될 수 있다 | 3절에서 일부러 켰다. 끄는 법 있음 |

## 9. 못 정한 것

| 물음 | 지금 생각 |
| --- | --- |
| 둘째 색을 칸마다 고르면 선이 얼룩질 수 있다 | 1판은 칸마다. 얼룩이 보이면 「이어진 선 토막마다 다수결」로 2판에서 바꾼다 |
| `--color-dark` 이름 | 면이 어두운 자리에서 쓰지만 색 자체는 더 밝을 수도 있다. `--color-alt` 가 더 맞을 수 있다 — 사용자 확인 |
| `shift --light` 를 HSV V 로 | check 와 맞추려 V 로 정했다. 사람 눈 밝기(HSL L)를 바란 것이면 다르게 보인다 — 실물로 한 번 견준다 |
| `odd_size` 기본 켬 | 3절대로 켬. 사용자가 「옛 결과 그대로」를 더 무겁게 보면 끔으로 바꾼다 |
