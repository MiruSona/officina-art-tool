# 도형 렌더러 설계 (시험 판)

> 2026-11-08 · 상태 : 시험 구현 끝, 실측은 `Docs/Research/2026-11-08-도형렌더러슬라임실측.md` · 게임 그림 1 · 2차 `Docs/Research/2026-11-08-도형렌더러게임그림실측.md` · 틀 시험 `Docs/Research/2026-11-08-도형렌더러틀시험.md` · 소품 블라인드 `Docs/Research/2026-11-08-도형렌더러소품블라인드.md`
> 표의 (1차) · (2차) 는 게임 그림 실측에서 더한 칸이다.

## 결론

- **픽셀을 찍지 않고 물체를 적는다.** 물체를 「기본 도형 + 재질」 명세(JSON)로 적으면, 렌더러가 우리 화풍 규칙(빛 방향 · 팔레트 램프 · 디더 · 외곽선 · 색 수 상한)으로 **언제나 같은 그림**을 그린다.
- **방향은 명세가 아니라 보는 각도(view yaw)로 바꾼다.** 명세 하나에서 앞 · 뒤 · 옆이 나온다. 회전 · 변형은 픽셀로 바꾸기 **전에** 도형 단계에서 한다.
- **얼굴 같은 무늬는 「도장」(작은 손그림 격자)을 표면에 붙인다.** 도장은 늘이지 않고 칸 그대로 찍는 「카드」가 기본이다 — 화풍 기준의 「눈 카드」와 같은 생각이다.
- 새 패키지 `arttool.shape` + 명령 `arttool shape render`. 의존성은 기존 numpy · pillow 만.

## 1. 왜 이 길인가

draw 고리 실측(`Docs/Research/2026-10-07-draw고리실측.md`)에서 에이전트가 픽셀을 찍는 길은 원본 닮음(near_shifted)이 .533 → .537 로 거의 안 늘었다.
픽셀 하나하나를 고르는 일은 사람도 에이전트도 틀리기 쉽다. 대신 「둥근 덩어리 · 앞에 눈 둘 · 오른쪽 위에 왕관」 같은 **덩어리 수준**만 적고,
명암 · 외곽선 · 색 고르기 같은 **규칙으로 정해지는 일**은 렌더러가 맡는다.

## 2. 명세 JSON

```json
{
  "version": 1,
  "canvas": { "size": [64, 64], "origin": [32, 50] },
  "light": "top_left",
  "outline": { "mode": "solid", "color": "#CCCCCC", "inner_gap": 3 },
  "max_colors": 16,
  "dither": 0.0,
  "views": { "front": 0, "left": -68, "back": 180, "right": 68 },
  "materials": {
    "slime": { "ramp": ["#E2E2E2", "#FFFFFF"], "ambient": 0.9,
               "rim": { "below": 0.3, "index": 0 },
               "highlight": { "color": "#FFFEF9", "above": 0.9 } },
    "gold":  { "color": "#EDC800", "steps": 4, "ambient": 0.35 }
  },
  "shapes": [
    { "type": "lathe", "material": "slime", "profile": [[0, 0], [13, 0], [20, 8], [20, 16], [11, 31], [0, 34]] },
    { "type": "group", "pos": [15, 30, -6], "rot": [0, 0, -25], "shapes": [ ... ] }
  ],
  "stamps": [
    { "on": "slime", "at": [-7, 18], "grid": ["##", "##", "##"], "legend": { "#": "#000000" } }
  ]
}
```

### 2-1. 좌표

- 단위는 **픽셀**. x 오른쪽 · y 위 · z 보는 사람 쪽(앞). 모델 원점 (0, 0, 0) 이 캔버스 `origin` 칸 경계에 놓인다.
  슬라임이면 원점 = 바닥 가운데.
- 보는 각도 `view` 는 **물체를 y 축으로 돌린 각도(도)** 다. `front` 0 · `back` 180 기본, `left` −90 · `right` 90 기본.
  옆모습을 몇 도로 볼지는 명세의 `views` 로 덮는다 (실물 그림의 「옆」 은 정확히 90° 가 아닌 경우가 많다).
- 빛은 **화면 기준**이다. 물체를 돌려도 빛은 늘 왼쪽 위에서 온다 (스프라이트 방향마다 빛이 같아야 한다 — 화풍 기준 「빛 방향 하나」).
  `top_left` · `top` · `top_right` 또는 [x, y, z].

### 2-2. 도형

| type | 칸 | 뜻 |
| --- | --- | --- |
| `sphere` | `r` | 공 |
| `ellipsoid` | `radii` [a, b, c] | 찌그러진 공 |
| `capsule` | `r` · `length` | y 축 막대 + 양끝 반구 |
| `box` | `size` [w, h, d] · `round` | 둥근 모서리 상자 |
| `lathe` | `profile` [[반지름, 높이], …] | **회전체.** 아래에서 위로 단면 반쪽을 적으면 y 축으로 돌린 몸이 된다. 항아리 · 슬라임 · 왕관 띠 |
| `extrude` | 단면 하나 + `depth` · `round` · `y_down` | **돌출 판.** 2D 단면을 두께로 민다. 앞에서 보면 실루엣이 단면 그대로라 「겹친 색 판」 그림에 쓴다. `y_down` 이면 그림 좌표(아래 +)로 적는다 (1차) |
| ↳ 단면 | `points` · `rect` [x0, y0, x1, y1] · `ellipse` [cx, cy, rx, ry] · `mirror` x | 셋 중 하나만. `mirror` 는 points 반쪽을 x 선에 거울로 비춰 닫는다 (2차) |
| `cone` | `r` · `top` · `height` | 원뿔대 (1차) |
| `group` | `shapes` | 묶음. 안쪽 도형은 묶음 좌표로 적는다 |

모든 도형은 `pos` [x, y, z] · `rot` [x, y, z](도, x → y → z 차례) · `material` · `op` 를 받는다.
`copies` [[dx, dy], …] 를 주면 같은 도형을 그림 칸(아래 +)만큼 옮겨 여러 번 놓는다 — 그릇 둘 · 떡 셋 · 차양 물결 (2차).
앞에서 본 판들은 `pos` z 로 앞뒤를 정하고, z 차가 `outline.inner_gap` 보다 크면 앞 판 둘레에 안쪽 선이 생긴다. 선이 없어야 할 겹침은 z 차를 gap 아래로 둔다.
`op` 는 앞까지 합친 몸과 어떻게 합치나다 — `union`(기본) · `smooth`(+ `k`, 이음매를 둥글게) · `subtract`(파내기).

### 2-3. 재질

| 칸 | 뜻 |
| --- | --- |
| `ramp` 또는 `color` + `steps` | 램프. `color` 를 주면 기존 `palette.shade()` 로 램프를 만든다 |
| `ambient` | 빛이 안 닿는 면의 밝기 (0 ~ 1). 높을수록 납작한 화풍 |
| `rim` | 둘레(보는 쪽과 노멀이 비스듬한 칸)를 램프 `index` 칸으로. 말랑한 물체의 안쪽 테 |
| `highlight` | 반사가 `above` 넘는 칸을 이 색으로 |
| `level` | **납작 칠.** 빛을 안 보고 늘 이 램프 단 (2차) |
| `line` {color, light} | 이 재질 둘레의 바깥 외곽선 · 안쪽 선 색. 빛 쪽 선은 `light` 색 (1차) |
| `bands` [{offset [dx, dy], level, mode}] | **띠 그늘.** 도형 실루엣을 (dx, dy) 옮겨 밖으로 나가는 칸 = 그 쪽 가장자리 띠. `mode: min`(기본, 그 단까지 어둡게) · `set`(그 단으로 — 밝은 띠도 된다, 2차). 차례대로 덮는다 (1차) |
| `pattern` | 재질 무늬 목록 (아래 표) |

| 무늬 kind | 칸 | 하는 일 |
| --- | --- | --- |
| `speckle` | `density` · `seed` · `dot` · `cell` | 점 뿌리기 (1차) |
| `stripes` | `axis` · `period` · `phase` · `width` · `wobble` · `fan` [cx, cy, ref_y] | 줄. `fan` 이면 한 점으로 모이는 부채꼴 줄 — 원근 차양 (1차, fan 2차) |
| `rows` | `rows` [그림 줄…] · `width` | 정한 그림 줄에 가로줄 — 지붕 판자 사이 그늘. 앞에서 본 그림 기준 (2차) |
| `strokes` | `density` · `seed` · `length` · `lean` · `colors` · `jitter` | 잎 붓질. 해시로 시작점을 뿌려 위로 짧은 선을 긋고, 높이에 맞춰 밝은 · 어두운 색을 고른다 (2차) |

색은 `color`(한 색) 또는 `darken`(n 단 내림). strokes 는 둘 다 없어도 된다(`colors` 또는 재질 램프).

밝기 t = ambient + (1 − ambient) × max(0, 노멀 · 빛). 램프 단 = ⌊t × 단 수⌋, 경계는 Bayer 4×4 디더(`dither` 0 ~ 1)로 섞는다.
`level` 이 있으면 이 값 대신 그 단을 쓰고, 그 뒤에 `bands` · `pattern` 이 얹힌다.

`outline` 에는 `inner_width`(1 ~ 4, 2차)가 있다 — 안쪽 선을 앞 판 안쪽으로 몇 칸 두께로 그릴지. 2칸 선 그림(가게 건물)에 쓴다.

### 2-4. 도장 (stamp)

- `at` [x, y] = 앞에서 본 그 자리. 렌더러가 그 자리에서 앞쪽으로 광선을 쏴 **표면 위 한 점**을 찾고 그 점에 도장을 붙인다.
  `yaw` 를 주면 그만큼 돌린 쪽에서 찾는다 (옆구리 무늬).
- 보는 각도마다 그 점을 화면에 비추고, **노멀이 보는 쪽을 향할 때만**(`hide_below`, 기본 0.15) 격자를 **칸 그대로** 찍는다(`mode: card`).
  앞을 가린 도형이 있으면 그 칸은 안 찍고, `on` 재질 칸 밖으로도 안 넘친다.
- `mode: decal` 은 표면을 따라 늘여 붙인다(옆으로 갈수록 좁아진다). 이번 시험은 카드만 쓴다.
- `copies` [[dx, dy], …] 로 같은 격자를 여러 자리에 찍는다 (1차).

### 2-5. 틀 (template)

> 틀 시험 : `Docs/Research/2026-11-08-도형렌더러틀시험.md` · 코드 `src/arttool/shape/template.py` · 시험 `tests/test_shape_template.py`

- **같은 구도로 색 · 부품만 바뀌는 그림 묶음(떡 아이콘 같은)은 틀 하나 + 짧은 값으로 적는다.**
  따라 그린 명세에서 공통 구조를 틀로 빼 두면, 새 그림 명세는 5 ~ 13줄이다.
- 명세 파일이 `{"template": "<틀 파일>", "preset": "<묶음>", "params": {…}}` 이면 `load()` 가 틀을 펼쳐 보통 명세로 읽는다.
  틀 경로는 명세 파일 폴더 기준. 틀 명세에는 이 셋과 `note` 만 둔다. 틀이 다른 틀을 가리킬 수는 없다.

틀 파일

```json
{
  "template_version": 1,
  "params":  { "skin":  { "type": "color", "default": "#C9BCA6" },
               "light": { "type": "color", "default": { "$shade": "$skin", "steps": 6, "base": 3, "pick": 4 } },
               "filling": { "type": "choice", "choices": ["none", "redbean"], "default": "none" },
               "sesame": { "type": "bool", "default": false } },
  "presets": { "mugwort": { "skin": "#4C7433", "light": "#6E9B4A" } },
  "spec":    { "materials": { "m": { "ramp": ["$skin", "$light"] } },
               "stamps": [ { "$if": "sesame", "on": "m", "at": [11, -14.5], "grid": ["ff"], "legend": { "f": "#8A5A2C" } } ] }
}
```

| 틀 식 | 뜻 |
| --- | --- |
| `"$이름"` (문자열 전체) | 그 값으로 바꾼다 |
| `{"$shade": 색, "steps", "base", "pick"}` | `palette.shade(색, steps, base_index=base)[pick]` — 바탕색 하나에서 램프 칸 하나 |
| `{"$mix": [a, b, t]}` | 두 색을 RGB 로 t 만큼 섞기 (0 = a, 1 = b) |
| `{"$add": [a, b, …]}` · `{"$sub": [a, b]}` · `{"$mul": [a, b, …]}` | 수 셈. 부품 크기 값에서 자리를 셀 때 (2-6절) |
| `"$if": 조건` (사전 안) | 거짓이면 그 사전을 통째로 뺀다 — 목록 칸이면 그 칸, 사전 값이면 그 키. 조건 : `"이름"`(참 · choice 는 `none` 이 거짓) · `"!이름"` · `{"이름": 값 또는 [값…]}` |

| 값 type | 받는 것 |
| --- | --- |
| `color` | `#RRGGBB` (대문자로 고쳐 넣는다) |
| `bool` · `number` · `text` | 그 꼴 |
| `choice` | `choices` 중 하나 |

- 값 차례는 **틀 기본 < preset < 명세 params**. 기본 식은 앞에 적은 값을 쓸 수 있어서, `skin` 만 바꿔도 `light` 가 따라 바뀐다.
- 모르는 이름 · 틀린 꼴 · 없는 preset 은 어느 칸인지 한 줄로 `ArtToolError` 를 낸다.
- 일부러 **반복 · 조건 안 조건은 없다.** (수 셈은 2-6절 부품 때문에 더했다.) 여러 자리 찍기는 도장 `copies` 로 한다. 필요해지면 그때 더한다.

### 2-6. 부품 사전 (kit)

> 소품 블라인드 : `Docs/Research/2026-11-08-도형렌더러소품블라인드.md` · 코드 `src/arttool/shape/kit.py` · 시험 `tests/test_shape_kit.py`

- **서로 다른 물건은 틀 하나로 못 덮는다.** 그래서 「나무 틀 · 화분 · 잎 · 리본」 같은 **부품**을 틀 파일로 만들고, 명세에서 여러 부품을 놓아 조립한다.
- 부품 파일은 틀 파일(2-5절)과 같은 꼴이고 `spec` 에 `materials` · `shapes` · `stamps` 만 둔다. 좌표는 부품 기준점(보통 바닥 가운데)이 (0, 0) 이다.
- 명세 `shapes` 맨 위 칸에 놓기 칸을 적는다. `load()` 가 틀 펼치기 다음에 부품을 풀어 묶음(group) 하나로 넣는다.

```json
{ "part": "kit/pot.part.json", "as": "pot", "at": [21, 86], "z": 20, "scale": [1.2, 1], "flip": false,
  "preset": "terracotta", "params": { "w": 26, "h": 27 } }
```

| 칸 | 뜻 |
| --- | --- |
| `part` | 부품 파일 (명세 파일 폴더 기준) |
| `as` | 이름. 부품 재질은 `<as>.<재질>` 로 바뀐다 — 같은 부품을 여러 번 놓아도 안 섞인다. 도장 `on` 도 같이 바뀐다 |
| `at` [x, y] | 기준점을 그림 칸(아래 +)만큼 옮긴다. 도장 `at` 도 같이 옮긴다 |
| `z` | 앞뒤 |
| `scale` | 수 또는 [sx, sy]. **x · y 만** 늘인다(도형 칸 값을 고쳐 정확한 거리 함수를 유지). z(두께 · 앞뒤)는 그대로라 안쪽 선 규칙이 안 바뀐다. 공은 x · y 가 다르면 타원체가 된다 |
| `flip` | 좌우 거울. 돌림 y · z 와 도장 격자도 뒤집는다 |
| `preset` · `params` | 부품 틀 값 |

- 부품이 자기 재질에 없는 이름을 쓰면 **바깥 명세 재질**을 가리킨다(공용 선 재질 나눠 쓰기).
- 부품 안 부품은 4겹까지, 제 자신을 다시 부르면 오류. 모르는 칸 · 같은 `as` 두 번 · 재질 이름 겹침은 어느 칸인지 한 줄 `ArtToolError`.
- 바깥 명세는 놓은 부품 재질에 도장을 더 찍을 수 있다(`"on": "face.m"` — 시계 바늘).
- **파내기 재질** : 파내기(subtract)는 앞 도형의 재질 거리도 같이 깎는다. 그래서 틀에 판 구멍 뒤의 판(액자 종이)이 제 재질로 보인다.
- 늘이기는 도형 자기 축 기준이다 — 돌린 도형에 sx · sy 를 다르게 주면 돌린 뒤가 아니라 돌리기 전 축으로 늘어난다.

### 2-7. 질감 (texture)

> 실측 : `Docs/Research/2026-11-08-도형렌더러질감규칙.md` · `2026-11-08-도형렌더러마무리흐름.md`(follow · fold mass) · 코드 `src/arttool/shape/texture.py` · 시험 `tests/test_shape_texture.py`

- **3단 납작 칠은 게임 그림과 섞으면 티가 난다.** 게임 소품은 반 단 색 · 곁색으로 40 ~ 48색을 쓰고 재질마다 결을 넣는다. 그래서 명세 맨 위 `texture` 목록으로 **모양은 그대로 두고 질감만** 붙인다. 틀 명세(2-5절)도 `template` · `preset` · `params` 옆에 `texture` 를 둘 수 있다.

```json
"texture": [
  { "kind": "wood_grain", "on": ["*.wood", "rim.m"], "density": 0.45, "length": 4, "knots": 0.5, "seed": 3 },
  { "kind": "mottle", "on": "body.m", "cell": 3, "share": 0.16, "strength": 0.3 },
  { "kind": "hue_side", "on": "*", "shift": 8, "share": 0.2, "cell": 3 }
]
```

| kind | 하는 일 | 칸 (기본) |
| --- | --- | --- |
| `wood_grain` | 도형마다 긴 쪽(판 방향)을 따라 끊어진 결 줄. 일부는 밝은 줄, 가끔 옹이(한 단) | `density` 줄 비율(.4) · `length` 토막(5) · `gap` 끊김(.25) · `light` 밝은 줄(.25) · `knots` 100칸당(0) · `dir` auto/x/y |
| `weave` | 칸 `period` 마다 방향이 엇갈리는 사선 줄 (짚 · 바구니) | `period`(4) · `light` 가운데 밝은 줄 · `gap` 빼는 짜임 |
| `mottle` | 값 잡음 덩어리 얼룩. 낮은 곳 어둡게 · 높은 곳 밝게 · 아주 낮은 곳 두 배 | `cell`(2) · `share` 몫(.3) · `deep`(.08) |
| `fold` | 짧은 사선 · 곡선 주름 그늘 + 빛 쪽 옆 칸 밝게. `style: mass` 는 가운데가 넓고 끝이 가는 그늘 판 + 빛 쪽 한 칸 밝은 테 (게임 옷 주름 꼴) | `density` · `length` · `lean` · `bend` · `light` · `style` line/mass(line) · `width` 판 너비 1 ~ 8(3) |
| `hue_side` | 같은 밝기(luma)에서 색조만 ±`shift`° 돈 곁색을 덩어리로 섞는다 | `shift`(10) · `share` · `cell` |

- 공통 칸 : `on` 재질 이름(글자 맞추기 `*` · `?`) 또는 목록 · `seed` · `strength` = **램프 한 단의 몇 몫**(기본 .5 = 반 단, 반 단 색은 램프 두 칸을 섞는다). 램프 밖은 색을 셈한다(어두우면 파랑 쪽, 밝으면 노랑 쪽으로 8°).
- **`follow` (기본 `none`) 은 질감을 모양 · 빛에 묶는다.** `light` : 칸의 램프 단으로 밝은 정도를 잰다. 그늘 쪽 어두운 결은 그대로, 밝은 쪽은 `fade`(.85) 몫만큼 덜고, 밝은 결은 가운데 단에만 남긴다(맨 밝은 단은 비운다). 하이라이트 칸에는 아무 질감도 안 얹는다. 덜어 낼 칸은 2칸 덩어리 잡음으로 골라 결이 점으로 부서지지 않는다.
  `form` : `light` 와 같되 밝은 정도를 노멀(n · 빛)로 부드럽게 재고, 둥근 도형(칸 상자 긴 변 / 짧은 변 < 1.6)은 도형 가운데를 축으로 한 (둘레 길이, 반지름) 좌표로 잡음을 뽑는다 — 얼룩 · 곁색은 둘레 방향으로 2.5배 늘어나고, 나뭇결은 고리를 따라 돈다.
- 규칙은 적은 차례대로 쌓인다. 무늬(pattern) 다음 · 안쪽 선 앞에 얹으므로 선 · 도장 · 외곽선은 질감 위에 그대로 그려진다.
- 질감이 만든 색은 팔레트에 한 색 램프로 덧붙인다(lint stray_color 0). 색 수가 넘치면 `max_colors`(7단계)로 묶는다 — 게임 소품 실측은 「불투명 1000칸당 40색, 많아도 47색」.
- **`texture` 가 없으면 렌더는 질감 전과 칸까지 같고 보고 사전에 `textured` 칸도 안 생긴다.** 모두 정수 해시라 같은 seed 면 같은 그림이다.

### 2-8. 팔레트 잠금 · 안쪽 선 색 · 도장 흔들림 · 주름 자리 (보완 고리 1)

> 실측 : `Docs/Research/2026-11-08-도형렌더러보완고리.md` · 코드 `src/arttool/shape/lock.py` · `render.py` · `texture.py` · 시험 `tests/test_shape_lock.py`

모두 **옵션**이다. 안 쓰면 렌더 결과는 고리 전과 칸까지 같다.

| 칸 | 어디 | 하는 일 |
| --- | --- | --- |
| `palette_lock` | 명세 맨 위 (틀 명세에도) | 모든 색을 정해 둔 팔레트 안 색으로 바꾼다. `file`(램프 파일 또는 목록, `real_len` 존중) 또는 `colors` · `ramps`(글자 맞추기, `!` 빼기) · `keep_steps`(기본 true) · `merge_cost`(기본 10) |
| `outline.inner_color` | `outline` 안 | `line`(기본, 예전) · `material` : 안쪽 선을 그 칸 재질 램프 맨 아래를 같은 색조로 더 어둡게(×.62, 파랑 쪽 6°). 뒤 칸이 빛 쪽이면 맨 아래 칸 그대로 |
| `stamps[].jitter` | 도장 안 | 반복 흔들림 `{seed, shift, gap, thick, seg}` : 복사본마다 위아래 ±`shift` 칸, 가로 `seg` 칸 토막마다 `gap` 몫 끊김 · `thick` 몫 한 칸 두께 (토막 경계도 복사본마다 다르다) |
| `texture[] fold mass` `spots` · `tone` | 질감 규칙 | `spots` [[x, y] 또는 [x, y, 길이]] 를 주면 해시로 뿌리지 않고 그 자리에만 판을 놓는다(어깨 아래 · 팔꿈치 · 주머니 위). `tone: light` 는 밝은 판(머리 빛 띠) |

- **팔레트 잠금 짝짓기** : 색 거리는 CIE Lab ΔE. 재질마다(바깥 외곽선 칸은 따로 한 무리) 색을 밝기(L) 차례로 늘어놓고, 팔레트 색도 L 차례로 늘어놓아 「앞 색보다 어둡지 않은 팔레트 색」만 고르게 하는 동적 계획법으로 (칸 수 × 거리) 합 + 단 합쳐짐 값(밝기 차 5 L 이상인 두 단이 한 색이 되면 `merge_cost` × 적은 쪽 칸 수)을 가장 작게 한다. 램프 단 순서가 안 뒤집히고, 될 수 있으면 단이 안 합쳐진다.
- 렌더 순서에서 잠금은 **7 색 수 상한 바로 앞**이다 (질감 · 안쪽 선 · 도장 · 외곽선이 만든 색까지 모두 잠근다). lint 는 잠금 팔레트를 팔레트로 본다.
- 마무리 흐름에서 잠금을 쓰면 ArtTool `outline` · `merge-colors --palette` 프로필 램프도 같은 팔레트로 둔다 — 그래야 선 색도 팔레트 안이다.
- ArtTool `outline` 에 selout 깊이 `--steps N`(기본 없음 = 예전 두 단 · 빛 쪽 한 단)을 더했다. 두 단씩 끊어 이어 밟아 「selout 을 여러 번 건 것」과 같은 끝 색이 나온다(맨 아래에서 한 번 멈추고 다음 번에 outline 색). 소품 마무리의 selout 두 번은 `--mode selout+light --steps 4` 한 번이 된다.

### 2-9. 잠금 계열 지킴 · 종류별 잠금 프로필 · 빛 띠 한 색 (보완 고리 2)

> 실측 : `Docs/Research/2026-11-08-도형렌더러보완고리.md` 「고리 2」 · 코드 `lock.py` · `texture.py` · `render.py` · 시험 `tests/test_shape_lock_family.py`

모두 **옵션**이다. 안 쓰면 고리 1 과 칸까지 같다.

| 칸 | 어디 | 하는 일 |
| --- | --- | --- |
| `palette_lock.family` | 잠금 안 (기본 false) | **계열 지킴.** 색마다 같은 계열 팔레트 색만 짝 후보로 둔다 — 채도 있는 색은 색조 차 `hue_tol` 안의 채도 있는 색, 회색은 채도 낮은 색끼리. 계열 밖 짝은 거리에 300 을 더해 피하고, 그래도 계열 밖이거나 ΔE 가 `max_de` 를 넘으면 **그 색은 잠그지 않고 둔다** |
| `palette_lock.max_de` | 잠금 안 (기본 14) | family 일 때 잠글 수 있는 가장 큰 색 거리 |
| `palette_lock.hue_tol` | 잠금 안 (기본 35도) | family 일 때 같은 계열로 보는 색조 차 |
| `palette_lock.profile` · `kind` | 잠금 안 | 종류별 잠금 프로필 파일 `{"kinds": {"customer": {...}, "building": "bldg.json", "food": null}}` 에서 `kind` 칸을 읽는다. `null` 이면 잠금 끔. 함께 적은 다른 칸이 프로필 값을 덮는다 |
| `texture[] fold mass tone: band` | 질감 규칙 | 빛 띠를 **한 색**으로 : 띠 안 칸은 `on` 재질 모두(머리결 줄 포함)를 `on` 첫 재질의 가장 많은 색 + `strength` 단 한 색으로 칠한다 |

- **왜 램프 이름이 아니라 색조로 계열을 가르나** : 종류별 팔레트 파일(`mozzi_*_palette.json`)의 「램프」는 밝기 단이 아니라 비슷한 색 무리다(건물 `orange` 램프 6색이 모두 크림). 램프 하나만 고르면 재질 단이 한 밝기로 무너진다.
- 곁색(`hue_side`)은 family 잠금에서 자동으로 같은 계열 안 이웃 색으로 간다 (다른 계열로 튀지 않는다).
- 보고 사전에 `lock_kept`(계열 · 문턱 때문에 안 잠근 칸 수)가 생긴다 (family 일 때만).
- 마무리 흐름에서 family 잠금을 쓰면 `merge-colors --palette` 검사 프로필에 **본 색(안 잠근 색)** 을 램프로 더해야 한다 — 안 그러면 snap 이 안 잠근 색을 다시 팔레트로 끈다.

### 2-10. 둥근 테 결 · 이웃 색 더하기 (보완 고리 3)

> 실측 : `Docs/Research/2026-11-08-도형렌더러보완고리.md` 「고리 3」 · 코드 `texture.py` · 시험 `tests/test_shape_texture_c3.py`

모두 **옵션**이다. 안 쓰면 고리 2 와 칸까지 같다.

| 칸 | 어디 | 하는 일 |
| --- | --- | --- |
| `texture[] wood_grain dir: around` | 질감 규칙 | 둥근 도형(칸 상자 긴 변 / 짧은 변 < 1.6)의 결을 `follow` 와 상관없이 **둘레를 따라** 돌린다. 둥글지 않은 도형은 `auto` 와 같다. wood_grain 에만 쓴다 |
| `texture[] ramp_extra` | 질감 규칙 (모든 종류) | 한 단 옮길 때 **이웃 색을 재질 램프 + 이 색 목록**에서 찾는다. 한 색 재질(틀 색 갈이)에서 그늘 색을 셈하지 않고 정해 둔 색으로 내린다 |

- **왜 around 가 따로 필요한가** : 둘레 결은 원래 `follow: form` 에만 있었다. 그런데 벽시계 테처럼 앞을 보는 판은 노멀 빛이 0 에 가까워 form 이 밝은 결을 다 지운다. 그래서 `follow: light` 로 바꾸면 결이 살지만 가로줄로 돌아간다. around 는 이 둘을 떼어 놓는다.
- **왜 ramp_extra 가 필요한가** : 틀(옷 · 머리) 재질은 한 색 램프다. 이웃 색이 없으면 셈한 색(어두울수록 파랑 쪽으로 돈다)이 나오고, 크림 앞치마에서는 이 색이 회색이 되거나 잠금이 분홍(살빛)으로 보낸다. `ramp_extra: ["#F3D7AF"]` 를 주면 크림 한 단 어두운 색으로 내려간다.
- 잠금 쪽 바꿈은 없다. 종류별 프로필에 램프 파일을 하나 더 적거나(곁 팔레트) `ramps: ["!살빛"]` 로 램프를 빼는 것은 2-8 · 2-9 의 칸으로 된다.

## 3. 렌더 순서

1. 명세 읽기 · 틀 펼치기 · 부품 풀기 · 묶음 풀기 (도형마다 최종 회전 · 자리 행렬)
2. **픽셀 중심마다 정사영 광선** → 거리 함수(SDF) 따라가기 → 표면 깊이 · 노멀 · 맞은 도형
3. 빛 내적 → 램프 단계로 끊기 + 경계 Bayer 디더 → rim · highlight → 재질 무늬(pattern) → 질감(texture, 2-7절)
4. 도장 찍기 (`jitter` 가 있으면 복사본마다 흔들어)
5. 안쪽 선(`inner_gap`) : 깊이가 뒤 칸보다 이만큼 넘게 앞인 칸을 한 단 어둡게 (앞 물체 테두리, `inner_color: material` 이면 재질 램프 맨 아래보다 어둡게)
6. 바깥 외곽선 — **기존 `draw.outline.outline()` 을 그대로 쓴다.** 재질 램프를 `Ramps` 로 묶어 넘겨 selout 도 팔레트 안에 머문다
7. (`palette_lock` 이 있으면) 팔레트 잠금 → 색 수 상한 — 넘으면 가장 적게 쓴 색을 가장 가까운 색으로 합친다
8. **`draw.lint.lint()`** 를 돌려 보고에 싣는다

- 코드는 두 쪽이다 (11-08 P3) : 1~2 = `render.trace()` → `Hits`, 3~8 = `render.finish(spec, hits, yaw, view)`. `render()` 는 둘을 잇기만 하고 출력은 칸까지 같다(`test_shape_flatten.py` 해시 고정).
- 납작화 `shape/flatten.py` 는 진짜 그림에서 가짜 `Hits` 를 만들어 `finish()` 를 그대로 돌린다 (작은 다듬기 모델 설계 3절, `arttool shape flatten`).

## 5. 명령

```
arttool shape render <spec.json> --out <png> [--view front|back|left|right] [--ref 원본.png] [--report r.json]
```

`--ref` 를 주면 원본 대비 닮음(silhouette_iou · exact · near · near_shifted)을 보고에 싣는다.
near_shifted 는 draw 고리 실측 2-2 절 정의 그대로다(원본 불투명 칸 중 RGB 각 칸 차 24 이하 칸 비율, ±2칸 밀어 본 최댓값). 그때 채점기는 저장소에 없어 정의대로 다시 짰다(`shape/score.py`).
