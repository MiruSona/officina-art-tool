## 결론 먼저

1. **한글 깨짐은 실제로 재현했고, 더 나쁜 것도 찾았다.** 출력이 파이프로 나가면 파이썬이 `cp949` 로 쓴다.
   Git Bash 에서 글자가 깨지고, `—` 처럼 cp949 에 없는 글자가 JSON 에 들어가면 **`UnicodeEncodeError` 로 종료 1** 이 난다.
   `cli.main` 첫 줄에서 stdout·stderr 를 UTF-8 로 바꾼다.
2. **받은 그림 손질 명령 셋** — `cutout`(배경 지우기) · `trim`(여백 걷기) · `ui preview`(안내선 없는 9조각 늘려 보기).
3. **비교판 `sheet` 하나** — 확대 · 실루엣 · 4색 · 흐림 · 타일 반복 다섯 판을 한 장에. 판정은 사람이 한다.
4. **기준과 요령은 스킬로 둔다** — `ArtTool/.claude/skills/arttool-usage/`. 그림 그리기 직전에 에이전트가 읽어야 하는 글이라서다.
   숫자 문턱값의 정본은 코드(프로필 기본값 · 템플릿 JSON)에 하나만 둔다.
5. **새 검사 일곱은 모두 「경고」다.** `check` 보고에 `warnings` 칸을 더하고 **`status` · 종료 코드 · `bake` 는 안 바꾼다.**
   (`bake` 는 `status == "ok"` 만 받으므로 `status: "warn"` 을 새로 만들면 기존 길이 깨진다 — `bake.py:56-58`.)
6. **템플릿 = 그리기 전에 까는 밑판.** JSON(값) + 가이드 PNG(겹) + 프롬프트 문장 + 순서 몇 줄. `arttool template list / show / render`.
   같은 템플릿이 `check --template` 로 검사 값까지 넘겨 「그린 것이 밑판대로인가」를 본다. **1차 템플릿은 11개 + 움직임 가이드 `motion` = 12개(확정).**
   보강 판에서 실물에 맞춰 `building` · `machine` · `screen_piece` 를 더해 **15개**다(8-5).
   템플릿 값과 프로필 값이 다르면 **프로필이 이긴다(확정).**
7. **화풍 뽑기 `arttool style extract`** — 기준 그림 폴더에서 주요 색 팔레트 · 외곽선 방식 · 빛 방향 · 도트 배율 · 크기와 색 수의 평소 값을 재서
   팔레트 JSON · 견본 PNG · 프로필 조각 YAML · 보고 JSON 을 낸다. **프로필은 안 덮는다** — 사람이 보고 붙인다.
   프로필에 붙인 화풍은 `template show/render --profile` 이 읽어 견본 띠 · 프롬프트의 색 hex · 램프 · 검사 값에 그대로 쓴다(9절).
8. **실물 시험·보강** — 게임 저장소 그림과 도트가 아닌 그림 무리를 **읽기 전용 사본**으로 써서 화풍 뽑기 · 경고 문턱 · 템플릿 줄을 맞춘다.
   **도트가 아닌 그림 무리**(매끈하게 칠한 그림 · 반투명 가장자리 · 색 수백 이상)는 「도트 아님」 판정 · 오탐 막이 · 크기 / 여백 비율 · 손질 명령 실물에 쓰고,
   화풍 뽑기에도 `--force` 로 돌려 견줌용 결과를 본다(11절).
9. **겹 나누기(묶음 8)** — 「그릴 때부터 겹으로」가 기본 길이다. 모든 템플릿이 기본 겹 구성(`layers`)을 갖고, 겹 묶음 = `layers.json` + 겹별 PNG.
   겹을 얻는 길 셋 : PIL 로 겹별로 그림(`arttool.draw`) · PixelLab 기본체 + inpaint + **차이로 겹 떼기**(`layers diff`, 나중 일에서 당김) · 한 장이면 기존 `split`.
   기존 `layers` 를 묶음 명령(compose · diff · mask · view · check · export)으로 넓힌다. 옛 줄(`arttool layers --profile …`)은 `layers compose` 로 고치고 옛 꼴 살리기 코드는 안 둔다(10절).
10. **스킬은 PixelLab 길과 PIL 길을 둘 다 덮고 스크립트까지 넣는다.** 로직은 코드(`arttool.draw` 공개 모듈 · `arttool intake` 명령)에, 스킬 스크립트(캐릭터 · 타일 · 이펙트 예시 셋)는 얇게(6절).
    비교판 딱지는 **한글을 바로 찍는다** — Pretendard Medium(OFL 1.1, 1.58MB)을 원본 그대로 툴 안에 넣는다(5-1).
11. 구현은 **틀 먼저(직렬) → 갈래 일곱(병렬) → 합치기 → 스킬 → 실물 시험·보강** 순서다(소단계 24개). `effort estimate` 합은 3시간 5분이지만
    L급 새 코드를 2.5배 작게 잡는 버릇이 있어(mem, 10-01) **어림 약 20시간 50분**(합치기 3시간 30분 포함)으로 본다.

## 3. 묶음 1 — 바로 고칠 것

### 3-1. 출력 인코딩

- `cli.main` 맨 앞에 `_utf8_streams()` 를 부른다. `PYTHONIOENCODING` 이 **없을 때만**
  `sys.stdout.reconfigure(encoding="utf-8", errors="backslashreplace")`, stderr 도 같이.
  - 콘솔(tty)은 원래 UTF-8 경로라 바뀌는 것이 없다. 파이프 · 파일로 나갈 때만 바뀐다.
  - `PYTHONIOENCODING` 을 존중하는 것이 비상구다. cp949 로 받아야 하는 사람은 그 값을 준다.
  - `errors="backslashreplace"` 라 어떤 글자가 와도 죽지 않는다.
- **PowerShell 5.1 에서 `$x = arttool …` 로 받는 경우**는 PowerShell 이 `[Console]::OutputEncoding` 으로 읽는다.
  cp949 콘솔이면 이쪽이 깨질 수 있다. README 에 「받아 쓸 때는 `--report` 파일을 읽는다 · 또는
  `[Console]::OutputEncoding = [Text.Encoding]::UTF8`」 한 줄을 둔다. 보고 파일은 이미 UTF-8 이다(`jsonio.py:18`).
- 시험 : `subprocess` 로 `python -m arttool check …` 를 `PYTHONIOENCODING` 을 뺀 환경에서 돌리고
  stdout 바이트가 UTF-8 로 풀리는지 · `—` 가 든 보고가 종료 0 인지 본다.
- **기존 시험 하나를 같이 고친다.** `tests/test_cli.py:139` `test_module_entry_point` 는 `text=True` 라 로캘(cp949)로 풀어 읽는다.

## 4. 묶음 2 — 받은 그림 손질

세 명령 모두 **원본을 안 덮는다**(`--out` 이 `--in` 과 같은 파일이면 거절, `recolor` 와 같은 규칙).
입력은 PNG 한 장이나 폴더(바로 아래 `.png`, `check` 와 같은 규칙). 보고 JSON 은 `--report` 로.

### 4-1. `cutout` — 배경 지우기

```
arttool cutout --in raw/a.png --out clean/ [--key edge|corner|#RRGGBB] [--tol 10] [--shave N] [--report r.json]
```

| 인자 | 뜻 | 기본 |
| --- | --- | --- |
| `--key edge` | 네 변의 모든 칸에서 번진다 | **기본** |
| `--key corner` | 네 모서리 칸에서만 번진다 | |
| `--key #RRGGBB` | 그 색과 가까운 칸을 **그림 전체에서** 지운다 (번지지 않는다) | |
| `--tol N` | 「가까운 색」의 폭. RGB 각 칸 차이의 최댓값 | 10 (화면 배경 피드백의 실측 값) |
| `--shave N` | 지우기 전에 바깥 N 칸을 먼저 투명으로 | 0 |

**알고리즘** (번지기) :

1. `--shave N` 이면 네 변에서 N 칸 띠를 투명으로 만든다. PixelLab 이 흰 띠를 둘러 보낸 그림(목업 피드백 「4px 안쪽을 자른 뒤 지웠다」 ·
   「위 30줄 · 아래 29줄 흰 띠」)을 위한 것이다.
2. 씨앗 색을 정한다. `edge` 면 깎은 뒤의 바깥 한 바퀴에서 가장 많은 색, `corner` 면 네 모서리 색(서로 다르면 넷 다 씨앗).
3. 씨앗 칸에서 4방향으로 번진다. 이웃 칸이 **씨앗 색과** `tol` 안이면 지운다.
   이웃 색과 견주지 않는 까닭 : 그러데이션 바탕을 따라 그림 안까지 번지는 사고를 막는다.
4. 결과 알파는 0 · 255 둘뿐이다. 반투명을 만들지 않는다.

**보고** : 장마다 지운 칸 수 · 남은 bbox · `enclosed`(번지기로 못 닿았지만 씨앗 색과 같은 칸 수 — 고리 안쪽 바탕 같은 것) ·
`edge_left`(지운 뒤에도 바깥 변에 닿은 불투명 칸 수).
**경고** : 90% 넘게 지움(키가 그림 색이었을 수 있다) · `enclosed > 0`(`--key #hex` 로 한 번 더) · `edge_left > 0`(흰 띠가 남았을 수 있다 → `--shave`).
경고는 `status: "warn"`, 종료 0 (`split` · `tile inspect` 와 같은 세 단계).

**못 하는 것** : 바탕과 그림 사이의 밝은 테두리(헤일로)는 안 걷는다. 09-23 설계 7절의 `--rim` 과 같은 일이라 그 판에 같이 한다.

시험 : 모서리 흰 바탕 지움 · 그러데이션 바탕이 그림 안으로 안 번짐 · 흰 띠 + `--shave 4` · 고리 안 바탕이 `enclosed` 로 셈 ·
`#hex` 는 떨어진 자리도 지움 · 같은 경로 출력 거절 · 결과에 반투명 0.

### 4-2. `trim` — 여백 걷기

```
arttool trim --in raw/ --out trimmed/ [--pad N] [--square] [--common] [--report trim.json]
```

- 불투명 칸의 bbox 로 자른다. 정사각형이 아니어도 된다(건물 144×146 같은 것).
- `--pad N` : 자른 뒤 둘레에 투명 N 칸.
- `--square` : 긴 변에 맞춰 정사각으로 채운다. 가운데 맞춤은 `fit_square` 와 같은 `floor(v + 0.5)` 공식(`split.py:284` 주석) — 아이콘 들이기 앞에 쓴다.
- `--common` : **폴더 전체에 bbox 하나**를 써서 모든 장을 같은 자리로 자른다. 겹(레이어) 폴더에 쓰면 쌓았을 때 자리가 그대로다.
  09-23 설계 9-4 의 「겹 `--trim` 은 앵커가 오프셋을 들고 가야 한다」 걱정을 이것으로 피한다.
- 보고에 장마다 `offset: [x0, y0]`(원본에서 잘린 왼쪽 위)을 적는다. 원래 자리로 되돌릴 때 쓴다.
- 빈 그림은 건너뛰고 `warn`.

시험 : 네모 아닌 그림 · `--pad` · `--square` 가운데 · `--common` 이 겹 자리를 지킴 · offset 값 · 빈 그림.

### 4-3. `ui preview` — 안내선 없는 9조각 늘려 보기

```
arttool ui preview --in panel.png --border 26 --size 300x62[,96x48…] --out p.png [--mode stretch|tile] [--scale 2]
```

- `--border` 는 숫자 하나(네 변 같음) 또는 `L,B,R,T` — README 의 **[왼, 아래, 오른, 위]** 순서를 그대로 쓴다.
  `.9.png` 를 주고 `--border` 를 빼면 안내선을 읽는다(`ninepatch.read_guides` 재사용).
- `--mode stretch` 는 Unity Sliced 와 같이 가운데 · 변을 **nearest 로 늘린다**(기본). `tile` 은 되풀이해 붙인다.
- `--size` 를 여럿 주면 옆으로 나란히 한 장에 그린다.
- 거절 : `size < L+R+1` 이나 `T+B+1`(UI 설계의 최소 크기 공식 `_min_size_of`) · border 합이 원본 이상 → 종료 2.
- **늘리는 함수는 `ui/ninepatch.py` 에 둔다.** 나중의 「9-slice 이음매」 검사가 같이 쓴다.

시험 : 모서리 네 칸은 원본과 같은 픽셀 · 변은 한 방향으로만 늘어남 · `.9.png` 경로 · 최소 크기 거절.

## 5. 묶음 3 — 비교판 `sheet`

```
arttool sheet --in a.png b/ c.png --out sheet.png [--kinds zoom,silhouette,colors4,blur,tile] [--scale auto|N]
              [--tile 2|4] [--bg checker|#RRGGBB] [--label] [--report sheet.json]
```

- **그림 하나 = 한 줄, 판 하나 = 한 칸.** 1차 · 2차 · 3차 판을 위아래로 놓으면 그대로 견주기 표가 된다(강좌모음 피드백 7번).
- 기본 `--kinds zoom`. `--scale auto` 는 가장 큰 그림이 256 px 안팎이 되는 정수 배(1~8).

| 판 | 하는 일 | 근거 |
| --- | --- | --- |
| `zoom` | 정수 배 nearest 확대 | denchan 08-19 「정수배로만」 |
| `silhouette` | 불투명 칸을 한 색으로 | 강좌모음 9번 「한 색 채우기」, 강좌자료 4장 #12 |
| `colors4` | 밝기로 4단만 남긴 판 (회색 4색) | 강좌모음 10번 「4색」, denchan 08-18 |
| `blur` | 확대한 판을 가우스 흐림 (반지름 = 배율) | denchan 02-25 「눈을 가늘게」 |
| `tile` | 2×2 또는 4×4 로 이어 붙인 판 | 강좌자료 4장 #26 |

- `colors4` 셈 : 불투명 칸의 밝기(`0.299R + 0.587G + 0.114B`)를 칸 수 기준 4분위로 나눠 네 회색으로 칠한다. 같은 그림이면 늘 같은 결과.
- `blur` 는 Pillow `GaussianBlur` 를 `image.py` 에서 부른다(Pillow 는 `image.py` 에서만 부른다는 기존 결정).
  투명 칸은 먼저 `--bg` 위에 얹은 뒤 흐린다.
- **딱지(`--label`)** : 이름 · `WxH` · 색 수. **한글 파일 이름을 그대로 찍는다(사용자 확정 2026-10-04).** 3×5 박은 글꼴 안은 버렸다.
  글꼴은 **Pretendard 를 ArtTool 안에 넣는다**(5-1). 번호 ↔ 이름 표는 그래도 보고 JSON 에 둔다(긴 이름은 딱지에서 잘리므로).
- 보고 JSON 에 장마다 크기 · 색 수 · 외톨이 칸 수 · 외곽선 몫(6절 검사의 「재기만 하는」 함수를 같이 쓴다)을 적는다.
  판정은 없다 — `status` 는 늘 `ok`.
- 출력이 `image.MAX_PIXELS`(8192×8192)를 넘으면 그리기 전에 거절(기존 `contact_sheet` 와 같다).
- `recolor --sheet` 는 그대로 둔다.

시험 : 판 다섯의 크기 · `silhouette` 색 1개 · `colors4` 색 4개 이하 · 같은 입력 같은 출력 · 한글 이름 딱지(5-1) · 상한 거절.

### 5-1. 딱지 글꼴 — Pretendard

**왜 Pretendard 를 툴 안에** : 툴 폴더는 그 자체로 완결돼야 한다(저장소 규칙 11). 게임 저장소의 글꼴을 가리키면 툴을 떼어 낼 때 깨진다.

**라이선스 (2026-10-04 공식 저장소 `orioncactus/pretendard` 에서 확인)**

| 확인한 것 | 결과 |
| --- | --- |
| 라이선스 | **SIL Open Font License 1.1**. 글꼴만 따로 파는 것 말고는 상업 사용 · 고치기 · 다시 나눠 주기 가능. 눈누 페이지 안내도 같다 |

**어느 파일**

| 후보 | 크기 | 한글 | 판단 |
| --- | --- | --- | --- |
| `Pretendard-Medium.otf` (정적 · 한 굵기) | 약 1.58MB | 11,172자 전부 | **고른다.** 굵기 하나면 되고, 가변 글꼴보다 4배 작다. 흑백 두 값으로 찍으면 가는 획이 끊길 수 있어 Regular 보다 한 단 굵게 잡았다(구현 때 둘을 찍어 견준다) |

- 받는 곳 : `https://github.com/orioncactus/pretendard/releases/download/v1.3.9/Pretendard-1.3.9.zip`(47MB) 안의 `public/static/Pretendard-Medium.otf` 와 `LICENSE.txt`. 판 번호 v1.3.9(2023-11, 지금 최신).

  — `pyproject.toml` 에 `[tool.setuptools.package-data] arttool = ["assets/fonts/*"]` 한 줄이 필요하다. `README` 의 「라이선스」 절에 글꼴 한 줄.
- 찍는 법 : `image.py` 에 `draw_label(arr, text, x, y, px=13)` 를 더한다(Pillow `ImageFont.truetype` — Pillow 는 `image.py` 에서만 부른다는 결정 그대로).
  **글자 크기 13px**(12~14). 도트 글꼴이 아니라 흐려질 수 있으므로 `ImageDraw.fontmode = "1"` 로 **흑백 두 값으로 찍는다** — 반투명 칸이 안 생겨 확대판과 결이 맞다.
  딱지는 확대한 판 아래 띠에 찍으므로 그림 픽셀 크기와 상관없다. 띠 높이 = 글자 크기 + 4.
- **시험이 글꼴 판에 흔들리지 않게** : 픽셀 대조를 하지 않는다. 「딱지 띠 안에 글자 색 칸이 있다 · 띠 밖은 안 바뀌었다 · 한글이 빈 네모(`.notdef`)로 안 나온다(서로 다른 한글 두 글자의 모양이 다르다)」만 본다.
  글꼴 파일이 없으면(설치가 깨짐) 딱지를 빼고 `warn` 한 줄 — 비교판 자체는 그린다.

| | 스킬 스크립트 | `arttool intake` 명령 |
| --- | --- | --- |
| 하는 일 | cutout → trim → sheet → check 를 차례로 부름 | 같다 |
| 보고 | 넷을 따로 남기거나 스크립트가 이어 붙임(로직이 스크립트로 샌다) | `intake_report.json` 하나에 넷 + 가장 나쁜 `status` · 종료 코드 하나 |

| 고를 값 | 넷의 옵션을 스크립트가 다시 받아야 | 넷의 옵션을 그대로 받는다 |

→ **명령으로 둔다(사용자 확정 2026-10-04, 16-1 13번).** 보고 합치기 · 종료 코드가 로직이라 원칙상 코드 몫이다.
꼴 :

```
arttool intake --in raw/ --out clean/ [--key edge|corner|#hex] [--tol N] [--shave N] [--pad N] [--square]
               [--profile P] [--template t.json] [--sheet sheet.png] [--report intake.json]
               [--no-cutout] [--no-trim] [--no-check]
```

- 차례는 cutout → trim → check(`clean/` 폴더, `--template` 이면 템플릿도 견줌) → sheet(`--sheet` 를 줄 때만). 원본은 안 건드린다.
- 단계가 실패하면 거기서 멈추고 `status: fail` · 종료 4 · `failed_step`. 실패 = 다 지워진 그림이 있다(cutout) · 다 비었다(trim) · check 가 `fail`.
  인자가 틀리면(`--tol 999` · `--out` 이 원본 폴더) 아무것도 안 쓰고 종료 2.
- 새 로직은 「차례로 부르고 보고 넷을 묶기」뿐이다. 각 단계는 그 모듈의 함수(`cutout.cutout` · `trim.trim_one` · `check.run` · `sheet.run`)를 그대로 부른다.
  보고는 `steps.<단계>` 에 단계 보고, 맨 위 `warnings` 에 같은 `{rule, ok, detail, items}` 꼴 + `step` 칸.
- **보강 판** : ① 배경 그림(`is_background` + 지운 뒤 남은 칸이 캔버스 3변 이상에 변마다 10% 이상 닿음)이면 그 장의 cutout 을 건너뛰고 `cutout.background_kept` 경고(불투명 큰 배경에 구멍을 뚫던 버그).
  「90% 넘게 지움」 은 실패가 아니라 경고. ② 이번에 쓴 파일만 검수한다(`checked_files` · `not_checked`). `--sheet` 가 `--out` 안이면 거절.
  ③ check 가 `fail` 이어도 `--sheet` 비교판은 만든다 — `status: fail` · `failed_step: check` · 종료 4 는 그대로.

예시 스크립트는 게임 저장소에서 `Tools/ArtTool/.venv/Scripts/python.exe <스킬>/scripts/draw_tile.py --out …` 로 돈다(ArtTool 가상환경에 `arttool` 이 깔려 있다). `그리기-pil.md` 에 이 한 줄을 적는다.

## 7. 묶음 5 — 새 검사 1차 (모두 경고)

### 7-1. 틀 — 보고 · 종료 코드 · 프로필

- `check` 보고에 **`warnings` 칸**을 더한다. 꼴은 `ui check` 와 같다 : 걸린 경고만 `{rule, ok: false, detail, items}` 로.
- **`status` · `failed` · `skipped` · 종료 코드는 안 바꾼다.** 경고가 몇 개든 `status` 는 기존 다섯 규칙으로만 정한다.
  `bake` 는 보고의 `status` 와 `skipped` 만 보므로 그대로 돈다.
- 보고 `version` 은 1 그대로 둔다(칸을 더하기만 한다). 사람용 출력은 JSON 앞에 「경고 N건」 한 줄을 더 찍는다.
- 한 판만 경고를 끄려면 `check --no-warn`. 보고에 `"warnings_off": true` 가 박힌다. `skipped` 에는 안 넣는다(경고는 `bake` 를 안 막으므로).
- **프로필 칸** (모두 `DEFAULTS` 에 더해 옛 프로필도 그대로 읽힌다) :

```yaml
style:                         # 새 최상위 칸 — 「이 게임은 이렇게 그린다」. 템플릿도 읽는다
  outline: unset               # unset | none | black | solid | selout | selout+light  (solid 는 보강 판)
  light: top_left              # 빛이 오는 쪽 : top_left | top | top_right
  scale: 1                     # 그림 한 칸 = 게임 픽셀 몇 개 (보통 1)
  materials: {}                # 램프 이름 → metal | ice | gem | goo | stone | wood | cloth
check:
  max_colors: 48               # 기존 — 실패 규칙 그대로
  warn:
    integer_scale: { enabled: true, block_ratio: 0.95, smooth_ratio: 0.15 }
    outline:       { enabled: true, black_ratio: 0.8 }
    isolated:      { enabled: true, max_ratio: 0.15 }        # 보강 판 : 0.03 → 0.15
    color_cap:     { enabled: true, table: { 8: 4, 16: 8, 32: 16, 48: 44, 64: 48, 128: 48, 256: 64 } }   # 보강 판
    near_colors:   { enabled: true, max_delta: 4, min_pairs: 20 }   # 보강 판 : min_pairs
    ramp_shape:    { enabled: true, steps: [4, 6], hue_min: 5, hue_max: 30 }
    loop_seam:     { enabled: true, k: 2.0, anims: [idle, walk, run] }
  background:
    auto: true                 # 투명 칸이 하나도 없고 짧은 변이 min_side 이상이면 배경으로 본다
    min_side: 128
    color_cap: 64              # 배경 그림의 색 수 경고 한도
    max_colors: null           # null 이면 위 max_colors(실패)를 그대로. 값을 주면 배경 그림에만 그 한도로 실패
```

- 켜고 끄는 칸 이름은 **`enabled`** 다(갈래 0 이 정함). 처음 안의 `on` 은 YAML 1.1(PyYAML)이 열쇠 `on` 을 참거짓 `True` 로 읽어 못 쓴다.
  `on:` 이라고 쓰면 「모르는 항목 : True」 와 함께 이 까닭을 알린다.
- `style.outline: unset` 이 기본이라 **옛 프로필에서는 외곽선 검사가 「방식 미정이라 건너뜀」**으로 지나간다. 오탐을 안 낸다.
- `check --mode auto|sprite|background` 로 배경 판정을 덮어쓸 수 있다. 배경으로 본 그림은 보고 `items` 에 `"background": true` 가 붙는다.

### 7-2. 검사 일곱

각 검사의 문턱값 옆 「(실측)」은 **조사에 숫자가 없어 우리가 정한 시작값**이다. 구현 뒤 소단계 21~23(실물 시험·보강, 11절)에서 그림 사본으로 다시 잰다.

#### ① `integer_scale` — 정수 배율 · 부드러운 확대

- **도트 굵기 섞임** : 그림을 덩어리(투명으로 갈린 8방향 덩어리, 배경이면 32×32 칸)로 나눈다.
  덩어리마다 2×2 격자(어긋남 네 가지 중 가장 잘 맞는 것)를 깔고, **색 경계가 지나가는 칸**만 골라 그 칸 안 네 픽셀이 한 색인 비율을 잰다.
  ×2 로 키운 그림은 이 비율이 거의 1 이고, 1배 그림은 경계에서 한 칸 안에 두 색이 섞여 훨씬 낮다.
  비율 ≥ `block_ratio`(0.95, 실측) 인 덩어리는 「×2」, 3·4 도 같은 방법으로 본다.
  **한 장 안에서 덩어리마다 배율이 다르면 경고**, 모두 같은데 `style.scale` 과 다르면 경고.
- **부드러운 확대** : 왼쪽·오른쪽(또는 위·아래) 이웃 색이 32 넘게 다른데 가운데 칸이 두 이웃의 **딱 중간색**(각 칸 ±8)인 칸의 비율.
  이 비율 > `smooth_ratio`(0.15, 실측)면 경고. bilinear 확대는 경계마다 중간색을 만든다.
- 근거 : denchan 3절 「표시 배율」(08-19 · 06-23) · 강좌자료 4장 #13 · 메인화면목업 피드백 「한 장에 섞인 도트 굵기」.
- 오탐 : 큰 평면 덩어리만 있는 그림(경계 칸이 거의 없음) — 경계 칸이 16개 미만인 덩어리는 판정에서 뺀다. 손으로 넣은 AA 가 많은 그림은 부드러운 확대로 걸릴 수 있다.
- **보강 판** : 경계가 가로 · 세로 직선뿐인 칸(벽 줄 · 2px 줄무늬)은 배율 판정에서 뺀다 — 꺾인 자리 8개 이상이고 (꺾인 ÷ 경계) × n ≥ 0.4 인 칸만 센다(실물 배경 6/8 오탐).
  색이 8가지 이하인 그림은 부드러운 확대를 안 본다(5~7색 부품의 넓은 단계 명암이 0.44 로 걸렸다). 경고 메시지의 비율은 소수 3자리.

#### ② `outline` — 외곽선 방식

- **가장자리 칸** = 투명과 4방향으로 맞닿은 불투명 칸. 그중 **안쪽 불투명 이웃이 있는 칸만** 센다(1~2px 가는 머리카락 끝은 뺀다).
- 잰다 : 순흑 비율(`max(R,G,B) ≤ 24`), 어두움 비율(가장자리 밝기 < 안쪽 이웃 평균 밝기 × 0.85), 색조 차(가장자리 vs 안쪽, 채도 낮은 칸은 뺀다).
- 판정 :

| 판정 | 조건 |
| --- | --- |
| `black` | 순흑 비율 ≥ `black_ratio`(0.8) |
| `selout` | 순흑 < 0.2 · 어두움 ≥ 0.6 · 색조 차 평균 ≤ 40° |
| `selout+light` | `selout` 이면서 빛 쪽 가장자리(`style.light` 방향으로 투명과 맞닿은 칸)의 **안쪽 이웃 대비 밝기** 평균 ≥ 반대쪽 × 1.15. 칸마다 안쪽 이웃과 견주므로 위 · 아래 칠한 색이 달라도(밝은 머리 · 어두운 옷) 빛 방향만 남는다(합치기 판에서 고침 — 처음엔 절대 밝기라 `draw.outline` 의 selout 이 selout+light 로 읽혔다) |
| `none` | 어두움 < 0.3 |
| `mixed` | 위 어디에도 안 맞음 |

- 판정이 `style.outline` 과 다르면 경고. `unset` 이면 판정만 보고에 적는다.
- 덧붙여 **외곽선 몫**(가장자리 칸 ÷ 불투명 칸)과 크기 n 의 (4n−4)/n² 을 적는다. n ≤ 16 인데 `style.outline` 이 `none` 이 아니면 정보 한 줄.
- 근거 : denchan 06-11 · 09-09 · 3절 「외곽선」 · 다른작가 3절 외곽선(HG_EX 계산) · 강좌자료 4장 #4 · #5. 0.8 · 0.6 · 1.15 는 (실측).
- 오탐 : 원래 검은 물건(검은 고양이) · 배경 그림(가장자리가 없음 — 배경 모드면 건너뛴다).
- **보강 판** : 안쪽 색은 바로 안쪽 1px 이 아니라 **1~3px 안쪽 중 가장 밝은 칸**으로 견준다(2px 어두운 선을 「없음」 으로 보던 것 — 실물 「없음」 47장 중 37장이 바뀜).
  순흑 문턱 `BLACK_MAX` 24 → 32. 새 판정 **`solid`**(검정이 아닌 한 색 선)를 더했고 프로필 `style.outline` 도 `solid` 를 받는다.

#### ③ `isolated` — 외톨이 픽셀

- 8이웃에 같은 색이 하나도 없는 불투명 칸. 가장자리 칸(②의 정의)은 뺀다 — 바깥 AA 칸이다.
- 비율(외톨이 ÷ 불투명) > `max_ratio`면 경고. `items` 에 좌표 앞 50개.
  시작값 0.03 은 기준 무리 40% 가 걸려 **보강 판에서 0.15**(기준 8.2%)로 올렸다. 옛 무리와 차이가 작아 좋고 나쁨을 잘 가르지는 못한다.
- 근거 : 강좌자료 4장 #1 · 3장 「cluster · 노이즈」 · denchan 4-1 「축소 흔적」 · PixelLab손님시험 「±2 흔들린 잡색」.
- 오탐 : 눈 하이라이트 같은 「강한 점 하나」 — 비율로 보므로 몇 개는 안 걸린다. 디더를 쓴 거친 재질 — 프로필에서 끈다.

#### ④ `color_cap` — 크기별 색 수 상한

- 크기 n = 불투명 bbox 의 긴 변. `table` 에서 n 이상인 가장 작은 칸의 한도를 쓴다(64 넘으면 마지막 칸).
- 기본 표 8 → 4 · 16 → 8 · 32 → 16 · 48 → 24 · 64 → 32.
  근거 : 8·16 은 강좌자료 3장 「색」(16×16 4~8) · denchan 08-18(4색), 32 는 강좌자료 4장 #6(12~16), 64 는 Derek Yu 전체 16~32.
  48 은 사이 값(실측).
  **보강 판 표** : 8:4 · 16:8 · 32:16 · **48:44 · 64:48 · 128:48 · 256:64** (64 넘으면 마지막 칸). 실물 기준 무리 48 칸 p90 42.2 · 64 초과 p90 54.5 에 맞췄다.
  16 · 32 를 조이는 것은 사용자 판단으로 남겼다.
- 배경 모드 그림은 `background.color_cap`(64, 실측 — 화면배경 피드백에서 단순화한 가게가 38색) 하나를 쓴다.
- 기존 `max_colors`(실패)는 그대로다. 이 검사는 그 아래의 「권장」 줄이다.

#### ⑤ `near_colors` — 비슷한 색 쌍(합치기 후보)

- 그림 한 장의 불투명 색 쌍 중 RGB 각 칸 차이의 최댓값 ≤ `max_delta`(4)인 쌍. 적게 쓰인 쪽 → 많이 쓰인 쪽으로 합치기 후보를 낸다.
- 값 4 의 근거 : PixelLab 출력의 잡색이 각 칸 ±2(PixelLab손님시험) → 두 잡색 차이는 4 까지. 강좌자료 4장 #9.
- 쌍이 `min_pairs`(보강 판 20) 이상이면 경고, `items` 에 쌍 · 개수 앞 20개. 처음엔 한 쌍이라도 걸었는데 기준 무리 38% 가 걸렸다(지금 3.4%, PixelLab 날것 잡색은 그대로 잡힘).
- 색이 4096 넘는 그림은 건너뛰고 info `near_colors.skipped` 한 줄(보강 판 — 1024² 잡음 한 장에 77초 걸렸다).
- 오탐 : 의도한 아주 가까운 AA 색 — 그럴 일은 드물다(4 이하는 눈으로 안 갈린다).

#### ⑥ `ramp_shape` — 램프 모양

- **그림이 아니라 램프 파일을 본다.** 램프 파일이 없으면 건너뛴다(설정상 없는 검사).
- 램프마다(어두운 → 밝은 순서) :
  - 단 수가 `steps`(4~6) 밖 → 경고. `style.materials` 에 재질을 적었으면 재질 표로 바꾼다 : 점액 4 · 목재 4~5 · 돌 5 · 얼음 6 · 보석 7.
  - 밝기가 한 칸이라도 안 오르면(단조 아님) 경고.
  - 이웃 칸 색조 차가 `hue_min`(5°) 미만이 계속되면 「hue shift 없음」, `hue_max`(30°) 초과면 「튐」. 채도 0.12 미만 칸과 `palette.outline` 색은 뺀다.
  - 방향 : 밝을수록 따뜻한 쪽(노랑 60°)으로 가는지. 재질이 `metal` 이면 반대를 기대한다. `cloth` 는 맨 밝은 칸 검사를 뺀다.
- 근거 : denchan 3절 「색 · 팔레트」(4~6단) · 강좌자료 3장 「색」(Slynyrd 약 +20°/칸) · 4장 #7 · #23 · 「재질」 표.
- **걸림돌** : 한 램프 파일 안 길이가 모두 같아야 한다(`palette.py:73-78`, LUT). 재질마다 단 수가 다른 팔레트는 지금 못 담는다
  → 지금은 「재질이 원하는 단 수 ≠ `ramp_len`」을 경고로만 알리고, 길이 다른 램프는 나중 일(15절).
- 오탐 : 그림에서 자동으로 뽑은 예시 팔레트(`palettes/slime_example.json`)는 거의 다 걸린다. 사람이 고른 팔레트에만 뜻이 있다.
  (이 파일을 만드는 명령은 없다. 08-25 구현 때 `Example/` 그림에 쓰인 색을 밝기 순으로 늘어놓고 여섯 칸씩 잘라 한 번 만든 것이다 — 파일 안 `comment` 칸.
  그래서 램프 하나에 노랑과 회색이 섞여 있다.
  묶음 7 의 `style extract` 는 이 「밝기 순으로 자르기」 대신 이웃한 색끼리 램프로 묶는다.)

#### ⑦ `loop_seam` — 애니 루프 이음새

- 프레임 모드는 `frames.json` 의 anim/방향 줄마다, 낱장 모드는 이름이 `<anim>_<방향>_<번호>.png` 인 것끼리 묶는다.
  `anims` 목록(기본 idle · walk · run)에 든 것만 본다 — 공격처럼 안 도는 동작이 걸리지 않게.
- 이웃 프레임 차이 dᵢ(칸마다 RGBA 차이 합, `tile seam` 과 같은 셈)와 마지막 → 첫 차이 d_loop 를 견준다.
  d_loop > `k`(2.0) × dᵢ 중앙값이면 「이음새가 튄다」, d_loop = 0 이면 「마지막 장이 첫 장과 같다(한 박자 멈춤)」.
- 근거 : denchan 06-07 · 05-16 · 4-1 「루프 이음새」 · 강좌자료 3장 「이펙트」 반복(마지막 프레임은 첫 프레임 바로 앞) · 4장 #19. k 2.0 은 `tile seam` 의 값을 빌린 시작값(실측).
- 오탐 : 3장 미만이면 안 본다. 1-2-3-2 핑퐁은 정상이라 d_loop 도 다른 칸과 비슷하게 나온다.

### 7-3. 템플릿과의 관계

`check --template <template.json>` 을 주면 템플릿의 `check` 칸(8-2)을 프로필 위에 겹친다(`deep_merge`, 검증도 같은 함수).
단 **프로필에도 있는 칸(`style.*` · `palette.*` · `tiles.size`)은 프로필 값이 이긴다**(확정 2). 겹치는 차례는 9-4 끝을 본다.
그래서 「이 이펙트는 흰 1색 · 5프레임 · 외곽선 없음」 같은 값이 그대로 경고 문턱이 된다. 템플릿 대조로 생긴 경고는 `rule` 이름 앞에 `template.` 를 붙인다
(`template.frames` · `template.size` · `template.colors`).
템플릿의 최소 규칙 `must` 도 여기서 본다 — `warnings` 안 `"must": true` 줄과 보고 맨 위 `must_failed` 칸(9-4 끝).

### 7-4. 시험

검사마다 코드로 만든 그림으로 「걸려야 하는 것 · 안 걸려야 하는 것」 한 쌍 이상 :
×2 로 키운 사람을 1배 배경에 붙인 그림 / bilinear 로 키운 그림 / 순흑 · selout · 빛 쪽 밝은 외곽선 / 외톨이 5% / 32px 에 20색 /
±2 잡색 / hue shift 없는 램프 · 금속 램프 / 첫 장과 같은 마지막 장. 그리고 **경고가 있어도 `status: ok` · 종료 0 · `bake` 통과**,
옛 프로필(새 칸 없음)이 그대로 읽힘.

## 8. 묶음 6 — 템플릿 (밑판)

### 8-1. 무엇인가

**그리기 전에 깔아 두는 밑판이다.** 사람이 Aseprite 에서 가이드 겹을 깔고 그리듯, 에이전트가 그리기(PIL) · 뽑기(PixelLab) 전에 부른다.
한 템플릿은 넷으로 이뤄진다.

| 구성 | 무엇 | 누가 만드나 |
| --- | --- | --- |
| 값 (JSON) | 크기 · 비율 · 프레임 수 · 프레임 길이 · 색 수 · 외곽선 방식 | 템플릿 파일에 적힌 숫자 + 크기에 맞춘 셈(코드) |
| 가이드 PNG | 기준선 · 상자 · 점 · 이펙트 프레임 모양을 그린 **따로 된 겹** | 코드가 그린다 |
| 프롬프트 문장 | PixelLab 에 붙일 영어 한두 줄(값이 채워진 것) | 템플릿 파일의 틀 + 값 |
| 순서 | 「실루엣 먼저 → …」 몇 줄, 쓸 명령 | 템플릿 파일 |

### 8-2. 파일 꼴 (스키마 v1)

`ArtTool/templates/<이름>.json`. 프로필처럼 `tool_home()` 아래에서 찾고, 경로를 주면 그 파일을 읽는다(게임 저장소가 자기 템플릿을 둘 수 있다).

```json
{
  "version": 1,
  "name": "fx_ring_burst",
  "kind": "effect",
  "title": "고리 폭발 (16×16 · 5프레임 · 흰 1색)",
  "sizes": [[16, 16]],
  "values": { "frame_ms": 50, "colors": 1 },
  "frames": [
    { "draw": [{ "shape": "dot", "size": 2 }] },
    { "draw": [{ "shape": "disc", "r": 8 }] },
    { "draw": [{ "shape": "ring", "r": 8, "width": 2 }] },
    { "draw": [{ "shape": "ring", "r": 8, "width": 1 }] },
    { "draw": [{ "shape": "ring", "r": 8, "width": 1, "dash": 2 }] }
  ],
  "check": { "style": { "outline": "none" }, "check": { "max_colors": 1 }, "frames": 5 },
  "fixed": ["style.outline"],
  "must": ["canvas", "alpha", "scale"],
  "prompt": "pixel art {w}x{h} white burst ring effect, {frames} frames, single color, no outline",
  "steps": ["흰 1색 실루엣으로 다섯 장을 먼저 맞춘다", "색은 그 다음에 입힌다"],
  "sources": ["X도트강좌조사-denchan 3절 프레임 공식 「고리 폭발」"]
}
```

- `kind` 는 코드에 있는 처리기 이름이다 : `character` · `parts` · `background` · `ui9` · `icon_set` · `tile` · `palette` · `effect` · `cycle` · `motion`.
  `cycle` · `motion` 처럼 갈래가 여럿인 템플릿은 `presets` 칸에 이름별 값을 두고 `--preset` 으로 고른다.
  **그리는 법 · 셈은 처리기(코드)에, 숫자는 JSON 에** 둔다. JSON 에 식이나 스크립트를 넣지 않는다.
- 모르는 칸은 거절한다(프로필과 같은 규칙).
- `check` 칸은 프로필 꼴 그대로라 `check --template` 이 겹치기만 하면 된다. `frames` · `size` 처럼 프로필에 없는 대조 값은 따로 읽는다.
- `fixed` : 프로필보다 템플릿 값을 앞세울 칸의 점 경로 목록(예 `style.outline`). 없으면 `[]`. 뜻 · 검증은 9-4 끝.
- `must` : 이 템플릿의 **최소 규칙** — 프로필 · `fixed` 와 상관없이 늘 보는 것. 낱말은 `canvas` · `alpha` · `scale` · `palette` 넷뿐.
  안 적으면 `kind` 의 기본 목록(9-4 표)을 쓰고, 적으면 **기본 목록에 더한다**(빼지는 못한다 — 「최소」라서). 뜻 · 보고 꼴은 9-4 끝.

### 8-3. 명령

```
arttool template list   [--kind K]
arttool template show   <이름|경로> [--size WxH|N] [--preset NAME] [--profile P] [--base #hex] [--material NAME]
arttool template render <이름|경로> --size WxH|N --out guide/ [--preset NAME] [--scale N] [--profile P] [--over 그림.png] [--base #hex] [--material NAME]
arttool check           --in work/ --template guide/template.json
```

- `show` : 크기에 맞춰 셈한 값(예 : 32×32 이면 머리 높이 · 눈 줄 · 가랑이 줄 · 무릎 줄의 y)과 채운 프롬프트 · 순서를 JSON 으로.
  `--profile` 을 주면 프로필의 화풍을 입힌다. 무엇을 어떻게 입히나는 **9-4 에 한 곳으로 모았다.**
  템플릿 값과 프로필 값이 다르면 **프로필이 이긴다(사용자 확정 2026-10-04)** — 외곽선 방식 · 타일 크기는 게임 전체의 결정이다.
- `--size 32` 처럼 수 하나면 정사각(32×32)이다(합치기 판). `--base` · `--material` 은 `palette` 템플릿만 받는다 — 바탕색과 재질(`--preset` 과 같은 뜻의 다른 이름, 둘이 다르면 종료 2).
- `render` 가 쓰는 것 :

| 파일 | 내용 |
| --- | --- |
| `<이름>_guide.png` | 1배 가이드 겹. 투명 바탕에 선 `#FF00FF` · 점 `#00FFFF` · 지키는 자리 `#FFFF00`. 알파 0/255 |
| `<이름>_f<번호>.png` | `effect` · `cycle` 이면 프레임별 밑그림(흰 1색 모양 · 기준선 위치) |
| `<이름>_mask_<겹>.png` | `parts` 면 겹별 마스크(흰 = 그릴 자리). PixelLab `inpaint` 와 `split` 의 `masks` 에 그대로 쓴다 |
| `<이름>_preview.png` | `--scale` 배 확대 + 2px 격자 미리보기. 오른쪽에 선 · 상자 이름표(색 칩 + 끌어낸 줄), 프레임이면 아래에 프레임 이름. 글꼴이 없으면 이름표를 빼고 경고. 사람이 본다 |
| `template.json` | `show` 결과 그대로. `check --template` 이 읽는다 |
| `layers.json` | 겹 목록 뼈대(10-3). PIL 길의 `draw.Canvas` · PixelLab 길의 `layers diff` 가 이어 쓴다 |
| `<이름>_over.png` | `--over` 를 주면 가이드를 그 그림 위에 얹은 확대판. 이미 있는 그림이 밑판과 맞는지 볼 때(11-3) |

- 가이드 색은 프로필 램프에 없는 색이라 **가이드 겹이 결과에 섞여 들어가면 `check` 의 램프 밖 색 · ⑤ 에서 바로 걸린다.**
  `check` 는 **render 폴더(`template.json` 이 있는 폴더) 안에서 그 템플릿 이름으로 시작하는** `<이름>_guide` · `_preview` · `_over` · `_mask_*` 파일만 건너뛰고,
  건너뛴 파일은 보고 `skipped_files` 에 남긴다(보강 판 — 처음엔 이름 꼴만 봐서 `game_over.png` 같은 보통 그림이 검수에서 빠졌다).
- 보강 판 : `--over` 는 그림을 **아래 가운데**로 맞추고 판을 큰 쪽으로 늘린다(처음엔 왼위 맞춤 · 잘림). render 는 템플릿 원본 · `--over` 그림을 못 덮고,
  이미 그린 겹 묶음 폴더에 다시 render 해도 `layers.json` 의 `items` 를 지킨다(겹 목록이 다르면 거절). 빈 마스크는 안 쓰고 `template.mask_empty` 경고.
  `steps` 의 `{셈 이름}` 빈칸은 실제 값으로 채운다. **render 폴더는 커밋하지 않는다** — `template.json` 에 절대 경로가 박힌다.

```json
    "aura":  { "points": 4, "frames": 4, "delay": 1, "amp": 1, "path": "corner" },

```

**나중 템플릿** : 초승달 지우기 · 번개 · 레이저 · 물방울 착수 · 낙하 4종 · 둥근 모양 절차(`shape_round`) · 계단 길이 표 · 7×7 글꼴 틀 · 폭발 · 막기 · 로켓 분사 · 구르기.
(머리카락 · 오라 · 천 셋은 위 `motion_guide` 로 옮겼다.)

### 8-6. 시험

스키마 : 모르는 칸 · 없는 kind · 크기 밖 거절. 셈 : `char_small` 32×32 의 줄 y 값이 표와 같음 · 프로필 `style.outline` 이 템플릿 값을 이김.
그리기 : `fx_ring_burst` 다섯 장의 불투명 칸 수 · 모양(점 · 원 · 고리 두께) · 가이드 색 셋만 씀 · 알파 0/255.
`char_parts` 마스크끼리 안 겹침(`split` 이 거절하지 않음) · `split.json` 초안이 `split` 로 그대로 읽힘.
대조 : 6장짜리 폴더에 5프레임 템플릿 → `template.frames` 경고.
화풍 입히기(9-4) : 견본 띠 줄 수 = 램프 수 · 프롬프트에 프로필 색 hex 가 들어감 · 팔레트 없는 프로필이면 띠 없이 그대로 · `template.json` 에 램프 파일 경로가 박힘.
`fixed` · `must`(9-4 끝) : `fixed` 칸만 템플릿 값이 이김 · 값 없는 `fixed` 경로 거절 · `"must": []` 로 적어도 kind 기본은 남음 ·
크기 다른 그림 → `must.canvas` 경고 + `must_failed` · `allow_alpha: binary` 면 반투명은 기존 `fail` 하나만(`must.alpha` 줄 없음) · `--no-warn` 이어도 `must` 줄은 남음 · `status` 는 그대로.

## 9. 묶음 7 — 화풍 뽑기

### 9-1. 무엇을 · 왜

**「이 게임은 이렇게 그린다」를 기준 그림에서 재서 숫자로 뽑는다.** 새 그림이 같은 화풍으로 나오게, 그리기 전(템플릿)과 그린 뒤(검사)에 같은 숫자를 쓴다.
지금은 화풍이 사람 머릿속과 피드백 글에만 있다. 프로필 `style` 칸(7-1)은 사람이 손으로 채워야 하고, 팔레트는 손으로 고르거나 예시(`slime_example.json`)뿐이다.

**지금 있는 것** — 다시 만들지 않고 넓힌다.

| 있는 것 | 하는 일 | 묶음 7 에서 |
| --- | --- | --- |
| `palette.py` (`load_ramps` · `Ramps` · `to_hex`) | 램프 파일 읽기 · LUT. 쓰기 함수는 없다 | `save_ramps` 를 **더한다**(읽기와 짝) |
| `palettes/slime_example.json` | 그림 색을 밝기 순으로 여섯 칸씩 자른 예시. **만든 명령이 없다**(7-2 ⑥) | 이것을 명령으로 만든 셈. 단 밝기 순 자르기가 아니라 이웃 색 묶기 |
| `recolor` | 겹 + 색표 → N장 | 안 고친다. 뽑은 팔레트로 옛 그림을 맞출 때 보고의 `merged` 표를 색표로 쓴다 |
| 프로필 `style` · `check.warn` (7-1) | 화풍 · 경고 문턱 | 뽑은 값을 이 꼴 그대로 YAML 조각으로 낸다 |
| 검사 ① · ② · ③ 의 「재기」 함수 (`checks/`) | 배율 · 외곽선 · 외톨이 재기 | 그대로 불러 쓴다. 판정 문턱도 같은 값 |
| 배경 판정 (7-1 `check.background.auto`) | 배경 그림 가르기 | 스프라이트와 배경을 따로 잰다 |

### 9-2. 명령

```
arttool style extract --in refs/ [--in more/ …] --out style/ [--name NAME] [--profile P]
                      [--ramp-len N] [--max-colors 64] [--by-folder] [--mode auto|sprite|background] [--with-backgrounds] [--force]
```

- **보강 판** : `--max-colors` 기본 32 → **64**. **`--by-folder`** 는 `--in` 아래 하위 폴더(종류)마다 따로 뽑아 `NAME_<종류>_*` 넷과 요약 `NAME_kinds.json` 을 낸다 —
  무리 전체로 뽑으면 외곽선 · 빛 표가 늘 갈려서(실물시험 2-2) **종류별 뽑기가 권장 길**이다.

- 입력은 PNG 폴더(바로 아래, `check` 와 같은 규칙) 여럿. 원본은 읽기만 한다. `--out` 이 `--in` 중 하나와 같으면 거절.
- `--profile` 은 램프 길이(`palette.ramp_len`) · 경고 기본값을 읽는 데만 쓴다. **프로필 파일은 절대 안 고친다.**
- 결과 넷 (`NAME` 기본은 첫 `--in` 폴더 이름) :

| 파일 | 내용 | 누가 쓰나 |
| --- | --- | --- |
| `NAME_palette.json` | `palettes/` 꼴 그대로(`version` · `name` · `ramp_len` · `outline` · `ramps`) + 덧칸 `comment` · `usage`(hex → 쓰인 몫) · `hue_step`. `load_ramps` 는 모르는 칸을 무시하므로 바로 읽힌다 | 사람이 고쳐 `palettes/` 나 게임 저장소로 옮긴다 |
| `NAME_swatch.png` | 램프 한 줄 = 색 칸 한 줄(8px × 배율). 채운 칸(9-3 ④)은 반 칸 크기로 찍어 구별. 맨 아래에 버린 색 한 줄 | 사람 눈 |
| `NAME_profile.yaml` | 프로필에 붙일 조각(아래). 값마다 주석으로 「몇 장 중 몇 장」 | 사람이 보고 프로필에 붙인다 |
| `NAME_report.json` | 장마다 잰 값 · 무리 요약 · 버린 색 · 합친 색(`merged`) · 경고 | 실물 시험(11절) · 다시 뽑을 때 견주기 |

```yaml
# arttool style extract 가 뽑은 조각 — 보고 고쳐서 프로필에 붙인다. 자동으로 안 붙는다
palette:
  ramp_len: 6
  outline: "#1A1020"             # 순흑 외곽선일 때만. selout 이면 null
  ramps_file: palettes/NAME.json # 팔레트를 그 자리로 옮긴 뒤
style:
  outline: selout                # 18장 중 15장 (83%)
  light: top_left                # 18장 중 12장 · 모름 4장
  scale: 1                       # 18장 모두
check:
  warn:
    color_cap: { table: { 16: 8, 32: 14, 64: 30 } }   # 크기 칸마다 5장 이상일 때만, p90 올림
    isolated:  { max_ratio: 0.045 }                    # 기본 0.03 → p95
```

- 조각에는 **`DEFAULTS` 에 있는 칸만** 쓴다(모르는 칸 거절 규칙, `profile.py:301-321`). **불러온 프로필(`--profile`, 없으면 기본값)과 같은 값은 안 적는다** — 붙여도 바뀌는 게 없는 줄이라서다.
- 상태 : 잴 수 있었으면 `ok`, 아래 오탐·한계에 걸리면 `warn`(종료 0), 그림이 0장이거나 쓸 수 없으면 종료 2.

### 9-3. 무엇을 어떻게 재나

**① 주요 색 팔레트**

1. **잡색 합치기** — 색마다 칸 수를 센다. RGB 각 칸 차이 ≤ 4(검사 ⑤ `near_colors.max_delta`) 인 색은 많이 쓰인 쪽으로 합친다. PixelLab 의 ±2 잡색이 여기서 사라진다.
2. **몫 셈** — 「쓰인 칸 수 순」이 기본이지만, 큰 그림 한 장이 몫을 다 먹지 않게 **장마다 몫(그 장 안의 비율)을 낸 뒤 장끼리 더한다.**
   몫 0.2% 미만이면서 2장 미만에만 나온 색은 버린다(보고 `dropped`).
3. **램프로 묶기** — 밝기 순으로 자르지 않고 **그림에서 맞닿은 색끼리** 묶는다. 램프의 색은 그림에서 이웃해 있기 때문이다.
   - 4방향으로 맞닿은 두 색 쌍을 센다. 쌍 수가 적게 쓰인 쪽 칸 수의 5%(실측) 이상이고 색조 차 ≤ 35°(둘 다 채도 < 0.12 면 색조 무시)면 잇는다.
   - 이어진 덩어리 하나 = 램프 후보 하나. 덩어리 안을 밝기 순으로 세운다. 외곽선 색(② 판정이 `black` 일 때 가장 많이 쓰인 검정)은 램프에서 빼 `outline` 칸에 둔다.
4. **램프 길이 맞추기** — 한 파일 안 램프 길이가 모두 같아야 한다(`palette.py:73-78`, LUT). 길이 L = `--ramp-len` → 프로필 `palette.ramp_len` → 6.
   - L 보다 길면 : 2L 이상이면 밝기 틈이 가장 큰 곳에서 둘로 나누고, 그래도 길면 **밝기가 가장 가까운 이웃 둘을 합친다**(적게 쓰인 쪽 → 많이 쓰인 쪽). 합친 짝은 보고 `merged` 에.
   - L 보다 짧으면 : **끝 색을 되풀이해 채운다**(밝은 쪽 끝). 채운 칸은 보고 `padded` 에. `load_ramps` 는 같은 색 되풀이를 막지 않는다.
     → 검사 ⑥ `ramp_shape` 는 **같은 색이 이어지면 채운 칸으로 보고 건너뛴다**(D 갈래에 넘긴다).
   - **이 길(끝 색 되풀이 + 보고)로 정했다(사용자 확정 2026-10-04, 16-1 9번).**
     길이가 다른 램프를 허락하는 길(팔레트 꼴 v2)은 나중 일이다(15절).
5. **전체 상한** — `--max-colors`(처음 32, Derek Yu 의 16~32 → **보강 판 64**) 를 넘으면 몫이 작은 램프부터 뺀다(보고에 남김).
   뺀 램프가 있으면 `palette_cap` 경고, 뺀 색이 16가지 이상이면 「종류별로 뽑아라」 안내를 붙인다(32 일 때 램프 82개가 잘려 6개만 남았다).

**보강 판에서 램프 묶기에 더한 것** : 검정 · 거의 검정(각 칸 ≤ 24)은 외곽선 판정과 상관없이 **늘 램프에서 빼** `outline_candidate` 로 둔다(`#000000` 이 6번 되풀이된 램프가 나왔다).
외곽선 판정이 `solid` 면 외곽선 칸에 가장 많이 쓰인 색을 `palette.outline`(램프 파일 `outline` 도)에 넣고 램프에서는 뺀다(보고 `edge_color` · `edge_color_count`). 램프 처음~끝 색조 차 상한 40°(분홍 · 베이지 · 노랑 사슬을 끊는다).
한 색뿐인 램프는 덧칸 `singles`, `merged` 는 끝 색까지 따라가 정리하고 `merge_table {from: to}` 로도 낸다(`recolor` 색표로 바로 쓴다). 견본 칸 8px → 16px.
6. **색조 걸음** `hue_step` — 램프마다 이웃 칸 색조 차의 중앙값, 그 중앙값. `palette_ramp` 템플릿이 쓴다(9-4 ⓒ).

**② 외곽선 방식** — 장마다 검사 ② 의 판정 함수를 그대로 부른다. 표를 내어 60% 넘는 판정이 있으면 그것, 없으면 `mixed` 로 적고 조각에는 `outline: unset` 을 둔다.

**③ 빛 방향 어림** — 장마다 불투명 칸의 「밝기 무게중심」이 실루엣 무게중심에서 어느 쪽으로 치우쳤나를 본다
(밝기 − 평균 밝기를 무게로). 외곽선이 검어도 안쪽 칠이 끌고 가므로 외곽선 방식과 상관없이 잰다.
- 치우침이 그림 크기의 5% 미만이면 「모름」. 아래쪽이면 「아래」로 적되 `style.light` 는 위쪽 셋만 받으므로 조각에서 뺀다.
- 위쪽이면 각도로 `top_left` · `top` · `top_right` 셋 중 하나. 장마다 판정 → 표 → 60% 넘으면 조각에.
- **보강 판** : 밝기 무게중심을 그림 전체가 아니라 **같은 색조 램프 덩어리 안에서만** 본다(검정 뺌). 바탕색이 아래쪽에 어두운 평면 아이콘이 「아래」 로 나오던 것 — 실물 「아래」 19 → 14.
  같은 색조 안의 밝은 다른 면(잘린 면)은 아직 못 가른다(다음 판).

**④ 도트 배율** — 검사 ① 의 재기 함수로 장마다 배율(1~4)을 잰다. 가장 많은 값을 `style.scale` 로. 한 장 안에서 섞인 장은 보고 경고에.

**⑤ 크기 · 색 수 분포** — 불투명 bbox 긴 변을 `color_cap` 표의 칸(8 · 16 · 32 · 48 · 64 · 그 위)으로 나누고, 칸마다 장 수 · 색 수 p50 · p90 을 낸다.
칸에 5장 이상이면 p90 올림을 `color_cap.table` 제안으로 쓴다.

**⑥ 「이 게임의 평소 값」** — 외톨이 비율 · 비슷한 색 쌍 수 · 외곽선 몫 · 부드러운 확대 비율 · 덩어리 한 색 비율을 장마다 재고 p50 · p95 를 낸다.
p95 가 기본 문턱보다 높으면(평소 그림이 걸린다는 뜻) p95 를 제안 값으로 조각에 적는다. 낮으면 안 적는다 — 문턱을 조이는 것은 사람이 정한다.

### 9-4. 화풍이 적용된 템플릿 — `template show/render --profile P`

8-3 의 `--profile` 이 하는 일을 여기 한 곳에 모은다. 프로필에서 읽는 것은 `style` 넷 · `palette`(램프 파일) · `tiles.size` · `ui.icon.sizes`.

| | 하는 일 | 프로필에 팔레트가 없으면 |
| --- | --- | --- |
| ⓐ 견본 띠 | `_preview.png` 아래에 그 게임의 램프를 한 줄씩 찍는다. 가이드 겹(`_guide.png`)에는 안 넣는다 — 가이드 색 셋 규칙(8-3)을 지킨다 | 띠 없음 |
| ⓑ 프롬프트 | 템플릿 `prompt` 의 빈칸 `{palette}` · `{outline}` · `{light}` 를 채운다. `{palette}` = `usage` 가 있으면 몫 큰 순 8색 hex, 없으면 램프마다 가운데 칸. `{outline}` = 표 : `none` → "no outline" · `black` → "black 1px outline" · `selout` → "selective outline, darker shade of each fill color" · `selout+light` → 앞 말 + ", lighter on the lit side". `{light}` → "light from top-left" 꼴 | `{palette}` 가 든 마디를 통째로 뺀다 |
| ⓒ `palette_ramp` | `--base` 없으면 프로필 램프를 그대로 견본으로 내고 ⑥ `ramp_shape` 로 재 본다. `--base #hex` 면 새 램프를 만들되 **팔레트의 `hue_step` · `ramp_len` 을 써서** 기존 램프와 결이 같게 | 기본 +20° · 6단 |
| ⓓ `template.json` 의 `check` | `palette.ramps_file`(절대 경로) · `palette.outline` · `style` 을 박는다. `check --template` 만 줘도 그 게임 팔레트로 램프 밖 색을 본다 | 박지 않음 |

**겹치는 차례(확정 2 를 지키는 법)** : `show/render` 가 「템플릿 값 → 프로필 값」 순으로 겹쳐 `template.json` 을 만들고 `"profile_applied": true` 를 적는다.
`check --template` 은 그 표시가 있으면 그대로 프로필 위에 겹치고(이미 프로필이 이긴 값이다), 없으면 프로필에도 있는 칸은 프로필 값을 남긴다.
**예외 `fixed` (사용자 확정 2026-10-04, 16-1 10번)** : 이펙트처럼 「이 템플릿은 늘 이렇다」인 값은 템플릿에 `"fixed": ["style.outline"]` 로 적어 프로필보다 앞세운다(흰 1색 이펙트에 게임의 `selout` 을 들이대지 않게).
- `fixed` 에 적을 수 있는 것은 템플릿 `check` 칸에 실제로 값이 있는 점 경로뿐이다. 값이 없는 경로 · 프로필 `DEFAULTS` 에 없는 경로는 스키마 검사에서 거절.
- `show/render` 가 겹칠 때 「템플릿 → 프로필 → `fixed` 칸만 다시 템플릿」 순서로 겹치고, `template.json` 에 `"fixed"` 를 그대로 옮겨 적는다.
- 1차 템플릿 중 `fixed` 를 쓰는 것 : `fx_*` 셋(`style.outline`). 나머지는 `[]`.

**최소 규칙 `must` (사용자 확정 2026-10-04, 16-1 10번)** — 템플릿마다 「무슨 일이 있어도 지키는 몇 가지」를 둔다.
`fixed` 는 「어느 값을 쓰나」, `must` 는 「무엇을 꼭 보나」라서 서로 다른 칸이다.

| 낱말 | 보는 것 | 셈 |
| --- | --- | --- |
| `canvas` | 캔버스 크기가 맞나 | 그림 크기 = `template.json` 의 고른 크기(`--size`). `icon_set` 은 `ui.icon.sizes` 중 하나 |
| `alpha` | 반투명 칸이 없나 | 알파가 0 · 255 말고 다른 값인 칸 수 = 0 |
| `scale` | 정수 배율이 맞나 | 검사 ① 의 재기 함수로 한 장 안 배율 섞임 없음 · 부드러운 확대 비율 ≤ `smooth_ratio` |
| `palette` | 팔레트 밖 색이 없나 | 팔레트(램프 파일)가 있을 때만. 없으면 「팔레트 없음 — 건너뜀」으로 지나간다 |

**kind 별 기본 목록**

| kind | canvas | alpha | scale | palette | 까닭 |
| --- | --- | --- | --- | --- | --- |
| `character` · `parts` · `cycle` | ✓ | ✓ | ✓ | ✓ | 게임 스프라이트의 기본 |
| `tile` | ✓ | ✓ | ✓ | ✓ | 크기가 어긋나면 격자가 깨진다 |
| `icon_set` | ✓ | ✓ | ✓ | ✓ | 크기는 `ui.icon.sizes` 로 본다 |
| `ui9` | ✓ | ✓ | ✓ | ✓ | 원본 크기 = 9조각 원본 |
| `background` | ✓ | ✓ | ✓ | ✓ | 배경도 도트다. 색 수 한도는 `must` 가 아니라 경고(7-1 `background`) |
| `effect` | ✓ | ✓ | ✓ | — | 이펙트 색(흰 1색 등)은 게임 팔레트 밖일 때가 많다 |
| `motion` | ✓ | ✓ | ✓ | — | 가이드 점 겹이다. 색은 그 위에 그리는 그림이 정한다 |
| `palette` | — | — | — | — | 그림이 아니다 |

**보고 꼴 — 경고 원칙과 안 부딪히게** : `check` 의 「새 검사는 경고만 · `status` · 종료 코드 · `bake` 불변」(7-1)을 지킨다.

- `must` 어김은 **`warnings` 안에 `"must": true` 를 단 줄**로 낸다. `rule` 이름은 `must.canvas` · `must.alpha` · `must.scale` · `must.palette`.
- 보고 맨 위에 **`must_failed`**(어긴 낱말 목록, 없으면 `[]`)를 더한다. `intake` 와 스킬은 이 칸 하나로 「꼭 지킬 것을 어겼나」를 본다. 사람용 출력은 「꼭 지킬 것 어김 N건」 줄을 「경고 N건」 앞에 따로 찍는다.
- **이미 실패 규칙이 같은 것을 보고 있으면 그 실패가 그대로 이긴다.** 프로필 `check.allow_alpha: binary` 면 반투명은 지금처럼 `alpha` 규칙 `fail`, 램프 파일이 있고 `--no-ramps` 가 아니면 램프 밖 색은 `ramp_colors` 규칙 `fail` — 이때 `must.alpha` · `must.palette` 줄은 안 낸다(두 번 세지 않는다).
  실패 규칙이 꺼져 있을 때(`allow_alpha: any` · `--no-ramps`)만 `must` 줄이 경고로 나온다.
- `--no-warn` 은 `must` 줄을 끄지 않는다. 「늘 지키는 것」이라서다. `must` 를 실패로 올리는 스위치는 15절 「경고를 실패로 올리는 스위치」의 첫 후보다.
- **왜 실패가 아니라 표시 단 경고인가** : `--template` 을 주느냐로 같은 그림의 `status` 가 갈리면 `bake` 와 기존 보고를 믿는 길이 흔들린다. 그리고 `canvas` · `scale` 의 셈은 아직 실물로 안 쟀다(11절). 표시와 `must_failed` 칸으로 다른 경고와 섞이지 않게만 해 두고, 실측 뒤 올린다.

### 9-5. 오탐 · 한계

| 경우 | 무엇이 틀어지나 | 다루는 법 |
| --- | --- | --- |
| 기준 그림이 적다 (5장 미만) | 표 · p90 이 흔들린다 | `warn` 「기준 그림이 적다」. 조각에 `style` 만 적고 `check.warn` 제안은 안 낸다 |
| **판정 보류** (보강 판) | 도트 아닌 그림이 절반 넘음 · 도트 그림 5장 미만 · 외곽선 표나 빛 표가 방향끼리 갈림 | `check.warn` 제안을 통째로 빼고 보고에 `held`(처음엔 보류여도 놓친 19장만으로 color_cap {64: 154} 을 냈다) |
| AI 가 뽑은 그림의 ±2 잡색 | 비슷한 색이 수십 개로 갈려 램프가 엉킨다 | ① 1단계에서 합친다. 합친 수를 보고 `noise_merged` 에 |
| 배경과 스프라이트가 섞인 폴더 | 배경 한 장이 몫 · 크기 분포를 흐린다 | 배경 판정(7-1)으로 갈라 **팔레트는 스프라이트만**(기본). 배경은 따로 요약하고 색은 `background_colors` 에만. `--with-backgrounds` 로 섞는다 |
| 도트 그림이 아닌 그림 (반투명 가장자리 · 수백 색 · 부드러운 확대) | 팔레트 · 외곽선이 뜻이 없다 | 장마다 「도트 아님」을 가른다 : 가장자리 칸의 반투명 몫 > 0.2 · 256px 이하인데 색 > 256 · 부드러운 확대 비율 > 0.3 · **크기와 상관없이 색 > 4096** 중 하나(앞 셋은 실측, 넷째는 화풍 갈래가 더함 — 256px 넘는 사진 · 그러데이션이 앞 셋을 빠져나가 장마다 수 초씩 무거운 재기를 탔다). 그런 장은 뺀다. **절반 넘게 도트 아님이면 팔레트를 안 내고 `warn`**, `--force` 로만 낸다. **보강 판** : 둘째 문턱을 「256px 이하 & 색 > 128」 로 내렸다(95.1% → 97.4%, 기준 최대 72색).
`--force` 는 긴 변 256 까지 nearest 로 줄인 표본 + RGB 8걸음 반올림으로 어림한다(391장 12분+ · 6.5GB → 9.9초 · 245MB) |
| 원래 검은 물건 · 겹 하나짜리 파츠 | 외곽선 판정이 `black` 쪽으로 쏠린다 · 색이 2~4개라 램프가 짧다 | 표를 보고 사람이 고친다. 파츠 폴더는 합친 그림으로 뽑으라고 스킬에 적는다 |
| 외부 참고 그림이 섞임 (웹 · 다른 AI 생성) | 남의 화풍이 섞인다 | 툴은 못 가린다. 기준 폴더를 사람이 고른다 — 외부 참고 그림은 뺀다(11-3 ②, 16-1 11번) |

### 9-6. 시험

코드로 만든 그림만 쓴다. 두 램프(빨강 5단 · 파랑 5단, 칸마다 +20°)로 칠한 캐릭터 셋 → 램프 둘이 그대로 나옴 ·
같은 그림에 ±2 잡색을 뿌림 → 결과 같음 · 램프 7단 그림 + `--ramp-len 6` → `merged` 1건 · 3단 → `padded` 3칸 · 결과 JSON 이 `load_ramps` 로 읽힘 ·
왼쪽 위가 밝은 공 → `top_left` · 순흑 외곽선 → `palette.outline` 채움 · 배경 한 장 섞음 → 팔레트 그대로 · bilinear 로 키운 그림만 → 팔레트 없음 + `warn` ·
3장 → 「적다」 · 조각 YAML 을 프로필에 붙이면 `load_profile` 이 받음 · 원본 파일 바이트가 안 바뀜.
템플릿 쪽은 8-6 끝 줄.

## 10. 묶음 8 — 겹 나누기 (「그릴 때부터 겹으로」)

### 10-1. 무엇을 · 왜

사용자 요구(2026-10-04) : 「그림 그릴 때 기본으로 겹을 나눌 수 있어야 한다 — 배경은 바탕 / 장식, 캐릭터는 본체 / 장식 / 머리 / 눈 …」.
지금은 **한 장으로 그린 뒤 나누는 길**만 있다. 피드백에서 겹은 늘 뒤늦게 손으로 떼어졌다 —
주인공 한 장을 몸 · 볼터치 · 표정 · 악세사리 넷으로 손으로 자름(09-20), 손님 파츠는 기본체 + inpaint + 차이 떼기를 손으로 짬(10-03),
화면 배경은 차양이 벽 소품을 가려 PIL 로 다시 그림(10-03), 목업은 글자를 겹 순서 없이 찍어 패널 위로 올라옴(10-03).
그래서 **겹을 「나중에 떼는 것」이 아니라 「처음부터 갖고 가는 것」으로** 바꾼다.

**지금 있는 것**

| 있는 것 | 하는 일 | 묶음 8 에서 |
| --- | --- | --- |
| `split` (`sprite/split.py`) | 한 장 → 겹. 마스크 > 자리 규칙 > 색 표 > 외곽선 투표 순. 출력 `<out>/<겹>/<원본>.png` + `split_report.json` + `anchors.json`. 되돌림 다름 ≠ 0 이면 `fail` | 그대로 쓴다(길 ⓒ). 출력에 **`layers.json` 하나를 더 쓴다** |
| `layers` (`sprite/layers.py`) | 프로필 rig 의 `layer_order` 로 겹을 쌓는다(LPC). 평평한 명령 하나 | **묶음 명령으로 넓힌다**(10-4). 옛 일은 `layers compose` 가 그대로 한다(옛 줄은 고친다) |
| `recolor` | 겹 폴더 × 색 벌 → N장 | 안 고친다. 겹 묶음 꼴이 입력 꼴과 같다 |
| `anchors` · `bake` | 앵커 뽑기 · 프레임 굽기 | 안 고친다. 겹별 앵커는 `split` 의 bbox 앵커를 쓴다 |
| 템플릿 `char_parts` (8-5) | 겹별 마스크 PNG + `split.json` 초안 | **모든 템플릿이 `layers` 칸**을 갖게 넓힌다(10-3) |
| `trim --common` (4-2) | 폴더 전체를 한 bbox 로 자름 + `offset` | `layers export` 가 같은 함수를 쓴다 |
| 「차이로 겹 떼기」 (나중 일, 15절) | — | **1차로 당긴다**(`layers diff`) |

**겹은 캔버스를 안 자른다**는 기존 규칙(README 「겹 나누기」)을 그대로 지킨다. 같은 크기 · 같은 좌표라 쌓기만 하면 맞는다.

### 10-2. 정본 꼴 — 겹 묶음

`split` 출력 꼴을 그대로 정본으로 삼고 목록 파일 하나를 더한다. 새 꼴을 만들지 않는 까닭 : `split` · `layers` · `recolor` 가 이미 이 꼴을 주고받는다.

```
set/
  layers.json          ← 새로 : 겹 목록 (이름 · 순서 · 종류)
  body/idle.png        ← <겹>/<그림>.png (그림 하나면 파일 하나)
  hair/idle.png
  face/idle.png
```

```json
{
  "version": 1,
  "canvas": [32, 32],
  "layers": [
    { "name": "body",  "kind": "body" },
    { "name": "cloth", "kind": "cloth" },
    { "name": "face",  "kind": "face", "exclusive_with": ["hair"] },
    { "name": "hair",  "kind": "hair" },
    { "name": "deco",  "kind": "deco", "optional": true }
  ],
  "items": ["idle"],
  "template": "char_small"
}
```

- `layers` 순서 = 아래에서 위로 쌓는 순서. `kind` 는 정해진 낱말(아래 표) — 검사 · 마스크 · 내보내기가 읽는다. 모르는 칸은 거절.
- `exclusive_with` : 서로 같은 칸을 칠하면 안 되는 짝(얼굴과 머리카락처럼 한쪽이 다른 쪽을 「깎아야」 하는 자리). 나머지 겹끼리는 겹쳐도 정상이다(위 겹이 가린다).
- `optional` : 비어도 경고하지 않는다(장식 없는 손님).
- 프로필 rig 의 `layer_order` 가 있으면 `layers.json` 순서와 같아야 한다(다르면 거절 — 지금 `split --rig` 규칙 그대로).

### 10-3. 템플릿의 기본 겹 구성 — 모든 템플릿에 `layers` 칸

| 그림 종류 (템플릿) | 기본 겹 (아래 → 위) | 비고 |
| --- | --- | --- |
| 캐릭터 (`char_small` · `char_parts` · `cycle_char`) | `body` 본체 · `cloth` 옷 · `face` 눈 · 입 · `hair` 머리카락 · `deco` 장식 | `face` ↔ `hair` 는 `exclusive_with`. `char_parts` 는 옷 겹이 둘(`cloth_bottom` 아래옷 · `cloth_top` 윗옷, 둘 다 kind `cloth`)이고 겹마다 마스크도 낸다 |
| 배경 (`bg_screen`) | `base` 바탕(하늘 · 먼 층) · `structure` 구조물 · `deco` 장식 · 소품 · `front` 앞 층 띠 | 화면배경 피드백 「차양이 소품을 가림」 → 소품을 따로 두면 구조물만 다시 그린다 |
| UI (`ui9_panel`) | `frame` 테 · `fill` 가운데 · `deco` 모서리 장식 | 9조각 늘리기는 합친 판으로 |
| 아이콘 (`icon_set`) | `frame` 테 · `content` 내용 · `badge` 표식(↑ ↓) | 한 벌이 같은 `frame` 을 나눠 쓴다 |
| 타일 (`tile_base`) | `base` 바탕 · `variant` 변종 | 변종은 가운데만(지키는 줄 밖은 `layers check` 가 잡는다) |
| 이펙트 · 움직임 (`fx_*` · `motion_guide`) | `fx` 하나 | 겹을 안 나누는 것도 기본 구성이다 |
| `palette_ramp` | 없음 | 그림이 아니다 |

- `template render` 는 `layers.json` 뼈대(그림 없이 목록만)를 같이 쓴다. 마스크가 뜻 있는 템플릿(캐릭터 · 배경)은 `_mask_<겹>.png` 도.
- 겹 이름은 템플릿의 것이 기본이고, 게임 저장소는 자기 템플릿 파일로 바꿔 쓴다(8-2).

### 10-4. 겹을 얻는 세 길과 명령

| 길 | 언제 | 어떻게 |
| --- | --- | --- |
| ⓐ PIL — 처음부터 겹별로 | PIL 길 전부 | `arttool.draw.Canvas(template="char_small", size=32)` 가 템플릿의 겹 목록으로 빈 겹을 만든다 → 겹마다 그림 → `save("set/")` 가 겹 묶음 꼴로 쓴다 |
| ⓑ PixelLab — 기본체 + inpaint + 차이 | PixelLab 길의 캐릭터 · 파츠 | 기본체 1장 → 템플릿 마스크(또는 `layers mask` 색 칸 마스크)로 겹마다 inpaint → **`layers diff`** |
| ⓒ 한 장으로 받은 그림 | 이미 있는 그림 | 기존 `split`. 템플릿 마스크를 `split.json` 의 `masks` 로 그대로 물린다(이미 있는 칸) |

**명령 체계** : 기존 `layers` 를 `tile` · `ui` 처럼 **묶음 명령**으로 넓힌다. 새 이름(`stack` 같은)을 따로 두지 않는 까닭 : 겹 일은 이미 `layers` 라는 이름에 있고, 묶음이 둘이면 어느 쪽인지 헷갈린다.
`split` 은 「한 장 → 겹」이라는 뜻이 분명하고 쓰는 곳이 있어 그대로 둔다. `bake` 는 프레임 굽기라 손대지 않는다.

```
arttool layers compose --profile P --rig R --in parts/ --out build/ [--anim A]   (옛 `arttool layers …` 가 하던 일)
arttool layers diff    --base base.png --in inpainted/ --out set/ [--template t.json] [--carve report|common|apply]
arttool layers mask    --in base.png --colors #hex[,#hex…] [--grow N] --out mask.png
arttool layers view    --in set/ [--only a,b | --hide c] [--each] --out v.png [--scale N]
arttool layers check   --in set/ [--original a.png] [--template t.json]
arttool layers export  --in set/ --out unity/ [--flat] [--each] [--trim-common] [--anchor bbox_bottom_center]
```

- **옛 꼴은 살리지 않는다(사용자 확정 2026-10-04, 16-1 14번)** : 옛 줄(`arttool layers --profile …`)을 쓰는 곳을 ArtTool 안(README · Docs · tests · 스킬)에서 찾으니
  README 두 줄뿐이었고 시험 · 스킬에는 없었다. 그래서 그 줄을 `layers compose` 로 고치고 호환 코드는 안 둔다.
  옛 줄을 주면 argparse 가 「하위 명령이 없다」로 종료 2 를 낸다. 지난 설계 문서(09-23)의 `arttool layers` 는 그때의 기록이라 안 고친다.
  게임 저장소 쪽 문서에 옛 줄이 남아 있을 수 있다 — 그쪽 일로 넘긴다.
- **`diff`** (손님파츠 피드백을 명령으로) : `inpainted/` 의 장마다 「기본체와 다른 칸」을 그 겹으로 뗀다. 파일 이름 = 겹 이름.
  - 기본체는 `body` 겹이 된다.
  - **마스크 밖이 바뀐 칸**(inpaint 면 0 이어야 함) — `--template` 의 마스크가 있으면 세어 경고.
  - **깎인 윤곽 칸**(기본체에서 불투명 → 결과에서 투명) — 겹마다 수 · 좌표를 보고 `carved` 에. 피드백의 「정수리 한 줄 · 어깨선」.
    `--carve` 는 셋이다(합치기 판에서 고침, 16-1 15번) :
    `report`(기본) — 세기만 하고 **본체(`body`) 윤곽은 그대로 둔다**(피드백 「바라는 것」 2번) ·
    `common` — **모든 겹이 깎은 칸(`carved_all`)만** 본체에서 지운다 · `apply` — 어느 겹이든 깎은 칸을 본체에서 다 지운다(결과 그림을 그대로 따름).
    처음 안의 `keep` 은 `report` 와 하는 일이 같아 뺐다. 지운 칸 수는 보고 `carved_removed` 에 남는다.
  - 겹끼리 같은 칸을 바꿨으면(두 inpaint 가 같은 칸을 그림) `layers.json` 순서상 위 겹이 갖고 경고.
  - **보강 판** : 템플릿이 없으면 파일 이름 첫 낱말로 kind 를 짐작하고 body < cloth < face < hair < deco 순으로 쌓는다(처음엔 `cloth_*` 가 deco 로 들어갔다).
    `--base` 가 `--in` 폴더 안에 있으면 겹에서 빼고 경고.
- 보강 판 공통 : `view` · `export` · `mask` · `diff` 는 원본 보호(17절)를 탄다. `view --report` 를 더했고 `--scale` 상한은 64. `export` 이름 충돌은 `--flat` 이어도 거절(종료 1).
  `check` 의 `layer_poke` 는 `exclusive_with` 짝만 보고, 위 겹이 face 면 건너뛰고, 8이웃으로 4칸 이상 이어진 띠만 센다(32px 템플릿 눈 자리에서 6칸 오탐이 났다).
- **`mask`** : 기본체에서 「이 색 칸만」 마스크를 만든다. `--grow N` 은 N 칸 넓힌다. 네모 마스크가 앞머리를 일자로 자르던 문제(피드백 「바라는 것」 1번)의 답.
- **`view`** : 겹을 켜고 끄며 합친 그림. `--each` 면 겹마다 한 칸 + 합친 것 한 칸을 옆으로 — `sheet` 의 줄 그리기 함수를 빌려 쓴다(딱지 · 확대 같음).
- **`check`** (모두 경고, `check` 의 `warnings` 꼴) : 캔버스 크기 다름 · 반투명 · 빈 겹(`optional` 아니면) · `exclusive_with` 짝의 같은 칸 ·
  템플릿 마스크 밖 칸 · 아래 겹이 위 겹 바깥으로 1칸 삐짐(깎인 윤곽의 흔적) · `--original` 을 주면 **합친 결과 = 원본**(다르면 `fail` — `split` 의 되돌림 규칙과 같은 무게).
- **`export`** : `--flat` 합친 한 장 · `--each` 겹별 PNG(캔버스 그대로). `--trim-common` 이면 겹 전체에 bbox 하나로 잘라 `offsets.json`(`trim --common` 과 같은 함수) —
  Unity 에서 겹별 스프라이트를 같은 피벗으로 쌓을 때 쓴다. 앵커는 `split` 의 bbox 앵커 셋 중 하나.

### 10-5. 1차와 나중

| 1차 | 나중 |
| --- | --- |
| `layers.json` 꼴 · `split` 이 그것을 씀 · 모든 템플릿 `layers` 칸 · `layers` 묶음 명령 여섯(compose · diff · mask · view · check · export) · `arttool.draw.Canvas` 의 겹 저장 | AI 없이 색 덩어리로 겹을 짐작해 나누기 · 겹 순서를 가진 글자 합성(목업 피드백) · Aseprite 겹 파일로 내보내기(`sprite/aseprite.py` 를 넓혀) · 겹별 애니 프레임(겹 × 프레임) · `recolor --multiply` |

까닭 : 1차는 피드백에서 **손으로 한 일**(차이 떼기 · 색 칸 마스크 · 깎인 윤곽 세기 · 겹 켜고 끄며 보기)만 받았다. 나중 칸은 아직 바란 사람이 없다.

### 10-6. 시험

코드로 만든 그림 : 몸 + 머리 + 얼굴 세 겹을 쌓은 판.
`diff` — 기본체 + 머리만 바꾼 판 → `hair` 겹 = 바뀐 칸 · 마스크 밖 0 · 정수리 3칸 깎기 → `carved` 3 · `--carve report` → 몸 윤곽 그대로 · `apply` → 3칸 지움 · `common` → 모든 겹이 깎은 칸만 지움 · `keep` 은 종료 2.
`mask` — 두 색 칸만 흰색 · `--grow 1` 넓이. `check` — 빈 겹 · `exclusive_with` 겹침 · 크기 다름 · 원본과 다름 → `fail`.
`export --trim-common` — 겹마다 offset 같음 · 다시 붙이면 원본. `layers compose` 가 옛 `layers` 와 같은 결과 · 옛 줄(`layers --profile …`)은 종료 2(이 둘은 갈래 0 이 `tests/test_cli.py` 에 넣었다).
`split` 출력의 `layers.json` 을 `layers check` 가 받음. `draw.Canvas.save` 결과를 `layers check` 가 받음.

1. **「도트 아님」 판정이 맞나** — `style extract` 가 이 무리를 거의 다(목표 95% 이상) 「도트 아님」으로 가르나. 오탐 막이 시험.
2. **크기 · 여백 분포** — 이 무리 그림의 크기와 안쪽 여백 비율(여백 ÷ 변)을 `icon_set` · `ui9_panel` · `tile_base` 템플릿 값과 견준다. 도트가 아니어도 비율은 쓸 수 있다.
3. **손질 명령 실물** — 9조각으로 나눌 수 있는 그림으로 `ui preview`(9조각 늘려 보기) · `trim` · `cutout` 을 돌려 본다.
4. **화풍 뽑기 견줌** — `style extract --force` 로 이 무리에도 돌려 본다. 결과는 기준으로 안 쓰고, 도트 무리의 결과와 견주는 데만 쓴다(무엇이 얼마나 다르게 나오나).

### 11-2. 꼭 지킬 것

- **도트가 아닌 그림 무리의 출처 이름 · 경로 · 「썼다는 사실을 알아볼 단서」(폴더 이름 · 파일 이름 · 고유한 크기 조합 · 그림 묘사 · 종류 내역)를 저장소 어디에도 적지 않는다** — 문서 · 코드 · 시험 자료 · mem · 커밋 메시지 모두. 문서에는 「도트가 아닌 그림 무리」로만 쓴다. 장 수 · 크기 현황은 `real.local/현황.md`(git 밖)에만.
- 게임 저장소는 「게임 저장소」로만 쓴다. 게임 이름 · 캐릭터 이름 · 내용을 적지 않는다.
- **원본은 열기만 한다.** 사본에만 명령을 돌린다.
- 사본 자리 : **도트가 아닌 그림 무리는 저장소 밖 임시 자리만**(세션 스크래치패드 또는 `%TEMP%` 아래 — git 무시 폴더라도 저장소 안에는 두지 않는다).
  게임 저장소 그림은 `ArtTool/real.local/game/`(`.gitignore` 의 `*.local/` 로 이미 빠진다) 또는 같은 임시 자리.
  사본 폴더 이름은 `ga/` · `game/` 처럼 중립으로 바꿔 둔다. 끝나면 도트가 아닌 무리의 사본은 지운다.
- **실물 그림을 ArtTool 의 git 추적 자리(시험 자료 포함)에 복사하지 않는다.** 실물에서 찾은 오탐 꼴은 **코드로 비슷한 합성 그림을 만들어** 시험에 넣는다.
- 결과 문서에는 **숫자 · 종류 · 크기만** 쓴다. 그림 · 파일 이름 · 폴더 이름은 안 옮긴다.
- 마지막에 `참고프로젝트.local.md` 의 이름들로 ArtTool 전체를 찾아 **0건**을 확인한다(doc-writing 스킬 검사 가).

**소단계 21 — 사본 · 화풍 뽑기 · 경고 문턱 실측 (실측:M)**

### 12-1. 명령 → 모듈 약속 (갈래 0 이 만든 틀)

`cli.py` 는 새 명령을 **늦게 부른다**(맨 위 `LATE` 표). 갈래는 아래 모듈 파일과 함수만 만들면 바로 붙고, `cli.py` 는 안 만진다.
모듈 · 함수가 아직 없으면 `cli` 가 「아직 구현 안 됨」을 종료 2 로 낸다. 같은 표가 `cli.py` 맨 위 설명에도 있다.

**공통 약속**

- 함수 꼴 `run(args) -> dict`. `args` 는 argparse 결과 그대로다(아래 dest 이름).
- 프로필은 `arttool.profile.load_profile_args(args)` 로 읽는다(`--profile` · `--directions`). 공통 인자 `args.force` · `args.dry_run` 도 있다.
- 돌려주는 dict 의 `status` 는 `ok` · `warn` · `fail`. `fail` 이면 종료 4, 나머지 0.
- `args.report` 가 있으면 **cli 가** 돌려준 dict 를 그 파일에 쓴다. 모듈은 보고 파일을 따로 안 쓴다.
- 잘못된 인자 · 값은 `UsageError`(종료 2), 그 밖의 막힘은 `ArtToolError`(종료 1).
- 경고는 `warnings` 목록, 최소 규칙 어김은 `must_failed` 목록으로 돌려주면 사람용 출력이 「경고 N건」 · 「꼭 지킬 것 어김 N건」 을 찍는다.

| 명령 | 모듈.함수 | args 칸 (dest = 기본값) | 갈래 |
| --- | --- | --- | --- |
| `cutout` | `arttool.edit.cutout.run` | `in_dir` · `out_dir` · `key="edge"` · `tol=10` · `shave=0` · `report=None` | B |
| `trim` | `arttool.edit.trim.run` | `in_dir` · `out_dir` · `pad=0` · `square=False` · `common=False` · `report=None` | B |

- `check` 는 늦게 부르지 않는다. `check.run` 이 키워드 `warn` · `mode` · `template` 셋을 다 받게 되면 cli 가 늘 넘기고, 그 전에는 새 인자를 주면 「아직 구현 안 됨」(종료 2), 안 주면 예전 그대로 돈다. D 는 `check.py` 만 고치면 된다.
- 이 표는 `tests/test_cli_late.py` 의 `CONTRACT` 로 시험한다. 인자를 바꾸면 그 시험이 깨진다 — 바꿀 일이 생기면 「넘긴 것」 표에 적는다.
- 공용 약속 셋 : `arttool.layerset`(겹 묶음 꼴 10-2 — `from_dict` · `load` · `save` · `read_item` · `image_path` · `check_rig_order` · `KINDS`) ·
  `arttool.draw.shapes`(`box` · `dot` · `line` · `disc` · `ring` · `paint` · `to_image`, 불리언 마스크를 돌려준다) · `palette.shade(base, steps=6, hue_step=20, metal=False, base_index=None)`.
- 프로필 새 칸 읽기 : `prof.style` · `prof.warn("<검사>")` · `prof.color_cap_table()` · `prof.check["background"]`. 켜고 끄는 칸 이름은 `enabled`(7-1).

기대는 곳 : `sheet`(C) 와 `style`(G) 은 검사(D)의 재기 함수를, `layers view --each`(H) 는 `sheet`(C) 의 줄 그리기를, `draw.Canvas`(P) 는 템플릿(E)의 가이드 읽기를 쓴다.
→ 기대는 쪽은 처음에 자기 몫만 만들고, 남의 함수에 잇는 줄은 합치기(18)에서 잇는다. G 는 D 의 8 · 9 가 들어간 뒤 시작한다.
