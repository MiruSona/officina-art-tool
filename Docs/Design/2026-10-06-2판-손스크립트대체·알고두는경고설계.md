# ArtTool 2판 설계 — 손 스크립트 대체 열 개 · check 알고 두는 경고 (2026-10-06)

> 근거 : 피드백 원문 `Docs/Todo/2026-10-05-*피드백.md` (아이콘 · 가게 · 농장 · 반복06 · 반복07 · 준비 · 점검).
> 앞 설계 `2026-10-04-피드백후속설계.md` 1절 「공통 약속」(LATE 표 · 원본 보호 · 경고 꼴 · 종료 코드)을 그대로 잇는다.
> 이 문서는 설계까지다. 코드는 사용자 확인 뒤 다른 판이 짠다.

## 결론 먼저

- **사람이 PIL 로 손수 짠 자리 열 개(C1~C10)를 명령 · 옵션으로 넣고, `check` 에 「알고 두는 경고」 빼기(D)를 넣는다.**
- 새 명령 여섯 : `outline` · `fill` · `diff` · `measure shape` · `mask` (최상위) — 그리고 기존 명령 옵션 다섯 : `sheet --strip` · `tint --gif` · `sheet --kinds fit:N` · `check --in` 여럿 · `sheet --scale per`.
- **두 덩이로 나눈다.** 2-가 = C1~C6 + D (작고 기댈 코드가 있다) · 2-나 = C7~C10 (새 셈 · 기존 명령 뼈대를 건드린다).
- **기본값은 모두 지금 동작과 같다.** 옵션을 안 주면 결과가 1바이트도 안 바뀐다.
- **새 라이브러리 없다.** PIL · numpy 만. GIF 는 PIL `save_all` 로 쓴다.
- D 의 `must.*` 줄은 known 으로 **못 뺀다** (3절).

## 1. 공통 꼴 (새 명령마다 같다)

| 자리 | 내용 |
| --- | --- |
| 모듈 | `src/arttool/<묶음>/<명령>.py` 에 `VERSION` · `run(args) -> dict`. `cli.py` `LATE` 표 등록, `_add_<명령>(subs)` 는 `parents=[COMMON]` |
| 가드 | `edit.list_inputs` → `plan_outputs`(`guard_not_folder` · `guard_overwrite`, 원본 덮으면 종료 2). 폴더 입력은 `guard_outside`. 인자 잘못은 `UsageError`(종료 2) |
| dry-run | `cli.DRY_RUN_TAKES` · `DRY_RUN_HARMLESS` · `DRY_RUN_REFUSED` 중 한 곳. 빠지면 `test_dry_run_tables_cover_every_command` 가 깨진다. `is_dry_run` 이면 저장만 건너뛰고 `**dry_run_fields(dry_run, outs)` |
| 보고 | `{version, status, <인자>, images:[…], warnings, out}`. 경고는 `checks.warning("<명령>.<낱말>", …)` |
| 종료 코드 | 0 ok · warn / 1 `ArtToolError` / 2 `UsageError` / 4 `fail` |
| 시험 | `tests/test_<명령>.py` + `test_dry_run_wide` 에 한 줄. 문서는 `Docs/Guide/명령안내.md` · `Docs/Todo/진행상황.md` |
| 기존 명령에 붙는 인자 | 배선 전에도 돌게 모듈은 `getattr(args, "<dest>", 기본값)` 으로 읽는다 |

## 2. 명령별 설계 (C1~C10)

### C1. `outline` — 외곽선 두르기 (S · 아이콘 #5)

장면 : 「바깥에 1px 더 두르기」 · 「맨 바깥 1px 을 선으로 바꾸기」를 손 스크립트로 했다. 셈은 `draw/outline.py` `plan()` 에 이미 있고 `draw/canvas.py` 만 쓴다. 명령 껍데기만 만든다. 자리 : `sprite/outline.py` (`reline` 옆).

| 인자 | 기본 | 뜻 |
| --- | --- | --- |
| `--in` | (필수) | PNG 한 장 또는 폴더 |
| `--out` | (필수) | 출력 파일 · 폴더 |
| `--mode` | `black` | `outline.MODES` 그대로 (none · black · solid · selout · selout+light) |
| `--where` | `outside` | `outside` = 칠한 칸 바깥에 더함 · `inside` = 맨 바깥 칠한 칸을 선으로 |
| `--width` | 1 | 1 ~ 4 (`plan` 이 거른다) |
| `--color` | 없음 | `solid` 일 때만. 다른 mode 에 주면 `UsageError` |
| `--light` | `top_left` | `selout+light` 의 빛 방향 |
| `--grow` | 끔 | 켜면 그리기 전에 캔버스를 사방 `width` 만큼 늘린다 |

처리 순서 : 읽기 → (`--grow` 면 투명으로 늘림) → `plan(arr, mode, where=…, width=…, color=…, light=…, notes=…)` → 칸 목록을 칠함 → 저장.
selout 계열의 램프는 프로필 `ramps_file` 에서 읽는다 (`merge-colors --palette` 가 쓰는 자리). `reline` 은 램프를 안 쓴다 — 조사 때 「reline 과 같은 길」 이라 여긴 것은 틀렸다. 램프가 없는 프로필에 selout 을 주면 `UsageError`.

경고 : `outline.clipped` — `--where outside` 인데 `--grow` 를 안 줘서 캔버스 끝에 닿아 못 그린 칸이 있다 (items 에 `where`=파일 이름, `count`). `plan` 의 `notes` 는 그대로 경고로 옮긴다.

```json
{"version": 1, "status": "warn", "mode": "black", "where": "outside", "width": 1, "grow": false,
 "images": [{"where": "icon_a.png", "added": 84, "size": [32, 32]}],
 "warnings": [{"rule": "outline.clipped", "ok": false, "detail": "캔버스 끝에서 6칸을 못 그림 — --grow", "items": [{"where": "icon_a.png", "count": 6}]}],
 "out": "out/"}
```

dry-run : `DRY_RUN_TAKES` `("outline", None)`.

### C2. `fill --enclosed` — 틀에 갇힌 투명 칸 채우기 (S · 가게)

**`fill` 명령은 지금 없다** (cli 에 `fill` 파서 0건). 새 최상위 명령으로 만들고 이번엔 `--enclosed` 방식 하나만 둔다. 자리 : `edit/fill.py`.

| 인자 | 기본 | 뜻 |
| --- | --- | --- |
| `--in` · `--out` | (필수) | |
| `--enclosed` | (필수) | 지금은 이 방식뿐. 안 주면 `UsageError` (뒤에 다른 방식을 더할 자리) |
| `--color` | (필수) | `#rrggbb` 또는 `#rrggbbaa` |
| `--max-area` | 없음 | 이 칸 수보다 큰 갇힌 덩이는 안 채운다 (일부러 뚫은 창 지키기) |

처리 순서 : 투명 = `alpha == 0` → 그림 테두리의 투명 칸을 시작점으로 `cutout.flood(start, passable=투명)` (4이웃) → 닿은 칸 = 바깥 → **갇힌 칸 = 투명 & ~바깥** → 덩이별로 나눠 `--max-area` 거름 → 칠함.
4이웃으로 퍼지므로 대각선으로만 이어진 1px 선도 「막힌 틀」로 본다 (도트 외곽선은 대개 8이웃 선이다).

경고 : `fill.none` (갇힌 칸 0 — 틀이 열려 있을 수 있다) · `fill.large` (한 덩이가 그림 넓이의 25% 넘음 — 창일 수 있다) · `fill.skipped` (`--max-area` 로 건너뛴 덩이).
보고 `images[]` 에 `regions:[{area, box:[x,y,w,h]}]`.
dry-run : `DRY_RUN_TAKES` `("fill", None)`.

### C3. `diff --alpha-only` — 색 손질 뒤 알파가 그대로인가 (S · 농장)

`layers diff` 는 「기본체와 inpaint 결과로 겹을 떼는」 명령이라 뜻이 다르다. 최상위 `diff` 를 새로 만든다. 자리 : `check/diff.py` 또는 `sprite/diff.py`(구현 때 `layerops` 옆이 편하면 `sprite`).

| 인자 | 기본 | 뜻 |
| --- | --- | --- |
| `--a` · `--b` | (필수) | PNG 둘, 또는 폴더 둘 (같은 이름끼리 짝) |
| `--alpha-only` | (필수) | 지금은 이 방식뿐. 뒤에 「색까지」 방식을 기본으로 더할 자리 |

처리 : 크기가 다르면 그 짝은 `fail`. 같으면 `a[:,:,3] != b[:,:,3]` 칸을 센다. `layerops._changed` 의 알파 반쪽과 같은 셈이라, `_changed` 를 `_alpha_changed` + 색 반쪽으로 쪼개 함께 쓴다 (`_changed` 의 뜻은 그대로).
한쪽에만 있는 파일 이름은 경고 `diff.unpaired`.

```json
{"version": 1, "status": "fail", "alpha_only": true,
 "images": [{"where": "cow.png", "same": false, "changed": 3, "box": [10, 4, 2, 2], "points": [[10,4],[11,4],[10,5]]}],
 "warnings": [], "out": null}
```

종료 : 알파가 다른 짝이 하나라도 있으면 `status: fail` → 4. 이 명령은 「검사」라 다름이 곧 실패다.
dry-run : 파일을 안 쓰므로 `DRY_RUN_HARMLESS` `("diff", None)`.

### C4. `sheet --strip` — 낱장을 가로 시트로 (S · 반복06)

| 인자 | 기본 | 뜻 |
| --- | --- | --- |
| `--strip` | 끔 | 켜면 여백(`gap`)0 · 딱지 없음 · 배율 1 · 바탕 투명으로 `--in` 순서대로 가로로 붙인다 |

`--strip` 이면 `--kinds` · `--scale` · `--grid` 를 주면 `UsageError` (뜻이 섞인다). 프레임 크기가 다르면 `ArtToolError` (시트 칸은 같은 크기여야 엔진이 자른다).
보고에 `frame:[w,h]` · `count` 더함. `sheet` 는 이미 `DRY_RUN_TAKES` 에 있다.

### C5. `tint --gif` — 색마다 낸 장을 움짤로 (S · 반복06)

| 인자 | 기본 | 뜻 |
| --- | --- | --- |
| `--gif` | 없음 | GIF 경로. 주면 색마다 낸 그림을 순서대로 한 장씩 프레임으로 |
| `--duration` | 110 | 프레임 한 장 ms. `--gif` 없이 주면 `UsageError` |

**GIF 처리 방식 (정함)** — PIL 의 기본 변환은 팔레트를 프레임마다 새로 만들고 투명을 잃는다. 그래서 직접 만든다.
1. 모든 프레임의 불투명 색을 모아 **공용 팔레트 하나**를 만든다. 0번 = 투명 자리.
2. 색이 255 개를 넘으면 `ArtToolError`(종료 1) — 도트에서는 거의 없고, 줄여 넣으면 색이 몰래 바뀐다.
3. 알파 `< 128` 은 투명(0번), 나머지는 불투명으로 본다. 반투명 칸이 있으면 경고 `tint.gif_alpha` (count).
4. `save(save_all=True, append_images=…, duration=…, loop=0, transparency=0, disposal=2, optimize=False)`.
   `disposal=2` 로 앞 프레임 찌꺼기를 지우고, `optimize=False` 로 PIL 이 팔레트 칸을 줄여 번호가 밀리는 일을 막는다.
5. 쓰는 함수는 `image.save_gif(frames, path, duration)` 하나로 `image` 모듈에 둔다 (툴 첫 GIF 쓰기라 한 곳에 모은다). tmp → rename.

`--gif` 경로도 `plan_outputs` 쓸 목록에 넣어 원본 덮어쓰기를 막는다. `tint` 는 이미 `DRY_RUN_TAKES`.

### C6. `sheet --kinds fit:N` — 줄여 찍힌 모습 (S · 아이콘 #8)

32 그림을 24 자리에 nearest 로 찍으면 어떻게 보이나. `--kinds` 의 새 종류 `fit:N` (N = 목표 긴 변 px, 1 ~ 그림 긴 변).
셈 : 비율 지켜 긴 변을 N 으로 nearest 줄임 → **다시 원래 크기로 nearest 키우지 않고** N 크기 그대로 칸에 넣는다 (그 뒤 시트 배율은 다른 칸과 같다).
여러 개 가능 (`zoom,fit:24,fit:16`). N 이 그림보다 크면 그 칸은 원본 그대로 + 경고 `fit_upscale`. 기본 `--kinds zoom` 그대로.

### C7. `measure shape` — 합성 창 자리를 잰다 (M · 반복06 #1)

새 묶음 `measure`, 첫 하위 명령 `shape`. 자리 : `measure/shape.py`. 덩이 고르기는 `cutout.flood` 를 쓴다.

| 인자 | 기본 | 뜻 |
| --- | --- | --- |
| `--in` | (필수) | PNG 한 장 |
| `--at` | 없음 | `x,y`. 그 칸이 든 덩이를 잰다 |
| `--color` | 없음 | 이 색 칸 덩이 중 가장 큰 것. `--at` 과 둘 중 하나는 꼭 (`UsageError`) |
| `--tol` | 0 | 색 거리 허용 (`--color` 일 때) |

처리 : 덩이 칸 목록 → 칸 수 `area`, 둘레 칸 → 무게중심 `center` (소수 둘째 자리), 반지름 `r = sqrt(area/π)` 와 둘레 칸까지 거리 최댓값 `r_max`, `box`.
원다움 `roundness = r / r_max` (1 에 가까울수록 원). 0.85 밑이면 경고 `measure.not_round`.

```json
{"version": 1, "status": "ok", "in": "frame.png",
 "shape": {"center": [15.5, 12.0], "r": 6.98, "r_max": 7.21, "area": 153, "box": [9, 5, 14, 14], "roundness": 0.97},
 "warnings": [], "out": null}
```

`--report` 로 이 JSON 을 남기면 C8 이 그대로 읽는다. dry-run : `DRY_RUN_HARMLESS` `("measure", "shape")`.

### C8. `mask --from-shape` — 잰 원으로 흰 가림판 (S)

`layers mask` 는 「이 색 칸만」 이라 다르다. 최상위 `mask` 새 명령. 자리 : `edit/mask.py`.

| 인자 | 기본 | 뜻 |
| --- | --- | --- |
| `--from-shape` | (필수) | C7 보고 JSON (`shape.center` · `shape.r` 을 읽는다) |
| `--size` | (필수) | `w,h` 출력 크기. 또는 `--like 그림.png` 로 크기만 빌림 (둘 중 하나) |
| `--r` | `round` | `round`(r 반올림) · `max`(r_max) · 숫자 |
| `--invert` | 끔 | 켜면 원 바깥이 흰색 |
| `--out` | (필수) | PNG |

칸 중심 `(x+0.5, y+0.5)` 이 원 안이면 흰색 불투명, 아니면 투명. 원이 캔버스를 벗어나면 경고 `mask.clipped`.
JSON 에 `shape` 가 없으면 `UsageError`. dry-run : `DRY_RUN_TAKES` `("mask", None)`.

### C9. `check --in` 여럿 (M · 준비 #9)

지금 `--in` 은 하나(`dest="in_dir"`, `required=True`). `sheet` 처럼 `nargs="+"` 로 바꾼다 (`dest="in_dirs"`, 모듈은 `getattr` 로 옛 `in_dir` 도 받는다).

- **입력마다 따로 판정한다.** frames.json 길과 낱장 길을 입력마다 고른다 — 한 판에 섞여도 된다.
- **`where` 앞에 입력 딱지를 붙인다** — 입력이 둘 이상일 때만 `<폴더 이름>/<where>`. 폴더 이름이 겹치면 `1:<이름>` · `2:<이름>` 처럼 순번을 붙인다. 입력이 하나면 지금과 똑같다 (호환).
- 보고 위에 `inputs:[{path, label, mode, frames}]` 를 더한다. `rules` 는 합친 한 목록.
- `--files @list.txt` 는 **뒤로 미룬다** (2절 끝 「못 정한 것」).
- `check` 는 `DRY_RUN_HARMLESS` 그대로.

### C10. `sheet` 칸마다 배율 (M · 점검 #8)

`pick_scale` 은 가장 큰 그림 하나로 배율을 정한다. 25px 소품과 397px 조각이 한 판이면 소품이 1배로 나온다.

| 인자 | 기본 | 뜻 |
| --- | --- | --- |
| `--scale` | `auto` | 기존 값 그대로 + 새 값 `per` |

`per` 이면 **그림(줄)마다** `pick_scale("auto", [그 그림])` 로 배율을 따로 정한다. 줄 딱지 끝에 `×N` 을 붙여 읽는 사람이 크기를 오해하지 않게 한다.
`layout_rows` 는 이미 「줄마다 칸 수 · 크기가 달라도 된다」 이므로 배율 자체는 부르는 쪽(`sheet.run`)에서 끝난다. `layout_rows` 는 **줄 딱지에 배율을 싣는 자리만** 손댄다 (딱지 글자를 넘기는 쪽에서 붙이면 `layout_rows` 를 안 건드려도 된다 — 구현 때 더 작은 쪽).
보고 `images[]` 에 `scale` 을 그림마다 넣는다 (지금은 위에 하나).

## 3. D. `check` 알고 두는 경고 빼기

장면 : 게임 쪽 스크립트가 (묶음 · 규칙 · 파일 무늬) 목록으로 「새 경고」만 셌다 (준비 #11). 반복07 에선 KNOWN 목록 12줄을 손으로 옮겨 적었다.

### 인자

| 인자 | 기본 | 뜻 |
| --- | --- | --- |
| `--known` | 없음 | 목록 JSON. `[{"rule": "...", "where": "글롭", "note": "왜 두나"}]` |
| `--baseline` | 없음 | 옛 `check` 보고 JSON. 그 안 경고의 `(rule, where)` 를 같은 항목 꼴로 바꿔 `--known` 에 더한다 (`note` = `baseline:<파일>`) |
| `--fail-on-new` | 끔 | 켜면 새 경고 > 0 이 `fail` |

둘 다 여러 번 줄 수 있다 (`action="append"`).

### 맞추기

- 열쇠는 `(rule, where)` — `detail` 은 개수가 섞여 열쇠로 못 쓴다.
- `rule` · `where` 둘 다 `fnmatch.fnmatchcase` 글롭 (대소문자 가림). `*` 는 `/` 도 넘는다 — 프레임 길의 `where` 가 `anim/dir` 이라 `walk/*` 로 방향 전부를 쓸 수 있다. 이름에 `[` 가 든 파일은 `--baseline` 이 `[[]` 로 감싸 넣는다.
- **맞추는 단위는 경고 줄이 아니라 `items` 한 칸이다.** 한 경고 줄의 칸 일부만 맞으면 줄을 둘로 쪼갠다 — 맞은 칸은 `known`, 나머지는 `warnings` 에 남는다. `items` 가 없는 경고는 `where` 를 빈 글로 보고 `where: "*"` 항목만 맞는다.
- 입력이 여럿(C9)이면 `where` 에 입력 딱지가 붙은 뒤에 맞춘다.

### 보고 (더하는 칸만)

```json
{"status": "ok", "new_warnings": 1,
 "warnings": [{"rule": "palette.extra", "ok": false, "detail": "…", "items": [{"where": "walk/down"}]}],
 "known": [{"rule": "outline.gap", "ok": false, "detail": "…", "items": [{"where": "idle/left"}], "known_by": "outline.gap @ idle/*"}],
 "info": [{"rule": "check.known_stale", "detail": "아무 경고와도 안 맞은 목록 항목 2", "items": [{"rule": "tone.flat", "where": "run/*"}]}]}
```

- 맞은 경고는 **지우지 않고** `known` 으로 옮긴다. `new_warnings` = `warnings` 에 남은 칸 수 (칸 없는 경고는 1).
- 안 맞은 목록 항목은 `info` 에 `check.known_stale` (낡은 항목 — 고쳐졌거나 이름이 바뀜).
- `check` 는 원래 경고로 status 를 바꾸지 않으므로 known 처리도 status 를 건드리지 않는다. `--fail-on-new` 로 새 경고가 있을 때만 fail 이 된다 (구현 때 바로잡음). 종료 코드는 지금처럼 `status == "fail"` 일 때만 `EXIT_CHECK_FAIL`(4) 라서 `ok` · `warn` 은 둘 다 0 — 기본 종료 코드는 그대로다.
- `--fail-on-new` 이고 `new_warnings > 0` 이면 `status: fail` → 4.
- `--known` · `--baseline` 을 안 주면 `known` · `new_warnings` 칸을 **안 넣는다** (보고 1바이트도 안 바뀜).
- `--no-warn` 과 같이 주면 `UsageError` (경고를 안 셌는데 뺄 것이 없다).

### 정한 것 둘

| 물음 | 정함 | 까닭 |
| --- | --- | --- |
| `must.*` 줄도 known 으로 빼나 | **못 뺀다.** 목록에 `must.*` 에 맞는 항목이 있으면 그 항목은 `info` 에 `check.known_must` 로 알리고 무시 | must 는 「이거 깨지면 출하 못 함」 이라 `fail` → 종료 4 계약이 걸려 있다. 목록 파일 하나로 실패를 조용히 끄면 게임 쪽 CI 가 깨진 그림을 통과시킨다. 정말 끄려면 프로필(`check.warn.*` 처럼 버전 관리되는 자리)에서 규칙을 바꾸는 게 맞다 |
| 프레임 길 `where` 의 글롭 | `anim/dir` 전체에 `fnmatchcase`, `*` 가 `/` 를 넘는다 | 게임 쪽 목록이 「이 애니 전부」 를 쓰는 일이 가장 많았다. 단계별 글롭(`**`)은 `where` 가 두 칸뿐이라 필요 없다 |

`.known` 곁 메모 파일(그림 옆에 두는 목록)은 뒤로 미룬다.

## 5. 호환

- 새 명령은 새 이름이라 깨질 것이 없다. `diff` · `mask` · `measure` · `fill` · `outline` 은 지금 최상위에 없음을 cli 에서 확인했다.
- 기존 명령 옵션은 모두 「안 주면 지금과 같음」 : `sheet`(`--strip` 끔 · `--scale auto` · `--kinds zoom`) · `tint`(`--gif` 없음) · `check`(`--in` 하나면 `where` 딱지 없음 · `--known` 없으면 보고 칸 그대로).
- **`check` 는 `LATE` 표 명령이 아니다.** `cli.run` 이 `check_mod.run(_profile(args), args.in_dir, args.no_ramps, **extra)` 로 직접 부르고, `check.run` 은 `args` 가 아니라 `build_dir` 하나를 받는다. 그래서 C9 · D 는 `check.run` 에 키워드 칸(`known=` · `fail_on_new=`)을 더하고, 입력 여럿은 `cli.run` 의 check 갈래가 입력마다 `check.run` 을 부른 뒤 새 함수 `check.merge(reports, labels)` 로 합친다. known 걸기는 합친 뒤 한 번 (`check.apply_known(report, items, fail_on_new)`).
- `check --in` 의 dest 가 `in_dir` → `in_dirs` 로 바뀐다. `REPORT_GUARDED`(cli 634줄)에 `in_dirs` · `known` · `baseline` 을 더한다 (목록 · 튜플을 이미 받는 코드다).
- `layerops._changed` 는 뜻 그대로 두고 안을 쪼갠다 — `layers diff` 시험이 그대로 통과해야 한다.

## 8. 못 정한 것

- `check --files @list.txt` — 여러 폴더 대신 파일 목록. C9 로 장면이 풀리는지 써 보고 정한다.
- `.known` 곁 메모 파일 — 그림 폴더 옆 목록을 저절로 읽을지. `--known` 실사용 뒤.
- `diff` 의 기본 방식(「색까지」) — 지금은 `--alpha-only` 필수로 자리만 비워 둔다.
- `fill` 의 다른 방식(`--at x,y` 한 점 채우기 등) — `draw/shapes.flood` 가 이미 있으니 장면이 나오면 붙인다.
- `outline` 의 selout 램프 출처 — 프로필 `ramps_file` 로 적었다. `draw/canvas.py` 가 램프를 어떻게 받는지 구현 때 확인한다.
