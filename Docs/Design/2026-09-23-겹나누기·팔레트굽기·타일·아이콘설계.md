> 상태 : **1판(`split` · `recolor`) 구현 끝 (2026-09-26).** 2판 · 3판은 아직 설계뿐이다.

## 1. 결론

1. **새 명령은 여섯이다.** `split` · `recolor` · `tile inspect` · `tile seam` · `tile preview` · `ui icons --badge/--rim`.
2. **판은 셋으로 나눈다.**

| 판 | 무엇 | 왜 이 순서인가 |
| --- | --- | --- |
| **1판 (이번)** | `split` + `recolor` + 떨어진 조각 검사 | 게임 저장소가 정한 그림 작업 순서의 ④⑤ 단계라 **캐릭터마다 매번 돈다.** 손 스크립트가 있어 되돌려 볼 기준(자리다름 0)이 이미 있다 |
| 2판 | `tile preview` → `inspect` → `seam` | 타일은 지금 PIL 로 그려 쓰고 있어 급하지 않다. 우선순위는 진행상황 문서에 이미 정한 대로 |
| 3판 (필요할 때) | `ui icons --badge` · `--rim` | **AI 로 아이콘을 다시 뽑는 판이 나오면** 한다는 결정을 그대로 둔다. 지금 들어간 아이콘은 PIL 로 그렸다 |

3. **「AI 는 짧은 JSON 만 뱉고 결과물은 코드가 만든다」(mem `20260822-0fde5d9b`)를 그대로 따른다.**
   AI 가 쓰는 것은 나누기 표(`split.json`)와 색표(`recolor.json`)와 배치표(`layout.json`)뿐이다.
   픽셀은 코드만 만진다.
4. **겹은 캔버스를 안 자른다.** 모든 겹이 원본과 같은 크기·같은 좌표계다. 손님 시험에서 이렇게 해서
   쌓았을 때 자리가 한 픽셀도 안 틀렸다 (자리다름 0).
5. **이름은 `split` · `recolor` 로 한다.** `layers` 는 이미 「LPC 층 겹치기」, `bake` 는 이미 「Unity 데이터 굽기」다.
   같은 낱말을 두 뜻으로 쓰면 README 표가 헷갈린다.
6. **`split` 이 받는 베이스 PNG 의 출처는 가리지 않는다. PixelLab 은 선택이다** (09-26 사용자 결정).

## 2. 지금 무엇이 있나 (새 명령이 붙는 자리)

| 있는 것 | 새 명령과의 관계 |
| --- | --- |
| `cli.py` — 인자만 넘기고 셈은 모듈이 한다. 서브명령 표 `run()` | 여섯 다 같은 꼴로 붙인다. `split`·`recolor` 는 맨 위, 나머지는 `tile`·`ui` 묶음 안 |
| `sprite/layers.py` — `<in>/<층>/<시트>.png` 를 `layer_order` 순으로 겹친다 | `split` 의 출력 폴더를 **이 꼴로 맞춘다.** 그러면 `arttool layers` 로 다시 쌓는 것이 곧 되돌림 검사가 된다 |
| `sprite/anchors.py` — 한 줄 = 한 점 `{rig, anim, direction, frame, point, x, y, z}` | `split` 의 앵커도 이 여덟 칸으로 쓴다. 새 형식을 안 만든다 |
| `image.replace_colors` — 정확일치 색 바꾸기 | `recolor` 의 몸통. 새로 짜지 않는다 |
| `check` 낱장 모드 — 색 수 · 램프 밖 색 · 반투명 | `split`·`recolor` 결과 폴더를 그대로 넣을 수 있다 |
| 프로필 `palette.swap: bake` | **받아들이기만 하고 아무 일도 안 한다** (`bake.py` 는 `runtime_lut`·`both` 때 LUT 만 굽는다). `recolor` 가 이 자리의 실제 길이 된다 |
| `paths.safe_join` · `jailed_output` | 출력 이름 틀(`out`)이 폴더 밖으로 못 나가게 여기로 거른다 |

## 3. `split` — 한 장을 겹 여러 장으로

### 3-1. 명령 꼴

```
arttool split --in clean/customer_red.png --spec split.json --out layers/ [--rig humanoid_parts] [--min-piece 8]
arttool split --in clean/customer_red.png --list-colors --out colors.json
```

| 인자 | 뜻 |
| --- | --- |
| `--in` | 한 장 PNG. 반투명이 있으면 거절한다 (색으로 가르므로 섞인 색은 못 가른다) |
| `--spec` | 나누기 표 JSON (아래). AI 나 사람이 쓴다 |
| `--out` | 출력 폴더. `<out>/<겹>/<원본이름>.png` + `<out>/split_report.json` + `<out>/anchors.json` |
| `--rig` | 주면 프로필 `rigs.<rig>.layer_order` 와 표의 겹 목록이 같은지 본다 |
| `--min-piece` | 떨어진 조각 검사의 기본 크기. 표에서 겹마다 덮어쓴다 |
| `--list-colors` | 나누지 않고 **색 목록만** 낸다. 색마다 개수 · bbox · y 범위. AI 가 표를 쓸 때 읽는 입력이다 |

### 3-2. 나누기 표 (`split.json`)

손 스크립트의 색표·자리 규칙을 그대로 옮긴 꼴이다. 색이 손님마다 달라 **그림 한 장에 표 한 장**이다.

```json
{
  "version": 1,
  "layers": ["body", "hair", "shirt", "face"],
  "default": "body",
  "outline": "#030202",
  "colors": {
    "#332E2B": "hair", "#58534F": "hair",
    "#FEEACD": "body", "#CD3A31": "shirt", "#FE9DA2": "face"
  },
  "rules": [
    { "color": "#332E2B", "below_y": 45, "to": "body" },
    { "color": "#030202", "box": [12, 29, 27, 34], "to": "face" },
    { "color": "#030202", "above_y": 29, "from": "body", "to": "hair" }
  ],
  "masks": { "hair": "masks/hair.png" },
  "layer_opts": {
    "face": { "min_piece": 0, "anchor": "bbox_center" },
    "hair": { "min_piece": 8, "anchor": "bbox_top_center" }
  }
}
```

규칙 한 줄의 칸은 아래와 같다. `color` · `to` 에 조건이 하나 이상 있어야 한다.

| 칸 | 뜻 | 언제 도나 |
| --- | --- | --- |
| `box` | 끝을 뺀 네모 `[x0, y0, x1, y1)` 안 | 자리 규칙 (2단) |
| `above_y` · `below_y` | `y < 값` · `y >= 값` | 자리 규칙 (2단) |
| `from` | 투표까지 끝난 뒤 **그 겹으로 갔던** 픽셀만 | 투표 뒤 규칙 (5단) |
| `near` | 8방향 이웃에 그 겹 픽셀이 있을 때만. 선택 | 투표 뒤 규칙 (5단) |

`from`·`near` 중 하나라도 있으면 투표 뒤 규칙이 된다. 같이 적은 `box`·`above_y`·`below_y` 는 그때 조건으로 같이 본다.

### 3-3. 가르는 순서

한 픽셀의 주인은 **아래 순서에서 먼저 정해진 것**이다.

1. **마스크** — `masks` 에 적은 PNG 의 불투명 자리는 그 겹이다. 색이 같아 표로 못 가르는 자리의 비상구다.
2. **자리 규칙** — `rules` 를 위에서부터 본다. `box`(네모 안) · `above_y`/`below_y`(높이) 셋만 둔다.
   손 스크립트가 쓴 것이 이 셋뿐이다 (머리↔신발은 높이로, 눈↔외곽선은 얼굴 네모로 갈랐다).
3. **색 표** — `colors` 에서 찾는다. 없는 색은 `default` 로 가고 **보고에 「표에 없는 색」으로 적힌다.**
4. **외곽선 투표** — `outline` 색이면서 아직 주인이 없는 픽셀은 이웃 겹의 표로 정한다.
   반경 1 → 2 → 3 → 4 → 6 으로 넓히며, 가까울수록 무겁게 센다 (`1 / (|dx|+|dy|+1)`). 끝까지 못 정하면 `default`.
   **한 반경에서 정해진 외곽선은 그 반경이 끝난 뒤 다음 반경 투표에 낀다.** 표가 같으면 먼저 표를 준 겹이 이긴다
   (위 줄부터, 줄 안에서는 왼쪽부터 훑는다). 둘 다 손 스크립트와 같다.
5. **투표 뒤 규칙** — `from` 이나 `near` 가 붙은 규칙은 투표가 끝난 뒤에 한 번 더 돈다.
   손 스크립트의 「이마 위 먹색은 몸이 아니라 머리카락」이 이것이다 (몸에 두면 머리를 벗겼을 때 이마에 점선이 남는다).
   손 스크립트는 「몸으로 간 먹색 + y < 29 → 머리」라 `{"from": "body", "above_y": 29}` 로 적는다. 머리카락에 닿아 있을 필요가 없다.

**되돌림 검사는 늘 돈다.** 겹을 `layers` 순으로 다시 쌓아 원본과 픽셀마다 견준다. 다른 픽셀이 하나라도 있으면
`status: fail`. 모든 픽셀이 정확히 한 겹에만 가므로 정상이면 0 이어야 한다.

### 3-4. 떨어진 조각 검사

손님 시험에서 긴 머리 겹에 **옷 색면이 잘못 간 세 점짜리 조각**이 남았다. 원본에서는 윗옷에 가려 안 보였다.

- 겹마다 불투명 픽셀을 **8방향 연결**로 덩어리를 묶는다 (손 스크립트와 같다).
- 가장 큰 덩어리가 아니면서 `min_piece` 보다 작은 덩어리를 **조각**으로 본다.
- **지우지 않고 옮긴다.** 조각 픽셀을 외곽선 투표와 같은 방법으로 이웃 겹에 다시 붙인다. 지우면 되돌림 검사가 깨진다.
  (손 스크립트는 굽는 단계에서 지웠다. 나누는 단계에서 옮기는 쪽이 원본을 안 잃는다.)
- 옮길 이웃이 없으면(허공에 뜬 조각) 옮기지 않고 **보고에 좌표만 적는다** → `status: warn`.
- **표정 겹은 `min_piece: 0` 이어야 한다.** 눈 · 입은 원래 2~4 픽셀짜리 떨어진 덩어리다. 기본값 8 을 모든 겹에
  걸면 눈이 몸으로 옮겨 간다. 그래서 겹마다 따로 적게 했다.

### 3-5. 앵커

- **점 이름 = 겹 이름.** 한 겹에 한 점. 여덟 칸 꼴 그대로 `{rig, anim: "split", direction: "south", frame: 0, point, x, y, z}`.
  `rig` 는 `--rig` 값, 없으면 원본 파일 이름.
- `x, y` 는 겹 bbox 에서 뽑는다. `anchor` 로 고른다 — `bbox_bottom_center`(기본) · `bbox_center` · `bbox_top_center`.
  좌표는 **캔버스 왼쪽 위 기준 정수**다 (mem `20260825-b0f5014b`). 가운데는 `floor(x + 0.5)` 로 한쪽에 고정한다
  (`fit_square` 와 같은 공식 — `.5` 가 짝수 쪽으로 튀는 것을 막는다).
- `z` 는 `layers` 순서 × 10 (몸 0 · 머리 10 · …). 10 단위로 띄워 사이에 겹을 끼울 자리를 남긴다 (기존 결정과 같다).
- 겹이 캔버스를 안 자르므로 **Unity 에서는 앵커 없이 겹을 같은 자리에 쌓기만 해도 맞는다.** 앵커는
  프리팹 부착점(예: 머리 위 말풍선 · 표정 자리)을 코드로 찾을 때 쓴다.

### 3-6. 보고 (`split_report.json`)

```json
{ "status": "ok", "roundtrip_diff": 0,
  "layers": { "hair": { "pixels": 412, "bbox": [8,10,40,46], "pieces_moved": [[33,49],[34,49],[34,50]] } },
  "unmapped_colors": [], "warnings": [] }
```

### 3-7. 이번 판에 안 넣는 것

- **가려졌던 자리 채우기(밑판).** 손 스크립트는 윗옷 실루엣을 살색으로 메우고 두상을 둥근 네모로 그렸다.
  실루엣 메우기는 일반화되지만 두상 모양은 그림마다 다르다. 2판 뒤에 `underfill` 규칙으로 따로 본다 (5절).
- **표정 새로 찍기.** 손 스크립트의 웃음·시무룩은 좌표를 손으로 찍은 것이라 명령이 아니라 그림 작업이다.

## 4. `recolor` — 겹 몇 장 + 색표 몇 벌 → N장

### 4-1. 명령 꼴

```
arttool recolor --in layers/ --spec recolor.json --out Unity/Art/Customer/ [--sheet preview.png --scale 2]
```

| 인자 | 뜻 |
| --- | --- |
| `--in` | 밑감 겹 폴더. 표의 `src` 는 이 폴더 기준 상대경로 |
| `--spec` | 색표 JSON (아래) |
| `--out` | 구운 PNG 폴더 + `recolor_report.json` |
| `--sheet` | 주면 구운 겹과 조합 예를 한 장에 늘어놓은 미리보기를 낸다. `--scale` 배로 키운다 (NEAREST) |

### 4-2. 색표 (`recolor.json`)

손 스크립트의 규칙 **「밑감의 색면 하나 → 결과의 색면 하나, 1:1. 밝기를 계산하지 않고 표에 적은 값을 그대로」**를
그대로 옮긴다. 계산으로 그늘을 만들면 원래 색과 같은 색을 골랐을 때도 살짝 어두워지는 사고가 손 스크립트에서 났다.

```json
{
  "version": 1,
  "outline": "#030202",
  "families": {
    "hair":  { "black": { "base": "#332E2B", "light": "#58534F", "dark": "#22201E" },
               "brown": { "base": "#7A4E2C", "light": "#9E6C43", "dark": "#5A3820" } },
    "shirt": { "red":   { "base": "#CD3A31", "shade": "#A32B23" },
               "blue":  { "base": "#3C74B5", "shade": "#2C588A" } }
  },
  "jobs": [
    { "src": "hair/customer_red.png", "family": "hair", "out": "hair_01_{v}.png",
      "roles": { "#332E2B": "base", "#58534F": "light", "#92836C": "light" },
      "drop_pieces": 0 },
    { "src": "body/customer_red.png", "out": "body.png" }
  ],
  "combos": [ ["body.png", "hair_01_black.png", "shirt_red.png", "face_01.png"] ]
}
```

- **`families`** = 색 한 벌 이름 → 역할(`base`·`light`…) → 색. 벌마다 한 장이 나온다.
- **`roles`** = 밑감 색 → 역할. 여러 밑감 색이 한 역할로 가도 된다 (손 스크립트의 광택 두 단이 그랬다).
- **`outline`** = 모든 겹의 외곽선을 이 한 색으로 맞춘다. 밑감마다 먹색이 1단 달랐다 (`#030202` vs `#030302`).
  바꿀 대상은 「`outline` 과 RGB 각 칸 차이 ≤ 2 인 어두운 색」으로 한정하고 보고에 적는다.
- `family` 가 없는 줄은 외곽선만 맞추고 그대로 복사한다 (몸 · 표정).
- `out` 의 `{v}` 는 벌 이름. 결과 경로는 `safe_join(--out, …)` 로 걸러 `..` 와 절대경로를 거절한다.

### 4-3. 규칙과 검사

- 알파는 건드리지 않는다. 역할에 없는 색은 그대로 둔다 — **대신 보고에 「표에 없는 색」으로 적는다.**
  빠뜨린 색이 조용히 옛 색으로 남는 것을 막는다.
- 벌의 색이 밑감 색과 같으면 그 픽셀은 바이트까지 같아야 한다 (시험으로 박는다).
- **자리 검사** : 결과마다 「불투명 칸」이 밑감과 같아야 한다 (자리다름 0). 색만 바꾸는 명령이라 어긋나면 버그다.
- `combos` 를 주면 쌓아서 미리보기에 넣는다. 조합은 AI 가 고르는 짧은 목록이고 쌓기는 코드가 한다.
- 떨어진 조각은 1판에선 `split` 에서 옮긴다. `recolor` 의 `drop_pieces` 는 **이미 나눠 둔 옛 겹**을 위한
  비상구로만 둔다 (기본 0 = 안 지움).

### 4-4. 기존 `palettes/` 램프와의 관계

지금 램프 파일은 **길이 6 짜리 램프**다. 손님 겹은 2~3단이라 그대로 못 쓴다. 1판은 `recolor.json` 안에 색을 직접 적는다.
나중에 벌 색을 `"base": "ramp:cloth_red[3]"` 처럼 램프 칸으로 가리키는 길을 열 수 있게 역할 값을 문자열로 둔다.

`split` 과 `recolor` 는 **제공자를 타지 않는다.** 그림을 만드는 것이 아니라 있는 그림을 가르고 칠하는 것이다.

### 5-1. 시험 (그림은 코드로 만든다)

| 명령 | 시험 |
| --- | --- |
| `split` | 네 색 인형 한 장 → 겹 넷, 되돌림 0 · 표에 없는 색은 `default` 로 가고 보고에 적힘 · `below_y` 로 같은 색을 머리/신발로 가름 · `box` 로 외곽선 색 눈을 표정에 · 외곽선 투표가 가까운 쪽에 붙음 · `near`·`from` 규칙(이마 먹색 → 머리) · 마스크가 색 표보다 먼저 · 세 점 조각이 이웃 겹으로 옮겨지고 되돌림 0 유지 · 표정 겹 `min_piece 0` 이면 눈이 안 옮겨짐 · 허공 조각은 `warn` · 앵커 여덟 칸·정수·z 10 단위 · `--rig` 의 `layer_order` 와 다르면 거절 · 반투명 입력 거절 · 잘못된 hex · 표에 없는 겹 이름 거절 · 출력이 `arttool layers` 로 다시 쌓여 원본과 같음 |
| `recolor` | 1:1 바꾸기 · 알파 유지 · 같은 색 벌이면 바이트까지 같음 · 여러 밑감 색 → 한 역할 · 외곽선 맞추기(차이 2 이내만) · 표에 없는 색 보고 · 자리다름 0 · `out` 에 `..` 거절 · `{v}` 없는 `out` 에 벌이 둘 이상이면 거절(덮어쓰기 막기) · `--sheet` 크기 |

## 6. 2판 — 타일 낱장 검사 셋

우선순위는 진행상황 문서 그대로 **preview > inspect > seam** 이다. 셋 다 `tiles/` 아래 새 파일 하나씩이다
(`preview.py` · `inspect.py` · `seam.py`). 팔레트가 없어도 돈다.

### 6-1. `tile preview` — 여러 장을 실제 칸 수로 조립

```
arttool tile preview --layout layout.json --in tiles/ --out preview.png [--scale 2]
```

배치표는 둘 중 하나다. AI 가 쓰는 짧은 JSON 이고 조립은 코드가 한다.

```json
{ "size": [12, 13], "weights": { "grass_0": 6, "grass_1": 2, "grass_2": 1 }, "seed": 3 }
{ "size": [3, 2], "cells": [["grass_0", "grass_1", "grass_0"], ["fence_l", "fence_m", "fence_r"]] }
```

`weights` 는 `seed` 로 섞어 반복 티를 보는 용도, `cells` 는 울타리처럼 자리가 정해진 것용. 칸 크기는 첫 타일 크기이고
크기가 다른 타일이 섞이면 거절한다. `layout` 에 없는 이름은 거절한다.

### 6-2. `tile inspect` — 낱장 한 표

```
arttool tile inspect --in tiles/ --report inspect.json [--size 32]
```

장마다 크기 · bbox · 불투명 비율 · 반투명 픽셀 수 · 색 수 · **네 변에 닿았나**를 한 줄로 낸다.
`--size`(없으면 프로필 `tiles.size`)와 다르면 fail, 반투명은 프로필 `check.allow_alpha` 를 따른다.
「캔버스 밖으로 새는 픽셀」은 **그림이 `--size` 보다 클 때 그 밖(오른쪽·아래 넘친 자리)의 불투명 픽셀 수**로 센다.

### 6-3. `tile seam` — 이음매

```
arttool tile seam --in tiles/ --report seam.json [--sheet seams.png] [--pairs]
```

- 한 장씩 **3×3 으로 이어 붙인** 그림에서 오른쪽↔왼쪽, 아래↔위 이음 줄을 본다.
- 픽셀아트는 이음 줄의 양쪽 색이 같을 필요가 없다. 그래서 **안쪽 이웃 칸끼리의 평균 색 차이**를 기준으로 삼고,
  이음 줄 차이가 그 `k` 배(기본 2.0)를 넘는 줄을 좌표와 함께 적는다.
- `--pairs` 면 변종끼리 모든 순서쌍(A 오른쪽 ↔ B 왼쪽)도 본다. 「같은 바탕의 변종 2~3장 섞기」 요청이 이것이다.
- `--sheet` 면 3×3 그림을 늘어놓아 사람이 눈으로 본다 (`image.contact_sheet`).

### 6-4. 시험

preview : 가중 섞기가 `seed` 로 같은 결과 · `cells` 자리 정확 · 크기 섞임 거절 · 모르는 이름 거절.
inspect : 크기 다름 fail · 반투명 셈 · 네 변 닿음 · 넘친 픽셀 셈.
seam : 이어지게 만든 무늬는 통과 · 한 줄 어긋나게 만든 무늬는 그 줄 좌표가 찍힘 · `--pairs` 순서쌍 수.

## 7. 3판 — 아이콘 `--badge` · `--rim`

`ui icons` 낱장 들이기(`gather`)에 옵션 둘을 더한다. 순서는 **badge → rim → fit.** 원 값은
`2026-09-20-재료아이콘작업피드백.md` 의 실측이다.

```
arttool ui icons --in raw/icons/ --out build/ui/ --badge 14x9 --rim 0.72,0.5 --fit 28
```

- **`--badge WxH`** — 왼쪽 위 W×H 구석에 **통째로 들어가는** 덩어리만 지운다 (`pieces.py`). 구석 밖으로 걸친 덩어리는
  그림일 수 있어 안 지우고 경고한다. 손 방식의 「그림이 구석까지 닿으면 못 쓴다」 약점을 이걸로 막는다.
- **`--rim f1[,f2…]`** — 투명과 4방향으로 맞닿은 픽셀 중, 밝기가 **안쪽 불투명 이웃 평균 밝기 × f** 보다 어두우면 지운다.
  값 하나당 한 바퀴. 두 번째를 같은 세기로 돌리면 알 사이 어두운 골이 뚫려서 두 번째는 0.5 로 약하게 둔다.
- 보고 `icons.json` 에 장마다 지운 픽셀 수를 적는다.
- 시험 : 구석 숫자 덩어리만 지움 · 걸친 덩어리는 남기고 경고 · 테두리 한 바퀴 걷힘 · 밝은 테두리는 안 걷힘 · 순서(badge→rim→fit).

| 앵커 | 겹마다 한 점, 기존 여덟 칸 꼴, bbox 에서 뽑음, z = 순서×10 | 기존 앵커 결정 두 개와 같게 |
| 색 바꾸기 | 1:1 표, 계산 안 함 | 손 스크립트에서 계산 방식이 어두워지는 사고를 냄 |
| 외곽선 맞추기 | 한 색으로. 차이 2 이내 어두운 색만 | 밑감마다 먹색이 1단 달랐다 |
| 표에 없는 색 | 바꾸지 않고 보고에 적는다 | 조용한 누락 막기 |
| AI 몫 | `split.json` · `recolor.json` · `layout.json` 세 JSON 뿐 | mem `20260822-0fde5d9b` |
| 공용 도우미 | `pieces.py`(덩어리) · `image.contact_sheet`(확대 비교 그림) | 1·2·3판이 같이 쓴다. PIL 피드백의 「×8 비교 그림」 요청도 이것 |

| `palette.swap: bake` | `recolor` 에 안 잇는다. README 에 「`recolor` 를 따로 부른다」 한 줄 | 9절 2번을 1판 구현에서 정했다. 잇는 길은 필요해질 때 |

| 외곽선 투표 방식 (리뷰 뒤 바꿈) | 반경마다 정해진 외곽선을 다음 반경 투표에 넣는다. 동점이면 먼저 표를 준 겹 (위 줄 → 왼쪽부터) | 손 스크립트가 되돌려 볼 기준이다. 처음엔 「투표 전 주인만 · 동점은 앞쪽 겹」으로 짰다가 게임 저장소 실물에서 8·5 픽셀이 달라 바꿨다. 바꾼 뒤 두 장 다 0 |
| 투표 뒤 규칙 칸 (리뷰 뒤 바꿈) | `from: <겹>`(그 겹으로 갔던 픽셀만)을 더하고 `near` 는 선택. `near` 는 8방향 이웃. 둘 다 마스크·자리 규칙으로 정한 픽셀은 안 덮는다 | 손 스크립트의 이마 규칙은 「몸으로 간 먹색 + 높이」라 머리카락에 닿을 필요가 없었다 |
| 조각 다시 보기 (리뷰 뒤) | 앞 겹에서 옮겨 온 조각은 뒤 겹 차례에 다시 조각으로 안 본다 | 옮긴 조각이 또 떠돌지 않게 |
| 이름 겹침 (리뷰 뒤) | 겹 이름 · `recolor` 출력 이름은 대소문자를 안 가리고 겹침을 거절한다. 되돌림 검사는 **저장한 파일을 다시 읽어서** 한다. `recolor` 출력이 밑감 원본과 같은 경로면 거절 | Windows 는 `hair`·`Hair` 가 한 폴더다 |
| 조각 옮기기 (구현 때) | 조각 하나를 통째로 한 겹에 옮긴다 (조각 픽셀 표를 합쳐 한 번 투표) | 픽셀마다 따로 보내면 조각이 또 쪼개진다 |
| `split` 판정 (구현 때) | 되돌림 다름 ≠ 0 → `fail` · 표에 없는 색 · 빈 겹 · 떠 있는 조각 → `warn` | `check` 와 같은 세 단계 |
| `replace_colors` (구현 때) | 자리를 원본에서 찾게 고쳤다. A→B · B→C 가 A→C 로 번지지 않는다 | 색표에 맞바꾸기가 들어오면 옛 코드는 틀렸다 |
